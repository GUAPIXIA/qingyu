## 2. 逐项核验

### [x] 1) Bridge 不再凭 fingerprint 直接续签 Token

* **旧问题**：已知 `fingerprint` 直接 `POST /auth/pair` 签发 30 天 Token。
* **修复**：`electron/bridge/routes.ts:POST /auth/pair` 删除 fingerprint 直签分支，强制 `consumePairingCode(pairingCode)` + `enqueuePendingPair` + `onPairRequest` + `PAIR_WAIT_TIMEOUT_MS 55s` 人工确认。
* **代码**：`routes.ts:193` 注释"fingerprint 仅作设备标识..." + `199` "始终挂起等待 PC 端人工确认"。
* **测试**：`electron/bridge/__tests__/auth.test.ts:配对码一次性`、`securityRegression` 未覆盖直签即失败（反向证明）。
* **判定**：通过。

### [x] 2) JWT 密钥不再明文落盘

* **旧问题**：`bridge/secret` 明文存储，读文件即可伪造任意 Token。
* **修复**：`electron/bridge/auth.ts:getJwtSecret` 优先 `getCredential('bridge-jwt-secret')`（`safeStorage` 加密），发现 `bridge/secret` 明文即 `randomBytes(32)` 轮换 + `unlinkSync`，并对 `plain:` 降级凭据同样处理。
* **边界**：`isEncryptionAvailable()==false` 且 `NODE_ENV=production` 时直接抛 `安全存储不可用，已拒绝启动 Bridge`，防降级泄露。
* **测试**：`auth.test.ts:发现旧明文副本时删除并轮换密钥，使旧 token 失效` + `密钥跨重启稳定（加密/降级两路径）` 3 项通过。
* **判定**：通过。

### [x] 3) WebSocket URL 不携带长期 Token

* **旧问题**：`ws://host:port/ws?token=<30天JWT>` 进代理/路由器日志。
* **修复**：`electron/bridge/ws.ts:WsHub.attach` 仅 `request.headers.authorization` 取 `Bearer`，完全不读 `query.token`；`electron/bridge/server.ts` 未注册任何 query 鉴权。
* **测试**：`securityRegression.test.ts:WS 拒绝 query 长期令牌，只接受 Authorization Header` — `ws?token=` 期望 `4001` 关闭，通过。
* **判定**：通过。

### [x] 4) `/static` 媒体路由完成鉴权

* **旧问题**：`/static/avatars|/covers|/messages|/group-messages` 无鉴权，Origin Guard 可被原生请求绕过。
* **修复**：`electron/bridge/server.ts:48` `app.use('/static', originGuard, requireAuth, buildStaticRouter())`，`requireAuth` 校验 `verifyAuthorizedToken` + 设备仍存在 + `tokenVersion`。
* **测试**：`securityRegression.test.ts:静态媒体要求有效 Bearer，设备吊销后立即失效` — `401 / 401 / 200 / 吊销后 401` 四段断言通过。
* **判定**：通过。

### [x] 5) MCP 高风险工具具有权限拦截与确认流程

* **旧问题**：模型返回 `tool_calls` 直接 `mcpManager.findToolServer` + `callTool`，提示词注入变 RCE。
* **修复**：`electron/mcp/toolPermission.ts:classifyToolRisk` L0-L3 + `requestToolPermission`（L0 自动允许，L1-L3 `dialog.showMessageBox` 逐次确认）+ `electron/services/toolLoop.ts:chatWithTools` 调用前 `await requestToolPermission`。
* **测试**：`electron/mcp/__tests__/toolPermission.test.ts` 3 项（L0 自动 / L1 拒绝 / L2 允许）通过。
* **判定**：通过。

### [x] 6) MCP Server 在每次启动前重新验证配置

* **旧问题**：`mcp-servers.json` 被离线篡改后 `autoStartAll` 直接 `spawn`。
* **修复**：`electron/mcp/manager.ts:startServer` 首行 `validateServerConfig(config)`（解释器黑名单/内联参数/相对路径/危险 env 校验），`autoStartAll` 逐个 `await startServer` 即逐个重验。
* **测试**：`electron/mcp/__tests__/manager.test.ts` 覆盖 `validateServerConfig` 的 `command/args/env/url` 异常抛错。
* **判定**：通过。

## 3. 风险与建议

* **Windows safeStorage 降级**：当前已做 `plain:` 隔离，但长期应引导用户启用系统凭据保护，`0.12` 诊断包可增加 `safeStorage` 可用性检测提示。
* **旧客户端兼容**：`v1 Adapter` 仍需在 `0.12` M3 保留，避免 Android 旧版直接 401。
* **MCP 审计**：`0.12` `waiting_approval` 需补 `tool:approval_required/resolved` 事件，当前 `dialog` 仅覆盖桌面端，Bridge 工具需 WS 转发确认。
