# 0.12 双链路差异矩阵（V12-01-1 冻结稿）

> 基准：`main@290d95b`（`v0.11.28` 已发布，`main` 为 `0.12.0-alpha.1`）  
> 核验范围：桌面 `src/store/streamController.ts` + `chatGeneration.ts` + `src/context/contextBuilder.ts` + `rendererContextProvider` vs 安卓 `electron/bridge/chatService.ts` + `electron/context/mainContextProvider.ts`  
> 目标：为 `ChatOrchestrator` 迁移提供“逐项对齐清单”，本文为冻结稿，后续行为变更以本文为准。

---

## 1. 执行路径总览

```
桌面端
  ChatPage -> useChatStore.sendMessage()
    -> window.api.regex.list() 取规则
    -> applyRegex(content, 'input')
    -> window.api.chat.saveMessage(userMessage)
    -> fetchSemanticLoreHits + fetchSemanticFacts (向量 RAG，异步预取)
    -> buildContext(character, preset, { continuation }) [rendererContextProvider]
    -> window.api.ai.chat(params) [streamController.ts: streamAIResponse]
    -> 主进程 electron/services/ai.ts -> provider adapter
    -> chunk via window.api.ai.onChunk/onDone/onError -> flushStream (50ms 节流)
    -> applyRegex(fullContent, 'output') + truncateAtStop(stopStrings)
    -> saveMessage(assistant) + usage.record + memory/compression/title 后处理

安卓端
  Android POST /api/v1/sessions/:id/messages
    -> BridgeChatService.sendMessage(requestId, content)
    -> mainContextProvider.fetchBuildData(characterId, sessionId) [读盘]
    -> applyRegexRules(content, rules, 'input', 'text')
    -> chatData.saveMessage(userMessage) [同一 JSONL]
    -> freshData = fetchBuildData (CR-2: 落盘后再读)
    -> buildContextMessagesFromData(freshData) + buildChatParamsFromData
    -> chatWithRetry(getAdapter, params, onChunk, signal) -> hub.broadcast('ai:chunk/usage')
    -> applyOutputRegexRules + truncateAtStop
    -> chatData.saveMessage(aiMessage) -> hub.broadcast('ai:done')
```

**核心差异**：桌面在渲染进程组装上下文、节流渲染、触发记忆/标题；Bridge 在主进程组装、广播 WS、60s 内存幂等、无向量 RAG。

## 2. 能力差异矩阵（15 项，逐项对齐策略）

| # | 能力 | 桌面 `streamController` | 安卓 `BridgeChatService` | 0.12 统一规则（Orchestrator） |
| --- | --- | --- | --- | --- |
| 1 | input 正则 | `get().applyRegex(content, 'input')`，经 `src/utils/regex.ts` | `applyRegexRules(content, rules, 'input', 'text')` 同一 `regex.ts`，但在主进程执行 | **Orchestrator 执行一次**，输入落盘前统一 `applyRegex(input, input-rules)`，渲染层不再预处理 |

| 3 | stopStrings | `streamController` 收集 `collectStopStrings`，流中 `findStopIndex` 截断并 `cancelChat` | `chatService` 末尾 `truncateAtStop`，流中不拦截（费 token） | **Orchestrator 统一**：流中每 chunk 检测、命中即 abort + flush，主链路省 token |

## 4. 0.12 迁移约束（冻结）

1. **不再双实现**：`0.12` 后 `applyRegex/collectStopStrings/triggerLorebooks/buildContext` 只在 `electron/chat/contextService.ts` 实现，渲染层 `contextBuilder.ts` 改为 thin wrapper 或删除。
2. **向量能力下沉**：`fetchSemanticLoreHits/Facts` 从 `streamController.ts` 迁入 `ContextService`，`mainContextProvider` 补 `embedding` 调用。
3. **正则两阶段固定**：`text` 阶段在 `input` 落盘前/ `output` 落盘前各一次，`markdown` 阶段仅 `output`，顺序不可换。
4. **停止语义固定**：流中命中 `stopStrings` 即 `abort`，保留已截断文本，`generationStatus: cancelled`。
5. **幂等键固定**：`requestId` 为持久唯一键，`Message.requestId` + `TaskStore requestId index` 双重保证。
6. **后处理固定**：`title/memory/compression` 均为 `task:completed` 后 `BackgroundJob`，失败不改主任务终态。

## 5. Golden Fixtures 覆盖清单（对接 V12-01-2）

每个 fixture 为 `输入 + 上下文快照 + 模型假响应 -> 预期消息`，按以下分组创建（见 `tests/golden/chat/`）：

* `input-regex/` 5 组（input 触发、大小写、未匹配）
* `output-regex/` 5 组（text + markdown 两阶段、未匹配）
* `stop-strings/` 5 组（流中命中/末尾命中/多命中/无命中）
* `lorebook-keyword/` 5 组（scanDepth/递归/概率/预算裁剪）
* `semantic-lore/` 3 组（阈值/向量命中合并）
* `semantic-facts/` 2 组（相关/无关回退）
* `vision/` 2 组（含图切换/无图不切换）
* `swipe-regenerate/` 3 组（追加候选/失败不破坏旧候选）
* `continue/` 2 组（续写去重/空续写）
* `memory-title/` 2 组（标题生成/记忆注入）

总计 ≥34 组，全部在 `0.12` 前以旧引擎跑通并快照锁定。
