## 二、优化原则

1. **先核心后外围**：优先解决影响角色扮演核心体验的问题（世界书、token 预算、prompt 控制）。
2. **保持轻量定位**：不盲目照搬 ST 全部功能，取舍标准是"对中文用户开箱即用的价值"。
3. **每步可验证**：每阶段有明确验收标准 + 测试。
4. **向后兼容**：不破坏现有数据格式（会话、角色、世界书、预设）。

## 四、阶段 0：基础加固（v0.9.0）

> 目标：修正文档失实、补齐工程短板，为后续阶段打地基。

### 0.1 修正 README 失实承诺

- **问题**：README 宣称世界书支持"常量 / 向量索引 / LLM 三种匹配模式"，实际只有关键词匹配。
- **改动**：
  - [ ] 审计 README 全部功能宣称与代码实现的一致性
  - [ ] 删除或标注未实现功能，避免误导用户
  - [ ] 建立"功能状态表"文档（docs/功能状态.md），列明 已实现 / 部分实现 / 未实现
- **验收**：README 每项宣称均能在代码中找到对应实现或明确标注"规划中"。

### 0.2 接入真实 tokenizer（tiktoken + Claude/Gemini 编码）

- **问题**：`electron/services/tokenizer.ts` 预留了 tiktoken 接入点但依赖未安装，默认启发式估算对中文/Claude/Gemini 偏差大。
- **改动**：
  - [ ] 安装 `tiktoken` 依赖
  - [ ] 完善 `MODEL_ENCODING_MAP`：Claude（`cl100k_base` 近似但应为 Anthropic 官方分词）、Gemini（`o200k_base` 近似）
  - [ ] 中文字符启发式系数校准（对 3.4 ch/tok 等系数做实测校准）
  - [ ] 增加 `getEncoding` 失败兜底 + 日志
  - [ ] 补充 tokenizer 单元测试（中文/英文/混合/代码）
- **验收**：对 100 条真实消息样本，token 估算与 API 返回的 `usage.prompt_tokens` 误差 < 10%。

### 0.3 建立 CI（GitHub Actions）

- **改动**：
  - [ ] `.github/workflows/ci.yml`：pnpm install → lint → tsc check → vitest run
  - [ ] `.github/workflows/build.yml`：electron:build 产物上传 artifact
- **验收**：推送即跑，红绿清晰。

### 0.4 补充关键路径测试

- **问题**：128 个单测集中在解析器/Store，AI 适配层、IPC、流式、群聊时序无覆盖。
- **改动**（优先级从高到低）：
  - [ ] AI 适配层：4 个 provider 的请求构造 / 响应解析 / 错误处理
  - [ ] 流式解析：SSE chunk 拼接、断流、`<thinking>` 剥离
  - [ ] IPC 层：`safeHandle` 错误传播
  - [ ] 群聊时序：polling 调度、mention 提取、speaker 切换
- **验收**：核心路径覆盖率 ≥ 50%（可用 vitest coverage 统计）。

## 五、阶段 1：核心体验（v0.9.x）

> 目标：把角色扮演的"地基"对齐 ST——世界书、token 预算、prompt 控制。

### 1.1 世界书深度对齐（最高优先级）

**现状**：关键词/正则匹配 + 3 档 position + scanDepth，单层。

**改动**：

- [ ] **插入顺序 4 档**：`before_char` / `after_char` / `at_depth` / `at_end`，`at_depth` 按消息深度注入（ST 的 `depth` 语义）
- [ ] **双层级世界书**：全局世界书（LorebookPage 现有）+ 角色内嵌世界书（角色卡 `character_book` 字段，导入时已提取，需支持"内嵌条目参与触发"）
- [ ] **优先级 + 概率**：`order` 已存在，补 `probability` 触发骰子逻辑
- [ ] **递归扫描**：当前 `scanDepth` 只扫最近 N 条，ST 语义为"关键词出现在第 N 层时激活其子条目"，补子条目递归
- [ ] **选择性激活**：条目级 `enabled` + 收藏/临时激活开关
- [ ] **matchMode 落地**：如 README 承诺保留向量/LLM 匹配，则在此阶段实现（见 1.4 RAG）或从文档移除

**涉及文件**：`shared/types.ts`、`src/utils/lorebook.ts`、`src/store/useChatStore.ts`（buildContext）、`electron/ipc/lorebook.ts`、`src/pages/LorebookPage.tsx`

**验收**：
- [ ] 世界书条目可按深度注入并显示注入位置
- [ ] 角色卡内嵌世界书可独立启用/触发
- [ ] 导入 ST 世界书 JSON 后触发行为与 ST 一致（用 ST 导出样例回归）

### 1.2 作者注释（Author's Note）

- [ ] 新增 `AuthorNote` 配置：内容、启用、注入深度、注入位置（顶部/中部/底部）
- [ ] `buildContext` 增加 AN 槽位，纳入 token 预算
- [ ] 角色级 + 全局级两级 AN
- [ ] 设置页 + 快捷设置入口

**验收**：AN 出现在指定深度，预算裁剪正确，关闭即完全移除。

### 1.3 上下文模板（Context Templates）

- [ ] 预设增加可选 `contextTemplate` 字段：system 前缀/后缀、user 包装、assistant 包装、停止序列
- [ ] 预设编辑 UI 支持模板配置（高级模式折叠）
- [ ] `buildContext` 按模板包装消息（替换现在 `chatTemplates.ts` 仅服务 Ollama 的硬编码逻辑）
- [ ] 内置模板：ChatML / Llama3 / Alpaca / Mistral / Qwen

**验收**：Ollama 的 DeepSeek/Qwen 等模型可用对应模板正常对话，无需手工拼 prompt。

### 1.4 向量 RAG（Vectors）

> 若 1.1 保留"向量匹配"承诺则必须做；否则可移至阶段 4。

- [ ] 引入嵌入模型（本地：Ollama 嵌入 / 远程：OpenAI embeddings）
- [ ] 世界书条目向量化存储（SQLite + 简单余弦检索，或 `hnswlib`）
- [ ] 对话记忆向量检索（Memory 升级，见 1.5）

**验收**：语义相关世界书条目可被触发（如"猫娘"触发含"猫咪"的条目）。

### 1.5 长记忆升级

- [ ] 现状：总结最近 N 条消息的单摘要模式
- [ ] 升级：摘要 + 关键事实抽取，按会话存储；可选向量检索注入
- [ ] 记忆注入位置、预算、开启粒度（会话级/角色级）

**验收**：长对话中跨 100 轮的事实（角色名字、地点）能被模型回忆。

### 1.6 正则系统增强

**现状**：`pattern + replacement + flags + scope(input/output/both)`。

**改动**：
- [ ] 增加 **触发器**（trigger：消息前 N 条 / 消息内容匹配才执行）
- [ ] 增加 **停止字符串**（output 命中后终止生成）
- [ ] 增加 **Markdown 解析阶段介入**（ST 的 `markdown` 处理模式）
- [ ] 正则脚本**分组**管理（按用途：翻译修复 / 格式清理 / 越狱清理）
- [ ] 支持**预览测试**（输入样例 → 显示替换结果）

**验收**：ST 社区常用正则脚本（如去重、引号修复）可直接粘贴使用。

## 七、阶段 3：生态扩展（v0.11.x）

> 目标：扩大提供商覆盖面与宏能力。

### 3.1 API 提供商扩展

按优先级：
- [ ] **OpenRouter**（路由聚合，一个 key 全模型）
- [ ] **vLLM / LM Studio / TabbyAPI**（本地推理，OpenAI 兼容但需特化：vLLM 需要 `extra_body`、LM Studio 需要模型重载等）
- [ ] **NovelAI / KoboldAI / Horde**（角色扮演社区常用）
- [ ] 提供商注册表重构：`ProviderType` 从联合类型改为可注册的适配器表（为阶段 4 扩展系统铺路）

### 3.2 TTS 提供商扩展

- [ ] 架构抽象：`TTSEngine` 接口（现有 edge/openai/fish 三实现）
- [ ] 新增：ElevenLabs、Silero、OpenAI 已有时补流式播放
- [ ] 语音设置面板：语速/音调/音量调节

### 3.3 翻译后端扩展

- [ ] `Translator` 接口：现有 LLM 翻译保留
- [ ] 新增：DeepL（免费 key）、Google 网页翻译（免费、无需 key）、本地 Sugoi
- [ ] 双语对照模式（原文 + 译文，ST 的"translated"模式）

### 3.4 宏系统扩展

- [ ] 内置宏扩展：`{{time}}` `{{date}}` `{{random:选项A|选项B}}` `{{newline}}` `{{group}}` `{{lastMessage}}` 等
- [ ] 宏注册表：`src/utils/macros.ts`，各功能模块可注册自定义宏
- [ ] 快捷回复 / 预设 / 世界书 / 用户人设中全部支持宏展开
- [ ] 编辑器中宏自动补全提示（ST 的 autocomplete）

### 3.5 Token 预算精细管理

- [ ] 分层预算：system / AN / 世界书 / 聊天历史 / 记忆 各自上限与占比（替换现 `lorebookRatio` 单一比例）
- [ ] 超预算时优先级队列：世界书 > 记忆 > 历史（可配置）

## 八、阶段 4：架构演进（v1.0.x）

> 目标：从"封闭单机应用"走向"可扩展平台"。

### 4.1 最小扩展系统

- [ ] **声明式 manifest**：`manifest.json`（名称/入口/权限声明/UI 挂载点）
- [ ] **渲染进程扩展 API**：注册面板（侧栏入口）、注册命令（斜杠命令）、注册设置页、事件订阅（消息发送/接收/生成完成）
- [ ] **主进程扩展 API**：IPC 通道注册（受限白名单）
- [ ] **扩展安装器**：本地目录扫描 + ZIP 安装 + 启停开关
- [ ] 内置扩展迁移试点：将快捷回复（2.1）、表情（2.2）做成首个内置扩展验证机制

**验收**：一个 20 行的第三方示例扩展（如"发送消息时 ping 音效"）可零改源码安装运行。

### 4.2 本地 Web 服务模式（多端访问）

- [ ] Electron 内嵌 HTTP 服务（Express），复用现有 IPC 服务逻辑（`electron/services/` 与 HTTP 层解耦）
- [ ] 局域网访问：同网段手机浏览器可用（读取角色、对话、发送消息）
- [ ] 可选密码保护（复用 `safeStorage` 的加密能力存密码哈希）
- [ ] 移动端基础 UI 适配（响应式，低优先级做）

### 4.3 数据互通（ST 兼容导出）

- [ ] 对话导出为 ST `chats/*.jsonl` 格式
- [ ] 世界书导出为 ST worldinfo JSON 格式（与导入形成闭环）
- [ ] 预设导出为 ST preset 格式

### 4.4 自动更新

- [ ] electron-updater 接入（GitHub Releases 或自建服务器）
- [ ] 版本检查 + 增量更新提示

## 附：风险与注意事项

1. **数据格式变更风险**：世界书加字段（matchMode 等）需做旧数据迁移（`storage.ts` 读取时兜底默认值）。
2. **tokenizer 体积**：tiktoken 的 BPE 文件会增加打包体积，评估放 `asar` 外或按需下载。
3. **RAG 依赖取舍**：向量库选型优先"零原生依赖"（纯 JS 实现），避免 Electron 打包原生模块的坑。
4. **扩展系统安全**：扩展运行在渲染进程，需权限声明 + 白名单，防止恶意扩展读文件（复用 `pathGuard`）。
5. **每个阶段结束做一次回归**：跑 `pnpm test` + 手工验证核心链路（发消息→流式→swipe→世界书触发）。
