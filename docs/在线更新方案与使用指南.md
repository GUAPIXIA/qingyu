## 一、整体架构

```
┌─────────────────┐   检查/下载/安装    ┌──────────────────────┐
│  渲染层           │ ◄────IPC──────► │  主进程 updater 服务     │
│  UpdaterSection  │                  │  electron-updater       │
└─────────────────┘                    └──────────┬───────────┘
                                       优先 │        │ 兜底
                                            ▼        ▼
                              ┌────────────────┐  ┌──────────────────┐
                              │ 自托管镜像源      │  │ GitHub Releases  │
                              │ /qingyu/update  │  │ GUAPIXIA/qingyu  │
                              └────────────────┘  └──────────────────┘
```

| 环节 | 说明 |
|---|---|
| **镜像源（优先）** | 公告服务端静态目录，国内用户下载快；未配置或检查失败自动跳过 |
| **GitHub Releases（兜底）** | CI 自动发版的权威来源，保证任何情况下都能检查到新版本 |
| **增量更新** | NSIS `differentialPackage: true`，只下载 blockmap 差异部分，大幅减少流量 |

## 二、更新流程

1. **检查更新**：镜像源配置存在 → 先请求 `<镜像>/latest.yml` 比对版本；无更新或失败 → 回退 GitHub API。
2. **发现新版本**：状态变为 `available`，展示版本号与更新日志。
3. **手动下载**：用户点击下载，`download-progress` 事件实时推送百分比进度条。
4. **重启安装**：下载完成进入 `downloaded` 状态，点击「重启安装」退出并静默安装；即使不点击，下次启动应用时也会自动完成安装（`autoInstallOnAppQuit: true`）。

> 设计取舍：`autoDownload = false`，即**不自动下载**，由用户确认后再下载，尊重流量与带宽选择。

## 三、代码结构

### 主进程

| 文件 | 职责 |
|---|---|
| `electron/services/updater.ts` | 核心服务：双通道检查（`checkWithFeed`）、semver 比较、状态机、事件转发 |
| `electron/main.ts` | `app.whenReady` 后调用 `registerUpdaterIPC(ipcMain)` |

关键实现细节：

- **动态窗口引用**：IPC 注册时机早于 `createWindow()`，因此每次推送事件时通过 `BrowserWindow.getAllWindows()[0]` 动态获取主窗口，避免缓存空引用。
- **延迟加载**：`electron-updater` 通过动态 `import()` 加载，开发模式下检查失败会优雅降级为 error 状态而非崩溃。
- **版本比较**：内置 `semverGt()` 纯函数（主干数值逐段比较，预发布后缀低于正式版），不依赖 `builder-util-runtime` 类型。

### IPC 接口

```
updater:check      检查更新（镜像→GitHub）
updater:download   下载更新包
updater:install    退出并安装
updater:getState   当前状态快照
updater:getMirror  读取镜像源配置
updater:setMirror  写入镜像源配置（http/https 白名单校验）
updater:event      状态变化主动推送（shared/ipc-channels.ts）
```

### 共享契约（shared/ipc-api.ts）

```typescript
type UpdaterStatus = 'idle' | 'checking' | 'available' | 'none'
                   | 'downloading' | 'downloaded' | 'error'

interface UpdaterState {
  status: UpdaterStatus
  message: string
  version?: string        // 新版本号
  releaseNotes?: string   // 更新日志
  percent?: number        // 下载进度（downloading 时有效）
  source?: 'mirror' | 'github'
}

interface UpdaterAPI { check/download/install/getState/getMirror/setMirror/onEvent }
```

渲染层通过 `window.api.updater.*` 访问，`onEvent(listener)` 返回取消订阅函数。

### 渲染层

`src/pages/settings/UpdaterSection.tsx` —— 设置页「软件更新」卡片：

- 当前版本显示 + 检查更新按钮
- 发现新版本：显示版本号、可展开更新日志、「下载更新」按钮
- 下载中：进度条 + 百分比
- 下载完成：「重启安装」绿色高亮按钮
- 高级设置（折叠）：镜像源地址输入框，留空仅走 GitHub

### 构建配置（package.json > build）

```jsonc
{
  "artifactName": "QingYu-Setup-${version}.${ext}",  // ASCII 命名，避免中文文件名 URL 问题
  "nsis": {
    "differentialPackage": true                       // 增量更新（blockmap）
  },
  "publish": [
    { "provider": "github", "owner": "GUAPIXIA", "repo": "qingyu" }
  ]
}
```

## 四、发版操作指南

### 标准发版流程

```bash
# 1. 提升版本号（patch/minor/prerelease 三选一，脚本会同步更新 package.json 与 CHANGELOG）
pnpm version:minor

# 2. 手动整理 CHANGELOG.md：将 [Unreleased] 内容归档为 [x.y.z] - 日期

# 3. 提交并打标签
git add -A
git commit -m "release: v0.x.y - 版本主题描述"
git tag v0.x.y

# 4. 推送（tag 触发 release 工作流）
git push origin main v0.x.y
```

### CI 自动化（.github/workflows/release.yml）

推送 `v*` 标签后，GitHub Actions 自动执行：

1. pnpm 安装依赖（Windows runner）
2. 类型检查 + 渲染层构建（`pnpm build`）
3. 主进程 esbuild 编译
4. `electron-builder --win nsis --publish always` 发布到 GitHub Releases

产物清单（自动上传）：

```
QingYu-Setup-x.y.z.exe            # NSIS 安装包
QingYu-Setup-x.y.z.exe.blockmap   # 增量差异文件
latest.yml                        # electron-updater 版本清单
```

## 五、服务端镜像部署

### 服务端改动

`server/app/server.js` 新增 `/update` 静态路由：

- 目录默认为 `app/data/updates/`（Docker 卷内，重启持久），可用环境变量 `UPDATES_DIR` 覆盖
- `latest.yml` 强制禁用缓存（防止客户端读到旧版本清单），其余文件缓存 24h

### 发版后同步镜像

将 GitHub Release 的三个产物放入服务器目录：

```bash
scp latest.yml QingYu-Setup-x.y.z.exe QingYu-Setup-x.y.z.exe.blockmap \
    server:/path/to/qingyu/app/data/updates/
```

### 客户端接入镜像

设置页 → 软件更新 → 高级设置 → 镜像目录 URL：

```
http://cjbtj.xyz/qingyu/update
```

（nginx 剥 `/qingyu` 前缀转发到服务端 3000 端口，对应服务端路由 `/update`）

## 六、用户体验

| 场景 | 表现 |
|---|---|
| 已是最新版本 | 「已是最新版本」提示 |
| 镜像不可达 | 静默回退 GitHub，用户无感知 |
| 两者都失败 | error 状态显示具体错误信息 |
| 开发模式检查 | 「当前环境不支持在线更新」友好降级 |
| 未配置镜像 | 直接走 GitHub |

## 七、注意事项与已知限制

1. **仅限安装版**：在线更新只对 NSIS 安装器安装的正式版生效。开发模式、解压直跑版本不支持，需引导用户至少手动安装一次 v0.14.0+。
2. **未签名警告**：当前 `signAndEditExecutable: false`，首次安装/更新时 Windows SmartScreen 会提示"未知发布者"，不影响功能。未来购买证书后只需在 `win` 配置补充签名项即可，更新链路无需改动。
3. **镜像一致性**：若镜像源 `latest.yml` 与安装包版本不一致（如只传了 yml 忘了 exe），客户端会校验失败报错——发版时务必三个文件一起上传。
4. **测试覆盖**：`electron/services/__tests__/updater.test.ts` 覆盖 semver 比较与镜像配置白名单（7 例）；完整更新链路需打包后真机验证：
   ```bash
   pnpm electron:build   # 产出 release-v2/QingYu-Setup-x.y.z.exe
   ```
5. **CSP 提示**：生产 CSP 的 `connect-src` 已含 `https:`，HTTP 镜像源在开发模式可用，生产环境建议镜像也走 HTTPS。
