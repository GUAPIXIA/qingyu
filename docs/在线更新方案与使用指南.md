## 一、整体架构

```
┌─────────────────┐    检查/下载/安装    ┌──────────────────────┐
│  渲染层           │ ◄─────IPC──────► │  主进程 updater 服务     │
│  UpdaterSection  │                   │  双源结果独立保存         │
└─────────────────┘                    └──────────┬───────────┘
                                      并行检查 │        │ 并行检查/自动更新
                                               ▼        ▼
                              ┌────────────────┐  ┌──────────────────┐
                              │ 官方服务器        │  │ GitHub Releases  │
                              │ /qingyu/update  │  │ GUAPIXIA/qingyu  │
                              └────────────────┘  └──────────────────┘
```

| 环节 | 说明 |
|---|---|
| **官方服务器** | 固定读取 `https://cjbtj.xyz/qingyu/update/latest.yml`，展示服务器版本并提供手动下载 |
| **GitHub Releases** | 与服务器并行检查；负责自动下载、增量更新和安装 |
| **增量更新** | NSIS `differentialPackage: true`，只下载 blockmap 差异部分，大幅减少流量 |

## 二、更新流程

1. **检查更新**：并行获取服务器和 GitHub 两份 `latest.yml`，分别保留版本或错误结果。
2. **展示结果**：分别显示服务器最新版本与 GitHub 最新版本；单个来源失败不影响另一来源。
3. **发现新版本**：任一来源高于当前版本时显示对应手动下载；GitHub 有新版时额外提供自动下载。
4. **自动下载**：始终由 GitHub Provider 执行，`download-progress` 事件实时推送百分比。
5. **重启安装**：下载完成进入 `downloaded` 状态，点击「重启安装」退出并静默安装；即使不点击，下次启动应用时也会自动完成安装（`autoInstallOnAppQuit: true`）。

> 设计取舍：`autoDownload = false`，即**不自动下载**，由用户确认后再下载，尊重流量与带宽选择。

## 三、代码结构

### 主进程

| 文件 | 职责 |
|---|---|
| `electron/services/updater.ts` | 核心服务：固定双源并行检查、GitHub 自动下载、状态机、事件转发 |
| `electron/main.ts` | `app.whenReady` 后调用 `registerUpdaterIPC(ipcMain)` |

关键实现细节：

- **动态窗口引用**：IPC 注册时机早于 `createWindow()`，因此每次推送事件时通过 `BrowserWindow.getAllWindows()[0]` 动态获取主窗口，避免缓存空引用。
- **延迟加载**：`electron-updater` 通过动态 `import()` 加载，开发模式下检查失败会优雅降级为 error 状态而非崩溃。
- **版本比较**：GitHub 采用 `electron-updater` 判定，服务器清单使用同规则 SemVer 比较，正确处理 `beta.2 → beta.10` 等预发布版本。

### IPC 接口

```
updater:check      并行检查服务器与 GitHub
updater:download   下载更新包
updater:install    退出并安装
updater:getState   当前状态快照
updater:event      状态变化主动推送（shared/ipc-channels.ts）
```

### 共享契约（shared/ipc-api.ts）

```typescript
type UpdaterStatus = 'idle' | 'checking' | 'available' | 'none'
                   | 'downloading' | 'downloaded' | 'error'

interface UpdaterState {
  status: UpdaterStatus
  message: string
  version?: string
  releaseNotes?: string
  percent?: number
  server?: UpdateSourceResult
  github?: UpdateSourceResult
  hasAvailableUpdate?: boolean
}

interface UpdaterAPI { check/download/install/getState/onEvent }
```

渲染层通过 `window.api.updater.*` 访问，`onEvent(listener)` 返回取消订阅函数。

### 渲染层

`src/pages/settings/UpdaterSection.tsx` —— 设置页「软件更新」卡片：

- 当前版本显示 + 检查更新按钮
- 检查完成：分别显示服务器与 GitHub 最新版本
- 发现新版本：按实际可用来源显示手动下载；GitHub 有新版时显示自动「下载更新」
- 下载中：进度条 + 百分比
- 下载完成：「重启安装」绿色高亮按钮
- 未发现新版：隐藏服务器、GitHub 和夸克手动下载区域
- 不提供镜像源配置

### 构建配置（package.json > build）

```jsonc
{
  "artifactName": "QingYu-Setup-${version}.${ext}",  // ASCII 命名，避免中文文件名 URL 问题
  "nsis": {
    "differentialPackage": true                       // 增量更新（blockmap）
  },
  "publish": [
    { "provider": "github", "owner": "GUAPIXIA", "repo": "qingyu" }
  ]
}
```

## 四、发版操作指南

### 标准发版流程

```bash
# 1. 提升版本号（patch/minor/prerelease 三选一；脚本更新 package.json）
pnpm version:minor

# 2. 手动整理 CHANGELOG.md：将 [Unreleased] 内容归档为 [x.y.z] - 日期

# 3. 提交并打标签
git add -A
git commit -m "release: v0.x.y - 版本主题描述"
git tag v0.x.y

# 4. 推送（tag 触发 release 工作流）
git push origin main v0.x.y
```

### CI 自动化（.github/workflows/release.yml）

推送 `v*` 标签后，GitHub Actions 自动执行：

1. pnpm 安装依赖（Windows runner）
2. 校验 Git tag 与 `package.json` 版本完全一致
3. 类型检查 + Lint + 全量单元测试
4. 渲染层与主进程构建
5. `electron-builder --win nsis --publish always` 发布到 GitHub Releases

产物清单（自动上传）：

```
QingYu-Setup-x.y.z.exe            # NSIS 安装包
QingYu-Setup-x.y.z.exe.blockmap   # 增量差异文件
latest.yml                        # electron-updater 版本清单
```

## 五、服务端镜像部署

### 服务端改动

`server/app/server.js` 新增 `/update` 静态路由：

- 目录默认为 `app/data/updates/`（Docker 卷内，重启持久），可用环境变量 `UPDATES_DIR` 覆盖
- `latest.yml` 强制禁用缓存（防止客户端读到旧版本清单），其余文件缓存 24h

### 发版后同步镜像

将 GitHub Release 的三个产物放入服务器目录：

```bash
scp latest.yml QingYu-Setup-x.y.z.exe QingYu-Setup-x.y.z.exe.blockmap \
    server:/path/to/qingyu/app/data/updates/
```

### 客户端接入服务器

客户端固定读取官方地址 `https://cjbtj.xyz/qingyu/update/latest.yml`，不再提供用户自定义镜像选项。Nginx 剥 `/qingyu` 前缀转发到服务端 3000 端口，对应服务端路由 `/update`。

## 六、用户体验

| 场景 | 表现 |
|---|---|
| 两个来源均为当前版本 | 分别显示两个版本号，不显示手动下载区 |
| 服务器不可达 | 显示服务器获取失败，GitHub 更新仍可用 |
| GitHub 不可达 | 显示 GitHub 获取失败，服务器有新版时提供手动下载 |
| 两者都失败 | error 状态显示两个来源的具体错误信息 |
| 仅服务器有新版 | 显示服务器手动下载，不提供自动更新 |
| GitHub 有新版 | 自动更新默认通过 GitHub 下载 |
| 开发模式检查 | 「当前环境不支持在线更新」友好降级 |

## 七、注意事项与已知限制

1. **仅限安装版**：在线更新只对 NSIS 安装器安装的正式版生效。开发模式、解压直跑版本不支持，需引导用户至少手动安装一次 v0.15.0+。
2. **未签名警告**：当前 `signAndEditExecutable: false`，首次安装/更新时 Windows SmartScreen 会提示“未知发布者”。正式版只请求 HTTPS 清单和安装包，但 HTTPS 不能替代代码签名；未来配置签名证书后，更新链路无需改动。
3. **服务器一致性**：服务器 `latest.yml` 与安装包必须同步（安装包与 blockmap 先上传，`latest.yml` 最后替换），否则手动下载可能失败。
4. **测试覆盖**：`electron/services/__tests__/updater.test.ts` 覆盖双源并行结果、单源/双源失败、版本差异、开发模式、SemVer 与静默安装；渲染层覆盖条件展示、导航和外链；完整更新链路需打包后真机验证：
   ```bash
   pnpm electron:build   # 产出 release-v2/QingYu-Setup-x.y.z.exe
   ```
5. **固定地址**：服务器更新地址内置在主进程，不读取历史自定义镜像配置；请求不受渲染层 CSP 控制。
