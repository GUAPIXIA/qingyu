# 阶段 8 前置决策冻结（威胁模型 / 配额 / 对象存储 / 保留 / 轮换运维）

> 日期：2026-09-24  
> 依据：总方案 §8、§13.7；阶段 8 实施方案 §S8-01～S8-07。  
> 状态：已冻结（实现按本表执行；变更须单独立项）

## 1. 恶意服务端威胁模型

| 能力 | 服务端可见 | 服务端不可见 / 不可做 |
|---|---|---|
| 元数据 | spaceId、deviceId、entityType/entityId、schemaVersion、versionHash、dot、deleted、updatedAt、cipherHash、contentTag、密文长度、server_seq | 明文 payload、contentHash（业务）、spaceKey、API Key |
| 主动攻击 | 丢弃/重排/重放旧密文、拒绝服务、伪造 404、篡改 contentTag | 替换待批公钥后仍通过客户端校验（须带外 SAS + 批准设备 Ed25519 签名） |
| 日志/备份 | 只允许 requestId、批次大小、状态、耗时、错误码 | 正文、密文本体、token、key envelope、口令 |

**强制校验（客户端）**：

1. 密钥信封必须：transcript 与带外二维码/SAS 一致 + 批准设备 Ed25519 签名通过 + 解封后 challenge 可解密。
2. contentTag 相等但解密后 contentHash 不同 → 安全错误，拒绝自动收敛。
3. 密码库失败 fail closed，禁止明文回退。
4. 恢复包仅用户显式导出；服务端不可找回 spaceKey。

## 2. 恢复包 KDF（与 `shared/sync-crypto/types.ts` 一致）

| 项 | 值 |
|---|---|
| 算法 | scrypt（RFC 7914）——评估 Argon2id 后冻结：Node `crypto.scrypt` 与 BouncyCastle 双端零原生依赖 |
| 最低参数 | N≥2^15, r=8, p=1, dkLen=32（导入拒绝低于此或参数降级） |
| 导出推荐 | N=2^18, r=8, p=1, dkLen=32 |
| 口令 | 长度 ≥12 且至少 2 类字符 |
| 错误次数 | 调用方限流（UI 连续 5 次失败锁定 5 分钟） |
| 恢复后 | 立即轮换 spaceKey（`rotateAfterRestore: true`） |

## 3. 空间配额默认值（S8-05）

| 配额项 | 默认值 | 说明 |
|---|---|---|
| 实体总量 | 100 000 | 计 `sync_entity_heads` 行（含 tombstone） |
| 密文总字节 | 524 288 000（500 MiB） | DB 小实体 + 对象存储 blob 合计 |
| 单 blob | 67 108 864（64 MiB） | 超过拒绝，不切业务实体 |
| 单次 batch | 200 条 / 4 MiB | 与 PC `/sync/v1` 同参 |
| 设备数 | 10 | 含已退役未 GC |

超额：plan 显示所需/剩余；push **原子拒绝**整批；已提交数据不无提示删除。

## 4. 对象存储

| 项 | 决策 |
|---|---|
| 用途 | 大 ciphertext（>32 KiB）与 blob 分块 |
| 开发/单机 | 本地目录适配器 `RELAY_OBJECT_DIR`，key = 随机 32B hex，**不含**用户文件名/实体 ID |
| 生产 | S3 兼容；服务端加密（SSE）为第二层，不替代 E2EE |
| 小实体 | 直接存 `sync_entity_heads.ciphertext` |
| GC | 先标记 orphan → 延迟 7 天 → 核对 ref_count 与 committed manifest 后删除 |

## 5. 保留期

| 对象 | 保留 | 清理条件 |
|---|---|---|
| tombstone | 180 天 | 所有未退役设备 ack，或用户显式退役后 |
| `sync_batches` | 24 小时 | 过期可删（幂等窗口） |
| `sync_sessions` | 2 小时 | 过期 aborted |
| key envelope | 直至 epoch 轮换完成且全设备确认 | 旧 epoch envelope 可删 |
| orphan blob | 标记后 7 天 | ref_count=0 且无 committed manifest |

## 6. 密钥轮换运维（S8-06）

```text
设备吊销 / 怀疑泄漏
  → 持钥客户端创建 keyEpoch+1（服务端只记 epoch/状态）
  → 新写入只用新 epoch
  → 用户显式「维护」触发历史重加密
  → 可恢复游标 (fromEpoch, fromCipherRevision, lastEntityType, lastEntityId)
  → 每条只增 cipherRevision，不产生业务 dot/冲突
  → 完成并全设备确认后删除旧 key envelope
```

中断 0%/50%/commit 后均可从游标恢复。服务器不能独立重加密。

## 7. 对阶段 8 编码的约束

1. 服务端不解析加密 payload；只校验 envelope 元数据、version 结构、hash、大小与授权。
2. 并发 heads 同时保存，禁止 last-write-wins。
3. `dot.deviceId` 必须等于已认证调用设备；counter 单调不复用。
4. 重加密批次独立权限 + cipher revision，不伪造业务 dot。
5. 不使用业务 WebSocket；未点击同步不建 session、不刷 token。
