## 3. 发布阻断问题

### P0-01：恶意备份可写出应用数据目录

**位置：** `electron/services/backup.ts:258-280`、`electron/services/backup.ts:320-353`

恢复流程只对角色、世界书、预设的 JSON 文件名调用 `safeId`，聊天、群聊、图片及嵌套路径没有进行路径归一化后的根目录约束。外部工具生成的 ZIP 可以保留 `../` 条目，例如：

```text
characters/../../outside.txt
```

该条目会通过 `startsWith('characters/')`，随后：

```text
join(DIRS.characters(), '../../outside.txt')
```

会解析到角色目录之外。构造测试确认 `adm-zip` 读取外部 ZIP 时保留此条目名。

问题还被哈希策略放大：清单中没有对应哈希的条目只记录警告并继续恢复（`backup.ts:261-264`），因此攻击者甚至不必为新增恶意条目伪造哈希记录。

**验收要求：**

- 拒绝绝对路径、盘符、反斜杠变体、空路径、`.` 与 `..` 段。
- 对最终 `resolve(dest)` 做根目录边界校验，确保仍位于允许的目标根目录内。
- ZIP 中每个非目录条目都必须在 manifest 中有哈希；manifest 中的哈希条目也必须在 ZIP 中存在。
- 增加真实服务级测试，覆盖 `characters`、`chats`、`groups`、图片和 Windows 路径变体。

### P0-02：备份宣称不含凭据，但实际仍会导出敏感信息

**位置：** `electron/services/backup.ts:33-52`、`electron/services/backup.ts:106-115`、`shared/types.ts:518-528`

设置清理仅覆盖四类模型集合，遗漏：

- `settings.semanticTrigger.apiKey`；
- `mcp-servers.json` 中的 `env`，界面明确允许填写 `API_KEY=xxx` 等变量。

与此同时，设置页和 manifest 都显示“API Key / 凭据未包含”，会给用户错误的安全预期。

**验收要求：**

- 将语义检索 Key 纳入安全存储和备份剥离流程。
- MCP 环境变量不能原样进入备份；至少按敏感键规则脱敏，更稳妥的做法是将 MCP 凭据单独存入安全存储。
- 增加导出 ZIP 内容断言，直接搜索测试凭据文本，确保整个压缩包不存在明文密钥。

## 4. 高优先级问题

### P1-01：恢复失败时会留下半导入数据

**位置：** `electron/services/backup.ts:304-377`

代码注释称“先写临时目录，再原子移动”，但实际逐文件直接写入正式目录；失败时只恢复 config 单文件，已经写入的角色、世界书、聊天和群聊不会回滚。用户可能得到配置已回滚、业务数据只恢复一部分的混合状态。

建议先完整解压到临时根目录、完成格式和哈希校验，再按数据域原子替换；若采用增量合并，也必须在界面明确恢复语义并提供完整回滚。

### P1-02：设置页“已保存”不代表磁盘保存成功

**位置：** `src/pages/SettingsPage.tsx:56-63`、`src/store/useSettingsStore.ts:231-240`

页面在任意设置变化后固定等待 500 ms 就显示“已保存”，没有等待 IPC 保存结果；Store 又捕获并吞掉保存异常。因此磁盘写入失败时，界面仍会显示绿色“已保存”。

建议由 Store 暴露 `idle / saving / saved / error` 状态，以真实 Promise 结果驱动，并提供失败原因与重试入口。

### P1-03：MCP 添加弹窗不支持基本键盘操作

**位置：** `src/pages/mcp/McpServerFormModal.tsx:16-37`

实测结果：

- 打开后辅助功能焦点仍停留在根文档；
- `Tab` 没有进入弹窗表单；
- `Esc` 无法关闭；
- 弹窗容器没有 `role="dialog"`、`aria-modal`、标题关联和焦点圈定。

这说明通用 `Modal` 的改进没有覆盖 MCP 自定义弹窗。建议统一使用已完善的通用弹窗组件，避免页面继续自建遮罩层。

### P1-04：多个侧栏分组同时展开时，底部导航不可见

**位置：** `src/components/layout/Sidebar.tsx:185-248`

在 1266×800 窗口中同时展开“资源”和“系统”后，“用量 / 设置 / 公告 / 帮助”出现在可访问性树中，但视觉上被底部状态区裁掉；在侧栏区域滚轮滚动也没有移到这些项目。用户必须先猜测并收起其他分组。

建议让分组成为手风琴（一次只展开一个），或修正 flex 滚动容器的 `min-height: 0` / 高度约束，并加入展开后自动滚入视图。

## 5. 一般问题与未完成项

### P2-01：`electron:preview` 脚本打开空白窗口

**位置：** `package.json:14`、`electron/main.ts:34,74-78`

脚本执行构建后直接运行 `electron .`。此时 `app.isPackaged` 仍为 false，主进程会加载 `http://localhost:5173`，但脚本没有启动 Vite 服务，因此得到空白窗口。开发模式 `pnpm electron:dev` 正常。

### P2-02：世界书只有搜索和导入，仍没有批量操作

世界书列表与条目搜索已生效，导入入口也可见；但没有多选、批量启用/停用、批量删除或批量绑定等能力。此前“搜索与批量操作”的完善目标只完成了一半。

### P2-03：角色管理首次进入时长时间空白且无加载反馈

实测点击“角色卡”后约 0.5 秒仍是纯空白主区域，约 2.5 秒后才显示列表。数据量较大时页面同时渲染大量卡片文本和图片，冷加载期间没有骨架屏或加载状态。

### P2-04：构建体积仍偏大

Renderer 主 chunk 为 946.25 kB（gzip 287.90 kB），Vite 给出超限警告。角色页的大数据首屏表现与该问题叠加，建议继续拆分公共依赖并对长列表做虚拟化或分页。

- 对话头部主要操作更简洁，字符数口径可识别。

- 世界书具有世界书搜索、条目搜索和导入入口。
- 公告页显示未读状态、最后更新时间和刷新按钮。
- 用量页明确说明当前是字符统计，Token 和费用仍在开发中。
- MCP 的 SSE 选项已禁用并明确提示后端暂未实现。
- 通用 Tooltip 已改善键盘聚焦能力；通用 Modal 的改进通过现有单测，但自定义弹窗仍需统一。

## 8. 建议的修复顺序

1. 修复 ZIP 路径边界、完整哈希白名单和敏感字段剥离，并补真实 Backup V2 单测。
2. 把恢复流程改为可完整回滚的事务式流程。
3. 让设置保存状态由真实 IPC 结果驱动。
4. 统一 MCP 等自定义弹窗到通用 Modal，完成焦点圈定、Esc 和 ARIA。
5. 修复侧栏小高度下的导航可达性。
6. 清理 lint、修复 preview 脚本，再处理首屏加载与 chunk 体积。

## 9. 建议发布门槛

只有同时满足以下条件后再进行候选版本验收：

- P0、P1 全部关闭；
- `check`、`test`、`lint`、`build` 全绿；
- 使用真实 `createBackupV2` / `restoreBackupV2` 完成临时目录中的导出、清空、恢复、内容比对与恶意 ZIP 拒绝测试；
- 800px 与 720px 高度下所有侧栏入口可见或可滚动到达；
- 键盘仅使用 Tab / Shift+Tab / Esc 可以完成并退出所有主要弹窗。
