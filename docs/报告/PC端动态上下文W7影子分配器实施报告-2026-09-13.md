## 3. 分配器契约（§5.5）

### 3.1 候选

`ContextCandidate` 字段与主计划 §5.5 一致：`id / kind / estimatedTokens / mandatory / stablePrefix /
relevance / recency / importance / continuity / dedupeKey? / originalOrder`，另加只用于解释的 `origin?`。

- `kind` 八类：`protocol`、`character`、`current-state`、`memory`、`worldbook`、`history`、`example`、`group-state`；
- 候选**不携带正文**：只有 id、枚举、计数与 0~1 数值，因此影子记录在结构上不可能泄露内容；
- 未知 `kind` 退化为 `history`，空 `id` 生成 `candidate#<index>`（确定性，不引入随机）。

### 3.2 顺位与评分

- 顺位（§5.5 六步顺序的机械表达）：`mandatory → 0`；`group-state` 与"近期历史"（`recency ≥ 0.5`）→ 1；
  `current-state` 与"高相关记忆/世界书"（`relevance ≥ 0.5`）→ 2；`example`、低相关记忆、较早原始历史 → 3；
- 块内评分：`rel×0.35 + rec×0.25 + imp×0.25 + con×0.15`（权重合计 1，保留 6 位小数消除浮点噪声）；
- 排序：`顺位 → 评分降序 → originalOrder → id`（四级 tie-break，保证缓存前缀不抖动）；
- 分母口径：`0.35/0.25/0.25/0.15`、`RECENT_HISTORY_RECENCY = 0.5`、`HIGH_RELEVANCE_THRESHOLD = 0.5` 均为导出常量，改动会先打红定向测试。

### 3.3 选择算法与不变量

```
净化 → 去重（同 dedupeKey 留最优）→ 确定性排序
  → mandatory 全量保留（即使超出预算）
  → 其余"能放下就放，放不下跳过继续"
```

- **不超预算**：预算可行时 `selectedTokens ≤ effectiveBudgetTokens`；
- **mandatory 永不静默丢弃**：mandatory 单独超预算时置 `mandatoryOverBudget = true` 并返回，由上层按定义降级（W9），
  不在分配器内截断协议或角色核心；
- **单调性**：预算增大时，被移除的块顺位一律低于新入选的块（"不用低优先块挤掉高优先块"）；
- **确定性**：同输入两次分配结果一致，且不修改入参；
- **鲁棒**：NaN / Infinity / 负 token / 负分 / 空候选 / 预算 0 均不抛出，非有限 token 记 0。

## 4. 影子运行接线

### 4.1 登记点（全部为真实注入点）

协议（system prompt / jailbreak / 叙事模式 / thought 契约 / 正文格式尾部 / post-history / 续写指令）、
角色（角色核心、用户人设、作者注释）、当前状态、记忆（当前状态、逐条事实带 `fact:<id>` 去重键、时间线）、
世界书（按渲染锚点分桶 + `chat_depth`）、示例、历史（压缩摘要 + 保留下来的逐条消息，图片按 `IMAGE_TOKEN_ESTIMATE` 计入同一条）。

### 4.2 开关与生命周期

- `BuildOptions.shadow?: 'shadow' | 'off'`，默认 `'shadow'`；`'off'` 只服务对照测试与性能敏感场景，
  **不是产品开关、不落设置、不是回滚轨道**（§4.1 禁止的第三套开关不成立）；
- 采集器只存在于单次构建的局部作用域，不注册服务、不监听事件、不写盘；
- `collect()` 幂等；异常兜底为 `degraded: true` 的零值报告，生成链路不受影响；
- 每轮多一次逐块 `estimateTokens`（O(注入块数)），不读盘、不走网络。

### 4.3 报告与日志

`BuildResult.contextShadow`（可选字段，向后兼容）含：`budgetTokens / effectiveBudgetTokens /
existingTokens / existingReportedTokens / shadowTokens / deltaTokens / overBudget / mandatoryOverBudget /
existingOverBudget / candidateCount / selectedCount / droppedCount / dedupedCount /
stablePrefixSelectedTokens / byKind[] / degraded`。非 preview 构建额外落一行数值日志：

```
上下文影子分配：mode=shadow budget=7290 existing=18872 shadow=18780 delta=-92 over=1 mandatoryOver=1 cand=14 sel=7 dedupe=0 degraded=0 kinds=protocol:763->763/6->6,character:18036->18017/2->1,...
```

日志与报告只含枚举、计数与 id（`protocol:system-prompt`、`history:msg:<id>`、`worldbook:before_character`），不含内容。

## 5. 序列化后审计接口骨架（§5.6）

`auditSerializedInput(view, options)` 只做聚合，不做裁剪：

- 输入 = 各片段之和；总量 = 输入 + 与 `maxTokens` 同源的输出预留 + 协议安全余量（默认取 `1 − TOKEN_BUDGET_SAFETY`，单一来源）；
- 计数精度只允许 `exact / provider-reported / estimated`，**整体口径取最弱环节**：只要有一处估算就不宣称精确；
- 超限时返回 `overBudget` 与 `remainingReallocations = 1`（§5.6：只允许回到分配器降级一次），适配器不得私自截消息；
- `serialized: false`（本期调用方默认）即"仅估算"骨架态，`serializedViewMissing` 显式标记；
- 真实接入点（各 provider 的序列化视图 + provider tokenizer）属 W9，本期不做。

## 10. 口径差异与解释（"差异可解释"验收）

1. **`existingReportedTokens` 与 `existingTokens` 不相等是预期的**：
   既有 `lastContextUsage.used` 不含保留下来的历史正文 token（`cropHistory` 在内部累加、不回写外层），
   影子分类求和含历史正文；同时既有 used 按合并后的 `systemContent` 整体估算（含 `【当前状态】` 等小节标题与连接符），
   影子按块分别估算，故影子可能略低于既有 used。本机差值 < 5%（定向测试断言差值有界）。
2. **影子与既有选择在中长窗口下一致**：既有 `cropHistory` + 固定比例已经把总量压进 `budgetBase`；
   分配器的价值在于**归因**（哪一类吃了多少 token）与**不可行时的显式告警**，而不是"立刻改变选择"。
3. **世界书候选使用桶级占位评分**：`renderPlan` 只保留文本，逐条真实评分（关键词/语义/实体/近因）属 W9 接入范围；
   在 W9 之前，世界书差异只能解释到锚点桶级别。
4. **记忆事实使用中性相关度 0.5**：事实在 `fitLayeredMemoryBudget` 内被重排后，外部 `semanticScores` 不再与数组对齐；
   W8 从检索层直接透传真实分数后即可精确排序。
   > 更新（2026-09-13，W8）：已由 [W8 动态记忆注入实施报告](./PC端动态上下文W8动态记忆注入实施报告-2026-09-13.md)
   > 落实——记忆三层改为候选化，事实相关度直接复用官方 `scoreAndRankFacts`；本文件描述的 W7 行为仅作为历史口径保留。
5. **1M 场景的"不塞满"含义**：分配器**从不填充**（`selectedTokens` 只由候选总量决定），
   因此大窗口下的正确验收是"预算收紧时低价值尾部先丢、高优先块不丢"，而不是"大窗口下少选"。
