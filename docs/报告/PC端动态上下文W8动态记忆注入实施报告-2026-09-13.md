## 3. 候选化设计

### 3.1 三层映射

| 层 | 候选 | 顺位/评分 |
|---|---|---|
| 当前状态 | `memory:current-state`（单块，`dedupeKey: memory:state`） | `kind: 'current-state'` → 第 3 顺位（§5.5 第 3 条），`relevance 0.9 / recency 1 / importance 0.9 / continuity 0.9` |
| 结构化事实 | `memory:fact:<factId>`（逐条，`dedupeKey: fact:<factId>`） | `relevance` = **官方 `scoreAndRankFacts` 评分**；`importance = importance/5`；`recency` 取官方值；`continuity 0.4`。高相关事实落入第 3 顺位，回退口径下按 importance+recency 排序 |
| 时间线 | `memory:timeline:<index>`（按行/句切块） | `relevance 0.6` → 第 3 顺位；块内按近因排序（**新事件先保留**），`continuity = 0.3 + 0.4×recency` |

- 事实评分**只有一个来源**（`scoreAndRankFacts`），W7 影子中的"中性 0.5"占位已由本包替换；
- 非 active 事实不进入候选；旧字符串事实用位置 id（`legacy-<index>`），**不把内容写进 id**；
- 时间线切块：按行 → 超长行按句末标点再切（不依赖正则 lookbehind，各端一致）→ 相邻小块贪心合并到目标
  ~90 token → 条数超过 48 时把最早若干块并成一块（**保留文本，只减少候选数量**）。

### 3.2 与传统层内截断的两处有意差异（接管前需 G1 复核）

1. **时间线截断方向**：既有 `fitLayeredMemoryBudget` 的 `truncateMemoryText` 保留**开头**、截掉**末尾**；
   候选口径按近因保留**最新事件**、让位**最旧事件**。理由：记忆总结要求"最多 8 条按时间顺序排列的简短事件"，
   末尾即最近事件，对连续性影响最大。该差异在影子报告里可见（`timeline` 层 `candidateDroppedCount`）。
2. **记忆可占用的空间**：既有实现把记忆限制在 `min(800, budgetBase×0.1)`；候选口径不设上限，
   只在统一预算内与协议/角色/历史/世界书/示例竞争（§5.5 顺序）。极端样本下记忆可占到窗口的大部分——见 §5.3 复核项。

## 4. §7.10 验收证据（纯函数与端到端）

| 验收项 | 用例 | 结果 |
|---|---|---|
| 小模型安全降级 | 预算 = 对手全部 + 当前状态 + 一半时间线 | mandatory 与最近连续对话 100% 保留（`competitor.selectedTokens = 1100`）；当前状态保留；时间线部分保留、部分让位；`overBudget = false` |
| 预算极紧 | 8K 窗口 + 超长角色卡（mandatory 接近吃满） | 记忆整体让位（`selectedTokens = 0`），`overBudget = false`，候选集合与 `described` 不变 |
| 大模型可超过 800 | 200K 窗口 + 60 条事实 + 8 行时间线 | 既有 `existing = 584 ≤ cap 800`；候选 `candidate = 1751`，`exceedsLegacyCap = true`，`delta = +1167`（事实 11 → 60 条） |
| 简单话题可少注入 | 40 条全量事实 vs 3 条语义命中 | 命中计划 `factCount = 3`、`factTokens` 与 `selectedTokens` 均显著更小 |
| 失败可退原选择 | 竞争集合故意抛错 | 报告 `degraded = true`；**既有口径原样保留**、候选侧归零；不抛出，注入仍由既有实现决定 |
| 任何失败不删除记忆 | 分配后比对输入事实与候选集合快照 | 逐字节相等；模块无写接口，`dropped` 仅表示"本轮不注入" |

## 5. 匿名数值观测（本机测试构建，无内容）

### 5.1 16K 默认单聊

```text
mode=memory-shadow budget=15072 cap=800 existing=414 candidate=414 delta=0 exceedsCap=0 droppedFacts=0 droppedTimeline=0 retrieval=fallback
layers=current-state:49->49/1->1,fact:138->138/6->6,timeline:227->227/3->3
```

既有与候选一致：内容远小于预算，两层不需要取舍。

### 5.2 200K 大窗口 + 60 条事实（§7.10「大模型可超过 800」）

```text
mode=memory-shadow budget=189507 cap=800 existing=584 candidate=1751 delta=1167 exceedsCap=1 droppedFacts=0 droppedTimeline=0 retrieval=fallback
layers=current-state:94->94/1->1,fact:263->1430/11->60,timeline:227->227/3->3
```

既有实现把 60 条事实压到 11 条（800 token 口径），候选口径可保留全部 60 条。

### 5.3 8K 小窗口 + 超量记忆（200 条事实 + 60 行时间线）

```text
mode=memory-shadow budget=7290 cap=729 existing=690 candidate=6407 delta=5717 exceedsCap=1 droppedFacts=7 droppedTimeline=0 retrieval=fallback
layers=current-state:49->49/1->1,fact:240->4624/10->193,timeline:401->1734/5->20
```

**接管前复核项（请 G1/产品决策）**：极端样本下候选口径把记忆放到窗口的 88%（6407/7290），
仅剩 mandatory 与最近连续对话的空间。mandatory 与近期对话未被挤占（`overBudget = false`），
但"事实条目在极小窗口下的实际价值"需要人工评审：可选处置是给记忆一个**可配置软占比**（而不是新的硬上限，
后者违反 §7.10 第 3 条），或在 W9 的降级顺序里把低相关事实排到示例之后。
