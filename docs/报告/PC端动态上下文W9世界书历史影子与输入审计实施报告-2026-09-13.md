## 1. 结论

按主计划 §7.11，在 G1 未通过的前提下，本包只交付**可对照的影子能力**，不切换任何生产注入：

1. **世界书逐条评分**：`executeLorebookRuntime` 透出无正文的 `scoredEntrySnapshots`（key / score / priority / position / tokens / kept）；影子侧 always→mandatory，评分复用统一 score（关键词+语义+实体+近因），与全部非世界书块在统一剩余预算内竞争。
2. **历史分级降级**：`planHistoryDegradation` 按「保留最近 → 摘要替代被裁剪旧史 → 再删原文」产出对照计划；`cropHistory` 生产路径未改。
3. **序列化后输入审计接线**：对 `BuildResult.messages` 构建估算视图（`serialized:false`）并跑 `auditSerializedInput`；超限只报告一次重分配额度，不在本层裁剪。

验收对照（§7.11）：空间足够时完整注入；接近上限时显式 `mandatoryOverBudget` / 分层让位；关键块（always/协议）不被低价值历史静默挤出；审计不私自截消息；计数精度只报 `estimated`。

## 3. 世界书逐条评分影子

### 3.1 运行时快照（W7→W9 补口）

W7 只有桶级占位评分（`renderPlan` 只保留文本）。本包在 `executeLorebookRuntime` 返回前组装 `scoredEntrySnapshots`：

- key：条目定位键（无内容）；
- score：统一评分（已含关键词/语义/实体/近因权重）；
- priority：always / conditional / detail；
- position / depth / order；
- tokens：既有保留条目按注入正文（summary 替代时用 summary）估算，丢弃条目按原文估算；
- kept / usedSummary / ignoreBudget。

字段只挂在结果上，**分配与注入逻辑不读它**。

### 3.2 候选化与 always→mandatory

`buildWorldbookCandidateSet`：

| 优先级 | mandatory | importance | 备注 |
|---|---|---|---|
| always | **true** | 0.9 | §7.11 第 2 条；预算可行时不得丢 |
| conditional | false | 0.55 | relevance = 统一 score |
| detail | false | 0.35 | 同上 |

- 丢弃条目也进入候选（接管对照需要「既有没注入」一侧）；
- `at_depth` 不进稳定前缀；before/after_character 与 prompt_end 进稳定前缀；
- `dedupeKey = lore:<key>`。

### 3.3 影子报告

`buildWorldbookShadowReport`：既有固定比例（`legacyCapTokens = budgetBase × lorebookRatio`）vs 候选统一预算选择；竞争对手为协议/角色/记忆/历史/示例（由 `contextBuilder` 传入 `shadow.collectedCandidates()` 中非 worldbook 块）。

样例日志：

```text
世界书影子分配：mode=worldbook-shadow budget=15072 cap=4521 existing=22 candidate=22 delta=0 exceedsCap=0 alwaysSel=1/1 alwaysDrop=0 mandatoryOver=0 degraded=0 layers=always:12->12/1->1,conditional:10->10/1->1,detail:0->0/0->0
```

## 4. 历史分级降级影子

`planHistoryDegradation`（§7.11 第 4 条）：

1. 复用 `cropHistory`（或调用方已有 crop 结果）得到最近保留段；
2. 被裁剪范围若被既有 `compressedSummary` + `compressedRange` **完整覆盖** → 整段 `replace-with-summary`；
3. 否则 → `drop-raw`（无摘要可替代时不假装有摘要）。

生产侧仍是「crop → 覆盖则注摘要」；影子只把「摘要替代 vs 原文删除」变成可解释计数。

样例日志：

```text
历史降级影子：mode=history-degradation budget=1702 existingKept=349 existingSummary=17 candRaw=349 candSummary=17 replace=1 drop=0 delta=0 degraded=0
```

## 5. 序列化后输入审计接线

- `buildSerializedInputViewFromMessages`：按 role 映射片段，token 估算，`serialized: false`，精度一律 `estimated`；
- `auditMessagesAsSerializedInput`：叠加输出预留与协议安全余量，返回 `overBudget` 与 `remainingReallocations = 1`；
- **不在本层裁剪**（§5.6）：适配器不得私自截消息；真正的供应商序列化视图仍待适配器接入后把 `serialized` 置 true。

样例日志：

```text
输入审计（估算）：input=944 reserved=518 safety=820 total=2282/16384 over=0 accounting=estimated
```

## 8. 口径差异与解释

1. **世界书 `deltaTokens` 在中小窗口常为 0**：既有分桶已把总量压进 `legacyCap`；统一池差异在「cap 外仍可能选入高分条目 / always 不被历史挤出」时出现（纯函数测试覆盖突破 cap 与 mandatoryOver）。
2. **历史降级 `deltaTokens` 在覆盖场景为 0**：既有路径已注摘要，候选侧同样用摘要替代，差值应为 0；价值在于**归因**（replace vs drop）而非立刻改选择。
3. **输入审计超限 ≠ 上下文超限**：审计把 `budgetBase` 与 `maxContext` 分开；估算视图含全部消息，可能因安全余量触发 `overBudget`，与 `lastContextUsage.used` 口径不同（可解释）。
4. **桶级占位仍保留**：仅在 `scoredEntrySnapshots` 缺失时回退（旧缓存/异常路径），保证分类差异不消失。
