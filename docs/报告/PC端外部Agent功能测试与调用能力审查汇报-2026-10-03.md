# PC 端外部 Agent 功能测试与调用能力审查汇报

> 日期：2026-10-03  
> 状态：📖 参考 — 外部自动化能力静态审查，未启动工具建设  
> 产品基线：PC `0.18.0` 与审查时本地工作区；已有其他任务的源码/脚本改动，本次未修改它们。  
> 用户确认范围：其他 Agent 通过**终端命令和外部 MCP 工具**调用、测试 PC 功能。自然语言由外部 Agent 理解，PC 端继续运行现有功能。  
> 修订说明：替代此前把需求理解为“在应用内添加自然语言助手”的报告；此前普通聊天是否向模型提供工具清单的判断，不作为本需求的缺口依据。

## 1. 结论

**PC 已有丰富的业务接口和多类自动化测试基础，但还缺少供其他 Agent 稳定使用的统一调用层。** 外部 Agent 目前通常需要自己阅读源码、编写脚本、选窗口、调用 preload 或点击界面，再自行拼装断言和证据。

因此，当前的问题是测试与调用接口分散、场景脚本不够通用、状态与证据缺少统一协议。可在外部工具侧改善这些能力，无须增加应用内 AI 助手、改变聊天入口或给 PC 模型增加工具清单。

建议建设独立工具包：**CLI 与 MCP → 同一动作注册和运行器 → 实际 Electron 的现有 preload/IPC 或真实界面 → 结构化结果与证据。** 同时保留服务级脚本和 mock 浏览器回归，并明确它们各自能证明什么。

## 2. 本次审查范围

外部 Agent 收到“帮我测试新建角色、修改设置和会话导出”，应能发现相关动作、创建隔离客户端、调用现有功能、等待结束、读取实际结果并输出测试证据。

需要区分：

| 对象 | 与本需求的关系 |
|---|---|
| 外部 Agent 的终端/脚本工具 | 本次应完善的入口 |
| 提供给外部 Agent 的 MCP server | 本次应完善的入口，运行在应用之外 |
| 现有 `window.api`、preload、IPC、业务服务 | 可复用的被测和调用能力 |
| Playwright/桌面自动化 | 界面操作和验证手段 |
| PC 内部的 MCP 页面和模型工具循环 | 应用现有产品功能；不是外部 Agent 操作 PC 的统一接口 |
| PC 聊天的斜杠命令 | 可被外部 Agent 测试，但不是外部调用体系本身 |
| MiMoCode 桥接 | 历史外部 CLI 集成材料，不是当前 PC 功能调用框架 |

本次读取源码、脚本和现有报告，未启动客户端、未调用模型、未重新执行既有测试。下文对已有实测的描述均引用原报告，不声称本次复验通过。

## 3. 已有可复用基础

### 3.1 业务接口丰富，但还需要宿主

[IPC 契约](../../shared/ipc-api.ts)定义了角色、会话、群聊、设置、世界书、预设、正则、快捷回复、图片、TTS、语义检索、用量、MCP、同步、更新、画板和聊天任务等接口。

[preload](../../electron/preload.ts)将现有业务接口暴露为 `window.api`，真实客户端使用隔离上下文、关闭 renderer Node 集成并开启 sandbox。[main](../../electron/main.ts)

这些接口可以在受控的真实 Electron 页面中通过自动化调用。它们不等于普通终端进程已经能直接访问：外部工具还需管理 Electron 连接、实际应用窗口、上下文、输入参数、异步事件与输出。

部分动作由前端 store 或 UI 组合完成，直接调用单个 IPC 方法可能跳过 UI 的业务流程。例如一条消息的保存不等于发送并触发 AI，创建会话不等于界面已经选中它。外部动作应按用户功能封装，不能机械暴露每个方法后宣称全端可用。

### 3.2 已有公共测试设施

| 设施 | 实际用途 | 能证明的范围 |
|---|---|---|
| [electronHarness](../../scripts/lib/electronHarness.mjs) | esbuild 打包专项入口、启动 Electron 子进程、收日志/退出码 | 专项脚本确实在 Electron 环境执行；不自动等于主界面端到端验证 |
| [browserHarness](../../scripts/lib/browserHarness.mjs) | 启动 Vite、Playwright Edge、轮询就绪、收尾 | 渲染/UI 场景；是否真实业务要看该场景有没有替换 API |
| [PCE01 GUI A/B](../../scripts/pce01-gui-ab.mjs)与[应用内既有探针](../../electron/pce01GuiBench.ts) | 隔离数据下的启动/写入基准和特定 smoke | 固定基准，不是可任意选择功能的通用 Agent 工具 |
| [会话隔离模型启动器](../../scripts/run-session-isolation-model.mjs) | 运行固定真实模型专项 | 专项结果，不提供通用状态、动作和断言目录 |
| [脚本登记](../../scripts/README.md) | 记录运行方式、用途、输出和已知问题 | 有助于人工或 Agent 找入口，尚不是运行时可发现的工具协议 |

`browserHarness` 当前从 `spatial-board/package.json` 所属安装中获取 Playwright。未来通用 PC 工具需要明确依赖归属，避免根目录安装完成却无法运行自动化。

### 3.3 真实 Electron 外部调用已有实例

[空间画板 PC 实机报告](空间画板PC实机测试报告-2026-10-03.md)记录了 Playwright 操作真实 Electron、iframe、鼠标和表单，同时读取正式 preload/IPC 及磁盘结果，并验证重启恢复。

本次还核对了原报告指向的临时 `output/playwright/spatial-real-2026-10-03/run.mjs` 和 `extended.mjs`：它们使用 Playwright `_electron.launch`，生成外部 launcher，在加载现有主 bundle 之前设置隔离 `userData`，随后调用实际 `window.api`。

这证明**不新增产品功能也能通过外部驱动操作现有客户端**。但这些驱动主要位于临时证据目录、围绕画板场景编排；还不能作为其他 Agent 长期依赖的稳定公共入口。窗口误选和重启后旧 locator 复用问题也已在原报告中作为测试工具问题记录。

### 3.4 HTTP 桥接不提供全 PC 调用面

[Bridge server](../../electron/bridge/server.ts)当前挂载 `/sync/v1`，旧 `/api/v1` 伴侣业务面已移除，其他路径返回 404。[同步路由](../../electron/bridge/syncRoutes.ts)具有同步专属鉴权、staging、prepare/commit 和回执。

不能把这个 HTTP 服务当作通用角色/聊天/设置控制 API，也不应为本需求恢复旧伴侣接口。CLI/MCP 应由独立外部工具提供调用面。

### 3.5 浏览器预览存在 mock

[preview.ts](../../src/lib/preview.ts)在没有真实 `window.api` 时提供 mock；画板浏览器专项也有受控 host/API。因此网页能点击、保存函数返回，并不自动证明真实 IPC 或磁盘保存通过。

外部工具必须返回实际执行层级。对 UI 保存、IPC 和持久化验收，检测到 preview/mock 时应拒绝作真实通过结论。

### 3.6 历史外部 CLI 桥接已退出

[tools 登记](../../tools/README.md)注明 MiMoCode CLI 及 `tools/mimo-bridge/` 已随卸载删除。该材料用于另一外部 CLI 的派发，不应恢复为本轮 PC 自动化方案，也不能作为现有 PC 调用能力统计。

## 4. 主要缺口

| 编号 | 缺口 | 影响 |
|---|---|---|
| EXT-01 | 无统一 CLI/MCP 入口 | 外部 Agent 需要为每个功能重新写驱动，调用方式不稳定 |
| EXT-02 | 无按用户功能组织的动作目录与 schema | 知道底层方法不等于知道正确调用顺序和条件 |
| EXT-03 | 生命周期、窗口和隔离数据管理未通用化 | 易连错窗口、复用旧 locator，或误用正式用户数据 |
| EXT-04 | UI、真实 IPC、服务测试、mock 证据未统一标识 | 容易把低层通过误写成整个产品流程通过 |
| EXT-05 | 查询状态、等待异步结果和断言方式分散 | 需要临时轮询，可能把请求接受当作动作完成 |
| EXT-06 | 文件选择、保存对话框、嵌入画板等交互需专项编排 | 常见功能不能通过一条稳定工具调用完成 |
| EXT-07 | 操作组合缺明确对象和结果引用 | UI 选择、会话创建、生成控制等容易串对象 |
| EXT-08 | JSON 结果、截图、日志和重启核验不统一 | Agent 难自动判断结果、续做和生成可复核报告 |
| EXT-09 | 通用功能适配覆盖没有登记 | 单个画板或模型专项通过不能代表整个 PC 可调用 |
| EXT-10 | 安装版、源码版、已打开实例的支持边界未固定 | 外部 Agent 容易把“能启动专项 Electron”误认为任意实例均可接管 |

这些缺口属于外部自动化和工具组织，不等于 PC 对应产品功能不存在或必然有缺陷。

## 5. 全端接入现状与建议验证路径

以下是接口和入口盘点，不是本次运行通过清单。

| 功能族 | 现有基础 | 外部工具应封装的动作及验证 |
|---|---|---|
| 启动与导航 | 实际 Electron 窗口、路由、命令面板 | 启动/关闭/重启、选主窗口、打开页面、等待正确对象 |
| 角色和素材 | character IPC、制作/编辑页面 | 创建/读回/修改/删除、生成草稿、保存、导入导出和素材选择 |
| 单聊会话 | chat、chatTask、会话 UI | 创建/选择/改名/分支、发送/停止/重试、重启恢复 |
| 消息辅助 | feature task、输入框、消息按钮 | 编辑、翻译、方向、润色、swipe；等待并核对目标消息 |
| 群聊 | group IPC、群聊 UI 与调度 | 创建/成员/模式、发送与生成控制、会话隔离和导出 |
| 世界书 | 文档仓储、lorebook、扩词/索引页面 | 条目 CRUD、绑定、触发预览、翻译/扩词、健康检查和导入 |
| 预设/身份 | preset/persona IPC 与页面 | CRUD、切换、会话绑定、生成/保存；验证实际影响范围 |
| 正则/快捷回复 | regex/quickReply IPC 与页面 | CRUD、启停、试运行、插入/发送、导入导出 |
| 配置/模型 | settings、ai、生成规划页面 | 允许字段更新、连接测试、模型查询、保存和有效配置读回 |
| 图片/语音 | imageGen、tts、素材界面 | 生图、工作流校验、朗读/停止；分别核对输出和播放状态 |
| 空间画板 | spatial API、嵌入编辑器、既有专项 | 查询/手动编辑/助手提案/确认/撤销/重启恢复；已有较强实测依据 |
| 用量/公告/日志 | usage/announcement/log API | 查询、筛选、打开详情、导出和异常证据 |
| 字体/备份/更新 | 原生选择器及现有系统 API | 导入导出、取消、恢复和更新分级测试；真实系统交互单列 |
| 同步/设备/MCP | 现有同步中心和 MCP 页面 | 状态、连接、冲突/认证、外部工具配置与调用；依赖环境单列 |

## 6. 建议与结论边界

优先把临时的真实 Electron 驱动整理为独立运行器，提供 CLI 和外部 MCP 两个入口；统一操作目录、执行层级、异步等待、断言和证据，再逐项接入全端功能。

关键验收是“外部 Agent 能通过稳定工具调用真实现有功能并验证结果”。工具自身不需要理解自然语言或调用 LLM，规划由外部 Agent 完成。

本次没有评估所有现有功能的运行成功率，也没有验证已安装客户端是否允许调试连接。后者属于工具兼容性条件，不能靠改产品开启常驻控制端口来默认解决。

实施细则见[PC 端外部 Agent 功能测试与调用工具建设方案](../方案/PC端外部Agent功能测试与调用工具建设方案-2026-10-03.md)。
