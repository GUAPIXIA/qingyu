**两条修正**（已回写方案 §4.1/§4.3）：

1. **“已构建产物 + 外部 launcher”在当前产品代码下不成立。** `electron/main.ts` 以 `isDev = !app.isPackaged` 分流：源码启动必然走 `loadURL('http://localhost:5173')`，要加载发布产物必须让 `isPackaged=true`，即运行打包产物。因此“隔离 + 发布产物”只能通过**打包/安装版 + `--user-data-dir`** 实现，源码模式实际是 dev 渲染层并依赖 Vite。
2. **必须清除 `ELECTRON_RUN_AS_NODE`。** 本机（DSH 宿主自身跑在 Electron 上）该变量为 `1`，不清除时 `electron.exe` 退化为纯 Node，Playwright 直接报 `Process failed to launch!`。这与 [electronHarness.mjs](../../scripts/lib/electronHarness.mjs) 删除该变量的原因一致。

## 3. 探针 A：源码模式外部驱动（对应条件 ①）

命令：`node tools/pc-agent/probes/launch-source-dev.mjs`  
运行目录：`output/pc-agent/phase0/source-dev-20261003-170340`（结果 ✅ 通过）

两种隔离方式对照（同一 Vite 实例，逐个启动真实 Electron）：

| 方式 | 启动参数 | 产品版本 | app 名称 | appPath | 隔离生效 |
|---|---|---|---|---|---|
| A1 launcher-setPath | `electron <run>/launcher.cjs`（先 `setPath('userData')` 再 require 主 bundle） | **43.4.0（Electron 版本，非产品版本）** | 轻语 | run 目录 | 349 文件 |
| A2 user-data-dir | `electron . --user-data-dir=<run>/user-data` | **0.18.0** | 轻语 | 仓库根 | 349 文件 |

两方式共同通过的检查：

- 主进程 `app.getPath('userData')` 等于本次 run 的隔离目录；`app.isPackaged=false`（源码启动 → dev 渲染层）。
- 窗口枚举实测（A1 与 A2 顺序不同，说明不能靠 `firstWindow()`）：

| 窗口 URL | `window.api` | 标题 |
|---|---|---|
| `http://localhost:5173/` | `object` | 轻语 |
| `devtools://devtools/bundled/devtools_app.html?…` | `undefined` | DevTools |

  → **识别策略实测有效**：以 dev server URL + `window.api` 可用性综合判定主窗口，DevTools 窗口（`devtools://`，无 `window.api`）可稳定排除。
- `window.api` 暴露 28 个命名空间，`chat.renameSession` / `chat.listSessions` / `app.getVersion` 均为函数。
- 空隔离档案下的只读调用：`characters=array(0)`、`lorebooks=array(0)`、`personas=array(0)`、`regexes=array(0)`、`fonts=array(0)`；`presets=array(10)`（**产品内置预设**，见 `electron/ipc/preset.ts`，新档案即非空，不能当作“数据泄漏”）；`quickReplies` 返回对象。
- **缺参调用被原接口拒绝**：`chat.listSessions()` → `参数无效：ID 必须为非空字符串`。这为“目录必须携带参数 schema”提供了直接证据。
- 正式数据目录未被触碰：`%APPDATA%\轻语` 与 `%APPDATA%\qingyu` 的 mtime／条目数／文件数在运行前后完全一致。

**隔离档案的实际内容（实测，供阶段 1 设计 fixture 基线）**：隔离 `userData/data` 下自建 `characters/chats/config/groups/lorebooks/presets/vectors/backups`；首启种子包括默认角色**艾莉娅**（`characters/*.json`，1288 字节）、默认连接档案**Ollama**（`connectionProfiles` 数量 1）、`settings.json`（3903 字节，含 `userName=用户`）。`preset.list()` 返回 10 个预设而 `data/presets` 目录为 **0** 个文件 → 证实这 10 个是**代码内置预设**，不是磁盘数据。

**安全提示（实测印证 §4.4）**：隔离档案的 `settings.json` 中确实出现 `apiKey` 字段名。证据采集若整份拷贝 `settings.json` 或截图界面，必须按脱敏规则处理，不能把完整设置回传或原样入库。

**结论**：外部驱动现有应用可行；但源码模式是 dev 渲染层，`app.getVersion()` 与 appPath 依赖启动方式——**注入 launcher 的 A1 方式拿不到产品版本与 appPath**，构建身份必须另行记录（或改用 A2）。

## 4. 探针 B：打包/安装版 + CDP（对应条件 ④）

命令：`node tools/pc-agent/probes/launch-packaged-cdp.mjs`  
目标：`release-v2/win-unpacked/轻语.exe`（本仓库打包产物，**不是**用户安装实例，也不接管用户已打开的客户端）  
运行目录：`output/pc-agent/phase0/packaged-cdp-20261003-170355`（结果 ✅ 通过）

| 检查项 | 结果 |
|---|---|
| CDP 调试端点 | 可用（`Chrome/150.0.7871.224`） |
| `connectOverCDP` 连接 | 成功 |
| 主窗口 | `file:///…/resources/app.asar/dist/index.html#/chat`，`window.api=object` |
| 渲染层 | 发布产物（app.asar 内 `dist/index.html`） |
| detached DevTools | 未打开（打包运行走 `else` 分支，不调 `openDevTools`） |
| 产品版本 | `app.getVersion()=0.18.0` |
| 隔离 userData | `--user-data-dir` 生效，41 个文件（安全闸门：目录须先被写入才继续） |
| 正式数据目录 | `%APPDATA%\轻语`、`%APPDATA%\qingyu` 均未被触碰 |

**构建陈旧检出（关键发现）**：打包产物 `window.api` 只有 **27** 个命名空间，当前源码契约是 **28** —— 缺少 **`spatial`**。即 `release-v2` 打包早于画板 IPC 接入。

> 这正是方案 §4.3“构建陈旧必须显式报告”的实证：`installed` / 打包模式若不比对构建身份，会把旧版本行为当成当前版本结果。

**`installed` / `attach` 的可用条件结论**：

| 模式 | 技术前提 | 实测结论 |
|---|---|---|
| `installed`（已安装 exe） | ① 目标 exe 允许 `--user-data-dir` 隔离；② 允许 `--remote-debugging-port` 暴露 CDP | ① ② 在打包产物上**均已验证成立**；`electron/` 全目录无 `commandLine` / `remote-debugging` / `setPath` 干预，故打包版同样成立。**前置条件：必须记录并比对构建身份** |
| `attach`（连接已有实例） | 目标实例已带调试端点启动 | 产品**不提供**常驻调试端口，只能由外部带 `--remote-debugging-port` 启动后再连接；无端点时返回 `UNSUPPORTED_ATTACH` |

**未在本阶段实测、需显式授权的部分**：接管用户**已打开**的正式实例、以及用户机器上真正安装的客户端（本机未安装，仅有仓库 `win-unpacked`）。这两项按方案 §4.1 需用户明确授权后再做，本阶段不触碰。

## 5. 与方案原设想的差异（已回写）

| 方案原表述 | 实测修正 |
|---|---|
| §4.3 “默认路线：已构建产物 + 外部 launcher” | 源码启动恒为 dev 渲染层（`isDev` 分流）；**发布产物只能通过打包/安装版加载**。默认策略改为：`source-dev`（Vite + 隔离）用于开发期验证，`packaged-isolated`（打包产物 + `--user-data-dir` + CDP）用于发布产物验证 |
| §4.1 `source-isolated` 表述 | 补充实测形态：依赖 Vite dev server、渲染层为 dev bundle、会额外产生一个 `devtools://` 窗口（必须按 `window.api` 排除） |
| §4.2 未提环境变量 | 新增硬要求：启动 Electron 前必须清除 `ELECTRON_RUN_AS_NODE`（本机实测为 `1`） |
| 构建身份来源未定 | 实测：注入 launcher 时 `app.getVersion()` 返回 Electron 版本、`appPath` 落在 run 目录 → 构建身份必须从产物本身（包内 `package.json` / asar 时间 / git sha）采集，不能依赖 `app.getVersion()` |
| fixture 假设“空档案 = 全空” | 实测：新隔离档案自带默认角色「艾莉娅」、默认连接档案「Ollama」、10 个**代码内置**预设（`data/presets` 为 0 文件）；断言基线必须允许产品内置种子 |
