## 4. 边界与安全实测

| 场景 | 期望 | 实测 |
|---|---|---|
| 未知动作 `chat.doesNotExist` | 协议错误 | `rejected / UNKNOWN_ACTION`，退出码 **2** |
| 参数不足 `chat.renameSession` | 协议错误 | `rejected / INVALID_ARGS`（提示需要 3 个参数），退出码 **2** |
| 未知会话 | 环境阻塞 | `UNKNOWN_SESSION`，退出码 **3** |
| 只读会话调用写动作 `character.save` | 拒绝执行 | `blocked / NOT_AUTHORIZED`，退出码 **3**，提示 `--allow-write character` |
| 两个会话的数据可见性 | 互不可见 | 会话 1 有 `QA-测试角色-*`；会话 2 只有种子角色「艾莉娅」；`userData` 路径不同 |
| 重启后窗口绑定 | 重新识别 | 重启后窗口枚举 `devtools,main`，读回成功（旧句柄未复用） |
| 宿主退出 | 空闲自退 | 零会话后 60s 自行退出；退出后无遗留 `electron`/宿主进程 |
| 陈旧令牌 | 自动清理 | 已死宿主的 `hosts/*.token` 在下次 `ensureHost` 时删除，且删除前校验路径在本目录内 |

## 5. 设计决定（阶段 1 落地）

| 决定 | 理由 |
|---|---|
| 目录驱动执行，不写按动作的业务代码 | 动作来自 catalog 的 `apiPath`，新增模块只需登记目录 + 门禁，不改运行器 |
| `--allow-write <模块>` 而非按动作逐条授权 | 粒度够用且不易漏；未授权一律 `blocked`，在宿主侧强制 |
| 双令牌（宿主令牌 + 会话令牌） | 解决“建会话需要先连宿主”的先有鸡问题；两者均 0600、限定本机 |
| 单写者队列覆盖 `restart` | 重启与调用交叉会串对象/串窗口，队列化后顺序确定 |
| `playwright-core` 而非 `playwright` | 只驱动仓库内 Electron 与 CDP，不需要浏览器二进制下载 |
| 断言增加受限 `where` | 列表结果需要按 id 定位对象，用下标断言会碰运气 |
| 动作参数落盘前脱敏 | `settings` 类动作可能带凭据，证据不能原样入库 |
| `verified` 在 invoke 层恒为 false | 方法返回不等于验证通过；验证由 `assert` 显式完成并单独记录 |
