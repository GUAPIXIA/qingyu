**跨入口共享状态**（不是各自独立跑一遍）：

- MCP 启动的会话，`cli.mjs session list` 能立即看到（同一宿主、同一注册表）。
- CLI 写入的测试角色，MCP 立刻可读；MCP 创建的会话，CLI 立刻可读。
- 两个入口对同一会话的 `evidence` 返回同一个 run 目录与相同动作条数。

**错误路径一致**：

| 场景 | CLI | MCP |
|---|---|---|
| 未知动作 | `rejected / UNKNOWN_ACTION`（退出码 2） | `rejected / UNKNOWN_ACTION` |
| 未授权写动作 | `blocked / NOT_AUTHORIZED`（退出码 3） | `blocked / NOT_AUTHORIZED` |
| 未知工具 | — | `isError` + `UNKNOWN_TOOL`（不崩溃） |

> 注：实现过程中发现 MCP 侧若在工具层提前判定「动作不存在」，会返回 `TOOL_FAILED` 而与 CLI 的 `rejected` 不一致；已改为**不在 MCP 层预判**，未知动作交给宿主，保证两个入口的错误语义完全相同。

## 4. MCP 工具与协议

| 工具 | 关键约束 |
|---|---|
| `qingyu_doctor` | 返回构建身份与陈旧标记；陈旧时不应继续驱动客户端 |
| `qingyu_capabilities` | 只返回 `mapped` 动作（当前 8/254），含参数/层级/读写分类 |
| `qingyu_session` | `action` 枚举 `start/list/get/restart/close`；`profile` 枚举两个 profile |
| `qingyu_call` / `qingyu_observe` | 支持 `args` 位置数组，也支持按参数名传值（按契约顺序摊平） |
| `qingyu_operation` | 阶段 2 只覆盖同步 IPC 动作；返回值中显式注明异步等待属阶段 3 |
| `qingyu_assert` | 复用与 CLI 相同的断言规格（含受限 `where`） |
| `qingyu_run_suite` | `suite` 用枚举约束，避免 Agent 猜值 |
| `qingyu_evidence` | 返回 run 目录、动作与断言记录 |

协议实现选择：MCP SDK 1.31.0 的 `McpServer.registerTool` 走 zod raw shape；本工具的动作 schema 来自 catalog（JSON Schema 形态），因此改用底层 `Server` + `setRequestHandler(ListToolsRequestSchema/CallToolRequestSchema)`，避免引入 zod 与维护两套 schema。
