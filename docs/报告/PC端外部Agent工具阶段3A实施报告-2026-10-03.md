## 3. 三条旅程实测

命令：`node tools/pc-agent/cli.mjs suite run --session <id> --suite <chat.lifecycle|character.lifecycle|settings.lifecycle>`

| 旅程 | 关键步骤 | 结果 |
|---|---|---|
| `chat.lifecycle` | 建角色 → 建会话 → 改名 → 写消息读回 → 统计 → 记忆开关/模式 → 导出 → 断言 → **重启 → UI 进入角色卡点“开始对话” → 读界面标题 = 改名值** → 截图 → 失败路径 → 重启读回 → 删除 → 再重启确认删除持久化 | ✅ 18 步 |
| `character.lifecycle` | 建角色 → 读回 → 改名 → 列表 → 绑定世界书 → 失败路径（绑不存在的世界书）→ **重启后界面能看到该角色** → 删除 → 再重启确认删除 | ✅ 11 步 |
| `settings.lifecycle` | 读设置（脱敏）→ **写入测试凭据验证脱敏** → 改主题保存 → 立即读回 → 断言 → 本地 token 计算 → 生成诊断 → 本地模型/用量 → 重启项（如实跳过） | ✅ 12 步 |

## 6. 产品发现（按方案：另列缺陷与证据，修复属单独任务）

| 编号 | 严重度 | 现象 | 证据 |
|---|---|---|---|
| F1 | 中 | **外部 IPC 写入的设置会在应用退出时被渲染层内存值写回覆盖**：`settings.save` 写入 `theme=light`、立即读回为 light；重启后磁盘与读回均变回 `dark`、`fontSize` 变回 `comfortable` | `output/pc-agent/source-isolated-20261003-181224/`：动作时间线 18:13:04 写入并读回 light，settings.json 在 18:13:09（重启时）变为 dark |
| F2 | 低 | **`chat.renameSession` 对不存在的 sessionId 静默成功**（返回成功、无副作用、无错误） | `chat.lifecycle` 步骤“失败路径：改名不存在的会话不产生副作用”记录 `status=succeeded` |
| F3 | 低（行为特性） | **外部 IPC 写入不会推送已加载界面**：渲染层 store 在启动时加载，IPC 写入后需重启（或走 UI 流程）界面才可见 | `character.lifecycle` 早期版本失败 → 改为“重启后界面可见”后通过 |
| F4 | 中 | **消息缺 `timestamp`/`images`/`isEditing` 会导致整页渲染异常**（ErrorBoundary「Invalid time value」），而不是降级显示 | 截图 `screenshots/chat-lifecycle-ui-after-rename.png`（早期运行）显示「页面渲染异常 / Invalid time value」；触发数据为工具构造的不完整 Message |
| F5 | 待定位 | 会话切换器下拉项在真实鼠标序列下点击超时（可能为下拉在外层 mousedown 收起，或无障碍结构问题） | `ui.chat.selectSession` 已降级为 `pending` 并写明原因 |

> F4 由工具构造的**不合法 fixture** 触发；对工具的含义是“fixture 必须符合契约”，对产品的含义是“持久化数据异常时整页崩溃而非降级”。两者都记录，不混淆。
