## 2. 事件型异步等待（3B 核心基础设施）

产品提供的是**任务模型**（`chatTask.start/get/eventsAfter/cancel`）而不是裸事件，比订阅式等待更可靠：

| 能力 | 实现 |
|---|---|
| 终态判定 | `TERMINAL_TASK_STATES = completed / failed / cancelled / interrupted`，与 `shared/chat-core/events.ts` 保持一致 |
| 轮询等待 | `waitForTask({ taskId, fetchTask, timeoutMs, pollMs, onProgress, cancel })` |
| 瞬时缺失 | 单次查不到不算失败，**连续 3 次**才判 `not_found`（刚提交时快照可能未落盘） |
| 超时 | 超时先调用取消，再取末次快照；已终结则采用，否则返回 `timeout` |
| 状态映射 | `completed→succeeded`、`failed→failed`、`cancelled→cancelled`、`interrupted→unknown`、`not_found→unknown`、`timeout→timeout` |
| catalog 声明 | 动作可写 `awaitTask: { path, timeoutMs, pollMs, cancelAction }`；门禁校验其形状 |
| 证据 | 动作记录新增 `task: { taskId, outcome, polls, elapsedMs, state }` |

**动作侧接线**：`chatTask.start`、`ai.chat`、`chat.summarizeMemory` 已声明 `awaitTask`；接入模型环境后无需改代码即可验证终态、事件序号与取消。

**单测覆盖**（`tests/async.test.mjs`，12 条）：轮询到终态、各终态映射、瞬时缺失恢复、连续缺失判 not_found、超时调用取消、`fetchTask` 抛错不中断、任务 id 提取。

## 5. 过程中修掉的两个假通过（工具侧）

| 问题 | 处置 |
|---|---|
| 群成员取自档案种子角色，而首启种子存在**时序竞态**（本次为 0 个），导致 `characterId=undefined` 被写入 | 改为自建 2 个确定性测试成员；不再依赖种子数据 |
| 归属断言 `first.characterId === memberIds[0]` 在两者都是 `undefined` 时**假通过** | 断言改为“必须是非空字符串 + 等于预期”，并补批量条数与归属集合校验 |
