## 3. 空间画板旅程（3C 重点）

| 步骤 | 验证点 |
|---|---|
| 创建并绑定空间世界 | `createAndBind` 返回完整 `version`（worldId/runtimeId/bindingEpoch/revision/指纹），`listWorlds` 与 `loadBound` 一致 |
| 提交编辑批次（新建地点） | `ok=true`，回执 `revision 0 → 1`，读回 revision 与回执一致 |
| **幂等** | 原样重放同一 commit → `duplicate=true` 且 revision 不推进 |
| **同 id 换载荷** | → `ok=false, code=commit_id_conflict`（提交 ID 与操作绑定） |
| **过期 CAS** | 用 revision=0 提交 → `ok=false, code=version_conflict`，且不污染 revision |
| 空间上下文 | 启用画板后 `readContext` 返回 344 tokens 的投影（未启用时为 null，属真实前置条件） |
| 开关不丢数据 | 关闭/开启画板后 revision 与世界指纹不变 |
| 绑定不存在的世界 | 被拒绝且不改变原绑定 |
| 重启恢复 | 重启后 worldId / revision / 世界指纹全部一致 |
| **iframe 加载** | 打开画板 → 读到的 iframe 文本包含 `未参与对话`、`QA-地点-<stamp>`、`小地图`、`React Flow` 等真实控件与数据 |
| **iframe 重建** | 重启后重新打开画板，再次读到非空 iframe 文本并截图 |

截图 `screenshots/spatial-lifecycle-board.png` 同时可见：世界名、IPC 创建的地点节点、工具栏、小地图与「已保存」状态——**IPC 写入的数据被嵌入画板真实渲染**。

## 5. 过程中发现并修掉的问题（工具侧）

| 问题 | 处置 |
|---|---|
| `ui-adapter` 的 `frame` 支持缺失 | 新增 `frame`/`body`，并用画板 iframe 实测 |
| 断言不支持“对象内数组”定位 | 新增 `where.list`；快捷回复断言从“数量相等”（随会话状态漂移）改为“按标签定位内容相等” |
| 宿主曾静默退出（原因未捕获） | 加日志落盘与崩溃处理；并定位到**注册表竞写**（旧宿主退出时按陈旧快照重写，抹掉新宿主条目）→ 增加 run 目录兜底解析 |
| 幂等测试载荷写错（改了载荷还期望 duplicate） | 改为**原样重放**，并单独补一条“同 id 换载荷 → `commit_id_conflict`” |
| 空命令批次被领域校验先拒 | 幂等/CAS 用例改用真实非空命令 |
