# /imagine 提示词生成全排列评测报告

> 评测日期：2026-09-11　|　生成与评审模型：`deepseek/deepseek-v4.1-flash`
> 评测范围：仅提示词生成链路，**不调用生图服务**（生图调用被替换为捕获函数，只记录最终提示词与尺寸参数）

## 一、评测方法

脚本 `scripts/evaluate-imagine-prompts.ts` 以真实命令链路驱动被测代码，未改动任何业务实现：

```
imagineCommand.execute(args, ctx)
  -> buildSystemPrompt(mode, selfMode)         真实系统提示词装配
  -> ctx.callAiHelper(...)                     真实对话模型调用
  -> parseImagePromptResult(raw, style)        真实解析与“无效即重写一次”判定
  -> finalizeImagePrompt(...)                  真实占位符 -> 固定构图片段替换
  -> window.api.imageGen.generate(finalPrompt) 替换为捕获（不出图）
```

矩阵为「画面重点」（5 种）×「我方入镜」（4 种）。`background` 在命令内被强制归一为 `hidden`，
故 UI 可达组合为 4×4+1 = **17 个/风格**；两种提示词风格（`natural` 自然语言、`tags` 绘画标签）合计 **34 组**。
另做 5 项不调用模型的契约检查。

夹具为同一段对话结尾（雨夜旧公寓阳台、湿透黑风衣、右手先攥栏杆后松开、左手拨湿发、目光越过镜头看向台灯），
使唯一变量是构图组合。

## 四、发现的问题

### 4.1 场景还原偏差：阳台被改写为室内窗边（5/34，集中在 natural 风格）

评委判定 `scene_fidelity: fail` 的 5 组中，4 组源于同一模式：模型把「雨夜旧公寓阳台」改写成「室内窗边」，
并把阳台栏杆写成 `window railing`。按关键词统计：`natural` 风格 12 组中仅 3 组出现 balcony、9 组出现 indoor/interior；
`tags` 风格 22 组中 6 组 balcony、16 组 indoor。

这是**复用同一场景夹具下的系统性偏差**，与构图组合无关，指向系统提示词对「地点必须沿用最新对话末尾状态」的约束强度不足：
现行提示词要求「地点、服装、姿势、动作、表情、时间与光线必须采用最新对话末尾状态」，但未强调
**不得把半户外空间（阳台/门口/窗台）改写成室内**。建议在【事实优先级】补一句显式禁令，
并在【强制视觉清单】第 6 项要求写明空间类型。

### 4.2 natural 全身远景未真正覆盖下半身（1/34）

`natural / full / silhouette` 被判定 `framing: fail`：提示词使用 `medium-full shot`，且完全没有描述腿部、双脚、
鞋与重心落点。角色资料与 `full` 模式的系统提示词都要求「完整呈现从头到脚」，但模型仍收缩为半身取景。

### 4.3 半透明入镜被自行扩写为深色剪影（1/34）

`tags / moment / translucent` 被判定 `self_rule: fail`：模型在程序注入的固定片段（`faint translucent edge contour`）
之外，又自行写入 `main character solo focus as blurred dark foreground edge silhouette at frame border`，
把「极淡半透明轮廓线」扩写成「不透明深色剪影」，并额外写入 `under 6 percent of frame` 等限定语。

**这暴露了占位符机制的剩余风险**：程序只保证「占位符被替换成安全片段」，无法阻止模型在同一句提示词的**其他位置**
自行描述我方。`silhouette` 组合此前已有同类防护与测试（`builtin.test.ts` 的“拒绝会生成第二个完整人物的自由描述并自动重写”），
但该防护只覆盖 `silhouette` 的既有措辞，`translucent` 缺少等价判据。建议为 `translucent`/`pov` 补一条与 `silhouette` 对称的判据。

### 4.4 hidden 模式出现倒影，触发单主体判定失败（1/34）

`tags / interaction / hidden` 被判定 `single_subject: false`：提示词含 `faint reflection on wet glass`。
在「我方不出现」模式下，系统提示词禁止的是「我方肢体、倒影或影子」，模型仍可能生成任何倒影结构，
评审据此判定存在第二个主体的风险。该组同时命中 4.1 的场景偏差。

### 4.5 上游端点会忽略 `thinking: disabled`，重试设计因此更关键（观察项）

评测中稳定复现：经该聚合端点调用 `deepseek/deepseek-v4.1-flash` 时，`thinking: {type: disabled}` 偶发不生效，
推理内容吃满输出预算并返回 `finish_reason=length` + 空正文。实测同一请求 3 次中有 2 次为空，其后正常。

这不是本仓库的缺陷，但解释了两件事：一是 6/34 组触发重写、部分组首次尝试直接失败；
二是产品侧「无效则重写一次」的兜底确实必要。评测脚本因此在传输层吸收了空响应重试，
避免把端点抖动误记为链路缺陷。**建议**：`/imagine` 的失败提示目前统一为「提示词生成失败，请重试」，
可考虑区分「模型未返回内容」与「返回格式无效」，便于用户判断是否该换模型。

## 五、复现方式

```bash
# 全矩阵（两种风格 × 17 组），生成 + 评审
npx tsx scripts/evaluate-imagine-prompts.ts \
  --base-url https://api.example.com/v1 --model <模型> \
  --key-file <密钥文件> --style both --judge on --out ./tmp/imagine-eval

# 只跑部分组合（按「模式:入镜」精确筛选）
npx tsx scripts/evaluate-imagine-prompts.ts ... --only moment:hidden,full:pov

# 分批追加（结果按「风格|模式|入镜」键合并进同一份 results.json）
npx tsx scripts/evaluate-imagine-prompts.ts ... --style tags --append --out ./tmp/imagine-eval

# 只补评审，不重新生成
npx tsx scripts/evaluate-imagine-prompts.ts ... --judge-only --append --out ./tmp/imagine-eval
```

脚本产出 `results.json`（逐组系统提示词、原始响应、最终提示词、结构化校验、评审结论）与 `report.md`。
退出码 0 表示结构化校验与契约检查全部通过。密钥也可通过 `IMAGINE_EVAL_API_KEY` 环境变量传入。
