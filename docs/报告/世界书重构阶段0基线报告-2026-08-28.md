## 2. Fixture 范围

已覆盖格式族：

1. 轻语原生 `Lorebook` v1（当前 0.16.x 持久化结构）；
2. SillyTavern World Info；
3. CCv2/CCv3 `character_book`；
4. `lorebook_v3` 的 `{ spec, data }` 包装。

每个格式族都有：

- `minimal.json`；
- `full.json`；
- `invalid.json`；
- `unknown-extensions.json`。

样本均为去身份内容。当前仓库没有可确认授权来源的真实用户世界书，因此外部格式 fixture 标记为 `spec-derived`，依据公开规范重构；轻语原生样本标记为 `project-regression`。后续获得获准使用的真实世界书时，可以新增 `sanitized-real-world` 来源类型，但不得替换现有最小规范 fixture。

## 5. 阶段 0 发现的现状缺口

这些问题已被测试记录，但本阶段没有修改生产代码：

1. **未知字段被丢弃**：四个格式族的未知书级/条目级字段在当前归一化结果中都没有保留区。阶段 2 的 adapter `foreign` 机制必须改变这项基线。
2. **原生无效数据会被“修复后导入”**：缺少 `id`、字段类型错误的 native 输入会被当前 `normalizeImportedLorebook()` 尽力归一化，只要仍产生条目，IPC 就可能接受；新的 native v1 validator 会拒绝原始输入。
3. **部分原生字段无法往返统一归一化器**：`inclusionGroups`、`inclusionGroupPrioritized`、`inclusionGroupWeight`、`generationTriggers` 使用原生字段名时会被丢弃；`useGroupScoring` 等其他字段可保留。
4. **不支持的位置会提前折叠**：ST `position=2` 等当前无法表达的位置会在导入阶段变成 `at_end`。阶段 1/2 应先保留领域原意，再由 renderer 运行时降级。
5. **当前 semantic-only 无服务时仍是死条目**：golden 保留现状；本地词法 fallback 属于阶段 4/5，不能通过更新阶段 0 expected 偷改行为。

阶段 1 实现 canonical v2 和 migration/bridge 时必须：
