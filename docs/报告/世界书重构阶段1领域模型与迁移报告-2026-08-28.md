# 世界书重构阶段 1：领域模型与迁移报告

> 日期：2026-08-28  
> 对应方案：[世界书重构与多格式兼容方案](../方案/归档/世界书重构与多格式兼容方案.md)  
> 结论：阶段 1 已完成，可进入阶段 2

## 1. 交付结果

阶段 1 已将“磁盘持久化结构”与“现有 UI/触发器使用的 `Lorebook` 结构”分离。新保存的世界书统一使用 canonical v2；现有页面、聊天上下文、语义索引和移动端桥接继续读取兼容视图，因此不需要同步重写 UI。

| 交付项 | 结果 |
|---|---|
| Canonical 领域模型 | `CanonicalLorebookDocumentV2`、entry、activation、insertion、scheduling、source、foreign |
| 运行时校验 | 校验顶层版本、嵌套策略、插入位置、递归、分组、过滤器、JSON foreign/source |
| v1 → v2 迁移 | 原生 v1 先校验再迁移；未知字段进入 `qingyu.native-v1` 命名空间 |
| 兼容编译器 | canonical v2 编译为现有 `Lorebook`，供 UI 与运行时继续使用 |
| 集中式文档存储 | 统一读、列出、保存、备份恢复；原子写入复用现有 storage |
| 版本语义 | 首次保存 `revision=1`，后续每次保存 `revision+1`，保留 `createdAt` |
| 回归结果 | 166 个测试文件、1497 项测试全部通过 |

## 2. 数据流

```text
legacy Lorebook v1 ──校验/内存迁移──┐
                                    ├─ CanonicalLorebookDocumentV2
canonical v2 ────────校验───────────┘              │
                                                   ├─ 保存为 canonical v2
                                                   └─ 编译为 Lorebook 兼容视图
                                                          │
                                      UI / matcher / context / embedding / bridge
```

关键行为：

- 只读取 legacy 文件不会改写用户磁盘；
- 用户第一次保存该世界书时才升级为 canonical v2；
- canonical 文件校验失败时不会作为合法世界书继续执行；
- V1 JSON 备份导出兼容视图，V1 恢复统一升级为 v2；V2 ZIP 仍保留原始文件；
- 角色卡内嵌世界书和独立导入的保存结果都统一为 v2。

## 3. 模型与映射

主要实现：

- [v2.ts](../../shared/lorebook/domain/v2.ts)：canonical v2 类型与稳定枚举；
- [validation.ts](../../shared/lorebook/domain/validation.ts)：无新增依赖的运行时校验器；
- [v1-to-v2.ts](../../shared/lorebook/migrations/v1-to-v2.ts)：原生 v1 迁移；
- [migrations/index.ts](../../shared/lorebook/migrations/index.ts)：当前迁移入口与结构化错误；
- [compile.ts](../../shared/lorebook/runtime/compile.ts)：现有 `Lorebook` 兼容视图编译器；
- [lorebookDocumentStore.ts](../../electron/services/lorebookDocumentStore.ts)：版本化持久化边界。

领域命名已采用明确的 `activation.mode: constant | conditional`，没有沿用含糊的 `detail` 作为激活模式。旧 `priority: detail` 只在 bridge 中映射为 `budgetTier: supplemental`。

## 4. 兼容视图保真

旧 UI 不能表示所有 v2 字段。保存时采用“可见字段接受用户修改、不可见字段在未发生对应编辑时保留”的合并策略，覆盖：

- 书级与条目级 namespaced `foreign`；
- `source`、`sourceId`、`title`；
- aliases 与 primary keys 的分类；
- `keyLogic`、`semanticRequired`、特殊 budget tier；
- outlet/custom/扩展 prompt anchor；
- 多个 inclusion groups 各自不同的 weight 与 prioritized。

测试同时覆盖反方向：用户在兼容 UI 中明确删除 alias、修改 match mode 或修改插入位置时，新值会覆盖旧 canonical 字段，不会被保真逻辑错误恢复。

## 5. 生产入口接入

已切换到集中式文档存储的入口：

- `lorebook:list/save/importJson` IPC；
- embedding 索引读取；
- 主进程 context provider；
- 世界书自动推荐 matcher；
- 角色卡内嵌世界书提取；
- 移动端 bridge 的世界书列表；
- V1 JSON 备份导出与恢复。

V2 ZIP 备份仍按原文件复制；恢复后的 legacy 文件也能由集中式读取层兼容，并在用户下次保存时升级。

## 7. 阶段 2 边界

以下内容未伪装成阶段 1 完成项：

1. SillyTavern、CCv2/CCv3、`lorebook_v3` 等仍由现有归一化入口导入，独立 adapter registry 在阶段 2 实现；
2. 外部格式的 detection score、冲突报告和导出损失报告尚未实现；
3. 特殊插入位置已经能在 canonical 中保留，但旧运行时仍按兼容规则降级为 `at_end`，统一 renderer 属于阶段 3；
4. 旧 UI 不携带 revision，因此本阶段实现顺序递增与文件锁，基于 expected revision 的乐观冲突提示需在编辑 API 升级时补入；
5. 本地词法索引、语义降级和本地向量模型安装/卸载仍按方案的阶段 4—6 推进。
