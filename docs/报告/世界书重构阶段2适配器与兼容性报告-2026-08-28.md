## 2. 内建适配器

| Adapter ID | 格式 | 主要识别依据 |
|---|---|---|
| `qingyu.canonical-v2` | 轻语 canonical v2 | `schemaVersion: 2` 及完整 canonical 结构 |
| `qingyu.native-v1` | 轻语原生 v1 | 原生 entries 与轻语字段组合，导入前严格校验 v1 |
| `sillytavern.world-info` | SillyTavern World Info | 对象型 entries、`uid`/`key`、ST 扩展字段与文件名提示 |
| `character-card.character-book` | CCv2/CCv3 `character_book` | 数组型 entries、`keys`、`insertion_order` 和 extensions |
| `lorebook.v3` | `lorebook_v3` | `spec: lorebook_v3` 包装、版本与 `data` 结构 |

候选项按置信度、adapter 优先级和稳定 ID 排序；最高置信度低于 30 时拒绝。前两名相差不超过 5 分时，报告中加入格式歧义提示，不静默猜测。

新增格式只需实现协议、注册 adapter 并增加 fixture。注册表测试使用一个运行时注册的 future adapter 证明无需修改领域模型、触发器、预算器或上下文构建器。

## 3. 字段保留与降级策略

导入报告不是单一成功/失败布尔值，而是可追踪的动作清单：

- `mapped`：字段可映射为 canonical 语义；
- `preserved`：核心模型暂不认识，但原 JSON 值已进入 namespaced `foreign`；
- `approximated`：原意已保存，当前兼容运行时只能近似执行；
- `dropped`：非有限数值、函数等不可持久化为 JSON 的值被忽略并报告；
- `rejected`：结构无效或没有可导入条目，整个导入失败。

SillyTavern 位置 0—7 均有显式映射：角色前后、作者注释顶部/底部、聊天深度及角色、示例前后、命名 outlet。canonical 文档不会在导入时折叠这些位置；其中作者注释、示例区与 outlet 尚未由旧运行时原位渲染，所以报告为 `approximated`，阶段 3 再实现统一 renderer。

未知书级字段、条目字段、扩展字段及 `lorebook_v3` 包装字段均按 adapter ID 隔离。同一来源格式导出时重新合并，避免不同格式使用相同未知字段名时互相污染。

## 4. 生产数据流

```text
独立 JSON ─────────────┐
                       ├─ adapter registry ─ detect/import/report ─ canonical v2 ─ 文档存储
角色卡 character_book ┘                                               │
                                                                      ├─ 兼容视图 → 现有 UI/运行时
                                                                      └─ source adapter → 同格式导出
```

- [common.ts](../../electron/services/lorebookAdapters/common.ts)：外部格式共享的保真映射和同格式导出；

阶段 0 的 16 份格式样本均已纳入阶段 2 adapter 测试，但目录明确标注为 `spec-derived` 或 `project-regression`。当前没有获授权的真实用户世界书样本，因此“P0 四类格式有真实去隐私 fixture”仍未勾选为最终验收完成项，也不会把规范推导样本描述成真实数据。
