## 1. 交付结果

阶段 3 没有重写已稳定的触发算法，而是在现有触发、递归、分组、概率、去重、预算和压缩能力之上补齐统一生产入口、canonical 运行时元数据与独立位置 renderer。单聊、群聊和触发测试器现在执行同一套世界书规则，外部格式差异不会进入上下文组装代码。

| 交付项 | 结果 |
|---|---|
| 统一入口 | `executeLorebookRuntime()` 供单聊、群聊与触发测试器共同调用 |
| 兼容入口 | `triggerAndFitLorebooks()` 保留为 deprecated facade，结果与新入口等价 |
| 运行时元数据 | canonical 编译结果携带来源 adapter、retrieval 与完整 insertion，不再只剩 legacy 投影 |
| 位置 renderer | 标准 prompt/chat 位置精确分发；outlet/custom 有独立通道和显式 fallback |
| 上下文接入 | 单聊与群聊只组装角色、示例、历史和预算输入，不解释世界书触发规则 |
| 诊断链路 | 显示 adapter、retrieval、最终渲染目标、精确/回退状态及原因 |
| 持久化安全 | 保存兼容视图前剥离编译期 runtime 元数据，UI 的显式编辑仍能覆盖 canonical 字段 |

## 2. 统一运行链路

```text
外部格式
  → adapter import
  → canonical v2
  → compatibility compile（保留 adapter / retrieval / insertion）
  → executeLorebookRuntime
      eligibility → match → recursion → group → probability
      → dedupe → book/global budget → compression
  → renderLorebookItems
  → 单聊 / 群聊 / 触发测试器
```

旧的核心算法已有大量回归覆盖，因此本阶段将其收口为生产入口，没有为“管线化”复制一套新实现。压缩缓存和分组键也携带 canonical insertion，避免不同特殊位置的条目被错误合并。

主要实现：

- [lorebook.ts](../../src/utils/lorebook.ts)：统一执行入口、预算与诊断汇总。
- [lorebookRenderer.ts](../../src/utils/lorebookRenderer.ts)：位置分发和回退决策。
- [compile.ts](../../shared/lorebook/runtime/compile.ts)：canonical 到兼容运行时的元数据桥接。
- [contextBuilder.ts](../../src/context/contextBuilder.ts)：单聊输入组装与 render plan 消费。
- [groupChatContext.ts](../../src/store/groupChatContext.ts)：群聊输入组装与 render plan 消费。
- [LorebookEntryTriggerTester.tsx](../../src/pages/lorebook/LorebookEntryTriggerTester.tsx)：与真实聊天共用入口。

## 3. 位置渲染与降级边界

| Canonical insertion | 处理结果 | 是否降级 |
|---|---|---|
| `before_character` / `after_character` | 放入角色定义前/后 | 否 |
| `before_examples` / `after_examples` | 按预设的示例区位置包围示例消息 | 否 |
| `authors_note_top` / `authors_note_bottom` | 放入作者注释顶部或深度 0 底部 | 否 |
| `prompt_end` | 放入系统提示词末尾 | 否 |
| `chat` | 按 depth 与 role 插入聊天历史 | 否 |
| `outlet` | 保留在命名 outlet 通道，并镜像到 `prompt_end` | 是，显式 fallback |
| `custom` | 保留 JSON-safe 自定义位置，并镜像到 `prompt_end` | 是，显式 fallback |

`outlet` 与 `custom` 的原始语义没有在 canonical 或 render plan 中丢失。当前普通聊天消息协议没有命名插槽，所以 renderer 明确给出 `fallback`、目标和原因；以后协议增加原生插槽时，只需替换 renderer 消费端，不需要改 adapter、领域模型或触发器。

## 4. 诊断与可维护性

每条触发诊断除了原有的命中、递归、分组、概率、预算和排除原因，现在还可以回答：

- 条目来自哪个 adapter；
- 使用何种 retrieval 策略；
- canonical insertion 是什么；
- 最终渲染到哪个位置；
- 是否发生 fallback，以及为什么。

聊天调试面板和条目触发测试器都展示这些信息。新增格式仍以 adapter + fixture 为主要扩展点；新增运行时位置主要修改 renderer；新增检索方式留给 provider 层，三个方向互不要求修改对方的核心逻辑。

## 5. 保存语义

canonical 编译产生的 `runtime` 只读元数据不会写回用户文档。保存兼容视图时先剥离这些字段，再解释 UI 对 legacy `position`、`matchMode` 等字段的修改：

- 用户明确修改位置时，修改仍会覆盖对应 canonical 字段；
- 用户没有触及兼容视图无法表达的字段时，原 canonical-only 信息继续保留；
- `runtime` 不进入 `foreign`，不会污染未知字段往返。
