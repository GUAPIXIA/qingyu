## 2. 验证结果

* 全量 176 个测试文件 / 1623 项测试通过（阶段 4 时 1589 项，阶段 5 净增 34 项）；双端 `tsc --noEmit`、eslint 通过。
* 真实端到端评测（下载 HuggingFace 真模型 → 安装校验 → 自检 → 启用 → ONNX worker 推理 → 余弦召回排序）：
  * `bge-small-zh-v1.5`：dim=512，中文查询"想找一处能看见流星的山谷"正确召回星陨峡谷（0.4983 vs 0.2182 / 0.2463）。
  * `multilingual-e5-small`：dim=384，英文查询正确召回 Meteor Valley（0.8646 vs 0.7068 / 0.7579）。

## 3. 验收检查与后续修正

1. **e5 评测用例失败 → 定位为用例设计问题而非实现缺陷**。诊断确认模型与管线均正常（同语言召回排序完全正确），失败用例"中文查询 → 英文答案 + 中文干扰项"超出了该量化模型的真实跨语言能力（0.764 vs 0.827，同语言偏置）。评测脚本改为"英文查询 + 英文答案 + 中文干扰项"后通过；catalog 描述同步改为如实标注（"跨语言召回以英文查询为可靠方向，中文查询召回英文条目能力有限"），并新增 `scripts/sign-model-catalog.ts` 重新签名（注意签名顺序：先逐模型签名，再以携带新模型签名的目录计算总签名）。
2. **偏好设置假开关接线**：`updatePolicy` 由新增 `LocalModelUpdateAgent`（挂载于 MainLayout）执行——`download`/`auto` 在启动时自动安装已安装模型的目录新版本，`auto` 在新版本自检就绪后切换默认模型并重建索引（决策逻辑为纯函数 `planModelUpdates`：只升级已安装过的模型，不会替用户下载从未选择的模型，也不会劫持指向远程 embeddings 的配置）；`idleOnly` 使启用后的自动索引延迟到 `requestIdleCallback`；`batchSize` 从设置文件读取并传入 manager 分批；`cpuLimitPercent` 无现实接线点，已从类型与默认值移除。
3. **索引任务改造**：`runIndexJob` 改为按书 checkpoint（任务快照 `downloadedBytes` 记录已完成书数），支持暂停/继续/取消与单任务守卫（重复调用 rebuild 复用同一任务并自动续跑）；重启后索引任务如实标记失败（书目回调无法跨重启保留），不再伪装成可续传。顺带修复 `install()` 守卫把进行中的索引任务误认为安装任务、导致自动更新被索引任务永久卡死的 bug。
4. **卸载默认模型联动**：渲染层在卸载确认后同步停用指向该模型的 `semanticTrigger`，设置页不再残留失效配置；卸载影响弹窗继续提供"删除模型+索引 / 仅删除模型"选项。
5. **补齐交付条件缺口测试**："新版本自检失败时旧版本保持默认可用"（更新失败回滚）、索引 checkpoint 暂停续跑、batchSize 分批、`planModelUpdates` 五项决策用例、UI 卸载停用语义触发断言。
6. **默认模型可更新可见性**：catalog 新增 `updateAvailable` 字段，"当前默认"模型有新版本时显示"当前默认 · 有更新"，不再被 `in_use` 状态掩盖。
7. **模型目录跟随运行环境**：新增纯函数路径解析与回归测试；开发运行下载到 `<project>/models/embedding`，打包运行下载到可执行文件同级的 `<install-dir>/models/embedding`。索引继续保存在 `userData`。模型中心和安装确认框显示实际路径，打包规则排除开发目录 `models/**`，避免本机模型误入安装包。
8. **Windows 安装路径瞬时占用**：原实现每收到一个网络数据块就以固定 `tasks.json.tmp` 覆盖任务文件，且 `.part` 文件、在线 staging 目录、离线包 staging 目录均使用裸 `renameSync`；Windows 安全软件、索引器或 Vite watcher 短暂持有目标时会触发 `EPERM` 并中断安装。现将进度持久化与 IPC 更新限制为最多每 250 ms 一次，临时文件名加入进程与随机隔离，所有本地模型生命周期 rename 统一对 `EPERM` / `EACCES` / `EBUSY` 有限退避重试，并将 `models/**` 排除出 Vite 开发监听；不可重试错误仍立即上抛。可续传失败任务显示“继续下载 / 放弃任务”，恢复时逐文件校验并直接复用完整 staging，不重复下载。
9. **设置入口统一**：原“本地模型”与“语义”两个导航项合并为“语义检索”。`SemanticRetrievalSection` 以自动、本地、远程和仅词法作为唯一总策略，并在一次设置更新中同步 `localModels.retrievalMode` 与 `semanticTrigger`；无默认模型或远程档案时拒绝半切换。本地模型生命周期逻辑仍由独立组件维护，用户人设注入拆为无关的独立设置项。补充实施后全量 181 个测试文件 / 1713 项测试、双端类型检查、eslint、渲染端生产构建与 Electron 构建均通过。

## 4. 遗留事项

* 目录结构与方案 §11 建议不同（`electron/services/localModels/` 5 个文件 vs 建议 `local-models/` 9 个文件），功能等价；`manager.ts` 约 560 行，阶段 6/7 继续扩展时建议拆分 download-manager/integrity/task-store。
* 索引任务 checkpoint 粒度为"书"：暂停期间书目集合变化可能重复或跳过个别书（索引写入幂等，下次重建收敛）。
* 索引任务跨应用重启不续跑，需重新开始（安装任务不受影响，可从 staging 续传）。
* `batchSize` 已接线但暂无 UI 控件（对应方案 §8.4 中的高级设置项）。
* 本地模型端到端性能门槛未制定：方案 §13.5 规定待确定模型、量化方式与基准机后单独制定，当前仅有功能正确性验证。

## 5. 交付条件核对

* 全新安装、断网续传（HTTP Range）、更新失败回滚、卸载默认模型、保留/删除索引、崩溃恢复：生命周期专项测试 + 真实模型 E2E 均通过。
