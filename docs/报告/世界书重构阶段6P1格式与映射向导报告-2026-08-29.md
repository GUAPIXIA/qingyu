# 世界书重构阶段 6 验收报告：P1 格式、导出与通用映射向导

> 日期：2026-08-29\
> 对应方案：《世界书重构与多格式兼容方案》阶段 6\
> 结论：Risu / Agnai / NovelAI 三个 P1 格式以独立 adapter 接入并通过全部注册表合同测试（含同格式导出→再导入 compile 语义等价）；未知 Tavern fork 的受限映射向导与可复用模板已实现。全量 186 个测试文件 / 1662 项测试、双端 `tsc --noEmit` 与 eslint 通过。交付条件"新增一个格式只需 adapter、注册和 fixture，不修改领域模型和执行器"成立。

## 1. 格式事实来源

P1 格式没有稳定公开规范，字段以**上游源码/官方文档**为准（fixture 在 catalog 中标记 `source-derived`）：

| 格式 | 事实来源 | 关键字段结论 |
| --- | --- | --- |
| Risu Lorebook | RisuAI 源码 `src/ts/process/lorebook.svelte.ts` 与 `src/ts/storage/database.svelte.ts`（main 分支） | 独立世界书为 `{ type:'risu', ver:1, data: 条目数组 }`；条目 `key`/`secondkey` 为逗号分隔字符串（`secondkey` 为上游原始拼写）、`insertorder`、`comment`、`mode`（`multiple`/`constant`/`normal`/`child`/`folder`）、`alwaysActive`、`activationPercent`、`extentions.risu_case_sensitive`（上游拼写 `extentions`） |
| NovelAI Lorebook | docs.novelai.net 官方文档，并经 RisuAI 自带的跨格式转换器 `CCLorebook` 交叉确认 | `{ lorebookVersion: 4, entries }`；条目 `text`（正文）、`keys`、`secondKey`、`displayName`、`comment`、`forceActivation`（常驻）、`vectorized`、`caseSensitive`、`priority`（数字，决定插入顺序）、`useProbability`/`probability`、`useRegExp` |
| Agnai Memory Book | AgnAI 记忆书结构，经 RisuAI `convertExternalLorebook` 映射交叉确认 | `{ name, description, entries }`；条目 `name`（标题）、`entry`（正文）、`keywords`、`priority`（数字）、`enabled` |

## 2. 交付范围与实现

### 2.1 三个 P1 适配器（不混入 ST adapter）

* `electron/services/lorebookAdapters/risu.ts`（`risu.lorebook`）、`novelai.ts`（`novelai.lorebook`）、`agnai.ts`（`agnai.memory-book`），各自实现 detect/import/export。
* 复用统一导入管线（`normalizeImportedLorebook` → v1→v2 迁移）与未知字段保留机制；为准确区分"已消费"与"未消费"字段，`common.ts` 的 `ExternalAdapterConfig` 新增可选 `consumedEntryKeys`——P0 适配器行为不变。
* 导入时保留原始条目对象为底稿：预映射字段别名（如 NovelAI `text`→`content`、Risu `insertorder`→`insertion_order`），未消费字段进入 adapter 命名空间 foreign；导出时"未知字段作底稿、规范字段覆盖"，同格式往返可恢复。
* 非对象条目原样透传给统一导入器计数，生成结构化拒绝报告（`invalid_entries` / `empty_entries`），不静默丢弃。

### 2.2 语义保真决策

* **Risu `mode:'multiple'`**（全部关键词命中才触发）→ canonical `ActivationPolicy.keyLogic='all'`，导出时还原为 `multiple`；`mode:'constant'`/`alwaysActive` → 常驻。
* **NovelAI/Agnai 没有条目级插入位置**（正文按激活进入记忆区）：导出时对非 `prompt_end` 位置显式报告 `approximated`（`novelai_insertion_unsupported` / `agnai_insertion_unsupported`），不静默折叠。
* **Agnai 无常驻字段**：导出常驻条目时报告 `agnai_constant_unsupported`。
* NovelAI `lorebookVersion ≠ 4` 时按 v4 尽力导入并警告；目录 NovelAI/CC 检测存在 2 分内歧义时由注册表的 `ambiguous_format` 信息提示兜底。

### 2.3 同格式导出与 round-trip

* 三个格式的 `full` fixture 自动进入注册表合同测试：导出 → 再导入 → `compileCanonicalLorebookV2` 语义等价（覆盖关键词、二级关键词、顺序、概率、大小写、常驻、启用、向量标记、书名/标题、未知字段合并）。
* 未知扩展 fixture：`preserved > 0 && dropped == 0`，导出 JSON 中可找回 `futureBook*/futureEntry*` 字段。

### 2.4 受限映射向导（P2）

* 模板类型与纯函数（`shared/lorebook/adapters/mapping.ts`）：`LorebookMappingTemplate`（条目数组路径 + 受限字段路径集）、`guessMappingTemplate`（从常见形状猜测）、`resolveMappingPath`（拒绝 `__proto__` 等危险键）。
* 应用逻辑（`electron/services/lorebookAdapters/mappingImport.ts`）：字段搬运 → 统一归一化 → canonical v2；模板未覆盖字段保留在 `qingyu.mapping` 命名空间；路径不指向数组/含非对象条目时生成拒绝报告。
* 模板持久化（`electron/services/lorebookMappingTemplates.ts`）：`config/lorebook-mapping-templates.json`，结构校验、上限 50 条。
* IPC 与 UI：`lorebook:openMappingSource`（文件选择 + 截断预览 + 猜测模板，原始内容仅缓存在主进程内存，renderer 不接触路径）、`lorebook:importWithTemplate`、模板 CRUD；`LorebookMappingWizardModal` 挂入世界书页面（"映射向导"按钮），支持载入已保存模板、编辑字段路径、可选保存模板。按方案 §6.3，向导不提供导出。

## 3. 验证结果

* 全量 186 个测试文件 / 1662 项测试通过（阶段 5 时 1623 项，阶段 6 净增 39 项）；双端 `tsc --noEmit`、eslint 通过。
* fixture catalog 从 16 份扩展到 28 份（3 个 P1 格式 × 最小/完整/异常/未知扩展），全部通过注册表合同测试。
* 新增专项：Risu multiple/constant 语义、NovelAI text/forceActivation/priority 映射、Agnai 书名保留与条目映射、映射模板搬运/拒绝/缺失字段告警（6 项）。

## 4. 遗留事项

* P1 fixture 为 source-derived：依据上游源码与文档构造，真实去隐私样本仍是最终验收项（与阶段 0/2 的口径一致）。
* 映射向导按方案定位只做导入；模板不含表达式/脚本能力，属于"受限"映射。
* NovelAI `secondKey` 为单字符串：导入按逗号拆分为二级关键词列表，导出以 `, ` 合并，极端情况下含逗号的 key 会被拆分。
* Risu `child`/`folder` 组织模式仅作为未知字段保留，不改变条目行为。

## 5. 交付条件核对

> 新增一个简单格式只需 adapter、注册和 fixture，不修改领域模型和执行器。

**满足**。本次新增三个格式均只涉及：新增 adapter 文件、registry 注册一行、catalog 登记 fixture；领域模型（canonical v2）、执行器、检索与预算代码零改动。唯一适配层扩展是 `common.ts` 的可选 `consumedEntryKeys`（影响导入报告口径，不影响领域模型与执行行为）。
