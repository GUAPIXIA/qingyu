# 轻语局域网与服务器双通道连接实施验收报告

> 日期：2026-09-01  
> 目标版本：PC 0.17.0、Android 0.3.0 (9)、Relay 0.1.0  
> 结论：代码侧 PR 1–PR 6 及 PR 7 的文本通道生产化已落地，Relay 已部署到真实公网环境；真实 PC/Android 业务流、外部告警和媒体通道仍待验收。

## 1. 已交付

- 共享 Relay v1 帧、RPC、错误码、配对二维码契约与 Fixture。
- Bridge 运行时解耦，LAN HTTP/WS 与 Relay Agent 共用 `MobileFacade`、生成任务表和事件总线。
- Relay 服务的 Ed25519 Access Token、Refresh Token 旋转/重放链吊销、PC/手机配对、HTTP 网关、WSS RPC、设备吊销和 RLS 空间隔离。
- PC 端 Relay 状态机、指数回退、加密凭据、单飞行 Token 刷新、系统级配对审批、缓存快照/增量发布和独立设置开关。
- Android LAN/Relay 双入口、旧 JSON 兼容、加密凭据、唯一 URL 出口、Authenticator 单飞行刷新、Relay WS 帧和连接状态。
- PC 离线时的只读快照、普通文本消息 15 分钟短队列、幂等 requestId、完成/过期回执和手动重试语义。
- 配额保护、高修订号覆盖、保留期清理、健康/就绪检查、Prometheus 指标、幂等迁移、Docker Compose 和 CI 门禁。
- 媒体 Relay 在文件通道完成前显式返回 `415 MEDIA_UNSUPPORTED`，不泄露 PC 本地路径。
- Relay 已部署到阿里云 `/opt/qingyu-relay`，通过现有 TLS 域名的 `/relay/` 公开 HTTP/WSS，应用端口仅绑定 `127.0.0.1:3100`。
- 部署主机已增加 2GB 持久 Swap；Relay 使用独立锁文件和最小生产镜像，不安装 Electron/ONNX 工作区依赖。
- 已安装每日 PostgreSQL 备份、14 天保留、独立临时数据库恢复校验和每 5 分钟就绪检查定时器。

## 3. 待环境验收

- Android Gradle 在当前 Windows 主机上于项目配置前因 Java NIO 无法建立 loopback selector 而终止，尚未得到本机 Kotlin 编译结果。CI 已配置 Linux Android 编译、单测、Lint 和 APK 门禁。
- 需用真实 PC 与 Android 在局域网/移动网络完成配对、消息、AI 流、断网排队、设备吊销和切网恢复验收。
- S3/MinIO 预签名上传、下载与扫毒通道未纳入首个可用文本版；完成前媒体功能按契约禁用。
- 正式域名、TLS、本机加密密钥、备份/恢复已验收；外部告警通知、集中密钥托管和容量压测仍需运维签字。

## 4. 验收结论

当前代码已满足文本双通道 MVP 的实施边界，但不应在完成第 3 节的真实环境测试前宣布生产上线验收通过。
