## 1. 本阶段结果

主进程和渲染层共用 `shared/chatConnection.ts` 的有效连接解析。选中档案确定 provider、凭据和地址，模型采用 `activeModel || profile.model`；缺失档案不回退到其他连接。返回值复制模型能力覆盖配置，既有档案默认模型不会被修改。

`electron/services/chatConnection.ts` 保留磁盘读取、默认值和既有凭据回填，只转出共享解析函数。`useSettingsStore.getActiveProfile()` 返回同一规则的有效配置。翻译、标题、历史/世界书压缩、群聊记忆、用户草稿、角色卡及预设辅助使用解析出的 `profile.model`，避免再次叠加可能来自旧 React 闭包的模型值。主进程正文和记忆、单聊/群聊画板继续沿用既有上下文提供器与请求适配器。

单聊正文恢复将首次配置、上下文和识图配置传入内部重试；方向候选的结构修复和推理恢复保留首次连接，熔断也记录首次端点。群聊点名/轮询与自由发言恢复保留连接、模型、上下文和识图配置。补尾接收主生成的连接快照，避免旧模型搭配新连接。

单聊和群聊上下文构建接收请求配置快照，模型切换发生在异步预取期间时，预算和实际发送仍采用一致配置。群聊请求预算同时使用快照中的篇幅默认值和模型能力覆盖；完成时用量记录实际发送模型（含识图模型），不再读取已切换的 `activeModel`。

这些快照只在请求执行期间保留。功能历史不新增可编辑连接或模型字段；已有适配器重试、能力检测、任务预算和受控凭据链路继续复用。

## 2. 配置切换验收

| 场景 | 自动验证结果 |
|---|---|
| 活动模型与档案默认模型不同 | 使用活动模型；活动模型为空才回退档案；缺失档案返回空 |
| 切换设置或修改能力覆盖 | 已解析的模型和能力对象不受后续设置修改影响 |
| 单聊内部恢复期间切换连接/模型 | 恢复仍使用原 provider/地址/凭据/model；保留同一逻辑回复 |
| 正文截断后触发补尾 | 切换配置后补尾沿用正文连接和模型 |
| 方向结构非法时切换配置 | 内部重试沿用首次连接；下一次新请求使用新配置 |
| 群聊点名、自由发言恢复 | 原连接、模型与上下文保持一致 |
| 群聊生成期间切换模型 | 完成后的用量仍对应实际发送模型 |
| 画板请求等待空间锁时切换配置 | 开始执行后解析新连接/model，结果仍归属原作用域 |
| 画板运行后切换模型并再次请求 | 首次请求保留旧模型；第二次使用新模型；助手 ID 和历史保留 |

测试使用隔离的临时数据和模拟请求，未调用用户真实模型或改写用户聊天数据。正文、画板连续指令、翻译及后台记忆的综合真实模型联验仍需在功能阶段完成后补齐；既有画板专项的真实模型验收见相应报告。

## 3. 验证范围

专项回归 **24 个测试文件、682 项测试全部通过**，覆盖共享解析、设置 store、方向、单聊/群聊恢复、翻译、记忆、标题、压缩、上下文、画板助手、确认事务与相关编辑界面。完整运行日志位于工作区 `.qa/session-isolation-stage0-tests.log`。

`pnpm check` 和修改代码的定向 ESLint 均通过；主仓库/共享子模块的 `git diff --check` 无空白错误。深度流式测试补齐活动连接配置，轮询测试补齐现有会话列表，以继续覆盖真实请求入口所需状态。
