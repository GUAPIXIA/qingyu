| 范围 | 实施结果 |
|---|---|
| 输入草稿续写／润色 | 冻结角色／会话草稿对象与单调递增版本；内部续写重试沿用同一任务和连接／模型快照；成功或失败均不覆盖后续输入，冲突成功结果保留为旧建议 |
| 角色制作向导 | 扩展、字段和开场白生成共用编辑任务；预算等待期间即可取消；原值在发起时冻结；扩展冲突进入旧建议，字段替换核对版本，显式追加基于最新内容 |

| 恢复时的在途任务 | 文件替换前取消主进程功能请求及后台记忆，通知渲染层取消包括预算等待在内的任务；旧请求即使沿用相同会话／消息 ID，也不能排队提交到恢复后的数据 |

核心实现为 `src/store/editorAssistant.ts`、`src/store/featureTasks.ts`、`electron/services/featureBackup.ts` 和 `shared/featureHistory.ts`。编辑任务使用独立 editor owner、任务身份和来源指纹；模型不能声明写入对象。有效编辑结果继续通过既有草稿或编辑保存流程生效，未发送草稿不进入聊天正文。

## 2. 编辑提交与兼容规则

草稿版本每次编辑都推进，包括改后改回。仅比对文本相等不足以判断来源有效。本阶段先用两条失败测试复现润色成功结果覆盖新稿、失败回填覆盖新稿，再加入版本保护。

一次性编辑建议不建立长期对话历史。自动应用要求对象与版本均匹配；冲突结果在当前编辑器内保留可查看的旧建议，普通旧建议最多保留 10 条。角色字段／开场白沿用现有待确认区域，过期替换被拒绝；用户仍可明确选择追加或放弃。建议、取消句柄和编辑任务不随草稿持久化，重启或恢复后不自动继续执行。

续写使用专用用户草稿提示，不继承正文预设的越狱提示。预设测试器仍读取所测试预设的提示与参数，并通过独立任务运行，不保存测试输出为聊天消息。正文续写与补尾的原有主生成路径保持原有归属。

角色卡、预设、世界书的既有导入／导出继续处理对应业务对象。普通聊天 JSON 是可携带的正文记录；完整备份包含功能数据。当前全量恢复沿用包内角色、群组和会话身份，校验文件路径与声明归属，不把旧来源引用重新声明给其他会话。本阶段不新增单会话复制或聊天记录导入入口；后续若增加这类入口，须明确重新映射身份并重新建立来源引用。

## 3. 备份与恢复规则

原包先通过既有 manifest 哈希、路径和空间事务校验，再处理功能来源，最后统一写盘。任一归属异常在写入前拒绝；既有失败回滚继续保留。复核使用与读取一致的消息顺序和单聊追加覆盖规则，损坏旧行不参与来源核对，也不因本阶段的处理被删除。

恢复保留已提交的记忆事实等业务数据。失效来源引用不会赋予待执行建议新的提交资格。空间助手的 queued／running 请求恢复为 interrupted；处于自动应用中的建议降为需确认状态，已完成任务和已应用收据保留。主进程与渲染层的恢复取消通知覆盖模型返回后等待提交的任务，以及尚未发出网络请求的预算等待任务。恢复失败也不自动重发已取消请求。

功能任务公开模型描述只保留公开 provider／model／profileId；不备份任务的 apiKey、完整 baseUrl 或连接配置对象。既有设置和 MCP 的凭据裁剪继续保留。模型请求凭据只在请求参数中使用，不写入 editor owner 或 sourceRef。
