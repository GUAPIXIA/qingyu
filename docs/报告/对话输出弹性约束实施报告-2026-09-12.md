## 二、关键实现

### 2.1 篇幅与预算（阶段 1）

- `shared/responsePolicy.ts`：简短 40–140 / 适中 120–360 / 展开 300–700（硬保护线 260/600/1100）；自动模式按最近 3–5 条助手回复可见字符中位数回归，目标钳制在 80–700、900。
- `shared/modelOutputProfile.ts`：正文预算 `ceil(硬保护线×1.25)+96` 与推理余量分别估算；DeepSeek V4 为 `shared-unknown`（默认 3072、上限 4096），有近期样本时取 P90×1.2。
- 上下文输出预留与请求 `max_tokens` 由 `resolveChatRequestPlan` 单次计算（阶段一验收项）。
- DeepSeek V4 固定 8192 下限已删除；"适中"回合在该模型上请求约 3918 Token。

### 2.2 提示与收尾（阶段 2/3）

- 「本轮回应范围」+「正文结构」取代固定 2–6 段、强制对白、星号协议；篇幅数字随 ResponsePolicy 动态注入。
- 适配器返回 `AICompletion`（text + finishReason + usage）；`length` 走完成事件不再抛错；网络中断但有正文时主进程降级为 `network_error` 完成结果。
- `shared/assistantOutputFinalizer.ts`：完整即收；残缺回退最后稳定句界（剥离未闭合引号/星号/`<thought>`）；无稳定边界时一次短补尾（末段上下文、重叠去重合并、失败保留稳定前缀）。
- 收尾状态区分：中性提示 `generationNotice`（已收束/已补全/已停止）与失败提示 `generationError`（生成中断已保留）。

### 2.3 多端一致（阶段 4）

- 群聊（点名/轮询/自由发言）与 Bridge 单聊/重生成全部接入同一收尾器与补尾；错误分支对齐单聊 R2（正文保留 + `generationError` 字段，不把 ⚠️ 拼进正文）。
- 群聊自由发言的多角色拆分前先整体收尾；`GroupMessage` 新增 `generationError` / `generationNotice`。

### 2.4 语义分块渲染（阶段 5）

- `src/utils/roleplayBlocks.ts`：纯引号行→对白（说话人 1–4 字符短名）、整段 `*动作*`→叙述（剥离星号）、混写行→mixed、`<thought>`→思考；空行分段，同段相邻叙述合并。
- 新落盘消息标记 `contentRenderMode: 'blocks'`，气泡按语义块以 CSS 呈现；旧消息缺省走 Markdown 渲染，零迁移。
- 新正文停止调用 `normalizeRoleplayDialoguePrefixes`（保留为旧内容兼容工具，待后续版本删除）。

## 三、灰度开关（阶段 6）

- 设置项：`Settings.generationPipeline`，`unified`（默认）| `legacy`；入口在「设置 → 显示与行为 → 生成管线」。
- legacy 行为（一键回退，不删除新设置数据与会话数据）：
  1. 预算回退：预设 `maxTokens` 直用（单次推导保持；旧固定 8192 下限不恢复）；
  2. 提示回退：注入旧【正文排版协议】；
  3. 收尾回退：跳过 finalizer 与补尾，截断正文原样透传；
  4. 渲染回退：新消息不标记语义分块，恢复 `normalizeRoleplayDialoguePrefixes` 补前缀。
- 错误分支的 R2 式统一（正文保留 + `generationError` 字段）不随 legacy 回退（纯展示改进，无行为风险）。

## 四、清理项

- 删除 `ChatParams.allowTruncatedOutput`（阶段 3 起 length 不再抛错，字段无消费方），含全部调用点与测试。
- 删除 `DEEPSEEK_V4_MAIN_CHAT_MAX_TOKENS` / `resolveMainChatMaxTokens`（阶段 1）。
- 删除旧【正文排版协议】作为默认注入（保留为 legacy 回退路径的显式函数）。

### 5.1 复查结论（阶段 0—6 全面检查）

- 覆盖率（§10.4 目标 ≥90% 分支）：`responsePolicy` 100% / `modelOutputProfile` 95.1% / `roleplayBlocks` 88.6% / `assistantOutputFinalizer` **93.3%**（复查前 76.9%，补 14 个用例）。剩余 4 个未覆盖分支均为防御性死分支（`matchAll` index 兜底等）。
- 复查修复的问题：
  1. 补尾合并逻辑原有一处 shared 导出 + 两处内联实现（渲染层/Bridge），已统一为 `mergeTailRepair` 单一入口（§7.4 一致性）；
  2. 收尾器边界缺陷：句末紧跟悬空星号时，27 字可恢复前缀被降级为补尾——按 §5.2 步骤 6 修复（删除未闭合展示标记后重查）；
  3. 评测脚本两处 `join('\n')` 转义损坏导致脚本无法编译（静态用例因此从未真正运行），已修复；
  4. `ai.ts` 残留未用导入清理。
- 已知偏差（有意为之，代码内有注释）：
  1. 输出正则在收尾器**之后**执行一次（方案 §9.2 要求之前）——续写路径的重叠去重依赖正则后文本与路径内上下文，前移会破坏该链路；
  2. legacy 回退不覆盖错误分支的 R2 式统一（正文保留 + `generationError` 字段）——纯展示改进；
  3. §4.2 自动篇幅的场景系数与用户本轮要求检测：`userIntent` / `sceneFactor` 参数已预留，检测逻辑属后续增强（阶段 2 清单未包含）；
  4. 群聊 blocks 模式消息不经 @提及高亮插件（用户消息保持 Markdown 不受影响）。
