# 对话输出弹性约束阶段 7 实施报告：异常链路与跨端收口

> 范围：阶段 7.1（统一异常终止链路）、7.2（thought 契约 + 跨端语义分块）、7.3（后台任务档案与补尾治理）；

## 一、阶段 7.1：统一异常终止链路

### 1.1 应用层终止原因与供应商结束原因分离（方案 §3.2）

- `shared/types.ts` 新增 `GenerationTerminationCause`（provider_stop / provider_length /
  provider_content_filter / provider_tool_calls / transport_error / idle_timeout /
  user_cancel / protocol_error / unknown）与 `GenerationTerminalResult`；
  `finishReason` 保持供应商兼容口径，两者互不覆盖。
- `shared/generationTermination.ts`（新增）：终止原因映射（`terminationCauseFromFinishReason`、
  `effectiveFinishReasonForCause`）、行为矩阵文案（`terminationPromptWithContent` /
  `terminationPromptWithoutContent`）、`requestId + terminalState` 一次性终止状态机
  （`createGenerationTerminationLatch`：streaming → finalizing/cancelled → persisted，
  claim 之后迟到 chunk/done/error 全部忽略）。
- `GenerationOutcomeMeta` 与消息观测均携带 `terminationCause`。

### 1.2 共享异常收口入口（方案 §4.2）

`src/store/generatedReplyPipeline.ts` 新增 `finalizeGenerationTerminalResult`：按 §4.1 矩阵
决定是否保存部分正文、是否允许补尾（**只有 `provider_length` 允许，每条消息至多一次**），
生成 `generationNotice`/`generationError`，返回唯一可落盘结果。补充两条与矩阵配套的规则：

- 正常 `stop` / `tool_calls` 明确收尾但缺句末标点时透传保存完整正文（不丢弃、不补尾）；
- 内容审核拦截按审核策略不保存正文，只给明确审核提示；任何异常且无可用正文一律
  `persistable=false`（不创建空 AI 消息）。

### 1.3 各链路接入

| 链路 | 改动 |
|---|---|
| 桌面单聊 `streamController.ts` | 空闲超时（初始 + 续期计时统一 `fireIdleTimeout`）、普通 `ai:error`、done 全部分支接入协调入口与终止状态机；新增 `claimUserStop()`：用户停止抢占状态机并保留已显示正文，迟到 done 不再触碰消息（同时修复了旧链路停止后迟到 done 把 UI 消息误移除的问题）；错误文案不再写进 `content`（移除 `⚠️ 错误` 落盘占位） |
| `useChatStore.ts` / `chatGeneration.ts` | `onError` 扩展第二参数 `terminal`（收口后的稳定正文 + 提示字段）：有稳定正文 → 保存正文 + `generationError`；无正文 → 移除占位不保存。重生成错误不再写 `⚠️` 候选（撤销空候选），续写中断只保存经收尾管线的正文 |
| 群聊 `groupStreamController.ts` | 点名/轮询/自由发言的普通 `ai:error` 与超时统一进 `handleGroupStreamException`（不复制保存逻辑）；`finalizeGroupReply` 改走协调入口；活动流增加 latch + `stopStringsHit`（停止字符串命中后的 cancelled 按正常 stop 收口，不再误标“已停止生成”）；新增 `claimGroupUserStop()` |
| Bridge `electron/bridge/chatService.ts` | transport error 携带部分正文时经同一协调入口收口：稳定正文 + `generationError` 落盘，安卓端以 `ai:done` 替换流式占位；无正文不发空消息（`ai:error` + 错误响应）；`finalizeBridgeReply` 改走协调入口，regenerate 空结果不再追加空候选；桥接方向请求补 `taskType` 观测 |

### 1.4 验收测试（§4.4）

新增 `src/store/__tests__/generationTerminationPhase7.test.ts`（14 项）：状态机一次性/迟到忽略、

补尾仅 length 且至多一次、错误文案不进正文、legacy 约束、`claimUserStop` 幂等；
群聊 `ai:error` 收口与迟到事件测试（`groupStreamController.test.ts` 新增 3 项）；
Bridge partial error 测试（`chatService.finalizeOrder.test.ts` 新增 2 项）。
既有契约测试按新行为矩阵更新（超时提示“请求超时，已保留完整部分”；
无正文不保存 `⚠️` 占位；S1 补尾用例改为 length 触顶口径）。

## 二、阶段 7.2：thought 契约与 Android 语义分块

  `groupChatContext.ts`（群聊，思考主体绑定当前 speaker）改为共同消费，消除三处文案漂移。
  双通道隔离既有实现不变（供应商 reasoning 清理不误删角色 `<thought>`、reasoning 不包装为

- 跨端共享分块 fixture：新增 `shared/fixtures/roleplay-blocks.json`（31 个样本，期望块由

  的副本约定）。
- Kotlin 等价移植：`ui/components/RoleplayBlocks.kt`（含 JS `\s` 完整空白集对齐、

- 双端测试：`roleplayBlocksFixture.test.ts`（PC）与 `RoleplayBlocksFixtureTest.kt`（Android）
  读取同一 fixture 逐条比对块数量、类型、speaker 与文本。

## 三、阶段 7.3：后台任务独立策略与运行治理

- `shared/backgroundGeneration.ts`（新增）：`BackgroundGenerationProfile`
  （memory / compression / title / direction）与完整性判定
  `hasCompleteSummaryTail`；长记忆摘要与事实 JSON 分别判断完整性的既有行为对齐档案口径
  （摘要完整而事实残缺 → 保存摘要并记录事实未更新，残缺 JSON 不当作“无新增事实”）。
- 接入点：单聊/群聊长记忆预算与 taskType 观测统一走 `memory` 档案；历史压缩（单聊与群聊）
  改 `onComplete` 获取 `finishReason`，触顶或缺完整摘要边界时丢弃结果（原历史不丢）并记
  `compression` 档案预算；会话标题生成触顶直接丢弃（保持旧标题）；方向建议保持
  `structure_only_once`（已有的一次结构修复），触顶输出按结构不完整处理。
- 补尾治理（§8.1）：补尾只带 `repairContext`（不重发世界书与长历史，测试固化）；
  补尾期间用户停止 → `abortActiveTailRepair()` 立即取消并保留稳定前缀（单聊/群聊 stopStreaming
  均已接线），取消不计失败；同一模型连续补尾失败两次 → 本次会话关闭自动补尾
  （`resetTailRepairFailureCounts` 供测试）。
- 观测最小化（§9.1）：`GenerationObservation` 新增 `taskType` 与 `terminationCause`
  （`observationTerminationCause` 由主进程按结局分类推导）；默认观测不落完整提示词、
  世界书、角色卡与回复正文（既有 tailSample 尾部采样口径保持）。

## 五、遗留与后续（方案 §8.2 / §9.2 / 阶段 7.4）

以下按方案属运行期工作，代码已备好度量字段（`terminationCause`、`taskType`、
`truncationKind`、补尾耗时经 durationMs 观测），不构成本阶段阻塞：

1. **指标基线**：自动补尾率 <5%、成功率 ≥90%、P95 增幅 ≤10%、不可恢复截断率 <1%
   需真实样本建立基线后作为灰度门槛（`scripts/generation-baseline.ts` 扩展口径待真实数据后补）。
2. **legacy 退出**：满足 §9.2 七项可衡量条件后按三步退出；当前 `generationPipeline` 灰度
   开关保持默认 unified，未删除任何 legacy 代码路径。
3. **thought 真实模型评测**：`scripts/evaluate-generation.ts` 已含 S10 检查项
   （第一人称 / 无计划复述）；阶段 7.4 要求“真实模型评测确认 thought 不包含模型推理”
   在灰度期按方案清单复跑即可。
4. 本地调试模式（显式打开、脱敏、过期、一键清除）：默认观测已不含正文，本阶段未新增
   原始文本落盘开关；如后续需要，按 §9.1 的六条约束单独实施。
