## 一、世界书格式兼容性检查

### 1.1 支持的格式矩阵

所有格式走统一归一化入口 `normalizeImportedLorebook`（[lorebookImport.ts:223](file:///d:/Code/qingyu/electron/services/lorebookImport.ts#L223)），独立导入与角色卡内嵌世界书（[charCard.ts:186](file:///d:/Code/qingyu/electron/services/charCard.ts#L186)）共用同一条链路，不存在两套解析分叉。

| 来源格式 | 识别特征 | 兼容结论 |
|---|---|---|
| 轻语原生 | `keywords` / `matchMode` / `useRegex` 字段 | 完全兼容 |
| SillyTavern world info | `key` / `keysecondary` / `selective` / 数字 `position` / `disable` | 主流字段兼容，少数降级（见 1.3） |
| CCv2/v3 character_book（角色卡内嵌） | `keys` / `secondary_keys` / `insertion_order` / `use_regex` | 兼容 |
| Risuum lorebook_v3 | 顶层 `spec === 'lorebook_v3'` + `{ data }` 包装 | 兼容（unwrapLorebookPayload） |

格式识别 `detectEntrySource` 按字段特征区分三种来源（[lorebookImport.ts:30](file:///d:/Code/qingyu/electron/services/lorebookImport.ts#L30)）。

### 1.2 已正确兼容的字段（抽查确认）

- **关键词**：`keywords / keys / key`、`secondaryKeywords / secondary_keys / keysecondary`，数组与逗号/换行分隔字符串均可，`/pattern/flags` 正则字面量整体保留不切分（[lorebookImport.ts:38-51](file:///d:/Code/qingyu/electron/services/lorebookImport.ts#L38-L51)）
- **位置**：ST 数字 0/1/4 与字符串别名 → `before_char / after_char / at_depth`（[lorebookImport.ts:72-81](file:///d:/Code/qingyu/electron/services/lorebookImport.ts#L72-L81)）
- **二级逻辑**：`selective / selectiveLogic / selective_logic`，ST 数字 0/1/2/3 → `and_any / not_all / not_any / and_all`，映射与 ST 一致
- **启用/顺序/概率**：`disable` 取反、`insertion_order`、`useProbability=false → 100`、probability clamp 0-100
- **常驻**：`constant=true → priority 'always'`
- **语义标记**：`vectorized=true → matchMode 'both'（有 key）/ 'semantic'（无 key）`
- **递归控制**：`exclude_recursion / prevent_recursion / delay_until_recursion`
- **包含组**：`group / group_override / group_weight / use_group_scoring`
- **定时效果**：`sticky / cooldown / delay`；**过滤**：`character_filter`、生成类型 `triggers`
- **书级**：`scan_depth`（保留 0 不静默改 1，有注释说明）、`recursive_scanning`、`token_budget`、`entries` 支持数组与对象映射两种形态
- 有专门测试锁定（`lorebookImport.test.ts` 覆盖 ST / character_book / lorebook_v3 三类用例）

### 1.3 发现的兼容问题与降级点

按影响程度排序：

| # | 问题 | 位置 | 影响 |
|---|---|---|---|
| 1 | **`tokenBudget` 导入后未生效**（✅ 已修复 2026-08-27：`triggerAndFitLorebooks` 内新增 `enforceBookBudgets`，按书级上限裁剪该条目注入总量，超限先尝试手写 summary 替代；结果透出 `bookBudgetDropped` 计数并由调用方记录日志；ignoreBudget 条目与未定义预算的书不受影响） | contextBuilder.ts | 原：ST/CC 世界书作者设置的预算语义丢失；多本书共用一个全局额度，大书小书不分 |
| 2 | **`vectorized` 条目在无语义索引时失效**（✅ 已修复 2026-08-27：`triggerAndFitLorebooks` 新增 `semanticEnabled` 入参，语义不可用时对仅依赖语义通道的条目（matchMode=semantic / 无关键词的 both）warn-once 告警；单聊与群聊调用方均已接入） | lorebook.ts | 原：从 ST 导入的纯 vectorized 条目成为死条目，且无任何运行时警告 |
| 3 | **at-depth 的 `role` 未导入**（✅ 已修复 2026-08-27：`LoreEntry` 新增 `role` 字段，导入时解析 ST position=4 的 role（仅 at_depth 位置有效，非法值忽略）；触发链路全透传至 `applyDepthInserts`，注入消息按 role 构造（system/user/assistant），单聊与群聊均已接入） | lorebookImport.ts | 原：全部按 system 侧注入 |
| 4 | **ST position 2/3（AN 前后）降级为 `at_end`**：代码注释明确这是有意降级（避免旧映射把 2 当 chat depth），但注入位置与 ST 不一致 | lorebookImport.ts:78-80 | 位置语义丢失（作者注释前/后 ≠ 系统末尾） |
| 5 | **at_depth 深度默认值差异**（✅ 已修复 2026-08-27：ST/character_book 来源的 at_depth 条目缺省 depth 从 0 改为 4（ST 默认注入深度）；原生条目保持 0 不受影响） | lorebookImport.ts:176-179 | 原：ST 导入的 at-depth 条目注入位置比原设计更靠后 |
| 6 | **书名 fallback 固定为"导入的世界书"**（✅ 已修复 2026-08-27：独立导入的书名 fallback 改用文件名（去 .json 扩展名），文件名为空才回退固定文案；避免批量导入后多本同名书） | ipc/lorebook.ts:82-89 | 原：批量导入后多本同名书，靠内容区分 |
| 7 | **字符串关键词的逗号切分副作用**：非正则字面量的字符串 key 按逗号切分，含逗号的普通关键词（如 `"Hello, world"`）会被拆成两个 | lorebookImport.ts:50 | 少见但存在误拆可能（ST 主流导出是数组，实际风险低） |
| 8 | 只支持 `.json` 文件导入（对话框过滤器）；无世界书**导出/回写 ST 格式**能力 | ipc/lorebook.ts:50-54 | 单向兼容：进得来出不去，生态互通缺口 |

**总体结论**：格式兼容做得相当扎实——四种格式、单链路归一化、字段映射有测试锁定。真正的缺口不在"解析"，而在 #1（书级预算不生效）和 #2（vectorized 条目静默失效），这两个是功能性丢失而非字段解析问题。

## 二、无语义索引时的触发能力评估

### 2.1 触发流水线（完整链路）

```
发送消息
  → fetchSemanticLoreHits（streamController.ts:96）   ← 语义关闭时快速失败，清空命中
  → buildChatContext → contextBuilder.ts:207
      → triggerAndFitLorebooks（lorebook.ts:848）
          1. 收集启用条目（书级+条目级 enabled）
          2. 递归扫描（最多 5 层）：关键词匹配 → secondary 过滤 → 包含组仲裁 → 概率骰子
          3. 语义候选合并（semanticItems=[]，此路为空）
          4. 统一评分 scoreItems（lorebook.ts:661）
          5. 分桶瀑布裁剪 fitLorebookBudgetByPriority（lorebook.ts:406）
          6. 按位置分发 before/after/at_end/at_depth
```

### 2.2 无索引时实际生效的触发特性

| 特性 | 状态 | 说明 |
|---|---|---|
| 词边界匹配 | ✅ | ASCII `\b` 边界、CJK 多字子串、CJK 单字标点边界（[keywordMatch, lorebook.ts:72](file:///d:/Code/qingyu/src/utils/lorebook.ts#L72)） |
| 正则关键词 | ✅ | ST `/pattern/flags` 字面量 + 原生 useRegex，带轮次缓存 |
| 大小写/整词覆盖 | ✅ | 条目级 caseSensitive / matchWholeWords |
| secondary keys 四种逻辑 | ✅ | and_any / and_all / not_any / not_all |
| 递归触发 | ✅ | 5 层，含 excludeRecursion / preventRecursion / delayUntilRecursion |
| 常驻条目（constant） | ✅ | priority=always 无条件注入（预算内），内容参与递归扫描 |
| 包含组互斥仲裁 | ✅ | group scoring + prioritize + 权重随机 |
| sticky / cooldown / delay | ✅ | 会话持久化，条目哈希变更自动失效 |
| 触发概率 | ✅ | 每次激活掷骰 |
| 条目级 scanDepth 覆盖 | ✅ | loreEntryScanText 按条目裁剪扫描窗口 |
| 评分排序 | ⚠️ 部分 | 权重 keyword 0.35 + semantic 0.35 + entity 0.15 + recency 0.15；**semantic 分恒为 0** |
| 实体加分 | ✅ | 受控词表（角色 tags/群成员名/激活条目 keywords）零误报命中加分 |
| 近因加分 | ✅ | 最近 5 轮触发过的条目环形缓冲加权 |
| 预算裁剪 | ✅ | 全局 30% 比例 → always 硬上限 40% → 瀑布 → 手写摘要替代 → AI 压缩缓存（阶段三） |

### 2.3 结论：无索引时的能力判定

**功能完整度高**。ST 世界书的主要触发面（关键词、正则、二级逻辑、递归、包含组、定时效果、概率、预算）全部独立于语义索引工作，语义检索是纯增量通道（关闭时"快速失败、静默降级"，设计正确）。

**两个残留影响**：

1. **纯语义条目死区**（上表 #2）：`matchMode: 'semantic'` 且无关键词的条目永不触发。评分中 0.35 的 semantic 权重也归零——所有条目同减一个常数，**相对排序不受影响**，但 entity 0.15 / recency 0.15 的相对话语权从 15/70 放大到 15/65，属于可接受的偏移。
2. **评分区分度收窄**：有效分只由 keywordHits（0-1 归一化）+ 两个 0.15 布尔加成构成，多关键词条目与单关键词条目的排序区分主要靠命中率，区分度一般。

## 三、优化与加强建议（无语义索引场景）

按成本从低到高排列，前 5 项为纯关键词链路内的加强，不引入任何外部依赖：

### P0（低成本，建议优先做）

1. **扫描文本去噪**（✅ 已修复 2026-08-27：新增 `stripMarkdownNoise`，在 `triggerAndFitLorebooks` 入口对 scanText/scanMessages 剥离 markdown 语法——围栏代码块整体移除、图片/HTML 移除、链接保留文字、`*动作*`/粗体/斜体去标记、行首标题/列表标记剥离；带 200 条 LRU 缓存；递归条目原文不去噪）
2. **语义死条目告警**（✅ 已修复 2026-08-27，见上文问题 #2）
3. **关键词命中频率计分**（✅ 已修复 2026-08-27：`scoreItems` 的 keywordHits 改为 coverage（命中关键词数/总数）与 frequency（`1-e^(-命中次数)`，每词上限 3）各占一半；计数基于对话文本而非递归文本，避免条目自含关键词的递归自我强化；`loreEntryKeywordMatch` 重构为 `loreEntryKeywordCount` 的布尔 wrapper，匹配语义不变）

### P1（中成本）

4. **无索引时的 semantic 近似补偿**（✅ 已修复 2026-08-27：新增 `semanticScoreByOverlap`——大粒度 token（CJK 双字滑窗 + ASCII 词）+ Dice 系数计算对话与条目 keywords/content 的词面重叠，R=0.35 封顶保证与真实语义命中可比；`scoreItems` 中仅在该条目本轮无真实语义命中时启用近似，真实值始终优先；对话文本为空或条目无定位 key 时跳过。零依赖纯函数，语义关闭/未配置/未命中三种场景下 semantic 评分维度自动恢复满配）
5. **书级 tokenBudget 生效**（✅ 已修复 2026-08-27：`enforceBookBudgets` 书级裁剪 + `allocateGlobalBudgetByBooks` 配额分配——多书激活且书级预算总和超过全局预算时按预算比例分配全局额度（无预算书按带预算书平均值对待），大书不再挤占小书；配额充裕时足额分配，行为不变；单书场景与旧有书级裁剪完全一致）
6. **关键词倒排索引**：当前每轮 O(条目 × 关键词 × 文本)，条目上千的大书有性能余量风险。构建"关键词 → 条目"倒排表（已有 asciiKeywordRegexCache 可复用），扫描一次文本只处理命中的候选。

### P2（较高成本，按需评估）

7. **中文分词增强实体提取**：`extractEntities` 依赖受控词表（[lorebook.ts:604](file:///d:/Code/qingyu/src/utils/lorebook.ts#L604)），词表外的实体（新地名、昵称）拿不到 entity 加分。引入 jieba-wasm 之类轻量分词可扩大覆盖，但会增加依赖与初始化成本。
8. **recency 衰减化**：当前是 5 轮窗口内布尔加分，改为按轮数衰减（最近一轮 0.15 → 第 5 轮 0.03）更符合注意力曲线，改动只在 `scoreItems`。
9. **同义词/别名机制**：条目级 alias 字段或全局同义词表，解决"称呼变体不触发"（例如角色有多个名字/称号）。注意需与导入格式对齐（ST 没有对应字段，属原生扩展）。
10. **世界书导出（ST 格式）**：补上 #8 的单向兼容缺口，实现生态互通。归一化是单向的（normalizeImportedLorebook 无逆函数），需要单独写 serializer。

### 不建议做的

- 为无索引场景引入重量级本地 embedding（ONNX runtime 等）：现有"语义可关 + 关键词全量兜底"的架构分层是干净的，重量级方案会把一个可选增强变成必选依赖。

## 四、总体评价

| 维度 | 评价 |
|---|---|
| 格式兼容 | **良好**。四格式统一归一化 + 测试锁定，解析层无明显 bug；缺口集中在"导入字段未全量生效"（tokenBudget、role、vectorized 死条目） |
| 无索引触发 | **完整可用**。ST 主流触发特性全覆盖，语义是纯增量通道、降级路径干净 |
| 优化空间 | **明确存在**。P0 三项（扫描去噪、死条目告警、频率计分）收益直接、改动局部；P1 的语义近似补偿可让评分体系在无索引时恢复满配 |
