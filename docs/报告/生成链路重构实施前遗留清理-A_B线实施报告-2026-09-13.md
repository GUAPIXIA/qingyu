## 2. A 线实施明细

### 2.1 A1：ZIP 恢复目录穿越（P0-A，双重确认项关闭）

`electron/services/backup.ts` 重写恢复侧：

1. **路径统一校验**：新增 `safeEntrySegments()`，拒绝反斜杠变体、盘符、绝对路径、空段、`.` 与 `..` 段、含冒号的段；
   所有落盘路径统一经 `safePath(rootDir, ...segments)` 生成（`characters/`、`lorebooks/`、`presets/`、`chats/`、`groups/` 与 6 个 config 固定文件）。
2. **根目录边界二次断言**：`assertWithinRoot()` 对 `resolve(dest)` 复查，不依赖前置校验。
3. **manifest ↔ zip 双向一致性**：zip 任一条目缺哈希记录、manifest 任一条记录在包内缺失、条目重复，均整包拒绝；
   未知前缀条目同样拒绝（同时明确区分"路径非法"与"未知条目"，便于审计）。
4. **删除无效写法**：原 `idFromZipPath` 的"重复调用仅为触发校验"改为显式 `validateTopLevelId()`，只对
   `characters/`、`lorebooks/`、`presets/` 直属 `.json`（文件名即 id）做 `safeId` 强校验。

`safePath()`（`electron/utils/pathGuard.ts`）从"有实现有单测但零调用"变为生产真实调用。

### 2.2 A2：备份泄露凭据（P0-B，双重确认项关闭）

1. `semanticTrigger.apiKey` 纳入 `SECRET_COLLECTIONS` 同级的 `SECRET_SINGLETONS`，在
   `electron/services/backup.ts`（导出剥离 / 导入迁移）与 `electron/ipc/settings.ts`（保存剥离 / 读取回填）两侧同步；
   备份包与 settings.json 均不再出现该明文，恢复旧包时迁移进 safeStorage（键名 `semanticTrigger`）。
2. MCP：导出时对 `config/mcp-servers.json` 做 `sanitizeMcpServers()`——
   env 键名命中 `KEY|TOKEN|SECRET|PASSWORD` 的值置空（保留键名提示回填），URL 内嵌 userinfo 打码。
3. 用户可见声明同步：`EXCLUDED_ITEMS` 与 `SettingsPage` 的"未包含"清单改为与真实行为一致
   （新增 MCP 敏感环境变量条目）。

  `electron/bridge/auth.ts` lines 70 / branches 60。

**门禁**：`eslint.config.js` 新增 block——`electron/**/*.{ts,tsx}`（排除 `__tests__`/`*.test.*`）

**保真验证**：迁移仅改写 import 说明符——对 19 个迁移文件做「剥离 import 行后的内容指纹」比对，

  搬进唯一迁移链：
  1. 旧 `providers` + safeStorage 凭据 → `connectionProfiles`（凭据写入 `profile-<id>`，settings.json 不落明文）；
  2. `ttsProvider/ttsVoice/ttsModel`、`imageGenModel`、`visionModel` 单字段 → 模型数组；
  3. 删除 `ttsProvider/ttsVoice/ttsModel/visionModel/imageGenModel/authorNote`，存量 TTS `edge → system`。

- `src/store/useSettingsStore.ts`：兜底路径保留但**不再写盘**（两处 `settings.save` 移除），

- 测试：`migration.test.ts` 新增 6 个 v2→v3 用例（凭据迁移、activeProfileId 保持、单字段转换、
