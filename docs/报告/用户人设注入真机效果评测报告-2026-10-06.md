## 2. 评测方法与控制变量

### 2.1 走生产组装链路，不重写组装逻辑

```
mainContextProvider.fetchBuildData（按**会话 personaId** 解析身份，不读 settings 旧镜像）
  → contextService.build
    → shared/chat-core/contextBuilder.buildContextMessage（真人设注入点）
      → 真实 provider adapter（仅省略 IPC 传输层与流式 UI 回传）
```

隔离方式沿用既有真机基准范式（`scripts/session-isolation-model-bench.ts`）：把真实配置复制进临时 `userData`，**只读**真实目录，结束时校验源文件哈希并删除隔离副本中的凭据。

### 2.2 四组对照（同角色卡、同一条用户消息、同温度、同采样数）

| 组 | 会话身份 | 注入配置 | 设计意图 |
|---|---|---|---|
| `off` | 真实身份 | `enabled=false` | 基线：用户名仍经叙事提示出现（"与 大本 互动"），但没有身份区块 |
| `system` | 真实身份 | `enabled=true, position=system` | 生产默认；与 `off` 构成**唯一变量**对比 |
| `separate` | 真实身份 | `enabled=true, position=separate` | 只换位置 |
| `counter` | **同名对照身份** | `enabled=true, position=system` | 只换描述与性格内容 |

反事实身份刻意**与真实身份同名**：名字在所有组都经叙事提示出现，因此 `system` 与 `counter` 的差异只可能来自描述与性格的**内容**，排除了"名字不同"这一混杂变量。

角色卡与探针均为本脚本自建的中性夹具（小酒肆掌柜／打烊前的雪夜）。探针要求角色**评价用户这个人**（"说说看，我这个人，你看出什么来了？"），把"模型到底知不知道这个用户是谁"逼到台面上；探针本身不含任何身份线索，否则 `off` 组会凭空拿到身份信息、对照失效。

### 2.3 判分：盲测 + 位置翻转 + 确定性核对

- 判分模型**不知道**本轮注入了哪一条候选身份，只看到"候选 A / 候选 B / 回复"；
- A/B 位置按采样序号翻转（偶数真实在 A、奇数真实在 B），抵消位置偏置；
- 判分与主对话使用同一连接，`task='generic'`、温度 0、`resolveGenerationTaskBudget` 同源预算；
- **确定性层不经判分模型**：身份名出现次数、提示词元信息词、显式词表、`<thought>` 残留，全部字符串匹配。

> **控制变量说明**：推理档位固定 `off`。`deepseek-v4.1-flash` 为推理模型，实测 400 token 预算会被推理吃光并返回空正文（即仓库已记录的 `REASONING_BUDGET_EXHAUSTED` 现象）。若各组推理长度不同，会把"身份体现程度"的差异混入"推理占用预算"的差异，故固定关推理并给足正文额度。

## 3. 组装层结果

| 组 | 人设块存在 | 块所在消息索引 | 在首条 system 内 | 描述已注入 | 性格已注入 | 断言失败 |
|---|---|---|---|---|---|---|
| `off` | ❌ | — | — | — | — | 0 |
| `system` | ✅ | 0 | ✅ | ✅ | ✅ | 0 |
| `separate` | ✅ | 1 | ❌ | ✅ | ✅ | 0 |
| `counter` | ✅ | 0 | ✅ | ✅（对照内容） | ✅（对照内容） | 0 |

消息序列：`off`/`system`/`counter` 为 `system → user → system`；`separate` 为 `system → system(人设) → user → system`。四组均无断言失败，说明**注入文本、开关与位置三条语义全部按设计生效**——此前只有单测覆盖（`src/store/__tests__/personaInjection.test.ts`、`shared/__tests__/*Golden.test.ts`），本次在真机链路上再次确认。

## 4. 效果层结果

### 4.1 主指标：身份体现度（判分 0–3）

| 组 | 各样本 | 均值 | 对比 `off`（双侧置换检验，n=5/组） |
|---|---|---|---|
| `off` | 0, 1, 1, 1, 0 | 0.60 | — |
| `system` | 1, 2, 2, 2, 2 | **1.80** | 差 1.20，**p = 0.032** |
| `counter` | 2, 2, 2, 2, 3 | **2.20** | 差 1.60，**p = 0.008** |
| `separate` | 1, 2, 0, 2, 0 | 1.00 | 差 0.40，p = 0.68 |

`off`(5) vs 全部注入组(15)：差 1.07，p = 0.034。

### 4.2 次指标：判分认为"两条候选都不吻合"（NONE）的样本数

`off` 2/5、`separate` 2/5、`system` 0/5、`counter` 0/5。`off`(2/5) vs 全部注入组(0/15) 双侧 Fisher **p = 0.053**。方向与主指标一致：**关闭注入时，回复更像"一个陌生人"；注入后，回复稳定地被读成"认识这个用户"**。

### 4.3 可追溯性：注入内容真的被用上了

反事实组第 5 条原文：

> 「您这人，进门先看有没有别的客人，坐也挑背光的角。**话少**，可从来不空手走，**每回来都还了书**，连折角都捋平了。」

对照身份的描述是"旧书店的常客，作息颠倒，喜欢在深夜读绝版书"，性格是"温和守礼，与人保持距离，**话少**但不冷"。**"还书／折角"在角色卡、探针、任何其它组里都不存在**，只能来自注入文本。这是本轮最强的正面证据：注入内容确实进入了模型视野并被写进回复。

但同一证据也暴露了效果的不对称：对照身份是**良性日常设定**，在小酒肆场景里有落点；真实人设的描述是露骨性内容与身体能力设定，在"打烊前买酒"的场景里**没有可安全落地的位置**，因此 `system` 组 5/5 都没有出现描述中的独有事实，只出现气质层的呼应（"那点和气太匀了，匀得像画上去的"）。

### 4.4 护栏

20/20 样本中：替用户说话 0、改写/补全身份 0、提示词元信息泄露 0、无关场景引入露骨内容 0；`<thought>` 未泄漏到正文；确定性显式词命中 0 样本。**注入没有带来越界副作用**。

## 5. 发现

### 5.1 【中】群聊路径缺少单聊的【用户身份使用规则】段

单聊的注入块是：

```
【用户人设】
用户名：X
描述：Y
性格：Z

【用户身份使用规则】
将上述身份视为既定事实：……不得忽略、改写、擅自补全或生成冲突信息，也不得替用户说话、行动、思考、感受或决定。
```

群聊只注入到"性格：Z"为止，**没有使用规则段**，且这条差异**跨端一致**：

| 路径 | 位置 | 使用规则段 |
|---|---|---|
| PC 单聊 | `shared/chat-core/contextBuilder.ts:333` | ✅ |
| Android 单聊 | `android/.../ChatContextBuilder.kt:337`（注释声明"与 shared/chat-core/contextBuilder.ts 逐字对齐（含【用户身份使用规则】段）"） | ✅ |
| PC 群聊 | `shared/chat-core/groupContextBlocks.ts:149`（`buildGroupUserPersona`）+ `groupContextBuilder.ts:287`；渲染层同源调用见 `src/store/groupChatContext.ts:326` | ❌ |
| Android 群聊 | `android/.../ChatGroupContextBlocks.kt:132` + `ChatGroupContextBuilder.kt:252` | ❌ |
| 跨端夹具 | `shared/fixtures/.../context-builder.json` 有该段；`group-context.json` 无 | — |

群聊叙事边界段（"不替 X 说话、行动、思考、感受或作出决定"）覆盖了规则的后半句，但**"不得忽略、改写、擅自补全或生成冲突信息"这半句在群聊里没有等价文本**。

该漂移并非本次新发现：`docs/报告/PC端用户体验修复实施报告-第二轮.md` 已记录"Android context-builder 域既有漂移（`ChatContextBuilderGoldenTest` 期望【用户身份使用规则】段）**按用户指示忽略**"。本报告补充的是：**漂移的准确边界是"群聊 vs 单聊"，而非"PC vs Android"**，且**本轮真机评测未覆盖群聊**，所以它对实际表现的影响仍然未知。

#### 5.1.1 修复（2026-10-06）

按"唯一来源 + 两端同步"修复，而不是在群聊里再抄一遍规则文本：

| 改动 | 文件 | 说明 |
|---|---|---|
| 新增唯一来源 | `shared/chat-core/userPersonaBlock.ts`（Kotlin 对应 `chatcore/ChatUserPersonaBlock.kt`） | 标题、规则文本、分隔口径只在此定义；`buildUserPersonaBlock(body)` 把身份正文包成完整块，尾随换行差异在内部分摊 |
| PC 单聊接入 | `shared/chat-core/contextBuilder.ts` | 删除内联模板，改调共享构造（**输出零字节变化**，由 `context-builder.json` 与快照双证） |
| PC 群聊接入 | `shared/chat-core/groupContextBuilder.ts`、`src/store/groupChatContext.ts`（渲染层群聊） | `system` 与 `separate` 两个位置都改为注入完整块 |
| Android 接入 | `ChatContextBuilder.kt`（单聊）、`ChatGroupContextBuilder.kt`（群聊） | 同构改法；单聊同样零字节变化 |
| 夹具再生 | `shared/fixtures/.../group-context.json` + `android/shared/fixtures/...`（同仓第二挂载点） | 4 处（mention／polling／free／全局叙事）补上规则段；其余夹具的行尾噪音已还原 |
| 回归测试 | `shared/__tests__/userPersonaBlock.test.ts` + `chatcore/ChatUserPersonaBlockTest.kt` | 钉住"单聊正文（无尾随换行）与群聊正文（有尾随换行）产出**逐字一致**的块"——这正是原缺陷的可抓形态 |
| 接线测试 | `chatcore/ChatPersonaWiringTest.kt` | 真机请求文本必须含使用规则段（此前只断言描述与性格） |

修复后 `separate` 位置同样带上规则段（此前两个位置都缺）。

### 5.2 【方法学】"能否分辨注入的是哪一条身份"这一检验本轮未能成立

原设计的核心证伪手段是：让判分模型在两条候选身份间二选一，看它是否挑中真正注入的那条。结果是 **20/20 全部倒向对照身份**，包括完全没有注入身份的 `off` 组（5/5）。这说明该二选一指标被"回复的整体语气"（克制、疏离、像在观察对方）主导，而不是被身份内容主导——它是一个**失效的指标，不是"注入无效"的证据**。

结论：`counter` 组的"内容签名"（5.1 节的"还书／折角"）才是本轮关于"内容是否被用上"的可靠证据；二选一指标已从结论中剔除。若要恢复该手段，需要让两条候选身份在**同一维度上等距可分**（例如仅性别不同、仅职业不同），而不是气质取向不同。

### 5.3 【低】效果强度受场景可用性限制

同一套注入，在"打烊前买酒 + 评价我"的场景里只体现为气质层；若场景本身能容纳人设内容（对照组的良性设定即是），模型会直接复用具体细节。这不属于链路缺陷，但意味着**用户对"注入效果"的主观感受会强烈依赖场景**：设定里的具体信息若长期没有场景落点，默认就体现不出来。

## 6. 边界与未覆盖

1. **单轮**：每组只发一条用户消息，未测多轮对话中的身份保持与漂移。
2. **群聊真机未测**：PC 群聊上下文在**渲染层**组装（`src/store/groupChatContext.ts`），本脚本走的是主进程链路；覆盖群聊需要 Playwright/渲染层夹具，本轮未做。5.1 节的群聊结论是**源码与夹具层面的确定结论**，不是真机行为结论。
3. **`separate` 位置结论为"未观察到"**：n=5、功效不足；不得读作"无效"。
4. **判分模型与主对话同源同模型**：存在自评偏置风险，已用盲测 + 位置翻转 + 确定性核对三层缓解，但仍不是独立裁判。
5. **推理档位固定 `off`**：真实使用时用户可能处于 `standard` 档，推理占用会影响正文长度，本轮未覆盖。
6. **单一温度（0.8）与单一模型**（`deepseek-v4.1-flash`）：换模型/换温度的非确定性未测。
7. **真实人设的内容特性限制了本探针的可分辨上限**：真实身份的露骨内容在非露骨探针下无法落地，因此"系统组"天然缺少可与对照组对等的可复用细节。这是设计上的残留不等价，已在 5.2、5.3 明确。

## 7. 复现与证据

```powershell
# 完整评测（4 组 × 5 次采样 + 盲测判分）
$env:PERSONA_BENCH_SAMPLES='5'; node scripts/run-persona-injection-model.mjs

# 只跑指定组（重跑单组/快速自检）

# 零 token 成本：只组装上下文并校验断言
```

环境变量：`PERSONA_BENCH_SAMPLES`（默认 3）、`PERSONA_BENCH_TEMPERATURE`（默认 0.8）、`PERSONA_BENCH_JUDGE=off`（关闭判分）、`PERSONA_BENCH_SOURCE`（真实配置目录）。

证据文件（`output/` 不入库）：`model-report.json`（含四组完整上下文、逐样本回复、判分结果、统计摘要）、`cleanup.json`（凭据清理与源配置哈希自证）、`process.log`。
