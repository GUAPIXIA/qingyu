# 空间画板 PC 实机测试报告

日期：2026-10-03。结论：核心编辑、真实 IPC 保存和重启恢复通过；发现两项问题，本轮不能记为全部通过。

后续状态：两项问题已修复并复验，见[实机问题修复报告](空间画板PC实机问题修复报告-2026-10-03.md)。本文保留初次测试结论；修复后的截图与结果以修复报告为准。

## 测试环境与范围

在 Windows 本机启动当前源码的真实 Electron 客户端（仓库 Electron 43.4.0，应用 0.18.0），通过 Playwright 操作实际窗口、嵌入 iframe、鼠标与表单。所有测试使用独立 userData 和专用角色、单聊会话、群聊。单聊/群聊 GUI 测试调用正式 preload、IPC 和磁盘服务，没有替换业务 API。

真实模型联验使用当前有效连接 OpenCode Go / deepseek-v4.1-flash。隔离目录复制的配置、凭据和 Local State 已在退出后清理，并核对没有残留。正式用户的聊天和画板未被测试修改。

## 问题 1：单聊回答仍采用旧起点

复现：初始化林雪在厨房、旅人在花园；确认画板助手把林雪移到花园；询问两人现在在哪里。

预期：两人均在花园。实际：当前连接回答“林雪在厨房里，旅人在花园中。”首次联验失败后，复用相同输入重复两次，三次均返回同样的错误位置。

已核对正式上下文和实际序列化发出的 HTTP 请求消息，均包含 `当前聊天角色 "林雪"："青石城" > "花园"`，并说明最新位置优先于旧角色设定、开场与历史。因此当前证据不支持“位置未保存”或“空间块未发出”的解释。额外进行一次合并 system 消息的诊断请求仍失败；尚未定位供应商内部处理或模型遵循规则的具体原因，未通过放宽断言掩盖失败。

证据：[单聊联验结果](../../output/playwright/spatial-real-2026-10-03/single-model-result.json)、[复现与实际请求消息](../../output/playwright/spatial-real-2026-10-03/readonly-probe.json)。

## 问题 2：最小群聊窗口裁切画板顶部开关

复现：保持应用导航与群聊列表展开，打开已启用的群聊画板，把真实 Electron 窗口缩到 900×600。

预期：启用开关始终可见、可操作。实际：iframe 横向范围为 x=480 至 884，开关范围为 x=904.56 至 940.56，整个开关落在可见区域外。顶部使用不收缩的开关和其他固定宽度控件，嵌入区域宽度仅 404px 时不足。

已验证临时操作：点击“收起群聊列表”，开关恢复可见。此问题尚未修改产品样式。

证据：[裁切截图](../../output/playwright/spatial-real-2026-10-03/group-compact.png)、[收起列表后的截图](../../output/playwright/spatial-real-2026-10-03/group-compact-collapsed.png)、[坐标与 GUI 结果](../../output/playwright/spatial-real-2026-10-03/extended-result.json)。
