## 1. 交付结果

PC 嵌入画板现在发送领域命令，主进程重新读取并校验当前数据，执行命令后返回权威快照。原 `spatial:saveBound` 整份快照保存接口被拒绝，通用聊天会话 patch 也不能修改空间绑定。

| 能力 | 已实施行为 |
|---|---|
| 统一提交 | `spatialService.applyEditorBatch` 复用独立包纯核心；同一空间锁覆盖读取、检查、执行、记录与恢复 |
| 版本校验 | 同时核对 world/runtime ID、bindingEpoch、runtime revision 与 world fingerprint |
| 幂等 | 相同 commitId 和请求只执行一次；重试返回原收据和最新快照；同 ID 不同内容被拒绝 |
| 共享世界保护 | 删除、重挂父级、跨画板移动、入口移除或 actor 重新映射前检查全部 runtime 引用，列出受影响会话 |
| 事务恢复 | world、runtime、提交记录及创建时的会话绑定通过预写事务协调；中断后按文件哈希和绑定核对后继续完成 |
| 编辑器确认 | 命令串行发送，本地连续操作保留预览；自己的回执保持视口、选中对象和撤销历史 |
| 外部更新 | 无待提交操作时同步；有待提交操作时保留预览并提示冲突；重试保留原 ID 和版本 |
| 手动撤销 | 逆命令作为新的版本提交，重做通过相同命令服务；不回写旧文档快照 |
| 离开画板 | 返回聊天、切换角色/会话、创建会话、删除当前会话及侧栏导航等待 flush；失败留在原上下文处理 |
| 备份 | 现有递归空间数据备份覆盖新增 session-state 和 transactions，往返测试验证文件保留 |

世界继续共用，位置继续按单聊角色/会话隔离。世界指纹包含层级、几何、参与标记、距离和 actor 身份等有效数据，排除时间元数据、头像装饰和视口提示。

## 2. 提交协议

读取和创建返回 `world`、`runtime`、`version`。提交形状如下，指纹示例为占位值，实际取读取结果：

```json
{
  "commitId": "uuid-for-this-edit",
  "worldId": "world-id",
  "runtimeId": "single_session-id",
  "bindingEpoch": "binding-generation-id",
  "expectedRuntimeRevision": 3,
  "expectedWorldFingerprint": "64-character-sha256-from-version",
  "commands": [
    { "type": "update_world", "patch": { "name": "青石城" } }
  ]
}
```

成功响应包含确认后的快照、`revisionBefore/revisionAfter`、最终世界指纹以及 `duplicate`。版本冲突返回当前快照供核对，客户端不会偷偷改成最新版本再次提交。收据在 `session-state` 中独立保存，核心事件裁剪到 500 条不会删除去重信息。

重复提交可能发生在确认丢失后。此时响应中的当前快照可能晚于原提交收据；编辑器会停止自动回放旧的后续操作，等待明确核对或载入，避免把旧意图套到新的世界状态。

主要实现文件：

- `shared/spatial.ts`、`shared/ipc-api.ts`、`electron/preload.ts`：PC 协议与桥接 API。
- `electron/services/spatialService.ts`：绑定、版本校验、核心执行、共享引用保护与更新通知。
- `electron/services/spatialRepository.ts`：稳定哈希、持久化、事务和恢复。
- `electron/ipc/spatial.ts`：IPC 适配器与旧保存入口拒绝。
- `electron/ipc/chat.ts`：专用空间绑定 CAS，保留会话其他字段。
- `spatial-board/src/embedded/bridge.ts`、`commandQueue.ts`：命令提取、确认队列与冲突处理。
- `spatial-board/src/store/spatialStore.ts`：权威同步保持当前视图与自己的撤销栈。
- `src/components/chat/SpatialBoardPane.tsx`、`src/lib/spatialFlush.ts`：父窗口协议、同步和离开前确认。

独立画板包仍不反向依赖 PC 源码。嵌入模式的 IndexedDB 草稿不作为 PC 保存来源。

## 3. 持久化与恢复

```text
data/spatial/
  worlds/{worldId}.json
  runtimes/{characterId}/{sessionId}.json
  session-state/{characterId}/{sessionId}.json
  transactions/{commitId}.json
```

事务先保存各文件的前后哈希和后镜像，再逐文件原子替换，最后以 CAS 更新创建时的会话绑定并移除事务文件。正常编辑也记录预期绑定。启动以及后续空间操作前都会检查未完成事务。

恢复先核对全部文件，每个文件必须仍是事务的前态或后态；会话绑定必须仍匹配。若文件已经产生其他改动、会话被删除/解绑或记录损坏，则停止并保留记录供恢复核对，不盲目重放，不覆盖后来数据。

有效绑定的正常读取不会补 actor、重新生成位置或覆盖缺失/损坏文件。已有 V1 world/runtime 可以读取；没有提交 sidecar 的历史会话使用 `legacy` 绑定代次，首次成功编辑才写提交记录。新建/绑定使用新的随机代次。

这套验证覆盖进程提交中断及原子替换恢复。尚未进行系统断电、文件系统损坏或安装包运行的故障演练；内存中尚未发出的编辑也不是持久化草稿。强制结束窗口不能等价于界面 flush。

## 5. 后续范围

阶段 1a 接入沿用当前聊天连接/模型的独立画板 AI 会话，以及设定/聊天生成初始化草稿。阶段 1b 接入对话 AI 的只读位置投影和预算；阶段 2 接入正文保存后的剧情同步；阶段 3 完成提案确认、AI 任务生命周期和完整恢复闭环。

当前阶段没有新增 AI 调用、模型选择器、对话空间注入或自动剧情移动。群聊按通用隔离方案的共享 runtime 和批次规则另行接入。方案整体保持“待处理”，阶段 0 单独标记完成。
