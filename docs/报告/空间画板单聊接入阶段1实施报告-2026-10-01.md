## 1. 用户使用流程

1. PC 单聊打开画板，选择“从当前设定生成”“创建空白”，或绑定已有世界。
2. 在画板助手中按需补充场景说明、勾选当前启用世界书条目，点击“生成场景”。
3. 草稿直接显示在画板中，允许手动修改和撤销/重做；确认前不改变正式地图或人物位置。
4. 核对来源、起点和未明确项，点击“确认场景”，由主进程统一提交。
5. 画板 **✧** 打开独立助手。输入“把 Aiko 移到厨房”，先显示提案，点击“应用”才移动。
6. 普通聊天下一轮读取已确认的位置；助手内可以关闭“对话读取位置”。

已有非空地图提供“建议人物起点”，只将尚未放置的当前人物建议到已有地点，不重新生成地图、不重置已有位置。未知起点保留未放置。

## 2. 阶段 1a：独立助手与初始化

| 能力 | 实际实现 |
|---|---|
| 模型来源 | 共享聊天连接解析器，每次读取当前连接和 activeModel；不增加选择器、不保存密钥到助手会话 |
| 作用域 | `characterId + sessionId + worldId + runtimeId + bindingEpoch`；未绑定时使用临时范围，确认后同步更新范围 |
| 独立历史 | 指令、初始化请求、AI 说明、提案和实际提交结果保存在 `data/spatial/ai-sessions/{id}.json`，不写主聊天 JSONL |
| 初始化来源 | 本次说明、实际选中开场/首条正文、最近 12 条已保存正文、角色场景/描述、有效 persona、选中的启用世界书条目；排除思考、未选开场和示例对话 |
| 来源与规模 | 每个初始化节点、子画板、距离和起点需要来源 ID 与原文摘录；最多 20 节点、3 子画板、20 距离、当前两个人物起点；正式 ID 和显示布局由应用生成 |
| 草稿编辑 | iframe 命令写独立草稿，核对草稿版本并记录去重收据；确认前不写正式 world/runtime |
| 指令权限 | 严格声明式 JSON 转核心命令；只能移动当前聊天角色/有效 persona，未知实体、额外字段及身份替换拒绝 |
| 确认校验 | 助手文件、绑定、persona、world 指纹、runtime 修订；初始化/起点额外核对来源指纹，旧提案不能覆盖新手动操作 |
| 原子提交 | world、runtime、sidecar、AI 已确认结果和新会话绑定进入预写事务；断电恢复和重复确认不重复执行 |
| 请求生命周期 | 调用前登记任务；请求 ID 去重；独立停止；失败不自动重发；重启的未知结果标记中断 |
| 预算与统计 | 共享任务预算；地图索引、来源、助手历史限额及最终序列化检查；独立记录模型、tokens、耗时和裁剪来源 |
| 删除与备份 | 删除单聊前停止助手并清理该单聊当前/归档 AI 文件、runtime/sidecar，保留共享 world；整库备份恢复包含助手历史与提案 |

只有主进程提交成功后，助手才记录实际“已确认”结果。草稿及待确认移动不进入主聊天。

## 3. 阶段 1b：对话只读位置

| 项目 | 实际实现 |
|---|---|
| V2 | Orchestrator 传递真实客户端来源；desktop provider 读取一致快照，ContextService 保留快照身份 |
| Legacy | 正常发送先等待画板保存、读取位置并预检，再复用本轮快照；重生成/续写在流控制器预取；prebuilt 重试保留原投影 |
| PC 范围 | Android/桥接不启用 PC 空间投影，群聊尚未接入 |
| 主对话数据 | 当前角色/persona 的包含路径、参与状态、位置精度及相关明确距离；不传坐标、事件日志、命令 schema 或助手历史 |
| 叙事与知识 | 沉浸聚焦当前角色，persona 异地位置仅为引擎背景；全局聚焦聊天角色，persona 仅作背景；同画板/同住宅不等于面对面，已有依据可异地交流 |
| 位置基线 | 已确认空间块优先于旧起点；本轮明确完成的新位置声明可推进叙事，准备前往不是到达；普通聊天正文不写画板 |
| 参与规则 | 未放置为未知，允许发送；沉浸角色处于系统 offstage 区域时阻止发送并保留输入；全局旁白可继续，该角色不得作为现场参与者回应 |
| 预算与诊断 | 800 估算 tokens 上限；在记忆/世界书/历史分配前预留必要位置，裁剪补充关系，最小块放不下则拒绝发送；`current-state`、`origin=spatial`，预览显示 tokens、修订、快照及裁剪原因 |
| 只读与开关 | 读取和预览不增加 actor、不创建 runtime、不改位置；关闭或未绑定回归原上下文行为 |
