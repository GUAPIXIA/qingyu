## 1. 用户使用流程

1. 已初始化或绑定画板，并关联独立画板助手。
2. 从画板 **✧** 打开助手，“剧情同步”默认“需确认”，可切换为“关闭”。
3. 普通聊天完整正文保存成功后，主进程登记后台提取任务。聊天正文保持原来的完成状态。
4. 助手展示“剧情位置建议”、来源原文与空间版本；用户点击“应用”后才更新位置。
5. 计划、未知目标、歧义和未经用户声明的 persona 行动只展示诊断，不能应用。提取失败可显式“重新提取本轮剧情”。

关闭剧情同步会停止在途/排队剧情任务并使未应用剧情建议失效，主动画板指令仍可使用。“对话读取位置”保留独立开关。未确认的建议不改变下一轮读取的正式位置。

## 2. 保存完成点与独立队列

| 能力 | 实际实现 |
|---|---|
| V2 | desktop 单聊在发送时保存空间基线，最终正文成功保存且模型 `finishReason=stop` 后登记；Android 不接入。真实消息端口与编排器完整集成回归通过 |
| Legacy | 普通发送、重生成、续写共用完成入口；等待消息保存成功后通知主进程，主进程重新读盘；截断、停止、未知终态和保存失败不投递 |
| 检查点 | 完整成功正文保存 `spatialGenerationId`；V2 还核对主任务终态、客户端和来源消息归属，不能用取消任务的正文建立事件 |
| 冻结身份 | 世界、runtime、绑定代次、发送时完整快照、persona、叙事模式、生成序号、用户输入和续写来源 |
| 模型与历史 | 实际请求开始时读取当前聊天连接/模型；独立系统提示和本轮材料，不重发主聊天完整历史，不向主模型提供画板工具 |
| 并发 | 每个助手最多一个运行请求；主动画板指令优先于尚未开始的剧情提取；已发出请求保留原配置 |
| 预算 | 共享任务预算，输出最多 1,024 tokens，地点索引最多 2,000 tokens，30 秒超时；核对最终完整输入预算，不静默裁剪正文尾部 |
| 去重 | 来源消息、选中正文 hash、生成类型的持久处理标记；提交继续使用独立 commitId。重复通知/确认不重复调用或移动 |
| 恢复 | 只核对最新回复的保存检查点；未发出队列可继续，已发出但结果未知标记中断，不自动重复计费 |

后台模型调用不占主对话请求；提取失败不会反转已经保存的主对话终态。任务与用量单独记录为 `spatial_dialogue_sync`。

## 3. 候选与提交校验

- 严格 JSON 字段与数量校验，候选合计最多 16 个；完成状态、置信度、证据来源均须显式提供。
- actor 只允许本轮角色与有效 persona；目标只能是发送快照中检索到的已有地点，board/node 关系必须匹配。
- 证据逐字核对用户输入或已保存正文；排除思考。persona 移动须有本轮用户输入依据，AI 代替用户的行动仅作为诊断。
- 明确的计划、假设、回忆、在途、否定到达与离开旧地点不能变成当前位置。同名地点按原文中的路径唯一定位，无法区分就保留未解析项。
- 语义位置采用 `inside-only`；细节 note 必须出现在动作证据中。模型不能提交像素坐标、创建实体或修改地图。
- 同一人物只允许一个最终位置；目标与当前语义位置相同过滤为无操作。“无移动”是成功结果，解析失败不是“无移动”。
- 确认时重新核对来源、身份、绑定代次、runtime revision、world fingerprint 和助手文件版本。来源确认与聊天消息写入共用消息锁。
- 有效候选只编译为 `place_actor` / `move_actor`；整批核心校验、事务提交、记录 `source=story`。逆向命令与幂等收据沿用阶段 0 的 sidecar。

来源正文编辑、删除、切换候选，用户输入变化，persona/叙事模式变化或更新回复完成，都不能应用旧建议。提取期间手动编辑画板会保留手动结果并阻止旧版本提交。已应用来源被改写仅标记来源变化，不自动回退位置。

## 4. 持久化与主要文件

发送基线、来源正文 hash、队列、处理标记、候选证据和建议状态存入现有 `data/spatial/ai-sessions/{id}.json`；runtime 事务、逆向命令及 commit 收据存入现有 `data/spatial/session-state/{characterId}/{sessionId}.json`。沿用阶段 1 的备份与会话删除归属规则，不保存 API key 到这些记录。

| 文件 | 职责 |
|---|---|
| `electron/services/spatialAiScheduler.ts` | 主聊天与独立队列之间的登记接口 |
| `electron/services/spatialDialogueQueue.ts` | 冻结基线、保存检查点、排队、去重、来源失效、恢复、重试与请求预算 |
| `electron/services/spatialDialogueProtocol.ts` | 独立剧情提示、严格候选解析、证据和权限检查 |
| `electron/services/spatialAiService.ts` | 共用独立任务运行槽、助手历史、提案确认及原子提交 |
| `electron/chat/orchestrator.ts` / `messagePort.ts` | V2 保存完成点、完整终态与消息锁 |
| `src/store/streamController.ts` / `chatGeneration.ts` / `useChatStore.ts` | Legacy 保存完成点及普通发送/重生成/续写检查点 |
| `src/components/chat/SpatialAiPanel.tsx` | 紧凑同步策略、剧情建议、失效诊断和重新提取 |

## 6. 后续边界

指定模型的受控剧情场景已联验，其他模型和复杂剧情需分别验证。阶段 3 继续完善主聊天建议入口、未知目标选择/创建后的重新核对、版本冲突重新确认、剧情事务撤销，以及完整备份恢复场景。阶段 4 的自动应用和群聊接入尚未开放。

本阶段的“重新提取”只重试仍有效且发送基线未变化的失败/中断任务；不会把旧建议的版本直接改成最新版本后应用。明确的版本冲突仍需用户先核对当前状态，后续新回复使用新基线。
