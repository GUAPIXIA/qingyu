## 1. 用户操作

| 场景 | 实现 |
|---|---|
| 主聊天收到位置建议 | 输入区上方出现一行提示与“查看画板建议”，打开当前单聊的画板助手 |
| 继续普通发送 | 使用已确认位置；提案、助手历史、JSON 和确认流程不进入对话 AI 上下文 |
| 应用并发送 | 仅在一条有效、没有未明确项的建议下提供；先完成位置事务，再发送。失败保留输入稿；等待中切换会话不向新会话发送旧稿 |
| 应用 / 忽略 | 助手展示实际位置路径与原文证据；确认统一经主进程提交，忽略记录原因且相同正文不重复提议 |
| 目标缺失或同名 | 可选择已有地点；完成依据、人物与来源保存在助手记录中，不能靠输入一个 ID 补造行动 |
| 创建地点 | 先填写名称和上级，生成独立地点创建提案；确认只改地图。再选择新地点、重新核对原动作、第二次确认移动 |
| 版本冲突 | 保留当前画板；重新核对后显示“当前位置 → 实际目标完整路径”，生成新的待确认提案，旧提案不能继续应用 |
| 撤销剧情更新 | 使用该提交的逆命令和独立提交 ID；主进程核对应用后的版本。后续已有拖动或地图修改时拒绝覆盖，提示打开画板核对 |

详细依据按需展开。主聊天只保留简短入口，详细处理仍在独立画板助手内；画板与 PC 现有配色一致。

## 2. 提案与确认规则

- `dialogueCandidates` 保存人物、目标原文、完成标记、逐字证据、证据来源和可处理状态。计划、回忆、在途、未知人物及 AI 代用户行动不能通过选择地点变成完成动作。
- 重新核对不调用模型、不移动人物。它重新读取当前角色、persona、原正文、用户输入、消息顺序、叙事模式、绑定代次与地图版本，按当前位置重新编译有限移动命令。
- 核对产生新的 proposalId / commitId，保留 `reviewedFromId`；原提案标记为被替代。核对后再次改图仍会冲突，不能直接替换版本号强行提交。
- 关闭同步、改写 / 删除正文、切换候选、切换身份等使旧来源失效；重新开启开关不能复活已失效的建议。
- 应用保存 `appliedVersion`，撤销保存 `undoCommitId` 与 `undone` 状态。助手结果、runtime、world、提交收据同属一个空间事务，断电恢复后重复确认或撤销不增加移动。
- 来源改写只标记已应用提案的来源变化，不自动倒退画板。撤销只在当前版本仍等于该剧情应用后版本时执行。
- 阶段 3 以前缺少结构化原动作的旧提案仍可在原版本确认；发生冲突后需在助手明确指令调整，不从纯文字诊断推造动作。

## 3. 生命周期与恢复

恢复前取消旧助手请求并停掉队列；恢复后的请求使用新的运行边界。旧结果即使对应相同助手 ID，也不能写入恢复后的文件。

ZIP 写入前检查单聊索引、地图、runtime、sidecar、助手归属及绑定代次；缺失世界、孤立助手、其他聊天的助手引用和不匹配事务会拒绝整包。合法断电事务按完成后的逻辑状态校验，恢复时再完成实际事务。

空间数据以备份为准，清理备份之外的旧空间 JSON，保留失败回滚快照；避免旧事务和旧助手混入恢复后的数据。恢复完成后重新检查来源，并向画板发送更新通知。会话删除沿用阶段 1 的当前及归档助手清理规则，共用世界保留。
