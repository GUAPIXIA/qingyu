## 1. 更正此前的连接结论

阶段 1 的 `401 Invalid API key` 来自隔离联验环境，不能据此判断原聊天连接失效。脚本复制了加密的 `credentials.json`，却没有复制该 Electron userData 对应的 `Local State`。Windows safeStorage 无法用隔离环境新生成的 OSCrypt 密钥解密原凭据。

本地对照验证：原应用的加密状态能够解密原凭据，错误隔离环境不能。修复后当前小米连接通过真实服务端请求；本次没有验证旧 OpenCode Go 密钥的服务端有效性。

脚本现在先复制加密状态，再启动 Electron；请求前检查当前密钥是否可读。每次使用新的临时 userData，运行结束清理设置与凭据副本，保留虚构测试场景和脱敏验证结果。

## 2. 真实联验发现并修复的问题

| 问题 | 修复 |
|---|---|
| 初始化重复声明根画板、跨画板填写 parentKey | 明确根画板由应用提供、子画板入口和同画板父级规则；保留严格结构校验 |
| 普通移动混入初始化 evidence 字段，生成不合法 JSON | 初始化、起点建议、普通指令分别提供对应协议；示例由 `JSON.stringify` 生成，不再使用混合的伪 JSON 格式 |
| 初始化用本轮正式人物 ID 替代 character/persona 别名 | 将这两种等价引用归一到本轮允许人物；其他聊天的人物 ID 仍拒绝 |
| 旧开场覆盖已确认的新位置 | 当前位置在历史和后置提示之后单独注入一次；提前预留预算，并明确旧位置只代表过去 |
| 剧情跨入子画板时沿用人物旧 boardId | 提取协议明确 targetNodeId 与该目标的 boardId 必须成对复制；核心校验继续拒绝不匹配组合 |

错误输出仍作为失败保留，不能应用，不自动修补 JSON、猜测目标或重新调用模型。

## 3. 验证结果

最终完整联验共 **7 次真实模型请求、33 / 33 项检查通过**，连接为小米，模型为 `mimo-v2.6-flash`。

| 场景 | 结果 |
|---|---|
| 初始化 | 合法草稿、来源证据与两个人物起点；屋外花园没有归入屋内；确认前不绑定正式地图 |
| 直接指令 | 林雪从厨房移到花园，确认后修订更新；旅人位置保持在花园 |
| 主对话只读 | 真实对话模型回答两个人物都在花园，没有沿用开场中的厨房；desktop 带空间快照，Android 不启用 PC 投影 |
| 未知目标 | 不存在的月宫先澄清，不生成可执行移动 |
| 已保存剧情 | 受控正文“林雪已经回到厨房，站在灶台旁”由真实模型独立提取；生成需确认建议，确认后记录 `source=story`；下一轮上下文组装读取厨房 |
| 未完成计划 | 准备去花园但尚未到达，不生成移动命令 |
| 用户主权 | AI 正文代替旅人走进厨房，不生成用户移动命令 |
| 去重与隔离 | 重复投递只登记一个提取任务，重复确认不再次移动；主正文不变，助手历史不进入主聊天 |

定向回归：**4 文件 / 96 项通过**，包含先复现失败再修复的位置注入顺序用例，以及子画板、允许人物 ID、跨画板目标配对和模式协议隔离用例。`pnpm run check`、联验脚本类型检查、定向 ESLint、`pnpm run build` 和 `node electron-build.mjs` 通过；前端构建保留既有大 chunk 提示。

证据保存在 Git 忽略的 `output/`：

- `output/spatial-stage2/model-report.json`：完整检查、真实响应、主对话输入和剧情提取结果。
- 每次临时 userData 内的 `model-report.json`：该次记录；带有响应采集的失败运行也保留，便于复查修复依据。
- `output/spatial-stage2-model-regression.log`、`spatial-stage2-model-check.log`、`spatial-stage2-model-lint.log`、`spatial-stage2-model-build.log`、`spatial-stage2-model-electron-build.log`。

入口：[模型联验脚本](../../scripts/spatial-ai-model-bench.ts)。打包后以 Electron 执行，加 `--phase2` 同时验证阶段 1、2；不加则只验证阶段 1。`SPATIAL_MODEL_SOURCE` 可指定读取连接配置的原 userData 路径。

## 4. 验证范围
