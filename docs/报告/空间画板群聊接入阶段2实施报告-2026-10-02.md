## 1. 用户使用方式

群聊画板助手新增「剧情同步策略」，提供「关闭 / 需确认」，默认关闭。选择需确认并保持「对话读取位置」开启后，主对话继续只读已确认位置；正文完整保存后，独立画板任务读取本批内容并生成位置建议。用户确认才改变正式位置，后续对话读取更新后的结果。

继续使用所属群聊的有效聊天连接和模型，没有增加模型选择器。正文、画板助手历史、JSON 提案与任务状态分别保存。提取失败不会重发成员正文或改变正文成功状态。

| 发言规则 | 提取时机与来源 |
|---|---|
| 点名 | 一个目标成员的完整回复成功保存后，提取一批 |
| 自由发言 | 同一次生成的所有拆分消息成功保存后，整批提取一次；全知叙事保留整段 |
| 轮询 | 接力交还用户或用户停止时，将此前完整且成功保存的成员回复合为一批；各成员结束时不调用提取模型 |

取消、失败、截断、空回复、保存失败和半截内容不能成为完成行动的依据。用户停止轮询时可以保留半截正文供查看，但只提取此前完整保存的回复。手动点选某成员回复也会关闭其批次。

## 2. 来源检查与持久队列

主进程在正文请求前捕获 generation ID、burst ID、发送时空间版本、当前成员、persona、发言规则、叙事视角及有效配置 fingerprint。只有实际模型请求正常以 `stop` 完整结束、未提前中止，才允许保存消息获得完整检查点。渲染端自行传入的完整标记不能替代主进程认证。

正文通知只传有序消息 ID，队列重新读取磁盘并检查生成归属、整个消息集合、保存顺序、正文 hash 和完成标记。自由发言拆分不会成为多次模型调用。正文已保存但通知丢失时，关闭批次与重启恢复可以从主进程签入的完整检查点补登记。

批次与任务保存在该群聊会话的独立助手记录中。正文登记和关闭不等待模型；每份助手串行处理任务，显式画板指令优先。提取读取完整有序正文，不静默截去中间行动。地图索引可以按相关地点裁剪并记录，整体输入或地点索引超预算则失败提示。

只允许当前成员和有效 persona 的已有 actor；persona 行动仍需用户原文证据。同群不等于同地，群外人物不能移动。每个人只保留最终明确位置；重复候选、缺少逐字证据、备注不在本条证据中、未知节点和越界命令均被拒绝。证据歧义保留未明确项，不自动创建地点。

## 3. 确认、取消与恢复

发送、返回和确认分别复核来源。正文编辑、删除、重生成、新用户输入、新的完整批次、成员/身份/模式/连接配置变化、关闭同步或位置读取、绑定变化会使旧任务或提案失效。手动编辑画板导致版本变化时，旧建议不能覆盖新位置。

确认持有群聊正文锁，重新检查完整来源和空间版本，再通过空间事务将位置、提交收据与助手状态一起保存。重复确认使用原收据，不重复移动。提案被确认后来源改写会标明变化，本阶段不自动逆向移动。

提取没有自动传输重试。失败或中断后，用户可以显式重新提取仍有效的批次；已处理或在途批次不能重复重试。取消终止当前任务，迟到返回不能创建提案。队列有独立超时与取消退出路径，即使适配器没有及时响应 AbortSignal，也不会一直占用处理槽。

重启恢复已保存检查点和排队任务；在途未知结果标为中断，等待显式重试，不重新扫描旧聊天创建新任务。ZIP 备份包含批次、任务及提案；恢复先校验来源结构、快照所属世界/runtime 与版本，拒绝跨会话数据。整库恢复中暂停队列、清除旧临时检查点，恢复后重新核对。

### 真实模型联验

隔离用户目录中沿用当前连接「小米」、模型 `mimo-v2.6-flash`。使用生产 `ai:chat` 和群聊保存 IPC 生成及认证正文，再调用独立提取队列，检查确认前位置不变、确认采用最终位置以及重复通知不重提取。

点名和自由发言的两种视角均已完成真实正文、批次提取与确认。轮询沉浸首次提取超时；显式重试返回了不符合证据约束的候选，被严格拒绝，正文和正式位置保留。补充群聊提示中「每个 actor 只出现一次、备注必须来自本候选证据」后，再次显式重试成功并确认；没有放宽校验或自动重试。

全知轮询先前的流式与非流式补验等待中止，未计通过。用户随后提供原生异常截图：`model-bench.cjs → Logger.info → console.log → Socket._write` 抛出 `EPIPE`。联验以 PowerShell 管道启动，父命令结束后 GUI 子进程仍运行，日志读端关闭；日志异常发生在 `ai:chat` 的请求开始记录处，位于请求处理的 try 之前。不能据此认定凭据或模型连接配置错误，也不把前次所有超时统一归因于该异常。

2026-10-02 修复后，使用同一隔离目录和原连接再次补验：全知轮询的两条完整正文、整批一次提取、确认前不移动、确认最终位置、重复通知去重及 ZIP 恢复不重发均通过。前次中断批次在新输入下失效，已确认位置没有被旧结果覆盖。该补验使用非流式生产 AI IPC；渲染端流式结束与批次规则继续由专项测试覆盖，不能宣称六种模式都通过了完整 UI 流式模型联验。

六种短合成剧情组合现已有对应证据，其中轮询沉浸恢复此前已确认的重试结果，全知轮询由本次补验闭合。异常保留在任务历史与前次报告，不算作首次成功；模型报告中的 replies 包含前次被拒绝的输出，并非“全部首次成功调用数”。短剧情不能证明长接力中的所有角色知情边界和阶段 3 综合验收已完成。隔离进程正常退出，复制的连接配置和凭据已清除。

### 日志 EPIPE 修复

日志先写文件，再写控制台；stdout/stderr 的同步与异步 `EPIPE` / `ERR_STREAM_DESTROYED` 只关闭对应控制台出口，后续文件日志继续保存。其他异常继续显式抛出，未添加全局吞异常逻辑。正常桌面仍保留控制台与文件双输出。

阶段 2 联验初始化独立目录文件日志并关闭控制台日志，最终结果写 JSON。新增启动器直接向日志文件句柄输出，并等待 Electron 退出，避免 GUI 子进程继承短命 shell 管道：

```powershell
node scripts/run-spatial-group-stage2-model.mjs
node scripts/run-spatial-group-stage2-model.mjs --resume output/spatial-group-stage2/model-user-data-2xCEnI
```

8 项日志专项加 AI/群聊助手共 131 项通过；类型检查、相关 ESLint 和 Electron 重建通过。真实 Electron 断管道实验关闭 stdout/stderr 读端后，debug/info/warn/error 四级日志均落盘，进程退出码 0，没有出现未捕获异常弹窗。
