## 1. 用户流程

聊天输入区用一行显示位置提取进度、待核对建议、提取失败、已确认结果或来源变化。点击后直接打开当前群聊会话的画板助手；正文历史保持正常聊天内容。群聊剧情同步默认关闭，开启后仅提供「需确认」，沿用当前聊天连接和有效模型。

| 情况 | 操作与结果 |
|---|---|
| 明确地点的剧情建议 | 展示人物当前位置与目标路径；用户确认后才移动 |
| 地图已被手动修改 | 旧建议停止应用；重新核对当前地图和位置，生成新的待确认建议，再确认移动 |
| 未知或已经删除的地点 | 选择当前地图中的完整路径，或单独预览并确认创建地点；地点创建不移动人物，之后再核对移动 |
| 未完成、人物不明确或用户未声明的行动 | 不提供可应用移动，地点选择不能补造行动证据 |
| 已应用的正文被改写、删除或重生成 | 提示来源变化，保持已确认位置；用户可明确撤销 |
| 撤销一次剧情更新 | 两次点击确认；仅当没有后续空间修改时使用原收据逆操作，重复撤销不再次提交 |
| 正文、成员、身份、模式或有效配置变化 | 旧任务和建议失效；切回原值不复活建议 |
| 切换群聊或会话 | 提示、核对操作及迟到回调均按原 owner 隔离 |

助手沿用原有浅紫与暖金配色。聊天页只保留简短入口，来源与版本默认折叠；有路径比较时不重复列出相同摘要。

## 2. 主进程与数据边界

新增群聊专用目标查询、剧情核对、地点创建预览与剧情撤销接口，全部按 `groupId + sessionId` 定位独立助手和 runtime。核对使用保存的完成动作及连续原文证据，不再调用模型；只允许当前成员和有效 persona，地图中的明确不参与节点不能作为剧情目标。

核对、地点创建与移动确认重新读取正文来源。确认持有群消息锁，并通过空间绑定 epoch、runtime revision、世界 fingerprint 和助手记录 hash 执行事务。地点创建使用独立提交 ID，关联原剧情建议，确认创建后仍须重新核对人物移动。备份预检验证地点创建的原建议、批次与命令关系，错误归属在写任何数据前拒绝。

群聊成员/发言规则、会话身份/叙事规则/读取与同步开关、有效聊天配置分别保存主进程维护的来源 epoch。配置保存与凭据变更在设置锁内记录 epoch。主题修改不使建议失效，用户切换配置后再切回也不能确认旧提案。

已应用的动作使用空间收据作为事实。正文来源变化不自动逆向移动；撤销采用原逆操作与独立提交 ID，画板已被修改时拒绝覆盖。重启和 ZIP 恢复保留待确认建议、核对结果、已应用记录及撤销幂等性，不重发模型请求。

## 3. 综合验收中修正的两条边界

### 群聊翻译

原完成回调从页面当前群聊/会话取保存目标，只按消息 ID 更新，切换 owner 或编辑正文后可能更新错误消息；重新走完整正文保存接口还可能影响主进程完成检查点。

现在翻译冻结原群聊、会话、消息、发言者和正文。专用 `group:saveTranslation` 在消息锁内比对来源，仅更新翻译附属字段，保留正文、生成 ID 和完成检查点。目标已删除、内容或发言者已改变时拒绝；迟到成功/失败不进入其他群聊页面。修复前两项回归失败，修复后通过。

### 全局叙事与参与标记

原空间拦截在上下文、发送、自由发言保存及轮询续排中未完整区分叙事视角，可能在全体成员明确不参与时拦截旁白。

现在沉浸模式继续按参与标记过滤回应者；全局叙事保留事实标记，允许以成员作为叙事焦点继续旁白，完整或半截旁白不按角色回应过滤丢失。修复前三种发送和旁白保存共四项回归失败，修复后通过，并验证轮询续排。

## 4. 通用方案 §13.7 验收对应

| 条件 | 验证依据 |
|---|---|
| 1. 单聊、多个群聊和会话位置、任务及功能历史隔离 | 群聊空间与助手真实文件测试；浏览器共享世界/独立位置、会话切换与旧回调；记忆仅提交群会话 |
| 2. 三种发言模式 × 两种视角，保留 @ 语义 | 六组合真实模型联验、群聊上下文与 stream/store 测试；既有正文 @ 检测及点名目标回归 |
| 3. 明确不参与、全部不参与、未知、异地及旁白分别处理 | 主进程空间投影、沉浸发送过滤、三模式全局旁白、自由旁白保存和轮询续排测试 |
| 4. 自由拆分只形成一个批次，全局正文不归错动作主体 | 整批保存/通知、完整检查点、单次提取测试；真实 free 两种视角联验 |
| 5. 多人有序行动保留各自最终地点 | 多条有序正文一次提取，提取结果反向排列仍按 actor ID 提交；林雪厨房后到渡口、阿远客厅、小岚茶馆分别核实 |
| 6. 手动修改、取消、切换、移出、重生成不覆盖新位置 | 来源失效、取消/迟到、版本冲突、成员/身份/模式切回、重生成回滚、重启/ZIP 与撤销 CAS 测试 |
| 7. 相同有效连接/模型，预算、请求与记录一致 | 主对话/画板真实六组合参数检查；群聊记忆 activeModel 的预算、实际请求及任务用量归属测试 |
| 8. 方向在交还用户时生成，翻译关联消息，记忆不写成员单聊 | 群聊方向门控 8 项；翻译 owner/正文校验与检查点测试；群聊记忆版本提交和单聊接口隔离 |

真实模型使用当前连接「小米」/ `mimo-v2.6-flash`，在独立 userData 中运行。16 次请求包括初始化 1 次、显式调整 1 次、正文 8 次和剧情提取 6 次。每种组合分别验证正常完整正文签入、交还用户前不提取、只提取一次、手动修订导致冲突、无模型重新核对、二次确认、明确撤销及重复撤销。复原后的正式地图与助手通过 ZIP 验证，正文没有助手 JSON 或指令。

这些真实请求使用短篇指定动作，覆盖主进程 AI IPC、保存认证、提取、事务、核对与撤销。长接力、取消、超预算、未知地点、来源切回以及全体不参与边界由真实文件服务测试和渲染端受控请求验证；浏览器使用真实页面与编辑器、受控 API，不把模拟 API 当作真实模型证据。

Electron 联验沿用断管道修复后的文件日志与直接文件句柄启动方式，父进程等待子进程退出；复制的设置、凭据和 Local State 已清理。正式用户的群聊、画板和连接未被联验修改。
