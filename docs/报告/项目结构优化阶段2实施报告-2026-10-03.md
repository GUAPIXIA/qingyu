## 5. 方案偏差与理由（§3.3 条件的执行说明）

方案 §3.3 期望“编译后的 ESM 与类型声明”。实际采用**包导出 TS 源**（`exports` 指向 `src/index.ts`）：

- 全部消费者均为 TS 感知的打包链（Vite / esbuild / tsx / vitest），可直接消费 TS；
- Windows 上 pnpm 与 npm 的 file/workspace 依赖均为 junction，**不存在复制陈旧**问题；开发期改核心即时生效（§3.3 用“验证 npm 本地依赖是否为复制或链接”作为决策依据，本机实测为链接）；
- 避免为一层 14 文件的包引入独立构建产物与声明打包链。若后续需要发布或 Node 直连消费，再补 dist 构建（包内已预留 `scripts` 位）。
