## 2. 消除基线失败：w9Shadow 集成测试

**结论：断言不过时，是测试 fixture 未随「会话隔离」特性更新（既有失败的真实原因），已修复。**

- 失败点：`history.candidate.summaryReplacedCount` 期望 `> 0`，实测 `0`。
- 根因链：影子候选的摘要替代口径复用生产注入结果 `compressedSummaryInjected`；生产注入在 [contextBuilder.ts:835](../shared/chat-core/contextBuilder.ts) 要求 `validCompression(currentSession, data.chat.messages)` 为真。`validCompression`（[featureSource.ts:94](../shared/featureSource.ts)）要求会话具备可核对的 **`compressedSource`**（来源引用 + `range`）。该要求由「对话AI与功能AI会话隔离」特性引入，而 `w9Shadow` 用例的会话 fixture 只有 `compressedSummary`/`compressedRange`、没有 `compressedSource`，于是摘要注入被正确拒绝，候选 `replace` 计数为 0。
- 修复：在用例中使用同一批消息对象构造 `compressedSource = { messages: [messageRef(m1), messageRef(m2)], mode: 'range', range: { startTs: 0, endTs: 2500 } }`，与生产口径一致。修复后该用例 10/10 通过，影子日志显示 `replace=1`（摘要替代生效），并保留 `drop=0`、生产注入含「早期摘要」等既有断言。

修复触及 shared 子仓，按方案 §6 规则先在 shared 形成提交（`112ea0b`），再更新 PC 指针；Android 挂载点按迁移期兼容策略暂留旧版本（见 §4）。
