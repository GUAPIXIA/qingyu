## 0. 用途

1. 每个会发 LLM 请求的生产入口有唯一归属，不旁路统一预算（`resolveRequestBudget` / `resolveGenerationTaskBudget`）。
2. 新旧规划器、恢复链路变更时可逐入口对照（请求上限、门控、恢复策略、失败形态）。
3. 产品简化（去 Token 旋钮）验收时按入口核对：默认 UI 不要求用户配置 Token。

**与主计划的关系**：主计划明确**不**新建 `GenerationIntent` / `OutputPlanner` / `generationPlannerV2`。任务意图收编在 `ResponsePolicy` + `BackgroundGenerationProfile` + `GenerationTask` 枚举；本清单只做入口登记与产品验收，不另立架构。

## 4. 产品默认 UI（简单易用验收）

| 表面 | 要求 | 状态 |
|---|---|---|
| 快捷设置 | 只见回复篇幅；无 Token 占比 / 最大 Token | ✅ W10；文案去 Token 化（本轮） |
| 设置「生成规划」 | 思考强度 / 连续性 / 补尾 / 费用提醒；高级诊断折叠 | ✅ W10 |
| 预设编辑 | 默认「回复篇幅 + 文风手感」；温度/上限/惩罚进「高级参数」折叠 | ✅ 本轮 |
| 预设卡片摘要 | 只示篇幅 + 手感（偏创意/平衡/偏稳定） | ✅ 本轮 |
| 费用提醒 | 人话提示，不暴露预算公式 | ✅ 本轮 |

**验收口径**：默认路径不需要理解 Token、世界书占比或推理预算；硬上限仅在预设「高级参数」与连接能力覆盖中出现。

## 5. 基线指标（G1/G2 分母，C4 已冻结）

来源：`shared/generationBaseline.ts` + `scripts/generation-baseline.ts`；G2 已按 `unified/gate:none` 单段 ≥500 且 ≥2 供应商过关（509/500、3 端点）。

持续观测：推理挤占最终失败率、空正文恢复成功率、截断率、mandatory 丢失（必须 0）、延迟与费用分位。隐私：不记正文 / Key / 完整 URL。

## 6. 维护规则

- 新增会发 LLM 的入口 → 先加行再写代码。
- 删除旧链路时对照 §3 勾销并更新状态。
- 枚举以 `shared/generationTaskBudget.ts` 为准；产品 UI 不得重新引入固定 Token 旋钮。
- 与主计划冲突时以主计划 + 阶段 7/8 契约为准。
