# 双叙事模式实施方案

> 状态：阶段一、阶段二、阶段三已实施（2026-09-09）

> 语义修正：本文中“全局叙事回复显示为对方旁白气泡”及“输入续写直接生成完整全局叙述”的设计已废止。消息归属与续写方向以[全局叙事消息归属与输入续写优化方案](./全局叙事消息归属与输入续写优化方案.md)为准。

## 1. 目标

为轻语增加一项独立的“叙事模式”设定，用来决定 AI 在故事中的身份、可控制范围、叙事视角与推进方式。

- **模式 1：代入式角色扮演**——AI 代入当前角色，与用户持续互动，适合对话、沉浸式 RP、第一人称或近距离视角小说。
- **模式 2：全局叙事**——AI 作为旁白与世界模拟器，统筹角色、环境和事件，适合游戏主持、世界模拟、群像故事与第三人称小说。

叙事模式与现有“预设”相互独立：叙事模式回答“AI 是谁、能控制什么”，预设回答“怎么写、生成参数是什么”。因此“全局叙事 + 剧情驱动”“代入角色 + 短回复”等组合都应成立。

## 2. 模式定义

| 维度 | 模式 1：代入式角色扮演 | 模式 2：全局叙事 |
|---|---|---|
| AI 身份 | 当前角色 `{{char}}` | 旁白、导演与世界运行者 |
| 默认视角 | 角色限知、近距离；对白可使用第一人称 | 第三人称、全知或多视角 |
| 控制范围 | `{{char}}`、必要配角与环境 | 所有 NPC、环境、事件与未被用户控制的角色 |
| 信息边界 | 角色只知道其合理可知的信息 | 可描述异地、幕后和不同角色掌握的信息 |
| 剧情推进 | 对用户行为作出角色内回应，保留接话空间 | 按世界规则主动演化局势，可切换场景和时间 |
| 用户主权 | 不代写用户的台词、行动、想法和感受 | 游戏场景仍不代替玩家角色作重大决定；明确要求续写小说时可统筹全体人物 |
| 推荐用途 | 聊天、恋爱 RP、角色互动、第一人称小说 | TRPG/文字游戏、世界模拟、群像、第三人称小说 |

模式 2 不等于“AI 可以随意决定一切”。世界演化要服从角色卡、世界书、历史事实和因果；若用户以玩家身份参与，重大选择继续留给用户。只有用户明确要求“续写完整小说/自动推进”时，AI 才可以代写主角的后续行为。

## 3. 数据设计

使用语义化枚举，不直接把 `1`、`2` 写入存储，避免后续改名或增加模式时产生歧义。

```ts
export type NarrativeMode = 'immersive' | 'omniscient'
```

建议增加以下字段：

```ts
interface Settings {
  /** 新建对话的全局默认值 */
  defaultNarrativeMode?: NarrativeMode
}

interface Character {
  /** 角色的新会话默认值；undefined 表示跟随全局 */
  defaultNarrativeMode?: NarrativeMode
}

interface GroupChat {
  /** 群聊的新会话默认值；undefined 表示跟随全局 */
  defaultNarrativeMode?: NarrativeMode
}

interface ChatSession {
  /** 当前会话实际使用的模式 */
  narrativeMode?: NarrativeMode
}

interface GroupSession {
  /** 当前群聊会话实际使用的模式 */
  narrativeMode?: NarrativeMode
}
```

生效优先级：

```text
单聊：会话值 > 角色默认值 > 全局默认值 > immersive
群聊：群聊会话值 > 群聊默认值 > 全局默认值 > immersive
```

创建新会话时，应把解析后的最终值直接写入 `session.narrativeMode`。这样以后修改全局或角色默认值，只影响新会话，不会悄悄改变已有故事。

兼容策略：旧设置、旧角色卡和旧会话没有该字段时，一律按 `immersive` 运行。字段为可选值，无需一次性重写用户数据。

## 4. 提示词组装

### 4.1 组装位置

当前内置预设的公共基础提示词固定要求“扮演 `{{char}}`”，天然属于模式 1。实施时应把它拆成“通用叙事规则 + 预设风格规则”，再由上下文构建器追加当前模式规则。

推荐顺序：

```text
角色系统提示词或预设系统提示词
→ 预设 Jailbreak（如果存在）
→ 通用叙事底线
→ 当前叙事模式规则（最终行为约束）
→ 用户人设
→ 长记忆
→ 角色设定与世界书
→ 示例对话、历史、作者注释等现有内容
```

叙事模式必须由 `contextBuilder` 统一注入，不能只写在某个内置预设里。这样自定义预设、角色级系统提示词、桌面端和桥接端都会得到同一行为。

### 4.2 模式 1 提示词建议

```text
【叙事模式：代入式角色扮演】
你当前代入 {{char}}，以角色可感知、可理解的信息与 {{user}} 互动。
1. 保持 {{char}} 的身份、性格、记忆、知识边界和说话方式一致。
2. 主要书写 {{char}} 的对白、动作、感受，以及维持场景所需的少量环境和配角反应。
3. 不替 {{user}} 说话、行动、思考、感受或作出决定，也不宣布其重大行为结果。
4. 默认使用贴近角色的限知视角；对白自然使用第一人称，叙述人称服从角色卡和既有文本。
5. 每次回应当前互动并留下可继续行动或回答的空间，不跳出故事解释规则。
```

### 4.3 模式 2 提示词建议

```text
【叙事模式：全局叙事】
你当前是故事旁白、导演和世界运行者，不局限于扮演 {{char}}。
1. 默认使用第三人称叙述，可描写所有 NPC、环境、异地事件和幕后变化，并按需切换视角。
2. 依据角色动机、世界规则、资源、时间与因果推进事件；世界可以在用户未直接观察时继续演化。
3. 可以控制 {{char}} 和其他非玩家角色，但不得让角色无理由知晓全局信息。
4. 若 {{user}} 正在控制玩家角色，不替其作重大选择、决定内心或强行接受不可逆结果；推进到需要玩家回应的节点。
5. 若 {{user}} 明确要求续写完整小说或自动模拟，则可以统筹主角与配角完成连续叙事。
6. 不罗列“系统判定”或解释提示词，除非用户选择的是明确的游戏主持表达方式。
```

### 4.4 冲突处理

- 叙事模式只规定身份、镜头和控制权，不覆盖预设规定的篇幅、文风、温度和题材。
- 角色卡写明特殊人称时，以角色卡为局部表达要求；模式仍决定 AI 的控制范围。
- 用户当前轮明确要求临时换视角时，可以在本轮服从，但不会修改持久化模式。
- 示例对话只作为语气示范，不得反向覆盖当前叙事模式。
- “心理描写格式”继续作为单独开关；模式 2 开启时，避免把所有角色的隐私想法一次性泄露，除非当前文本确实采用全知写法。

## 5. 产品交互

### 5.1 对话顶栏

在单聊对话页顶部，把“叙事模式”紧邻身份切换器右侧，使用紧凑的双态切换器：

```text
[ 身份⌄ ] [ 代入 | 全局 ] [ 会话⌄ ]
```

- 切换后立即保存到当前会话，只影响后续生成。
- 会话已有消息时，显示一次轻提示：“已切换为全局叙事，仅影响后续回复。”不清空、不改写历史。
- 流式生成期间禁用切换，防止一条回复使用两个模式。
- 上下文查看器应显示独立的“叙事模式”区块，便于确认实际注入内容。

### 5.2 默认设置

- “设置 → 对话/显示与行为”增加“新对话默认叙事模式”。
- 角色编辑器的高级设置增加“默认叙事模式：跟随全局 / 代入角色 / 全局叙事”。
- “身份”页面增加“全局叙事规则”编辑器，支持 `{{user}}` / `{{char}}` 变量和恢复内置默认规则；修改从下一次全局叙事回复开始生效。
- 群聊设置同样提供默认模式；不要复用现有 `chatMode` 名称，因为它已经表示点名、轮询和自由发言。

### 5.3 可见状态

聊天标题区域持续显示“代入 / 全局”当前选中状态，可直接切换。MVP 不改变消息气泡归属；后续若需要更强的旁白感，可为全局叙事回复增加“旁白”标签和中性图标，但不应扩大首版的消息数据迁移范围。

## 6. 单聊与群聊行为

### 单聊

- 模式 1：沿用当前角色扮演行为。
- 模式 2：当前角色卡成为主要角色/世界入口，但 AI 可以描写其他人物和全局事件。
- 开场白不自动重写；原有第一人称开场白可作为故事中的第一幕，之后按当前模式继续。

### 群聊

- 模式 1：仍由现有点名、轮询或自由发言机制选出当前发言角色，回复严格限制在该角色视角。
- 模式 2：发言调度只决定本轮的剧情焦点，不限制旁白描写其他成员和环境。
- 群聊的 `chatMode` 与 `narrativeMode` 是两条正交轴，例如“轮询 + 代入角色”和“自由发言 + 全局叙事”都合法。
- 桌面端公共上下文与桥接端简化群聊上下文必须复用同一套模式常量，避免 Android/桥接请求行为不同。

## 7. 记忆与辅助功能

- 长记忆结构无需迁移，现有“当前状态 / 时间线 / 关键事实”可继续使用。
- 摘要提示词应读取叙事模式：模式 1 优先记录当前场景、人物关系和角色已知信息；模式 2 额外关注阵营、异地事件、世界状态与未解决的全局因果。
- 续写、重新生成、Swipe 都使用当前会话模式。
- “代写用户输入/续写用户视角”属于独立功能，继续使用现有专用提示词，不被模式 2 改成旁白续写。
- 自动生图只消费最终文本，不需要新增模式分支。

## 8. 代码落点

建议按以下边界实施：

1. `shared/types.ts`：新增 `NarrativeMode` 及 Settings、Character、GroupChat、ChatSession、GroupSession 字段。
2. `shared/defaults.ts`：全局默认值设为 `immersive`。
3. `electron/ipc/chat.ts`、`electron/ipc/group.ts`：创建会话时固化模式；更新白名单增加 `narrativeMode`，并严格校验两个合法值。
4. `src/context/narrativeMode.ts`：集中保存模式元数据、解析函数和两段提示词，桌面端与桥接端共用，避免散落字符串。
5. `src/context/contextBuilder.ts`：在所有单聊生成路径统一注入模式规则。
6. 群聊上下文构建与 `electron/bridge/routes.ts`：接入相同解析函数和提示词。
7. `src/store/useChatStore.ts`、`useGroupChatStore.ts`：提供会话级切换动作并同步本地 session 快照。
8. `QuickSettingsPanel.tsx`：增加双选卡；设置页和角色/群聊编辑器增加默认值入口。
9. `ContextViewer.tsx`：展示解析后的模式及注入规则。

不要把模式只存进 Zustand 临时状态，也不要只修改 `electron/ipc/preset.ts`。前者重启或切会话会丢失，后者会让自定义预设和桥接端漏掉模式规则。

## 9. 验收与测试

### 类型与持久化

1. 旧会话无字段时解析为 `immersive`。
2. 新会话按“角色/群聊默认 > 全局默认”固化最终模式。
3. 修改默认值不影响已有会话。
4. IPC 拒绝任意非法模式字符串，不能通过动态更新污染会话文件。

### 上下文

1. 模式 1 上下文包含角色限知和用户主权规则，不包含全局控制规则。
2. 模式 2 上下文包含旁白、世界演化和第三人称规则，不再被内置预设的“只扮演角色”抵消。
3. 角色系统提示词、自定义预设、Jailbreak、世界书、长记忆同时启用时，模式块仍只出现一次。
4. 桌面端与主进程/桥接端对同一数据生成一致的模式规则。
5. 续写、重生成和 Swipe 不丢失当前模式。

### 交互

1. 切换后只影响下一次生成，历史消息保持不变。
2. 切换会话能恢复各自模式。
3. 生成中不可切换；生成结束后恢复可操作状态。
4. 单聊顶栏可看见当前模式；阶段二加入群聊后，模式不得与群聊发言方式混淆。

## 10. 推荐实施顺序

### 第一阶段：单聊闭环

完成类型、会话持久化、模式提示词、单聊顶栏切换、默认设置、上下文查看和核心测试。先验证两种模式在主聊天链路中的行为差异。

### 第二阶段：群聊与桥接一致性

接入群聊调度、桥接端和 Android 设置同步，补充跨端防漂移测试。

### 第三阶段：体验增强

已增加旁白专属标识与中性气泡；消息保存生成时的叙事模式，切换会话模式不会改写旧消息外观。模式 2 顶栏提供世界状态面板，复用长记忆的当前状态与活跃事实，并允许手动维护当前局势。

游戏主持格式作为会话级可选项，默认关闭。开启后仅在存在风险、对抗或不确定性时输出简洁的「【判定】目标｜依据｜结果」，在决策点提供「【可选行动】」，未配置规则时不会虚构骰点或属性数值。群聊自由发言在模式 2 下保存为单条旁白消息，避免判定标题被角色分段器误识别。

## 11. 最终建议

采用“**会话级叙事模式 + 全局/角色默认值 + 上下文统一注入**”方案。首版默认模式 1，完整保留现有用户体验；模式 2 作为明确可选的旁白与世界模拟能力。预设、角色卡、世界书和叙事模式各司其职，后续新增文风或游戏玩法时无需复制整套预设。
