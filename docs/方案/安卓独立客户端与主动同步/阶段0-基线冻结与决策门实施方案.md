# 阶段 0：基线冻结与决策门实施方案

> 状态：👀 运行期观察  
> 目标：在改动运行时代码前，冻结功能范围、数据清单、行为样例、性能基线和不可逆架构决策。  
> 实施：[阶段0实施报告](../报告/Android独立客户端重构阶段0实施报告.md)（2026-09-16）；Android 实机 crypto/Keystore spike 环境阻断，进阶段 7/8 前补测。

## 1. 输入与输出

输入是当前 PC、Android、Bridge、Relay 代码和现有测试。输出必须包括：

- `docs/架构/android-parity-matrix.json`：机器可读能力矩阵。
- `docs/架构/android-parity-matrix.md`：供产品和测试阅读的矩阵。
- `docs/架构/data-domain-inventory.md`：所有持久化数据、敏感级别、同步策略、迁移版本和写入口。
- `docs/架构/adr/` 下的 ADR-001 至 ADR-010。
- `shared/fixtures/cross-platform/baseline/`：去隐私 golden 数据集。
- `output/baseline/android-independent/`：基线命令和性能结果；该目录若按项目策略不入库，报告中记录生成方式与摘要。
- 阶段 0 实施报告。
- `docs/架构/android-independent-baseline.json`：记录精确 Git commit、工作区是否干净、dirty patch hash、PC/Android/Relay 版本、fixture revision 与构建工具版本；只有版本号不能作为冻结基线。

## 2. 任务拆分

### S0-01 功能矩阵

逐一审计 PC 页面、命令、IPC、Bridge 路由和 Android 页面，至少覆盖：

- 设置/连接档案/模型测试；
- 角色创建、编辑、批量导入、导出、封面；
- 单聊的全部消息与会话操作；
- 群聊模式、成员、会话和消息操作；
- 世界书、预设、人设、正则、快捷回复；
- 记忆、上下文预算、语义检索；
- TTS、图片、附件、公告、更新、用量、备份；
- MCP、诊断和本地模型管理。

矩阵字段固定为：`capabilityId`、`pcEntry`、`pcService`、`androidStatus`、`targetTier`、`platformPolicy`、`testId`、`notes`。`platformPolicy` 只能是 `same`、`equivalent`、`pc_only_confirmed`，最后一项必须有产品签字。

### S0-02 数据域与写入口清单

从 `electron/services/storage.ts`、Backup V2、全部 IPC、Bridge 路由和 Android DAO 反向建立清单。每个数据域记录：

- 物理位置与格式；
- schemaVersion 与迁移函数；
- 主键、父子关系和删除语义；
- 所有创建/修改/删除入口；
- 是否含密钥、个人内容或可重建缓存；
- 是否同步、是否端到端加密、blob 策略；
- 预计最大单条与总量。

检查必须能发现绕过仓储直接写文件或 DAO 的路径；结果作为阶段 2 收口列表。

### S0-03 决策记录

创建并签字以下 ADR：

1. ADR-001：保留原生 Compose，不改用 WebView/Capacitor。
2. ADR-002：语言无关 schema + 双实现，不尝试直接运行 TypeScript 核心。
3. ADR-003：PC 暂保留文件存储，通过 Repository 和 journal 收口；SQLite 另立未来决策。
4. ADR-004：版本向量 + tombstone + 显式冲突，不采用最后写入胜出。
5. ADR-005：同步必须手动触发；LAN 由 Android 发起一次性会话。
6. ADR-006：服务器长期数据必须端到端加密，凭据默认不同步。
7. ADR-007：首个独立客户端版本采用单轨切换；不保留旧伴侣运行模式、隐藏开关或旧网络回退路径。
8. ADR-008：canonical JSON 采用 RFC 8785 兼容字节规范；版本 counter 以 UInt64 十进制字符串传输和持久化。
9. ADR-009：旧 PC/Android 迁移使用共同 genesis；同内容投影合并，未完成 Outbox 单独对账。
10. ADR-010：LAN 使用持久化 prepare/commit、X25519 + 一次性 secret 派生会话密钥；服务器新设备授权使用带外二维码/SAS 和设备签名。

ADR 必须包含背景、选择、否决方案、后果和重新评估条件。

### S0-04 Golden 数据集

生成至少以下脱敏场景：

- 角色卡 V1/V2/V3、内嵌世界书和外部头像；
- 单聊 1、100、10,000 条消息，含分支、swipe、编辑和删除；
- 群聊三种模式与不同发言顺序；
- 世界书各导入格式、关键词/正则/语义配置、未知字段；
- 预设、人设、快捷回复和正则；
- 记忆摘要、事实、向量缺失降级；
- 含中文、emoji、组合字符、长文本、Markdown、`<thought>`；
- 损坏文件、未知 schema、重复 ID、孤儿外键。

每份 fixture 带 `README`，注明来源为人工合成或去隐私样本，不得提交真实 API Key、Token、私聊正文或头像。

### S0-05 基线测量

记录：

- PC 冷启动、打开 10k 消息会话、生成首 token、备份与恢复；
- Android 冷启动、打开 10k 消息、滚动帧、Room 大小；
- Bridge LAN 拉取 10k 消息；
- Relay 当前快照与 RPC 延迟；
- 完整测试数量和当前已知失败。

性能结果用于后续“不得回退超过 20%”门禁，不把开发机绝对值当通用 SLA。

### S0-06 原型验证

只做最小技术 spike，不进入生产路径：

- Kotlin 与 TypeScript 对 RFC 8785 canonical JSON 的字节一致性，覆盖浮点指数、负零、转义、非 BMP 键名和边界整数；
- ULID 排序一致性；
- 版本向量十进制字符串解析、边界、溢出和比较的跨语言 golden；
- Android 8/12/14 上通过 Keystore wrapping key 加密保存 32 字节空间密钥，并验证选定密码提供方的 X25519/Ed25519 互操作；
- 10k 实体摘要扫描内存和耗时；
- 2 MiB payload 与分块 blob 的序列化上限。

原型失败必须回到 ADR 修订，不能把未验证假设传给阶段 1。

## 3. 测试与验收

- 矩阵中的每个 PC 用户入口都有唯一 `capabilityId`。
- 数据清单覆盖 Backup V2 的所有条目及所有额外写入口。
- golden 数据能被当前 PC 读取，Android 现有模型对适用子集可解析。
- fixture 中运行密钥扫描，无高熵令牌、私钥或用户真实内容。
- 十份 ADR 均有明确结论，无“待开发者决定”。
- 基线命令、设备/系统信息和原始结果可复现。

## 4. 禁止事项

- 不修改生产 schema、Room 版本或用户数据。
- 不增加新同步端点。
- 不以 README 功能列表代替代码入口审计。
- 不把 Windows 特有实现直接标成 Android 缺陷；先定义平台等价策略。

## 5. 完成定义

所有 S0 任务完成，评审者能仅凭矩阵和数据清单回答“还缺什么、数据在哪里、谁会写它、是否同步”，并且阶段 1 不再需要自行决定核心架构。
