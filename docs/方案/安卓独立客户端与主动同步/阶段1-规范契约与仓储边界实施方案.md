## 2. 任务拆分

### S1-01 冻结 canonical schema

为总方案列出的每种实体建立 schema。规则：

- 核心字段 `additionalProperties: false`；需要保留外部未知字段时统一放入 `extensions`。
- 时间为 Unix epoch 毫秒；ID 为非空字符串，新增实体使用 ULID。
- 内容字段明确最大长度、数组最大项数和二进制引用方式。
- `settings_public` 只含可同步且非敏感字段；设备偏好与连接凭据拆开。
- Character/Lorebook 等已有 schemaVersion 的 payload 保留自身版本，外层 envelope 版本独立。
- Message 明确 `speakerKind`、`generationKind`、`narrativeMode`、swipe 和附件引用。
- `usage_clear_marker` 使用 `clearedThrough` 版本向量表达清理前沿，不以本地时间作为删除边界；被该向量支配的 usage record 才能清理，并发新记录保留。

为每个 schema 提供最小、完整、边界、非法四类 fixture。

### S1-02 canonical JSON 与哈希

实现并测试 RFC 8785 兼容的统一算法：UTF-8、属性名按规范要求排序、数组保序、ECMAScript 数值序列化、禁止 NaN/Infinity、字符串不做隐式 Unicode 归一化。业务中需要十进制精确性的值使用 schema 约束的十进制字符串，不交给浮点序列化。`contentHash` 使用 SHA-256，格式为 `sha256:<lowercase hex>`。

TypeScript 与 Kotlin 必须对至少 100 份 fixture 产生相同字节和哈希，fixture 必须包含 `1/1.0` 归一结果、负零、指数边界、转义、组合字符、非 BMP 属性名和最大长度。禁止直接依赖各语言默认 JSON 输出顺序或默认浮点格式。

### S1-03 版本向量与冲突模型

定义：

- 逻辑类型为 `VersionVector = Map<DeviceId, UInt64>`，wire/schema/SQLite 中统一保存为无前导零的十进制字符串；零值不序列化，最大值固定为 `18446744073709551615`，禁止经过 JS Number 或 JVM Long。
- `Dot(deviceId, counter)` 必须等于本次修改后向量中该设备值。
- 比较结果固定为 `equal | dominates | dominated | concurrent`。
- 合并远端知识只取逐设备最大值，不代表已合并 payload。
- `ConflictRecord` 保存本地/远端 envelope、发现时间、来源会话和状态。

建立 equal、单设备前进、多设备并发、删除并发、计数溢出/倒退、未知设备等 golden 测试。

定义 `MigrationGenesis`：PC bootstrap 首次生成并持久化至少 128 位随机 `migrationGenesisId`（不得从用户内容推导），PC 全量数据和 Android 缓存投影通过受认证的 genesis manifest 携带同一 genesis 与规范内容哈希。并发版本但 genesis、实体 ID、业务哈希相同的 head，由同步发起端新增本机 dot，生成支配双方的新收敛 head，不创建用户冲突；任何内容差异仍按并发冲突处理。

定义跨实体约束：每个 envelope 可声明 `aggregateType/aggregateId/aggregateRevision` 与引用集合；父实体 tombstone 创建 delete fence。远端新增/修改若依赖已删除或并发删除的父实体，必须形成 `DEPENDENCY_CONFLICT`，不得以不同 ID 并集直接落成孤儿数据。

### S1-04 Repository 契约

接口至少包括：

```text
get(type, id)
list(type, filter, page)
transaction { put / tombstone / attach / detach }
changesAfter(localCursor, limit)
applyRemote(batch, expectedReceipt)
listConflicts / resolveConflict
checkpoint / restoreCheckpoint
prepareSync(sessionId, batchHash) / commitPrepared(preparedReceipt)
recoverPrepared(sessionId)
```

行为约束：

- 本地业务写与 journal 写同成同败。
- 远端 apply 不再次产生“待上传的本地变更”，但必须更新已知向量。
- tombstone 查询默认隐藏，审计查询可见。
- `applyRemote` 整批校验后才写入；中途异常必须回滚。
- `prepareSync` 必须持久化 staging、目标 head、引用检查结果和不可变 `preparedReceipt`；`commitPrepared` 幂等，重启后 `recoverPrepared` 能区分未提交、已提交和响应丢失。
- 所有实现运行同一 repository contract suite。

先实现内存版本作为测试 oracle，不在本阶段接管 PC 或 Android 生产数据。

### S1-05 同步协议契约

在 OpenAPI 中定义 session、plan、push、pull、blob、commit、abort。固定：

- 协议版本与 capability 协商；
- 最大批次条数/字节数；
- `batchId` 与幂等响应；
- cursor 仅由服务端签发，客户端不解析；
- 错误结构 `{code,message,retryable,requestId,details?}`；
- `SCHEMA_UNSUPPORTED`、`CONFLICT`、`HASH_MISMATCH`、`QUOTA_EXCEEDED`、`SESSION_EXPIRED`、`DEVICE_REVOKED` 等稳定错误码；
- dry-run plan 和 commit receipt 结构。
- `preparedReceipt`、`commitReceipt`、session 状态查询和 commit 响应丢失恢复语义。

### S1-06 迁移注册表

PC 与 Android 分别建立连续迁移注册表，但迁移 fixture 共用。每个 payload schema 必须：

- 只允许 `N → N+1`；
- 确定性、幂等、不访问网络；
- 未知高版本拒绝写回；
- 迁移前可创建 checkpoint；
- 迁移后重新验证 schema。

### S1-07 CI 漂移门禁

增加脚本检查：schema 合法性、OpenAPI 合法性、生成物无漂移、TS/Kotlin fixture 结果一致、敏感字段不进入 `settings_public`。在 Windows 和 CI Linux 上均可执行。

## 3. 关键接口约束

- Repository 不返回可变内部引用。
- UI DTO 不等于持久化 DTO；映射必须显式。
- 同步 envelope 中禁止绝对路径、`file://` URL 和平台临时 URI。
- 附件只引用内容寻址 `blobId=sha256(ciphertext)` 或规范 manifest ID。
- 任何 schema 变更都必须先更新 fixture 和兼容表，再更新实现。

## 4. 测试门禁

- TS/Kotlin canonical JSON 与哈希 100% 一致。
- 版本向量属性测试至少覆盖交换律、幂等性和支配传递性。
- Repository 内存实现通过所有契约用例，包括事务回滚。
- OpenAPI 中每个 operationId 唯一，示例均通过 schema 校验。
- 旧 fixture 能连续迁移到最新版；跳版、逆向和未知新版被拒绝。
- 敏感字段扫描证明 API Key、token、spaceKey 无法进入同步 payload。

## 5. 完成定义与回滚

完成后，阶段 2/3 可以只依赖接口和 fixture 独立开发。该阶段不接管生产路径，回滚方式是删除新增模块和 CI 入口；不得修改现有用户数据或协议版本。
