# 阶段 2 写入口收口实施规范（S2-04）

> 用途：把某个数据域的所有业务写入改为经统一事务入口，使
> `node scripts/check-write-bypass.mjs --strict` 对该域文件不再报 `SYNC_DOMAIN` 违规。
> 前置已完成：S2-01 仓储边界、S2-02 设备身份、S2-03 跨存储事务、S2-05 bootstrap。

## 1. 可用入口（`electron/domain/syncDomainService.ts`）

```ts
// 单实体 + 其落盘文件，同一事务提交
writeThroughDomain({
  domain,              // DomainFlagKey，见 electron/domain/featureFlag.ts
  entityType,          // SyncEntityType，见 shared/contracts/sync-envelope.ts
  entityId,
  payload,             // 规范 payload（必须符合 shared/contracts/schemas/*.json）
  parentId?, schemaVersion?, references?, aggregate?,
  files: [{ path, content }],   // content 为字符串；null 表示删除该文件
}): { journaled: boolean; changeSeq: number | null }

// 单实体 tombstone + 其落盘文件
deleteThroughDomain({ domain, entityType, entityId, parentId?, files })

// 多实体共用一次文件写（会话数组、JSONL 消息文件）
commitThroughDomain({
  domain,
  entityType,          // 容器内实体统一类型
  puts: [{ entityId, payload, parentId?, schemaVersion?, references?, aggregate? }],
  deletes: [{ entityId, parentId? }],
  files: [{ path, content }],
}): { journaled: boolean; changeSeqs: number[] }
```

## 2. 行为契约（必须保持）

1. **flag 关闭时语义与旧实现完全一致**：入口内部直接原子落盘（同目录 tmp + rename），不写 journal。
   因此调用点不需要再写一份「旧路径」，也不需要 try/catch 回退。
2. `files` 里的 `content` 必须与该文件原本写出的字节一致。原实现用
   `writeJson(path, data, domain)` 时，请改用 `serializeJson(data, domain)`（`electron/services/storage.ts`）
   并放进 `files`；原实现用 `JSON.stringify(data, null, 2)` 时保持一致。
3. JSONL 消息文件：内容 = `lines.map(l => JSON.stringify(l)).join('\n') + '\n'`（沿用该文件既有格式）。
4. `payload` 必须只含阶段 1 冻结 schema 允许的字段；敏感值（API Key、env、token、spaceKey）不得进入 payload。
5. 一次文件写涉及多个实体变化时用 `commitThroughDomain`，不要拆成多次事务。

## 3. 收口配方

1. 找到该域**最低层的落盘函数**（如 `savePersonas` / `writePersonas` / `saveLorebookDocumentInput` 的调用点），
   优先只改这些「瓶颈函数」，让上层调用点自动被覆盖。
2. 在瓶颈函数里：
   - 先算出新文件内容字符串；
   - 用磁盘旧状态 diff 出 `puts` / `deletes`（新增、内容变化、消失的实体 ID）；
   - 调用 `commitThroughDomain`（多实体）或 `writeThroughDomain`（单实体）。
3. 删除原有「额外调一次 journal」的代码（如 `journalPutIfEnabled(...)` / `journalDeleteIfEnabled(...)`），
   否则会重复记账。删完若某文件的旧 journal 辅助函数已无调用者，一并删除。
4. 若某处确实需要绕过事务（例如仅清理 `.tmp` 临时文件），**不要**用原始写函数：
   临时文件清理请保留在同一文件内并确认它不是业务数据文件；业务文件一律走事务入口。

## 4. 验证

```powershell
pnpm check
node scripts/check-write-bypass.mjs          # 查看本文件是否仍有 VIOLATION
pnpm exec vitest run <相关测试文件>
```

完成后该文件不应出现在 `VIOLATION [SYNC_DOMAIN]` 列表中；`pnpm check` 必须为 0 退出码。

## 5. 禁止事项

- 不得把 `writeBusiness` / `deleteBusiness` 回调形式重新引入（S2-03 已删除该旧 API）。
- 不得为了绕过检测而把写操作搬到未被扫描的目录（`electron/domain/**` 之外的搬运同样受审计）。
- 不得用 TODO、空实现或「稍后处理」代替收口。
