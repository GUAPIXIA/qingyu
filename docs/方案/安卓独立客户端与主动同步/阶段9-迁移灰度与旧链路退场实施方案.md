# 阶段 9：一次性迁移、旧链路删除与发布实施方案

> 状态：⚠️ 待处理  
> 前置：阶段 6、8 全部通过。  
> 目标：完成真实升级、全量验证、旧伴侣代码与协议清零、分批发布和故障恢复；任何对外候选版均不包含旧伴侣运行模式。

## 1. 发布策略

至少分四档，但所有可分发安装包都只有独立客户端模式：

1. **内部开发构建**：仅供开发环境验证迁移，可暂时包含尚未删除但不可从 UI 进入的旧代码，不得分发。
2. **邀请测试版**：仅独立模式；使用测试空间和保守服务器配额。
3. **公开候选版**：仅独立模式；旧客户端升级必须经过一次性迁移向导。
4. **稳定版**：仅独立模式；与候选版使用同一数据结构和同步协议。

PC、Android、Sync Server 版本兼容表必须公开维护。服务器先部署 `/sync/v1`，再发布 PC 独立数据版本并完成可验证的初始上传，最后发布 Android 独立版。新客户端和新 Sync Server 部署物不得包含旧业务路由。若已发布旧客户端需要迁移窗口，旧 Relay 只能以隔离、冻结、不可被新客户端发现的 legacy 部署短期运行，并在稳定版前按公告日期下线；不得以“灰度”为由把旧模式留在候选版安装包中。

## 2. 任务拆分

### S9-01 升级预检与向导

PC：

- 检查 Backup V2、可用空间、损坏 JSON/JSONL、重复 ID、孤儿媒体和 schema。
- 创建带 hash 的 checkpoint。
- 建立 journal heads；报告跳过/修复项。

Android：

- 识别旧缓存、当前配对和本地设置。
- 让用户选择导入本地副本、备份后不导入，或退出升级。
- 创建本地资料与新 deviceId；解析旧 Outbox 并要求用户处理状态不确定的消息。只有共同 genesis 建立、首次全量同步 receipt 成功且旧 Outbox 已对账/导出/明确放弃后，才吊销并删除旧 Relay device token。
- 把旧数据库复制为只读升级快照，生产代码不再打开旧 schema。

向导可以在写入前取消并退出新版；不能转入旧模式。进入写入阶段后使用 checkpoint 保证全成或全不成；失败时恢复升级前文件并停留在迁移修复页。

### S9-02 首次同步引导

- 用户选择局域网或服务器。
- 首次 plan 明确标注“将以哪边为初始资料”及冲突数量。
- 若 PC 与 Android 都来自同一旧 PC 数据集，先验证 `migrationGenesisId` 和业务 hash；相同投影自动收敛，只有真实差异进入冲突中心。缺少 PC 完整数据时不得宣称迁移已完整。
- 不提供模糊的“一键覆盖全部”；全量覆盖必须二次确认并先备份。
- 初始导入完成后记录 receipt 和恢复点，提供“撤销本次同步”。

### S9-03 自动化端到端套件

建立可重复环境：

- Windows PC 测试应用；
- Android 模拟器至少 API 26/31/34；
- 本地 PostgreSQL、Redis、对象存储和 Sync Server；
- 网络代理支持延迟、断包、重复、乱序和限速。

核心旅程：新用户、旧用户一次性升级、旧缓存不完整提示、未完成 Outbox 对账/转草稿/放弃、迁移取消、迁移失败恢复、共同 genesis 首次收敛、LAN 首次同步、服务器首次同步、双端离线编辑、冲突解决、父删除与子新增依赖冲突、附件、设备吊销、密钥轮换、恢复包和 Backup V3 恢复。

### S9-04 真实设备/服务器验收

至少覆盖：

- 家用路由器、AP 隔离、双频切换、移动热点；
- 移动网络与不同运营商；
- Android 后台限制严格设备；
- 低存储、弱网、大数据集；
- 公网 TLS、反向代理、备份、恢复和告警；
- 两个空间和至少三个设备的隔离/并发。

所有测试使用去隐私账户与测试数据，服务器生产密钥不进入报告。

### S9-05 发布门禁

除项目统一门禁外，必须满足：

- P0/P1 能力矩阵 100% same/equivalent；P2 遗留有签字。
- schema/fixture TS/Kotlin 一致，无 drift。
- 数据迁移成功率、同步成功率、冲突率和失败码达到试运行门槛。
- 无 P0/P1 数据丢失、安全或崩溃缺陷。
- 性能相对阶段 0 基线回退不得超过 20%；超过部分必须有批准和解释。
- 安全审查、恢复演练和密钥轮换通过。
- 用户文档、隐私说明、服务器数据删除说明与故障排查完成。
- Android 包、PC 包和服务器部署物中的旧伴侣入口、业务路由、RPC、缓存与命令队列均已清零。

### S9-06 遥测与隐私

只收集用户明确同意的匿名运行指标：版本、阶段、错误码、耗时、条目/字节区间、冲突类型。禁止正文、实体 ID、URL、模型密钥、设备名、公钥、密文和空间 ID 原值。支持完全关闭，不影响功能。

### S9-07 旧伴侣链路强制删除

Android、PC 和新 Sync Server 中的旧链路删除必须在公开候选版构建之前完成，不设置隐藏回退开关。仅服务已发布旧版本的隔离 legacy Relay 可按迁移窗口例外保留，并必须在稳定版前下线。按以下顺序分别提交并验证：

1. Android：在公开候选版前删除远程 `QingyuApi` 业务调用、Remote Repository、旧 ConnectionManager/自动重连、远程会话启动路径、旧配对 UI 和只服务远程模式的通知逻辑。
2. PC：在公开候选版前删除旧 `/api/v1` 伴侣业务路由、聊天流 WebSocket、Relay Agent RPC 接线和旧手机连接 UI；保留 `/sync/v1` LAN endpoint。
3. Relay：新 Sync Server 部署物不包含 `/relay/v1/bridge/*`、PC/Android 业务 WebSocket、RPC broker、短期业务快照和离线消息命令队列。迁移窗口需要时，从冻结提交构建隔离 legacy 服务，仅服务已发布旧版本；稳定版前停止该服务并删除数据。空间、设备、token、RLS 和密钥信封基础设施按新 schema 保留。
4. 共享层：删除旧 relay frame/bridge DTO、capability、fixture 和仅服务旧协议的兼容分支。
5. 文档与部署：删除旧模式说明、端口/监控项和环境变量；提供一次性升级公告。

验收必须包括：代码引用搜索清零、Android/PC 导航不可达、旧业务路由返回 404、旧 WebSocket 握手失败、旧队列表不再有生产读写者、依赖图中无旧模块。迁移读取器仅允许读取本地旧数据库/文件，不得发起旧网络请求；完成一个稳定版本后可再删除迁移读取器。

### S9-08 故障恢复演练

至少验证：

- 迁移 commit 前失败时恢复升级前快照并停留在修复页；
- 迁移 commit 后发现问题时从 Backup V3/checkpoint 恢复到独立架构数据库；
- 从升级前 checkpoint 重新执行 PC 数据迁移；
- Android 清除新版本地库后重新导入 Backup V3；
- Sync Server 回退到只读版本；
- 空间全量导出后迁移到新服务器；
- 密钥丢失时的明确不可恢复提示与本地数据保护。

客户端故障恢复只能发布修复后的独立客户端或恢复数据快照，不得重新启用、重新打包或远程下发旧伴侣模式。

## 3. Go/No-Go 指标

候选版进入稳定版至少满足连续两周，并达到发布评审预先冻结的最小设备数、同步次数和迁移样本数；时间和样本两个条件都必须满足：

- 已确认的数据丢失事件为 0；
- 跨空间越权/密钥泄漏为 0；
- 同步 commit 成功率 ≥ 99%，剔除用户取消和明确配额不足；
- 可重试故障最终恢复率 ≥ 99.5%；
- crash-free sessions ≥ 99.5%；
- 冲突解决后再次出现同一冲突的比例 < 0.1%；
- 备份与恢复抽样成功率 100%。

任一 P0 或指标跌破门槛：暂停发布、关闭新空间创建、把服务器切为只读并发布修复后的独立客户端；不得重新启用旧伴侣入口，也不得用自动覆盖数据的方式降低冲突率。

## 4. 文档和支持交付

- Android 独立版用户指南；
- 手动同步、冲突解决、设备退役、空间删除和密钥恢复指南；
- PC/Android/服务器兼容表；
- 运维部署、备份、恢复、扩容、轮换与告警手册；
- 常见错误码与不含秘密的诊断采集说明；
- 版本发布、迁移失败恢复和服务器只读降级 runbook。

## 5. 完成定义

真实升级和故障恢复均通过，稳定版指标达标，用户无需 PC 即可使用 Android 全部适用功能，手动同步在 LAN/服务器均稳定。Android、PC 和新 Sync Server 部署物的旧伴侣运行时代码、入口、业务路由、RPC、缓存和队列已在候选版前删除；隔离 legacy Relay 已在稳定版前停止并清理，且不存在隐藏 feature flag 或旧网络回退路径。
