## 1. 实施目标与边界

### 1.1 必须交付

- Android 首次连接页同时显示“局域网连接”和“服务器连接”，由用户明确选择并记住选择。
- 局域网模式保持现有 HTTP/WS、二维码、mDNS 和防火墙流程不变。
- PC 与 Android 均通过出站 HTTPS/WSS 连接 Relay；服务器模式不要求 PC 开放入站端口。
- 每个 PC 安装实例对应一个独立 Relay 空间，全部服务端数据按空间隔离。
- 在线中转支持会话列表、消息历史、发送消息、AI 流式输出和停止生成。
- Relay 缓存会话、最近消息和临时文件；PC 离线时 Android 可以只读浏览缓存。
- 普通消息可短时排队；编辑、删除、设置修改等操作只在 PC 在线时执行。
- 普通用户即使获得其他空间、会话或文件 ID，也不能访问其他用户的数据。

### 1.2 明确不做

- 首版不做端到端加密，Relay 可以读取中转和缓存正文。
- 首版不做多个 PC 同时写同一个空间。
- 首版不做账号好友、空间分享或公开链接。
- 首版不做局域网与 Relay 的无感自动切换。
- Relay 缓存不是权威数据库，不能向 PC 反向覆盖旧数据。

### 1.3 兼容要求

- `ServerConnection` 旧 JSON 必须继续读取，不要求用户重新进行局域网配对。
- Android 现有 `QingyuApi`、Room 缓存和发件箱尽量复用。
- PC 现有 `BridgeServer` 可独立启停，Relay 开关不得依赖局域网开关。
- 公告服务 `server/` 保持独立，不与 Relay 共用 SQLite、数据库账号或 JWT 密钥。

### 3.2 WebSocket 帧

```ts
interface RelayFrame<T = unknown> {
  v: 1
  type: string
  id?: string
  replyTo?: string
  sentAt: number
  payload?: T
}
```

规则：

- 未知可选字段忽略。
- 未知 `type` 受限记录后忽略，不立即断开。
- 不兼容 `v` 使用 WebSocket code `4406` 关闭并提示升级。
- JSON 帧上限 256 KiB；图片、音频不得放入 JSON 帧。
- Access Token 只通过 Upgrade Header 的 `Authorization: Bearer` 传输，不放在 URL query。

地址：

```text

wss://relay.example.com/relay/v1/ws/android
```

## 4. Relay 服务实施

### 4.1 技术栈

- Node.js 22 + TypeScript。
- 建议 Fastify；JSON Schema 用于所有公网请求校验。
- `ws` 处理 WebSocket，与 PC 现有技术栈一致。
- PostgreSQL 16 保存空间、设备、令牌、缓存投影和事件索引。
- Redis 7 保存在线路由、短期 RPC、配对等待和限流。
- S3/MinIO 保存图片和音频。
- Vitest + Testcontainers 运行 PostgreSQL/Redis 集成测试。

### 4.4 Row Level Security

应用数据库角色必须为 `NOSUPERUSER NOBYPASSRLS`。每个请求事务先设置：

```sql
SELECT set_config('app.space_id', $1, true);
```

策略示例：

```sql
ALTER TABLE cached_messages ENABLE ROW LEVEL SECURITY;
ALTER TABLE cached_messages FORCE ROW LEVEL SECURITY;

CREATE POLICY cached_messages_space_policy ON cached_messages
USING (space_id = current_setting('app.space_id', true)::uuid)
WITH CHECK (space_id = current_setting('app.space_id', true)::uuid);
```

代码只允许通过 `withTenantTransaction(spaceId, callback)` 获得租户 Repository。`src/http` 不得直接调用裸 `pool.query`。

### 4.5 Redis 命名空间

```text
space:{spaceId}:pc:presence                 TTL 75s
space:{spaceId}:rpc:{requestId}             TTL 65s
space:{spaceId}:pair:{pairRequestId}         TTL 5m
space:{spaceId}:event:latest                 TTL 8d

```

### 4.6 Token 与配对

- Access Token：Ed25519 JWT，15 分钟有效。
- Refresh Token：32 字节随机值，90 天有效，每次刷新轮换。
- 服务端只保存 `HMAC-SHA256(TOKEN_PEPPER, token)`。
- 二维码票据：32 字节随机值，5 分钟、一次性。
- 手输码：8 位 Crockford Base32，5 分钟、一次性，并要求 PC 再确认。
- 发现已轮换的 Refresh Token 被重复使用时，撤销该设备整条 Token 链。

二维码：

```json
{
  "version": 1,
  "scheme": "qingyu-relay-pair",
  "relayBaseUrl": "https://relay.example.com/relay/v1/",
  "ticket": "base64url_secret",
  "displayName": "家里的电脑",
  "expiresAt": 1788173100000
}
```

配对流程：

1. PC 调用 `POST /pair-tickets`。
2. Android 扫码或输入短码，调用 `POST /pair-tickets/claim`。
3. Relay 创建待审批设备，返回 `pairRequestId + claimSecret`。
4. Relay 通过 PC WSS 发送 `pair:requested`。
5. PC 用户批准或拒绝。
6. Android 用 `Authorization: PairClaim {claimSecret}` 长轮询配对结果，最长 60 秒。
7. 批准后仅在该响应中返回 Android Access/Refresh Token，票据立即作废。

`claimSecret` 必须与票据、request ID 分离，防止猜到 request ID 的人领取凭据。

### 4.8 Bridge 兼容网关

Android 当前 Retrofit 方法使用 `api/v1/...` 相对路径。Relay 连接的 Retrofit Base URL 固定为：

```text
https://relay.example.com/relay/v1/bridge/
```

最终请求成为：

```text
https://relay.example.com/relay/v1/bridge/api/v1/sessions
```

这样可以继续复用 `QingyuApi` 和现有 Repository。Relay 禁止任意 URL 代理，只开放白名单：

| 方法 | 路径 | PC 离线 | 缓存 |
|---|---|---|---|
| GET | `/api/v1/server/info` | 返回 Relay/PC 状态 | 否 |
| GET | `/api/v1/characters` | 返回缓存 | 是 |
| GET | `/api/v1/sessions` | 返回缓存 | 是 |
| GET | `/api/v1/sessions/:id/messages` | 返回缓存 | 是 |
| POST | `/api/v1/sessions/:id/messages` | 排队 15 分钟 | 完成后写入 |
| POST | `/api/v1/sessions/:id/swipe` | 503 | 完成后写入 |
| POST | `/api/v1/sessions/:id/translate` | 503 | 否 |
| GET | `/api/v1/settings/snapshot` | 返回缓存 | 是 |

路径必须先规范化，拒绝 `%2f`、`..`、重复斜杠、绝对 URL 和非白名单 query。其余端点按批次逐项开放。

### 4.9 RPC Broker

- HTTP 请求生成 `requestId`，写入 Redis，默认 deadline 60 秒。
- 根据 Token 的 `spaceId` 查找在线 PC 节点；跨节点通过 Redis Stream 投递。
- PC 用 `replyTo` 返回结果并完成等待中的 HTTP 请求。
- 同一 `commandId` 已完成时直接返回原结果，处理中返回 202。
- 单空间同时进行 RPC 默认上限 16，AI 生成上限 2。
- 客户端断开 HTTP 不自动取消已落盘消息；只有明确可取消任务才发送 `rpc:cancel`。

## 5. PC 端实施

### 5.1 解耦 Bridge 运行时

当前 `BridgeServer` 自行创建 `WsHub` 和 `BridgeChatService`，后者又直接依赖 `WsHub`。Relay 接入前必须拆开，否则会形成两套消息生成逻辑。

新增事件抽象：

```ts
export interface MobileEventSink {
  publish(event: string, payload?: unknown, targetDeviceId?: string): void
}

export class CompositeMobileEventSink implements MobileEventSink {
  constructor(private readonly sinks: MobileEventSink[]) {}
  publish(event: string, payload?: unknown, targetDeviceId?: string): void
}
```

修改要求：

- `BridgeChatService` 依赖 `MobileEventSink`，不再直接依赖 `WsHub`。
- `WsHub` 实现 LAN Sink，`RelayAgent` 实现 Relay Sink。
- `activeChatControllers` 从 `electron/bridge/ws.ts` 移至 `GenerationRegistry`。
- `BridgeServer` 接收共享 `BridgeRuntime`，不再私自创建核心业务对象。
- 主进程只创建一个 `BridgeRuntime`，LAN 和 Relay 共用。

完成这一步后先跑现有 Bridge 全量测试，确保局域网响应和事件没有变化。

### 5.2 共享 MobileFacade

从 `electron/bridge/routes.ts` 抽出 Relay MVP 所需业务：

```ts
interface MobileFacade {
  serverInfo(): Promise<ServerInfo>
  listCharacters(): Promise<CharacterDto[]>
  listSessions(): Promise<SessionPreviewDto[]>
  listMessages(input: ListMessagesInput): Promise<MessagePage>
  sendMessage(input: SendMessageInput, context: MobileRequestContext): Promise<Message>
  swipe(input: SwipeInput, context: MobileRequestContext): Promise<Message>

```

`routes.ts` 只做 HTTP 参数解析和状态码映射；`relayRpcDispatcher.ts` 只做白名单匹配和调用同一个 Facade。禁止复制业务逻辑。

### 5.3 PC 凭据


- Refresh Token 使用 `safeStorage.encryptString()`。
- `safeStorage` 不可用时拒绝启用 Relay，不降级为明文。
- Access Token 只保存在内存，到期前 2 分钟刷新。
- 日志禁止输出 Token、票据、二维码正文和完整设备指纹。

### 5.4 RelayAgent 状态机

```text
Disabled
  -> Registering
  -> Connecting
  -> Online
  -> Reconnecting(attempt, nextAt)
  -> NeedsAuth
  -> ServiceUnavailable
```

- 仅在 Relay 配置 enabled 时随 PC 启动恢复。
- 退避：0、1、2、4、8、15、30 秒，之后保持 30 秒，带 ±20% jitter。
- 心跳 25 秒，75 秒无 pong 主动重连。
- 网络恢复、手动重试、Token 刷新成功时重置退避。
- `DEVICE_REVOKED` 进入 `NeedsAuth`，不无限重试。
- 退出应用时先下线，再关闭 WSS，最多等待 1 秒。

## 6. Android 端实施

### 6.1 连接模型兼容迁移

暂不改成 sealed class，避免破坏 DataStore 旧 JSON：

```kotlin
@Serializable
enum class ConnectionMode { LAN, RELAY }

@Serializable
data class RelayConnectionMeta(
    val baseUrl: String,

// 在现有 ServerConnection 末尾新增，必须带默认值
```

- 旧记录自动按 LAN 读取。

- Relay 的 `host/port` 可保留派生值兼容旧 UI，但 URL 构造不能依赖它们。
- 活跃连接继续按 `deviceId` 索引，Relay Device ID 使用 UUID。

### 6.2 凭据存储

将现有单 Token 存储扩为：

```text

connection:{deviceId}:refresh
```

- DataStore 只保存加密占位，明文进入现有 `TokenCrypto` 使用的 EncryptedSharedPreferences。
- LAN 旧 Token 首次保存时迁移到 `access` 键，旧键兼容读取至少一个版本。
- Relay Refresh Token 丢失时要求重新配对，但不删除 Room 会话缓存。
- Android Auto Backup 继续排除凭据。

### 6.3 URL 唯一出口

修改 `NetworkModule`：

```kotlin
fun apiBaseUrl(connection: ServerConnection): String = when (connection.mode) {
    ConnectionMode.LAN -> endpointOf(connection).toHttpUrl()
    ConnectionMode.RELAY -> RelayUrlPolicy.bridgeBaseUrl(requireNotNull(connection.relay).baseUrl)
}

fun wsUrl(connection: ServerConnection): String = when (connection.mode) {
    ConnectionMode.LAN -> endpointOf(connection).toWsUrl()
    ConnectionMode.RELAY -> RelayUrlPolicy.androidWsUrl(requireNotNull(connection.relay).baseUrl)
}
```

`RelayUrlPolicy`：

- 仅接受 HTTPS。
- 拒绝 username、password、fragment 和 query。
- 规范化尾斜杠。
- 固定映射 `/relay/v1/bridge/` 和 `/relay/v1/ws/android`。
- 禁止重定向到 HTTP 或其他主机时携带 Authorization。

现有 Repository 继续使用 `QingyuApi`，首版不做全量重写。

### 6.4 Token 自动刷新

- OkHttp `Authenticator` 仅对 Relay 启用。
- 同一时刻只允许一个刷新请求，其他 401 等待结果。
- 刷新成功后原请求最多重放一次。
- Refresh 失败、设备撤销或重复 401 时停止重放并发出 `tokenInvalidated`。
- Retrofit/WS 缓存键加入 `deviceId + mode + tokenGeneration`。

### 6.5 双入口配对页

重构现有 `PairingScreen.kt`：

```text

├── SavedConnectionsSection
├── ConnectionMethodCard(LAN)
└── ConnectionMethodCard(RELAY)
```

- 点击局域网卡展开现有扫码、mDNS 和手动主机/端口/配对码。
- 点击服务器卡展开扫码、8 位连接码和等待 PC 确认状态。
- 官方构建可预置 Relay URL；私有服务器从二维码读取 URL。
- 两种模式使用独立 ViewModel 状态，不能共用同一个 `pairing/error` 字段。
- 已保存连接显示 `局域网` 或 `服务器` 标签。

### 6.6 ConnectionCoordinator

```text

  候选端点竞速 -> serverInfo -> LAN Token -> LAN WS

RELAY

```

- mDNS 只参与 LAN。
- Relay 不写 `lastSuccessfulEndpoint`，只记录 `lastConnectedAt`。
- 新增 `ConnectionState.UsingCache(cacheAgeMs, pcOnline=false)`。
- 手动切换模式时先退休旧 generation、关闭旧 WS，再激活新连接，沿用现有代次守卫防串台。

### 6.7 缓存状态

Relay 缓存响应头：

```http
X-Qingyu-Data-Source: cache
X-Qingyu-Cache-Age: 35
X-Qingyu-PC-Online: false
```

新增拦截器读取响应头并写入 `RelayStatusStore`：

- live + PC online：`服务器 · 已连接`。
- cache + PC offline：`服务器 · 电脑离线，正在使用缓存`。
- queued：消息气泡显示“等待电脑上线”。
- 缓存过期：显示“电脑离线，缓存已过期”，不能误显示“没有会话”。

### 6.8 发件箱与幂等

- Android Outbox 的 `requestId/commandId` 原样发送给 Relay。
- Relay 排队后返回 202 和相同 `commandId`。
- Android 从 `LOCAL_PENDING` 变为 `RELAY_QUEUED`，不创建第二条命令。
- `command:completed` 到达后合并正式消息。
- 15 分钟到期后标记失败，只能手动重试。
- 切回 LAN 时不能自动重发 Relay 队列。

## 7. 缓存与文件实施

### 7.1 PC 缓存发布

- PC 第一次连上 Relay 后发送角色、会话和最近消息 `cache:snapshot`。
- 本地 `session:changed` 后延迟 300ms 合并，发送 `cache:delta`。
- 每条记录带 PC 单调递增 revision。
- Relay 使用 `ON CONFLICT ... WHERE excluded.revision > current.revision`。
- Android 无权写服务端缓存。

### 7.2 默认策略

| 数据 | 默认保留 | PC 离线 |
|---|---|---|
| 会话列表 | 7 天 | 可查看 |
| 每会话最近 200 条消息 | 7 天 | 可查看 |
| 角色和缩略图 | 7 天 | 可查看 |
| 普通发送命令 | 15 分钟 | 可排队并取消 |
| 编辑/删除/设置 | 不排队 | 503 明确提示 |
| 图片/音频 | 24 小时 | 有效期内可查看 |

每空间默认 500 MB。达到限额后先停文件缓存，再删除最旧临时文件和消息投影，绝不能删除 PC 本地数据。

### 7.3 文件通道

媒体阶段实施：

1. PC 向 Relay 请求预签名 PUT URL。
2. PC 直接上传对象存储。
3. Relay 记录 `spaceId/fileId/objectKey/mime/size/expiresAt`。
4. Android 鉴权后获取 5 分钟预签名下载 URL。
5. Coil/ExoPlayer 不向对象存储域名附加 Relay Token。

限制建议：图片 20 MB、音频 50 MB；服务端检查声明 MIME、实际类型和大小。媒体阶段前，Relay 模式必须明确显示“不支持该媒体”，不得返回 PC 局域网地址。

### 7.4 清理任务

- 每 15 分钟执行一次。
- 顺序：过期文件 → 过期事件 → 超过 200 条的旧消息 → 过期命令。
- 使用小批次和 `FOR UPDATE SKIP LOCKED`，避免长事务。
- 删除空间时先标记 deleted 并关闭 WS，再异步清理数据库和对象前缀。

## 14. 实施硬性约束

1. 先做共享 Facade，再接 Relay，禁止复制 `routes.ts` 业务逻辑。
2. 空间身份只取自 Token，禁止信任请求参数中的 `spaceId`。
3. PC 始终是权威数据源，缓存只接受更高 revision。
4. 用户始终能看见当前使用 LAN、Relay 还是缓存。
5. 两种连接相互独立，任一通道故障不得拖垮另一通道。
6. 凭据不得明文落盘；安全存储不可用时拒绝启用 Relay。
7. 跨空间隔离测试是发布门禁，功能跑通不能替代安全验收。

按此顺序实施，可以先用在线中转解决 NAT、防火墙和移动网络连接问题，再逐步加入缓存与媒体，同时把对现有局域网功能的改动限制在可测试、可回滚的范围内。
