# PC 端外部 Agent 功能测试与调用工具建设方案

> 日期：2026-10-03  
> 状态：⚠️ 待处理 — 方案编制完成，尚未实施  
> 用户确认：同时支持**终端命令和外部 MCP 工具**。自然语言由其他 Agent 理解，工具调用轻语现有 PC 功能。  
> 现状依据：[外部 Agent 能力审查汇报](../../报告/PC端外部Agent功能测试与调用能力审查汇报-2026-10-03.md)。  <!-- 归档副本：原相对链接已按本文件层级修正 -->
> 修订说明：替代此前关于“应用内自然语言助手”的方案。本文建设范围为仓库外部调用/测试设施，不新增产品助手、聊天模式、模型规划器或业务控制 API。

## 1. 目标与建设范围

让 Codex 或其他 Agent 收到自然语言测试/操作要求后，可以使用标准工具：

1. 发现 PC 可调用的动作、参数、前置条件和执行层级。
2. 启动隔离的真实 Electron，或连接确实具备自动化条件的指定实例。
3. 调用现有 API 或按 UI 操作现有功能，读取状态、等待异步结果。
4. 对真实结果做断言，收集截图、日志、导出文件和持久化证据。
5. 通过 CLI 或 MCP 得到一致的结构化结果，组合完整的测试旅程。

**自然语言 → 外部 Agent → CLI/MCP → 外部驱动 → 现有 PC 功能。** 工具自身不内置 LLM、不把指令转送 PC 聊天模型，也不依赖 PC 普通聊天的 tools 参数。

实施改动限定在 `tools/pc-agent/`、`scripts/lib/`、必要的专项测试、依赖登记及文档。`electron/`、`src/`、`shared/` 产品行为和业务协议不因工具建设改变。发现产品缺陷应另列缺陷和证据，修复按单独任务范围执行。

## 2. 复用路线

| 现有设施 | 用法 |
|---|---|
| 真实 Electron + 现有 preload/IPC | API 调用和业务状态核验的主路径 |
| Playwright Electron/页面/frame 操作 | 主窗口、表单、消息、嵌入画板和交互流程 |
| 现有真实 GUI 临时驱动 | 提取生命周期、隔离 userData 和主窗口识别经验；去除写死的角色/端口/输出目录 |
| `electronHarness` | 保留服务级专项打包/启动/日志采集；结果标明服务级，不能冒充完整 UI |
| `browserHarness` | 保留页面/mock 回归；结果标明模拟层 |
| `ipc-api.ts` | 盘点可调用业务接口，工具侧建立精确映射和运行时 schema |
| 既有 AI/画板/同步专项 | 包装为可发现的 test suite，不复制其业务逻辑 |

不恢复旧 `/api/v1` 伴侣接口，不扩展 `/sync/v1` 为全端控制接口，不重建已删除的 MiMoCode 桥接。

## 3. 两个入口共用一个运行器

```text
外部 Agent
  ├─ 终端：pc-agent CLI（JSON 输入/输出）
  └─ MCP client：独立 pc-agent MCP server（stdio）
          ↓ 同一动作目录、schema、执行与结果协议
本地 Session Host / Driver
  ├─ 生命周期：启动、窗口识别、隔离数据、关闭/重启
  ├─ IPC/API adapter：实际页面调用已暴露 window.api
  ├─ UI adapter：真实点击、输入、选择、frame 与等待
  ├─ 专项 adapter：现有服务/模型/浏览器测试脚本
  └─ 观察/断言/证据：状态读回、日志、截图、产物
          ↓
      轻语现有 Electron / 原产品接口 / 原业务落盘
```

CLI 进程可以多次调用同一自动化会话。由外部 Session Host 持有 Playwright/Electron 句柄，CLI 与 MCP 经共享客户端调用它；默认使用 Windows 本地命名管道。宿主会话 ID、连接令牌和文件权限限定当前测试会话，stdout 不打印凭据。

MCP server 是外部 Agent 注册的独立程序，不配置到轻语自己的 MCP 页面。启动和连接描述由工具包生成；用户不需要在 PC 产品中启用新功能。

### 3.1 拟建目录

```text
tools/pc-agent/
  cli.mjs                  # 终端入口
  mcp-server.mjs            # 外部 MCP stdio 入口
  client.mjs / host.mjs     # 会话通信与运行器
  catalog.mjs / schemas/    # 动作目录与运行时协议
  adapters/                # ipc、ui、专项动作适配
  assertions/              # 有限、可复核的状态断言
  suites/                  # 参数化测试旅程
  tests/                   # 工具自身与映射回归
  README.md                # Agent 使用说明、支持条件和例子
```

拟建路径及命令均为实施设计，当前不存在可用的 `pc-agent` 命令。阶段 0 明确工具包的依赖和安装入口；不能继续隐式依赖画板安装中偶然存在的 Playwright。需要 MCP SDK 时仅登记在工具依赖中，不添加到产品运行依赖。

## 4. 启动、连接与数据隔离

### 4.1 支持配置

| 模式 | 支持原则 |
|---|---|
| `source-isolated` | 首选：使用现有构建和外部 launcher，设置独立 userData 后加载原主 bundle，启动实际主界面 |
| `source-service` | 独立 Electron 专项入口，调用原业务；用于服务级集成和现有模型专项 |
| `browser-mock` | 显式模拟回归，不允许作为真实 IPC/持久化验收 |
| `installed` | 指定可执行文件，验证自动化连接及安全数据隔离是否可用；不可用则返回限制，不修改安装包 |
| `attach` | 仅连接已显式提供调试端点或已有受控驱动句柄的指定实例；无连接条件则返回 `UNSUPPORTED_ATTACH` |

默认不接管用户已打开的正式客户端，也不自动把正式数据复制到测试目录。用户明确要求操作正式实例时，工具会话记录指定实例、允许对象和动作范围；查询与写入按该授权范围执行，不每一步重复问同一项。

若安装版不允许源码级 API 操作，但可通过外部桌面工具验证界面，登记为 `ui_only`，能力目录准确显示。不能为实现任意安装版接管而增加生产常驻调试端口或产品控制接口。

### 4.2 生命周期要求

- 隔离目录、launcher、日志和证据位于本次 run 目录，分别登记所有权。
- 源码启动需启动现有 Vite 或使用受支持的现有构建入口；主程序的 dev/packaged 加载差异在阶段 0 实测，不通过修改 `main.ts` 解决工具假设。
- 区分应用主窗口、DevTools、弹窗和画板 iframe；以 URL、实际 preload 和界面就绪状态综合识别，不依赖 `firstWindow()`。
- 重启后重新绑定页面、frame、监听器和 locator；旧对象引用立即失效。
- `session.close` 只关闭本次工具拥有的客户端、宿主和服务；`attach` 默认只断开。
- 清理前校验解析后的绝对路径位于本次 run 根目录。证据默认保留，清理由显式命令按所有权执行。

## 5. 动作目录与双入口协议

### 5.1 动作描述

每个动作登记：`id`、中文说明、参数 schema、结果 schema、支持模式、执行层级、目标引用、前置条件、副作用、等待条件、可取消性、断言建议和证据类型。

例如拟建 `chat.session.rename` 映射实际 `window.api.chat.renameSession`，并读回会话确认；`chat.send` 是完整发送功能，需要调用原聊天任务路径或 UI 发送，不能映射成低层 `saveMessage`。

不向外暴露任意 JS、任意 IPC 通道、任意进程命令或直接文件写入作为产品动作。映射实现可以在受控 Playwright 回调中执行可信代码，参数作为结构化值传入，不拼接 Agent 提供的脚本文本。

### 5.2 CLI 草案

```powershell
# 以下命令为拟建接口，不是当前可运行命令。
node tools/pc-agent/cli.mjs doctor --json
node tools/pc-agent/cli.mjs catalog --module chat --json
node tools/pc-agent/cli.mjs session start --profile source-isolated --json
node tools/pc-agent/cli.mjs invoke --session <session-id> --action chat.session.rename --args-file <absolute-json-path> --json
node tools/pc-agent/cli.mjs operation wait --session <session-id> --operation <operation-id> --json
node tools/pc-agent/cli.mjs observe --session <session-id> --target <target-ref> --json
node tools/pc-agent/cli.mjs assert --session <session-id> --spec-file <absolute-json-path> --json
node tools/pc-agent/cli.mjs suite run --session <session-id> --suite chat.basic --json
node tools/pc-agent/cli.mjs evidence --session <session-id> --json
node tools/pc-agent/cli.mjs session close --session <session-id> --json
```

机器模式 stdout 只返回完整 JSON，运行日志走 stderr/证据文件。参数 schema、输出协议与 MCP 相同；不把终端描述文本作为唯一结果。

### 5.3 MCP 工具草案

| 工具 | 用途 |
|---|---|
| `qingyu_doctor` | 检查构建、依赖、连接条件和支持模式 |
| `qingyu_capabilities` | 返回动作 schema、可用性和执行层级 |
| `qingyu_session` | 启动/连接/重启/断开受控实例 |
| `qingyu_call` | 选择已登记 action 并调用 |
| `qingyu_observe` | 读取允许的业务状态和 UI 状态 |
| `qingyu_operation` | 查询、等待、取消指定异步操作 |
| `qingyu_assert` | 执行有限断言，返回实际值及证据 |
| `qingyu_run_suite` | 运行固定或参数化测试旅程 |
| `qingyu_evidence` | 获取截图、日志和产物索引 |

首版用少量入口加可发现动作目录，避免向 Agent 一次塞入所有底层方法。CLI 和 MCP 输入同一动作时必须获得等价结果，差异只在传输方式。

### 5.4 返回结果

```json
{
  "schemaVersion": 1,
  "requestId": "req-...",
  "sessionId": "session-...",
  "operationId": "op-...",
  "action": "chat.session.rename",
  "layer": "ipc",
  "status": "succeeded",
  "invoked": true,
  "verified": true,
  "targets": [{ "type": "chatSession", "id": "test-session" }],
  "result": { "title": "QA-改名验证" },
  "evidence": [],
  "error": null
}
```

`accepted/running/succeeded/failed/cancelled/blocked/needs_interaction/unknown` 是动作状态；断言单独使用 `pass/fail/blocked`。请求受理不等于成功，方法返回不等于验证通过，取消选择器不等于导出成功。

CLI 退出码约定：0 表示此次请求/查询按协议成功返回，1 表示动作或断言失败，2 表示参数/协议错误，3 表示环境阻塞/不支持，4 表示需要用户交互。异步请求返回 `accepted` 时，Agent 仍必须等待或查询最终状态。

## 6. 执行层级与验证原则

| 层级 | 定义 | 不得扩大为 |
|---|---|---|
| `mock` | 受控 host 或 preview API | 真实 IPC/磁盘测试通过 |
| `service` | 专项脚本调用真实服务 | 实际主窗口的用户流程通过 |
| `ipc` | 实际应用页面通过正式 preload 调用 IPC | 按钮、表单、焦点和交互体验通过 |
| `ui` | 真实主窗口操作原控件，再核对业务状态 | 实际模型输出正确，除非还做模型核验 |

是否调用真实模型、外部服务、原生对话框以及是否重启核验，作为独立证据字段记录，不能只用“真实测试”一个标签概括。

### 6.1 读回与断言

- 保存后从原 API 读回；必要时重启客户端再读回，不直接写文件制造结果。
- UI 动作优先使用已有可访问名称、label、角色和稳定结构；未能稳定定位时登记工具限制，不为了方便添加产品按钮/调试入口。
- 前端状态或草稿动作走 UI，检查旧状态、脏编辑和保存时机；不能调用后强制刷新掩盖原 UI 流程故障。
- 状态断言提供等值、包含、数量、存在性、版本变化、会话隔离、产物存在等有限操作，输出 expected/actual 和证据。
- 仅读回磁盘文件不足以证明“操作由此请求完成”；关联请求、目标和原调用结果，防止沿用上次测试产物误报成功。

### 6.2 异步与重复调用

生成、翻译、索引、TTS、画板 AI 和同步须在触发前绑定事件，按 request/task ID 过滤。完成回调后还要核对指定对象或产物；窗口切换不能把结果归到新对象。

副作用动作不自动重试。外部工具的 request ID 记录用于查询和防止重复 dispatch；PC 原接口支持幂等时复用原标识。进程中断且无法证明提交结果时标记 `unknown`，先读回核对，不承诺通用 exactly-once。

取消复用原功能的停止/取消接口；不支持取消的提交明确返回限制。关闭 MCP client 不代表 PC 操作已撤销。

### 6.3 文件和原生交互

API 层需要原生选择器的功能优先通过现有 UI/文件交互完成，不能 monkey-patch 正式 dialog、替换业务 API 后宣称真实界面通过。

标准 web file input、画板 iframe 等由 Playwright 处理；系统原生对话框需要工具包明确支持的桌面自动化后端。后端不可用则返回 `needs_interaction/blocked`，保持任务可恢复。安装版/UI-only 环境不支持的 API 明确降级，不把打开页面算业务完成。

## 7. 全 PC 接入与测试旅程

阶段 0 从现有页面、[IPC 契约](../../../shared/ipc-api.ts)和[验证规范](../../../规范/PC端AI-Agent验证测试规范.md)建立逐功能矩阵；每行记录 API/UI 动作、支持模式、断言、证据及状态。

| 模块 | 首批动作/测试旅程 | 验证重点 |
|---|---|---|
| 生命周期/页面 | 启动、导航、窗口选择、截图、重启 | 实际主窗口、preview 拒绝、实例和 userData 归属 |
| 角色 | 新建/读取/编辑/保存/删除、生成草稿、素材/导入导出 | 名称、字段、持久化、取消与隔离测试数据 |
| 单聊 | 建会话/选择/改名/分支/导出、发送/停止/重生成/续写 | 消息身份、终态、swipe、会话隔离与重启 |
| 群聊 | 创建、成员、模式、发送/停止、会话和导出 | 点名/轮询/free 的真实调度与归属 |
| 世界书 | 新建/条目/绑定、翻译/扩词/触发/索引、导入导出 | revision、上下文触发、旧结果、真实索引状态 |
| 预设/人设 | CRUD、绑定、切换、生成/保存、规则 | 全局/会话差异，未请求字段不被覆盖 |
| 正则/快捷回复 | CRUD、启停、样例/消息效果、插入/发送 | 正确范围、非法输入、实际动作 |
| 设置/模型 | 查询、外观/篇幅、保存、模型列表/连接测试 | 防抖保存、有效配置、原 UI 与真实落盘 |
| 消息辅助/记忆 | 翻译、润色、方向、标题、记忆/压缩 | 对象与来源版本、任务终态、错误和取消 |
| 图片/TTS | 配置、生成、工作流、朗读/停止 | 服务条件、生成产物与实际播放分别核验 |
| 空间画板 | 开关/绑定、节点/人物/距离、提案/确认/撤销 | 实际 iframe、提交、队列、重启恢复 |
| 用量/公告/日志 | 查询/筛选/详情/导出/异常采集 | 实际统计口径、网络条件、文件内容 |
| 字体/备份/更新 | 选择/导入/导出/取消、恢复、检查/安装 | 原生交互、隔离数据和高影响动作范围 |
| 同步/设备/MCP | 状态、认证、预检、冲突、工具配置/调用 | 真实环境、原授权流程、错误/断连与结果 |

每个已有用户功能都要登记，缺接口时允许用真实 UI 适配。确实不能在限定模式下自动调用的项列出原因及交互路径，不为了填满覆盖率修改产品实现。

## 8. 授权、数据和证据

会话创建时记录运行对象、隔离目录、允许写入范围、允许测试套件以及用户已授权动作。对本次独立创建的测试对象，可连续执行已明确授权的测试动作；正式用户数据不自动纳入套件。

真实模型调用、备份恢复、更新安装、对外发送等按用户任务授权与既有[测试规范](../../../规范/PC端AI-Agent验证测试规范.md)执行。未提供所需模型或依赖时标记阻塞，继续其他可验证项；仅编写本方案不运行这些动作。

状态接口过滤密钥和非必要个人内容。尤其 `settings.get` 可能回填凭据，工具实现只能在受控回调内按需读取并返回允许字段，不把完整设置回传给 Agent。截图、日志、任务参数和导出证据有统一脱敏与保留规则。

建议输出结构：

```text
output/pc-agent/<run-id>/
  session.json            # 公开实例/版本/模式/构建身份
  actions.jsonl           # 输入摘要、状态、实际目标、耗时
  assertions.jsonl        # 预期/实际/层级/结论
  result.json / report.md
  screenshots/ logs/ exports/
  runtime/                # 私有会话描述、launcher、隔离 userData
```

私有连接令牌、凭据和权限描述不进入公开 manifest，不入 Git。关闭与清理只操作本 run 所有的进程和路径，默认保留测试证据。

## 9. 分阶段实施

| 阶段 | 交付内容 | 退出条件 |
|---|---|---|
| 0：盘点与原型验证 | 逐功能矩阵、支持模式、依赖和启动实测、CLI/MCP schema、动作/证据分层 | 证明外部 launcher 能驱动现有应用；明确安装版/attach 的可用条件，产品代码无需改动 |
| 1：公共运行器和 CLI | Session Host、隔离启动、窗口/frame 识别、catalog/invoke/observe/assert/evidence、异步句柄 | 新建测试角色/会话→改名→读回→重启读回闭环；失败/断开/重启不串实例 |
| 2：外部 MCP | stdio server、全部基础工具、共享客户端、配置例子 | 外部 MCP client 与 CLI 调同一动作得到等价结果；无独立第二套执行逻辑 |
| 3：高频全端适配 | 聊天/群聊/角色/世界书/预设/人设/正则/快捷回复/配置/画板及消息辅助 | 每项 API/UI 层可调用性真实登记，运行原业务，支持失败和取消验证 |
| 4：系统和专项适配 | 图片/TTS/文件/字体/备份/同步/更新/MCP；包装现有 suite，补原生交互后端 | 有环境时真实结果通过，无环境时准确阻塞；不以 mock 代替真实业务验收 |
| 5：全量验证与文档 | 动作目录回归、双入口旅程、依赖安装、安装版边界、证据和使用说明 | 全 PC 矩阵无未解释遗漏，已支持项有执行/断言证据；产品行为没有被工具改动 |

阶段 1 是第一可用交付点，阶段 2 完成用户指定的 CLI+MCP 双入口。阶段 5 才能按完整矩阵声明全端覆盖。当前所有阶段均未开始，不给出未经盘点的工期承诺。

## 10. 验收与回退

工具自身验证至少覆盖：错误参数/未知动作、错误实例、mock 检出、DevTools 误选、iframe 重建、事件先后次序、异步阻塞/取消、选择器取消、失败回执、重复请求、副作用结果未知、MCP stdout 污染和路径清理边界。

真实旅程必须同时从终端和 MCP 完成：创建测试角色及会话、修改并读回、UI 选择目标、执行适当动作、检查持久化、重启恢复、生成结构化报告。全端套件按现有规范覆盖每个模块，AI/外部系统依赖单独记测试环境和实测结果。

运行工具定向测试与项目必要门禁。只读/文档建设阶段不要求执行模型或系统操作；实现阶段不得改产品或测试断言来掩盖失败。构建和契约既有失败记录基线，工具新增失败必须处理。

停用时移除外部 Agent 的 MCP 配置并关闭工具所拥有的宿主与客户端即可；既有 PC 产品不依赖这套工具继续运行。已对测试数据或授权对象完成的业务操作不会因停用工具自动回滚。

每阶段更新 `tools/README.md`、工具使用说明、能力矩阵和实施报告。方案完成并验收后按项目归档约定处理。
