# 移除「自动生图」方案

> 状态：**已实施** — 代码改动完成，验证结果见第 10 节。
> 基线：PC `0.17.2` / Android `0.3.0 (9)`。
> 范围：**完整移除（含 Android 契约）**。


> 🗄️ **已归档（2026-09-13）**：按「方案完成后一律归档」移入本目录，仅作历史留档，不再更新。归档登记见 [归档 README](./README.md)。

## 1. 背景

「自动生图」指：AI 回复文本中出现 `[image: <prompt>]` 标记时，PC 主进程自动调用生图后端并把结果写回该条消息的 `images`，由设置项 `imageGenAutoEnabled` 控制开关。

本次决定**彻底移除该功能**，包括它的触发逻辑与 PC↔Android 设置快照契约字段。

## 2. 现状盘点

### 2.1 触发逻辑（PC / 渲染层）

仅有一处实现：[useChatStore.ts](file:///d:/Code/qingyu/src/store/useChatStore.ts#L656-L687)，挂在**旧生成链路** `sendMessage → streamAIResponse` 的 `onComplete` 回调里，逻辑为：

1. 读 `settings.imageGenAutoEnabled`；
2. 正则 `/\[image:\s*([^\]]+)\]/gi` 抽取全部标记；
3. 逐个 `window.api.imageGen.generate(p)`；
4. 成功的图追加进该消息 `images` 并落盘。

### 2.2 该功能当前已不可用

[chatTaskStore.ts](file:///d:/Code/qingyu/src/store/chatTaskStore.ts#L27) 中 `chatEngineV2` 默认 `true`，而 [sendMessage](file:///d:/Code/qingyu/src/store/useChatStore.ts#L476-L527) 在 V2 分支直接 `return`，**永远走不到** `onComplete`。因此这段代码是死代码。

补充事实：PC 端**没有任何 UI 入口**可以打开该开关（全仓仅 [L657](file:///d:/Code/qingyu/src/store/useChatStore.ts#L657) 读取一次；[QuickSettingsPanel.test.tsx](file:///d:/Code/qingyu/src/components/chat/__tests__/QuickSettingsPanel.test.tsx#L114-L131) 还专门断言"不在快捷设置中显示自动生图"）。即：只能手改 `settings.json`，且改了也不生效。

> 结论：移除是**净收益**——删除死代码 + 收缩跨端契约，无用户可感知的功能回退。

### 3.4 契约 fixture 与版本

`shared/fixtures/settings_snapshot.json` 的 `revision` 是**内容寻址**哈希 `sha256(stableStringify(values))`，删除字段后必须重算，否则 [contractFixtures.test.ts L67](file:///d:/Code/qingyu/electron/bridge/__tests__/contractFixtures.test.ts#L67) 的 `revision === computeRevision(values)` 断言会失败。

已实测重算结果：

```
旧 revision: f106f67ab23123a7424c66c206284d22f1a7bd5c5b929dcde57265dcd49c83c5
新 revision: a0c60f7927381ed84e58db9615c1fd97444d84833260ee97fc66880a93e3af44
```

同步更新两份 fixture（共享权威 + Android 副本，须逐字节一致）。

**schemaVersion 处理**：沿用 `imageGenSize` 退出安全子集时的既定先例（v2 → v3），本次 **3 → 4**，涉及：

- `electron/bridge/settingsSync.ts`：`SETTINGS_SNAPSHOT_SCHEMA_VERSION` 与 `SettingsSnapshot.schemaVersion` 字面量；
- `shared/fixtures/settings_snapshot.json`：`schemaVersion: 4`；
- `ProtocolContractTest.kt` L53：`assertEquals(4, ...)`；
- `android/.../SettingsSync.kt` L15/L18/L39：解码默认值与注释。

> capability 保持 `settings_snapshot_v2` 不变（端点协议未变，仅字段子集收缩），与 v3 处理一致。

## 4. 兼容性分析（关键）

这是本方案的核心判断，三端交叉均安全：

| 组合 | 结果 |
|---|---|
| **新 PC → 旧 Android** | 快照 `values` 少一个键。旧 Android 的 `imageGenAutoEnabled` 有默认值 `false`，缺失时取默认，**解码不抛**。 |
| **旧 PC → 新 Android** | 快照 `values` 多一个键。Android `NetworkModule.json` 配置了 `ignoreUnknownKeys = true`（[L175](file:///d:/Code/qingyu/android/app/src/main/java/com/qingyu/companion/network/NetworkModule.kt#L175)），未知键被忽略，**解码不抛**。 |
| **新 PC snapshot PATCH** | 旧 Android 若仍 PATCH 该字段，会落入 `rejectedFields: field_not_allowed`，不影响其它字段应用；Android 冲突面板不会渲染未知字段。 |
| **新 PC legacy PATCH** | 旧 Android 若仍 PATCH 该字段，`SETTINGS_WRITE_FIELDS` 不命中则静默跳过，仍返回 `{ok:true}`（既有语义）。 |
| **revision 变化** | 字段移除导致 revision 改变，旧 Android 首次 PATCH 会收到 409 并重新同步。这是**任何**设置变更的既有行为，非本次新风险。 |

> Android 侧 `SettingsSyncSerializationTest.kt` L75 已有 `assertFalse("imageGenSize" in SYNCABLE_FIELDS)` 的同型断言。建议本次**照抄该模式**，补一条 `assertFalse("imageGenAutoEnabled" in SYNCABLE_FIELDS)`，把"已移除"钉死为回归保护。

## 8. 风险与回滚

| 风险 | 等级 | 说明与缓解 |
|---|---|---|
| 漏改 `FIELD_VALIDATORS` 映射 | 低 | TS 穷举 `Record<keyof MobileSafeSettings, ...>` 在 `pnpm check` 直接报错，无法漏。 |
| fixture revision 未重算 | 中 | 上文已给出重算值；`contractFixtures.test.ts` 会立即红脸兜底。 |
| 旧 Android PATCH 被拒 | 低 | 仅该单字段进 `rejectedFields`，其余字段正常；属预期收敛。 |
| 用户曾手改该配置 | 极低 | 字段为可选，删除后残留键被 `Settings` 类型忽略；功能本就不生效，无回退感。 |
| 回滚 | — | 全部改动为删除 + 常量替换，`git revert` 单次即可还原。 |
