## 1. 已确定的原则

- 群聊空间归属为 `kind=group + groupId + sessionId`，一个群聊会话有一份公共位置状态。世界地图可复用，单聊、不同群聊及不同群聊会话的位置和功能历史各自隔离。
- 对话 AI 只读取位置关系。画板助手使用独立历史、任务与提示，继续使用所属群聊的有效连接和模型。
- `mention/polling/free` 是发言规则，`immersive/omniscient` 是叙事视角，分别实现和验证。
- 加入成员不证明成员已处于同一现场；没有证据的位置保持未放置。移出成员保留必要历史引用，退出当前参与范围。切换 persona 不复制旧身份的位置。
- 群聊首版剧情同步采用待确认建议，长接力中不自动修改位置。确认时重新检查来源、参与者和画板版本。

## 3. 阶段 0 的数据与界面

世界继续保存在 `spatial/worlds/<worldId>.json`。群聊另用以下目录，避免与同 ID 的单聊混淆：

```text
groups/<groupId>/sessions.json                # 世界与运行身份绑定
spatial/group-runtimes/<groupId>/<sessionId>.json
spatial/group-session-state/<groupId>/<sessionId>.json
```

运行身份根据完整 `groupId + sessionId` 计算稳定哈希；提交包含绑定 epoch、运行 revision 和世界 fingerprint，重复提交使用原收据。世界、位置和提交记录共用空间事务。共享世界的结构保护同时扫描单聊与群聊位置。

群聊页头保留一个「画板」按钮，打开后以画板替换消息和输入区域。创建空白世界或绑定已有世界均不预设人物位置。成员映射按角色 ID，用户实体按当前有效 persona ID；头像继续读取角色卡和身份资料。

角色托盘和画布只展示当前参与范围，历史 actor、位置与事件仍保留在权威数据中。成员管理沿用群聊设置；画板不新增与群成员无关的角色定义。手动编辑、撤销和重做继续走主进程命令提交。

切换群聊、切换/新增/删除会话、成员设定、用户身份及主导航前等待画板 flush。失败保持原上下文，提供重试与载入最新画板。删除群聊或会话先恢复待完成事务，再清理其空间绑定和位置记录，共享世界及其他会话保留。

备份先检查群聊归属、确定的运行身份、世界和提交记录，再写任何文件。合法中断事务按完成后的逻辑状态预检，恢复后按原提交 ID 去重。

## 4. 群聊差异与实施进度

### 阶段 1（已实施）

代入模式按当前说话成员投影自身位置、同地点关系与明确不参与状态，隐藏异地成员路径；全局叙事保留当前参与者的公共空间关系。自由发言按各段发言者区分知情范围。未知位置不等于缺席，异地也不自动禁止发言，同地不保证视线互通。明确不参与的成员不生成回应，自由发言保存完整或半截回复时也过滤该成员。

画板功能请求从群聊有效配置冻结 provider、profile、model、预算和凭据引用。正文与记忆请求已修正为 `activeModel || profile.model`，预算、实际发送和用量记录使用对应有效模型；画板沿用主进程解析，翻译继续使用原有效模型规则。界面没有新增功能模型选择器。

初始化允许选择成员场景材料和相关世界书，结合群聊设定、最近已保存正文及本次说明。不同角色卡住处不能直接拼成共同现场；默认开场白和示例对话不作为已发生事实。草稿可先在画板修改，确认后才建立正式世界和位置。手动指令和未知起点建议同样需要确认，来源或空间版本变化时拒绝旧提案。

群聊助手按 `groupId + sessionId + 画板绑定` 独立保存，初始化提交将世界、位置、收据和助手记录放进同一事务。取消、删除和恢复会终止旧请求，迟到结果不能复活旧任务；重启的未知结果不自动重发。只读投影限 1600 tokens，必要信息不能容纳时停止发送，不静默丢失当前位置。每个群聊会话可关闭位置读取。

### 阶段 2（已实施）

| 发言规则 | 来源批次 |
|---|---|
| 点名 | 当前生成完整结束，目标成员正文保存成功后形成一批 |
| 自由发言 | 同一次生成的拆分消息全部保存成功后形成一批；全局叙事保留整段语义 |
| 轮询 | 一次接力实际交还用户时，以已完成且保存成功的成员正文形成一批；失败与半截内容不作为完成行动 |

批次冻结 owner、generationId、burstId、有序消息 ID 与正文 hash、参与者、发言/叙事模式、有效 persona、发送时空间版本。按正文顺序判断最终位置；相同 actor 的矛盾证据进入核对，不能按回包顺序覆盖。

群聊助手提供「关闭 / 需确认」策略，默认关闭。启用需确认且允许对话读取位置时，主进程在正文请求前捕获批次，只有正常完整结束的生成才可签入已保存消息。失败、取消、截断、保存失败与半截正文不进入提取。轮询停止时此前完整保存的回复可独立组成一批；自由发言拆分消息全部保存后只提取一次。

登记与关闭批次不等待模型。持久队列沿用所属群聊的当前有效连接和模型，提取完整有序正文，不静默裁去中间行动；预算不足则失败提示。来源、成员、身份、模式、配置或绑定变化会使旧任务和提案失效。确认持有正文锁并再次核对来源与画板版本，正式空间事务保存结果。

提取失败不重发正文，也不自动重试。用户可显式重新提取仍有效的失败或中断批次；取消及迟到返回不写位置，超时会释放队列。重启恢复已落盘的完整检查点和排队任务，在途未知结果标为中断；ZIP 恢复校验批次快照归属、正文来源与版本。阶段 3 在此基础上完成未明确地点、版本冲突核对和剧情撤销交互。

### 阶段 3（已实施）

聊天输入区使用一行显示待核对、提取中、失败、已确认或来源变化，点击直接进入当前群会话画板助手。当前地点与目标使用完整路径；来源和版本折叠展示，避免重复摘要。

仅画板版本变化的建议可按当前地图重新核对，生成独立待确认建议后再确认移动；来源、成员、身份、模式、配置、读取或同步开关变化导致的失效不能通过核对复活。主进程保存来源 epoch，配置或身份切回原值仍拒绝旧建议。

未知或已删除的目标可以选择已有完整路径，或单独预览并确认创建地点；创建不移动人物，之后再核对移动。核对保留原文完成证据、当前成员及有效 persona 限制，不调用模型。已应用来源变化只提示，不自动移动；剧情撤销两次确认，按原收据逆操作，后续已有空间修改时拒绝覆盖，重复撤销幂等。

群聊翻译冻结群聊、会话、消息、发言者与正文，专用来源比对只更新附属翻译字段，保留完整生成检查点。参与过滤按沉浸/全局叙事分别处理：沉浸继续过滤明确不参与回应者，全局旁白及轮询焦点不被标记误拦截。

重启与备份恢复保留核对、地点创建、确认和撤销记录，错误来源在备份预检拒绝；迟到回调不串群聊或会话。详见[阶段 3 报告](../../报告/空间画板群聊接入阶段3实施报告-2026-10-02.md)的八条验收映射。
