# 语义检索统一设置实施方案

> 状态：已实施（2026-08-29）


> 🗄️ **已归档（2026-09-13）**：按「方案完成后一律归档」移入本目录，仅作历史留档，不再更新。归档登记见 [归档 README](./README.md)。

## 1. 问题与目标

旧设置页曾把“本地向量模型”和“语义触发”拆成两个入口，同时使用 `localModels.retrievalMode` 与 `semanticTrigger.enabled/provider` 表达同一项用户意图。两者可以互相矛盾，用户也需要在两个区块之间来回操作。统一后的入口现位于“模型 → 语义检索”。

本次调整的目标是：

- “模型”页面只保留一个“语义检索”页签；
- 用户只选择一次检索策略，界面同步维护底层两个配置对象；
- 本地模型、远程 embeddings、召回参数和索引维护放在同一设置卡片内；
- 本地模型管理与远程连接配置仍是独立组件，避免把安装逻辑和连接逻辑耦合；
- 没有 embeddings 时始终安全回退到关键词与 BM25，不阻塞聊天；
- “用户人设注入”与检索无关，位于身份页面。

## 2. 信息架构

“模型”页面调整为：

```text
语义检索
├─ 检索策略：自动 / 本地模型 / 远程 embeddings / 仅词法
├─ 当前生效状态与降级说明
├─ 语义召回参数
├─ 远程 embeddings（自动或远程策略时显示）
└─ 本地模型与索引管理

身份页面
└─ 用户人设注入开关、位置与字段
```

“语义检索”只有一个外层 `SectionCard`。内部使用轻量分区标题，不再嵌套第二层设置卡片。

## 3. 单一交互状态的映射

| 用户选择 | `localModels.retrievalMode` | `semanticTrigger.enabled` | 生效 provider |
|---|---|---:|---|
| 自动 | `auto` | 有可用来源时为 `true` | 当前可用本地模型优先，其次已配置的远程档案；均不可用则词法降级 |
| 本地模型 | `local` | `true` | `local`；没有已启用模型时拒绝切换并给出就地提示 |
| 远程 embeddings | `remote` | `true` | 连接档案对应的 `openai` 或 `ollama`；没有档案时拒绝切换 |
| 仅词法 | `lexical` | `false` | 无；关键词、正则与 BM25 保持可用 |

策略切换必须在一次 `updateSettings` 中同时写入两个配置对象，避免防抖持久化期间出现中间态。

安装模型不等于启用模型。用户点击“测试并设为默认”后，语义 provider 切换到该本地模型；若当前策略为“自动”则保留自动，否则切为“本地模型”。卸载当前默认模型后关闭失效的语义 provider；显式“本地模型”策略回到“自动”，使界面准确展示降级状态。

## 4. 组件边界

- `SemanticRetrievalSection`：唯一的用户入口，负责策略映射、状态摘要和组合子组件。
- `SemanticSection`：只负责远程连接、相似度阈值、最大召回数与连接测试，不再拥有总开关或外层卡片。
- `LocalModelsSection`：负责目录、下载安装、激活、卸载、更新、任务和索引；支持嵌入统一卡片，不再重复展示检索策略。
- `PersonaInjectionSection`：从旧语义组件中拆出，保持人设设置职责单一。

## 5. 失败与降级交互

- 本地策略无默认模型：保持原策略不变，在策略选择器下提示“请先安装并启用一个本地模型”。
- 远程策略无连接档案：保持原策略不变，引导到“模型 → 对话 API”创建档案。
- 自动策略无任何 embeddings 来源：允许保存为自动，但明确显示“当前使用词法降级”。
- 安装、校验、自检或索引失败：继续由模型卡片展示可重试任务；聊天不等待任务。
- 仅词法：隐藏无效的远程测试和语义参数，保留模型管理，便于用户预先安装后再切换。

## 6. 验收条件

1. 通用设置页不存在独立“本地模型”和“语义”入口；“模型”页面出现一个“语义检索”页签。
2. 页面只有一个“语义检索”外层设置卡片，本地模型管理位于其中。
3. 四种策略均按表格同步底层配置；无前置条件时不产生半切换状态。
4. 本地模型安装、续传、激活、卸载、回滚和索引操作保持原功能。
5. 用户人设设置可独立使用，不受检索策略影响。
6. 组件测试覆盖本地、远程、词法和自动降级；“模型”页面测试覆盖统一导航。
7. 类型检查、Lint、测试与生产构建全部通过。
