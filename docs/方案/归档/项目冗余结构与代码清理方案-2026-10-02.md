## 1. 清理范围与完成标准

主要范围为 `src/`、`electron/`、`shared/`、`scripts/`、`tools/`、构建与测试配置，以及仓库根目录的非源码产物。`spatial-board/`、`server/app/`、`relay-server/` 分别按各自入口核对；Android 在涉及共享契约时联验，客户端内部清理由独立批次承接。

本方案将条目分为四种处置：

| 处置 | 条件 | 示例 |
|---|---|---|
| 删除 | 已证实无入口、无动态消费者、无兼容职责，或可完整重建的生成物 | 失去消费者的辅助函数、构建缓存 |
| 合并 | 多处实现承担相同语义，可用同一权威实现替换 | 纯转换规则、重复的 Electron 联验启动逻辑 |
| 迁移／归档 | 仍有使用或证据价值，但当前位置不合适 | 可复用诊断工具、一次性验证材料 |
| 保留 | 仍服务运行时、外部契约、迁移、回退或回归验证 | 旧数据读取迁移、跨端 fixtures、备份事务与收据 |

完成以可核实结果为准：每个处置项有用途与调用证据、最终状态、验证结果和回退方式；被收敛的旧路径不再新增消费者；开发、测试、构建及必要运行流程可执行。删除数量、代码行数和目录数量仅用于统计，不设置强制删除比例。

## 3. 冗余认定方法

阶段 0 产出条目清单，例如 `output/project-cleanup/inventory.json` 与 `docs/报告/项目冗余清理阶段0盘点报告-日期.md`。每条至少记录：路径／符号、所属仓库、入口与消费者、动态引用、业务／兼容职责、报告引用、处置、风险、验证和回退依据。

认定死代码须覆盖以下引用类型：

1. 静态 import／export、路径别名、类型引用和动态 import。
2. IPC 注册、preload API、Bridge HTTP／WS 路由，以及 Android／外部客户端调用。
3. worker、Vite 多入口、插件、运行时拼接路径、`public` 资源和打包清单。
4. `package.json`、CI、启动脚本、人工操作文档、评测和真实模型联验入口。
5. 测试、golden、迁移、备份导入和异常回退职责。

静态扫描或文本零命中只能生成候选。实现可利用项目现有 TypeScript 工具链构建引用清单，再人工核对字符串协议和外部入口。工具不根据扫描结果自动删文件。

测试中的唯一引用需要判断意义：纯镜像废弃实现的测试可以随实现删除；兼容、安全、取消、恢复和跨端行为测试仍可能是必要消费者。先调整测试绑定的入口，再处理旧模块。

## 4. 分阶段实施

| 阶段 | 工作 | 交付与完成条件 |
|---|---|---|
| 0：盘点与基线 | 建立源码／产物／工具／证据清单；记录调用入口、工作区差异和各项目检查基线 | 每个候选有证据，确认受保护目录；记录既有检查失败，不将其计为清理新增问题 |
| 1：退出兼容转发 | 按上下文、记忆、世界书／宏、文本转换等分组迁移 19 个候选的消费者，包括类型与动态引用 | 可退出文件已无消费者；业务与 golden 回归通过；实现仍只有一份权威来源 |
| 2：整理脚本与目录 | 给工具登记用途、入口、输出、环境及敏感配置；抽公共联验启动设施；修正清理脚本；分批处理产物 | 有用工具能找到并运行；默认清理范围明确；保留证据链接有效 |
| 3：清理死代码与依赖 | 按引用清单处理未使用符号、旧内部接口、重复资源和依赖 | 删除理由逐项可核对；构建、动态加载、外部契约与对应行为验证通过 |
| 4：收敛重复逻辑与职责 | 只对已证实同语义的重复实现抽共享函数；必要时局部拆分大模块 | 行为保持；调用方向清晰；没有扩大公共类型或增加跨端业务分支 |
| 5：兼容及门禁收口 | 明确旧读写路径的保留条件；增加引用／边界门禁；更新文档、归档清单和最终统计 | 旧路径退出有最低版本和迁移依据；清理规则可复用；综合验证与阶段报告齐全 |

推荐实际起点是阶段 0，然后实施阶段 1 的纯转发退出。阶段 2、3、4 各自分批，不把目录搬迁、依赖升级和业务行为调整混在同一批中。

### 阶段 1 的迁移顺序

每组先把消费者指向现有 `shared` 权威入口；保留原来的导出名称、类型语义和调用时机。确认渲染端特定适配仍留在 `src`，不要把依赖 `window.api`、React 或 store 的实现下沉为共享纯函数。

同步迁移该组测试 import；跨端 golden 内容保持原值。通过搜索及类型检查确认旧路径没有静态、动态和配置消费者后，再删除转发文件。已有 `electron` 禁止反向 import `src` 的 lint 门禁继续保留。

### 阶段 2 的目录约定

建议按职责整理 `scripts/`：保留根 `scripts/version.mjs` 等固定入口，新增公共设施 `scripts/lib/`；可复用诊断归入 `scripts/diagnostics/`，长期评测归入 `scripts/evaluation/`，实时集成验收归入 `scripts/verification/`。仅在确有归类收益时搬迁，同步修复工作目录、`import.meta.url` 路径、CI、启动器和报告引用。

`tools/` 只保留确有外部集成或开发工具职责的项目；探索用中间文件和提取副本先核对是否可重建。`.qa/` 等目录属于本地草稿，不转为生产入口。仍支撑报告的结果可按必要范围保存为 `output` 验证包，不将整份测试 userData 长期复制保留。

`scripts/clean.ps1` 的改造要求：

- 默认仅预览明确白名单，不以“被 Git 忽略”作为可删依据。
- 每个目标先计算并验证绝对路径；拒绝仓库根、业务数据、凭据、模型和工作区外路径。
- 核对 junction／symlink 的最终目标，不跟随链接递归清理保护目录。
- 显式区分 build、cache、deps 和过期验证产物，依赖清理可单独选择；必要证据先归档。
- Windows 文件操作全程使用 PowerShell 原生命令及 `-LiteralPath`，不用拼接跨 shell 删除命令。

### 阶段 3、4 的认定边界

依赖要分别核对 PC 构建、Electron 运行、工具脚本、独立画板、公告服务与 Relay。根 pnpm workspace 目前仅列 Relay；独立画板使用独立锁文件且 React 主版本与 PC 不同，不能为“统一结构”直接合并包管理或强行共用版本。

同名 IPC、HTTP 路由和数据接口不等于重复实现。删除接口需先核对 preload 类型、Bridge、同步契约、Android 及外部消费。主进程是业务提交权威，渲染端保留交互适配，共享层承担纯规则；沿用现有分层，不新增万能服务。

大模块拆分必须说明具体职责和验证收益。例如将 IPC 参数校验与处理注册、独立纯解析、联验公共设施分开；状态机、锁、事务、提交顺序、取消和恢复围栏不能在拆分时被改变。

旧格式读取与迁移有长期数据职责。清除兼容写路径通常可以先做；删除旧读取链需要明确最低支持版本、旧备份支持范围和已完成的迁移验证，未满足时在清单中注明保留依据。

## 5. 验证与回退

### 5.1 批次门禁

| 改动类型 | 必要验证 |
|---|---|
| 纯源码转发／路径迁移 | `pnpm check`；涉及文件 ESLint；对应单元、上下文与跨端 golden；影响构建时执行 PC／Electron 构建 |
| 工具／入口搬迁 | CI 和文档入口核对；正确工作目录下启动；必要 smoke；输出与链接核对，真实模型入口默认只做预检 |
| 清理脚本 | 使用隔离目录验证白名单、路径边界、链接和默认预览；真实项目只执行预览核对 |
| IPC／保存／功能任务 | owner、来源变更、独立取消、旧回调、新旧会话、恢复与备份测试 |
| 共享契约 | `node scripts/check-contracts.mjs`、PC/shared golden；契约影响 Android 时补 Android 相关测试 |
| 独立画板 | 在 `spatial-board/` 执行其 `npm test`、`npm run build`；影响嵌入链路时补浏览器回归 |
| 公告服务／Relay | 在各自包执行测试；Relay 另执行类型检查与相关迁移／租户隔离门禁 |

结束 PC／共享源码清理后，执行一次综合 `pnpm check`、`pnpm test`、`pnpm lint`、`pnpm build` 与 `node electron-build.mjs`。按实际影响补对应独立包检查；仅修改文档不要求重新执行整套业务测试。

开始阶段 0 时重新建立全量基线。最近会话隔离的 1275 项定向回归及 16 次真实模型联验可作为相关能力证据，但不代表清理后的全仓验证。原有 lint／测试失败应单独登记并明确处置，不能通过排除相关文件、放宽断言或重写 golden 将失败隐藏。

### 5.2 回退与工作区保护

当前工作区包含大量未提交改动及未跟踪的新源码，`shared` 与 `android` 是独立 Git 子模块。实施前分别记录主仓库和子模块状态，建立可恢复的变更基线，覆盖已跟踪文件、必要未跟踪文件和需保留的本地资产。

每批仅操作清单中的文件；不使用全仓 `git clean -fdX/-fdx`、强制重置或删除全部未跟踪文件。产物删除必须先验证可重建，历史证据先确认替代位置。出问题时回退该批次的路径／实现与配置，保持已有业务数据和其他开发内容。

源码删除不得依赖仅存在本机的备份完成恢复；回退依据应能通过阶段变更集或受控归档定位。归档脚本和报告同步记录原路径、新路径、消费者更新及验证结果。

## 6. 长期门禁与交付

尽量复用现有类型检查、lint、契约检查、画板边界与 CI。新增小范围检查：已删除转发路径禁止新引用；协议／入口登记更新；脚本输出只落指定产物目录；清理名单排除受保护路径。逐步扩大门禁，不一次打开所有 TypeScript 严格开关制造大量无关修改。
