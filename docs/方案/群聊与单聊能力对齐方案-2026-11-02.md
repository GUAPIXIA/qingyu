## 2. 设计差异（不做强行对齐）

- 群聊特有：轮询/接力/立即接话、成员与发言规则管理、空间画板、旁白身份、系统开场旁白、群聊共同场景——单聊没有，属于产品设计差异。
- 引用回复：单聊与群聊目前都只做展示，**未把引用内容注入模型上下文**，两端一致。
- 群聊会话 `messageCount` 由主进程按 jsonl 行数计算，非缺陷。

## 3. 排期建议

**第一批（已完成）**：自动标题、备选开场白。

**第二批（低成本/可复用）**：消息复制、快捷键、清空后自动开场白、变量兜底抽 shared 并补单聊、截断消息继续生成。

**第三批（中等成本）**：消息 TTS、快捷回复、输入框续写/润色、命令/群聊生图（需先定群聊生图产品口径）。

**第四批（高成本，建议单独立项）**：回复候选 Swipe、消息分支。

## 4. 验收口径（后续批次沿用）

- 每个能力以「与单聊同口径」为验收前提，差异需在报告登记；
- 定向单测 + 组件/页面测试覆盖，`pnpm check` / `pnpm lint` / `pnpm test` 全绿；
- 涉及数据模型（`GroupMessage`/`GroupSession`/IPC 契约）的批次需单独评审持久化、导出、备份与恢复语义。
