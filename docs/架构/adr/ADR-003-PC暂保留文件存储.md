# ADR-003: PC 暂保留文件存储，经 Repository 与 journal 收口；SQLite 另立决策

- 状态：已接受
- 日期：2026-09-16
- 决策阶段：阶段 0（关联总方案决策门 3）

## 背景

PC 用户数据大量落在文件系统；写路径分散于 IPC、Bridge、服务层。要生成全域变更日志必须先收口写入口。同期把 PC 迁到 SQLite 会放大回归面，并与阶段 2“写路径收口”冲突。

## 选择

- 阶段 2 起：所有用户数据写入必须经 Repository 接口，并在事务内写 change journal。
- 物理存储保持现有文件布局（及必要元数据旁路），不强制本阶段迁 SQLite。
- SQLite/统一 DB 作为未来独立 ADR，不得在阶段 2 静默启动。

## 否决方案

1. **阶段 2 同步迁 SQLite**：否决。与 journal 收口耦合过大，失败难归因。
2. **继续允许绕过 Repository 直写文件**：否决。无法得到可靠 journal，同步与备份语义崩坏。

## 后果

- 需要静态/运行时绕过检测（总方案风险登记 P0）。
- 跨文件+SQLite 半提交风险需 staging/checkpoint/恢复（另见工程约束）。

## 重新评估条件

- Journal 收口完成且故障注入稳定后，若文件布局与索引性能成为瓶颈，另开 ADR 评估迁移。
