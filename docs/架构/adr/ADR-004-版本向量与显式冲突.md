# ADR-004: 版本向量 + tombstone + 显式冲突；拒绝 LWW

- 状态：已接受
- 日期：2026-09-16
- 决策阶段：阶段 0

## 背景

目标同步为用户触发的双向合并，而非最后写入胜出。`updatedAt` 单字段无法表达因果，多端离线编辑同一实体时 LWW 会静默丢数据。

## 选择

- 实体信封使用版本向量（per-device counter，JSON 为无前导零 UInt64 十进制字符串）。
- 删除写 tombstone；默认保留 180 天且需设备确认后才可压缩。
- 同 ID 并发：创建显式冲突，不静默覆盖；规范业务哈希相同的伪冲突由发起端收敛 head。
- 冲突解决本身是新变更，版本向量支配双方。

## 否决方案

1. **LWW（`updatedAt` 最大者胜）**：否决。违反总方案非目标，且无法解释用户可审计冲突。
2. **仅 CRDT 自动合并一切**：否决。消息编辑、删除与修改并发等场景需要用户可见冲突中心。

## 后果

- 存储与同步协议必须原生支持向量与 tombstone，不能事后补。
- 客户端冲突中心成为 P0 同步体验的一部分。

## 重新评估条件

- 无。除非产品正式放弃双向独立编辑；与本重构目标冲突。
