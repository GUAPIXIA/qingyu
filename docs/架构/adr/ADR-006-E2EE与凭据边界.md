# ADR-006: 服务器长期数据必须 E2EE；凭据默认不同步

- 状态：已接受
- 日期：2026-09-16
- 决策阶段：阶段 0

## 背景

现 Relay 设计假设“PC 为权威、服务器仅缓存”，可读正文。升级为长期多端存储后，服务端可见明文不可接受。API Key、设备令牌、空间密钥等若混入普通同步实体，泄露面扩大。

## 选择

- 每空间 256 位 `spaceKey`，仅存于授权客户端安全存储；payload AES-256-GCM；blob 分块加密。
- 服务端只处理密文、哈希、版本向量、keyed content tag 与路由元数据。
- API Key、连接档案密钥、设备令牌、spaceKey、MCP 敏感环境变量默认不同步。
- 若未来做加密凭据同步，必须单独产品决策与威胁模型。

## 否决方案

1. **TLS-only、服务端存明文**：否决。数据库/日志泄露即全文泄漏。
2. **默认同步连接档案与密钥**：否决。扩大跨端窃取与误备份面。

## 后果

- 服务端实现不得引入明文列或正文日志。
- 客户端需 Keystore/系统密钥库封装（Android 细节见 ADR-010）。

## 重新评估条件

- 威胁模型正式改为“信任服务器运营方”且有合规要求驱动时；仍须单独 ADR。
