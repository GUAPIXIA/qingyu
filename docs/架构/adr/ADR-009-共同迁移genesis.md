# ADR-009: 旧 PC/Android 迁移使用共同 genesis；同内容投影合并，未完成 Outbox 单独对账

- 状态：已接受
- 日期：2026-09-16
- 决策阶段：阶段 0

## 背景

旧 Android Room 仅是最近会话缓存，不是完整用户数据源。若两端各自 bootstrap 成“权威全量”，首次同步会出现大量同内容伪冲突。旧 Android 还可能有未完成发件箱。

## 选择

- PC 与 Android 从同一旧 PC 数据集迁移时共享 `migrationGenesisId` 与规范内容哈希。
- Android 缓存中的同内容投影不赋予独立并发祖先；应映射到共同 genesis 节点。
- 缺失内容列入迁移报告；在旧网络凭据吊销前通过首次同步补齐或由用户明确放弃。
- 未完成 Outbox 单独对账清单，不与业务实体 merge 规则混用。
- 旧缓存先只读快照隔离，再由用户显式导入；禁止自动把不完整缓存当权威。

## 否决方案

1. **两端各自独立导入并按版本向量对撞**：否决。产生全量伪冲突（风险登记 P0）。
2. **直接把 Android 缓存当完整用户库**：否决。缺角色/世界书等会假装“已迁移完整”。

## 后果

- 迁移工具必须输出 genesis、缺失报告与 Outbox 对账结果。
- 首次 receipt 之前不得吊销旧凭据（与总方案一致）。

## 重新评估条件

- 确认不存在共享旧数据集、或产品改为“从零重来”迁移策略时。
