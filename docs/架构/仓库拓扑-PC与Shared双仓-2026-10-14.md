> 日期：2026-10-14（承接 `2026-09-26` 三仓拆分文档；同日按 `android-compat` 冻结结论移除安卓端兼容）
> 状态：**main 不再挂载 android**；PC 仓 + [`qingyu-shared`](https://github.com/GUAPIXIA/qingyu-shared) 子模块为唯一拓扑。

---

## 1. 目标布局

```text
D:\Code\qingyu\              # PC 仓（Electron + React + server + docs）
├── .gitmodules              # 仅 shared 一条
└── shared/                  # 子模块 → qingyu-shared（唯一挂载点）

D:\Code\qingyu-shared\       # 契约 / chat-core / golden fixtures（独立仓）
```

| 仓库 | 内容 | 本地路径 | 拆分方式 |
|---|---|---|---|
| **PC** | `src/` `electron/` `server/` `docs/` `scripts/` `spatial-board/` | `D:\Code\qingyu` | 原 monorepo 去掉 shared 内联 |
| **Shared** | `shared/`：contracts、chat-core、sync-core/crypto、fixtures | `D:\Code\qingyu-shared` | `git subtree split --prefix=shared` |

**android 子模块已不在 main 上**：`.gitmodules` 不再声明 `GUAPIXIA/qingyu-android`，`android/` 与第二挂载点 `android/shared/` 一并移除，CI 的 android 作业与 `version.mjs android`／`--sync-android` 版本线同步退场。「移除安卓端兼容」前的完整现状冻结在 `android-compat` 分支；安卓侧改为在其独立仓 `GUAPIXIA/qingyu-android` 自行维护与发布，PC 仓既不消费其代码，也不再为其门禁、版本一致性或 APK 产物负责。

---

## 2. 为何 shared 独立成仓

- 跨语言 golden fixture 是 TS（oracle）↔ 各端实现的一致性锁，契约源必须单一。
- 契约变更（schema / envelope / chat-core / sync-core）与 PC 消费方解耦，独立仓 + 子模块钉版本可避免漂移。
- PC 仓只通过 `shared/` 子模块指针引用契约，改契约与改 PC 代码可以分别评审、分别回滚。

## 3. 日常用法

### 3.1 克隆

```powershell
git clone https://github.com/GUAPIXIA/qingyu.git
cd qingyu
git submodule update --init --recursive

# 本地开发期（子仓尚未推送到远程时）：
git config protocol.file.allow always
git submodule set-url shared D:/Code/qingyu-shared
git submodule update --init --recursive
```

`.gitmodules` 中的 shared URL 为相对路径（`../qingyu-shared`），要求两个仓库同级部署；CI 在 checkout 步骤声明 `submodules: recursive` 并校验缺失。

### 3.2 改契约 / fixture

```powershell
cd D:\Code\qingyu-shared
# 改 shared/contracts、shared/chat-core 或 fixtures ...
# 生成 / 校验 fixture（TS oracle）：
cd D:\Code\qingyu
$env:CHAT_CORE_UPDATE_FIXTURES="1"
pnpm exec vitest run shared/__tests__/chatCoreGolden.test.ts   # 重新生成
pnpm exec vitest run shared/__tests__/chatCoreGolden.test.ts   # 只读复核，连跑 2–3 次确认稳定
# 提交 shared 仓并推送，再在 PC 仓 bump shared 子模块指针
```

> 推送顺序：先在 `shared/` 提交并推送到 `qingyu-shared`，再在 PC 仓提交 gitlink 指针；只更新指针而未推送 shared 源码提交视为未完成。

### 3.3 PC 跑门禁

```powershell
cd D:\Code\qingyu
pnpm check        # tsc 双配置类型检查
pnpm lint         # ESLint 0 error
pnpm test         # vitest 全量
pnpm check:gates  # 结构与依赖边界门禁
node scripts/check-contracts.mjs   # 契约漂移门禁
```

## 4. 注意事项

1. **`protocol.file.allow`**：本地 file:// 子模块 clone 需 `git -c protocol.file.allow=always` 或仓库级 `git config protocol.file.allow always`（Git 出于安全默认拒绝）。
2. **备份目录**：`shared-inline-backup/` 为拆分时的工作区备份，确认无误后可删。
3. **子模块内部文件不在主仓暂存**：不得在主仓直接 `git add shared/...`，只提交 gitlink 指针。
4. **文档失效链接**：搬迁/删除文档时必须同步重算指向它的相对链接（见 [文档索引](../README.md) 的归档规则）。
5. 推送到 GitHub 前需用户创建 `qingyu-shared` 仓库；本工具不执行 push。

## 5. 回滚

若需回到内联 monorepo：

```powershell
# 1. 去掉子模块
git rm --cached shared
rm .gitmodules
# 2. 从备份或 subtree 分支恢复目录
# 3. 或直接使用拆分前 monorepo 历史（main 仍含完整内联历史至拆分提交之前）
```

「移除安卓端兼容」的完整回滚路径：`git switch android-compat`（移除前现状），或取本仓 `android-compat` 分支上被删除的文件；安卓侧代码在 `GUAPIXIA/qingyu-android` 独立仓内不受本次移除影响。
