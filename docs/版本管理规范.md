# 版本管理规范

> 适用项目：轻语 PC 端（`酒馆`）+ Android 伴侣端 + 公告服务
> 基准：`0.11.28` 已发布，`0.12.0` 开发中
> 规范版本：1.0（2026-08-19）

## 1. 版本号规则（SemVer 变体）

```
主版本.次版本.修订号[-预发布.序号]
0.11.28
0.12.0-alpha.1
0.12.0-beta.1
0.12.0-rc.1
0.12.0
```

| 段 | 含义 | 递增时机 |
| --- | --- | --- |
| 主版本 | 重大架构/不兼容 | 1.0.0 之前保持 0 |
| 次版本 | 架构升级/批量功能 | `0.11 -> 0.12` 如统一 ChatOrchestrator |
| 修订号 | 热修/安全修复 | `0.11.27 -> 0.11.28` |
| 预发布 | 开发阶段 | `alpha` 内部联调 `beta` 公测 `rc` 候选 |

Android 伴侣端独立版本 `0.1.x`，但在 CHANGELOG 中与 PC 同步发布说明，`libs.versions.toml` 为唯一权威。

## 2. 分支模型

```
main                永远可发布，保护分支，PR 才能合入
feat/*              功能分支，从 main 拉出
release/v0.11.28    热修分支（已合入即删）
release/v0.12.0     预发布分支（alpha/beta/rc 在此）
```

* `main` 的 `package.json#version` 始终指向**下一个开发版本**（如 `0.12.0-alpha.1`），Tag 才指向正式版。
* 热修直接从最新 Tag 拉 `release/vX.Y.Z`，合回 `main` 并打 Tag。

## 3. 发布流程（Checklist）

### 3.1 发布前门禁（必须全绿）

```bash
pnpm check      # tsc 双配置
pnpm lint       # 0 Error
pnpm test       # 1059 项通过（如有新增需同步更新基数）
pnpm test:coverage  # 按 docs/PC端0.12版本实施方案.md 第19章阈值
```

### 3.2 标准发布命令

```bash
# 1. 更新版本号（package.json + android/libs.versions.toml 如涉及安卓）
pnpm run version:patch  # 或 minor / premajor 等，见 §4

# 2. 更新 CHANGELOG.md（按 Keep a Changelog 格式，手写亮点）

# 3. 提交
git add package.json CHANGELOG.md pnpm-lock.yaml
git commit -m "release: v0.12.0-alpha.1 — <一句话摘要>"

# 4. 打 Tag（带签名信息）
git tag -a v0.12.0-alpha.1 -m "v0.12.0-alpha.1"

# 5. 推送（触发 CI 构建）
git push origin main --follow-tags

# 6. GitHub Release（从 Tag 创建，附 release-v2/*.exe SHA256 + SBOM）
```

### 3.3 回滚

* 未发布到用户前：`git revert <release-commit>` + 重新发修订版。
* 已分发安装包：关闭 `chatEngineV2` 等 Feature Flag，保留任务文件，见实施方案 §18。

## 4. 版本脚本

`scripts/version.mjs` 提供：

```bash
node scripts/version.mjs patch        # 0.11.28 -> 0.11.29
node scripts/version.mjs minor        # 0.11.28 -> 0.12.0
node scripts/version.mjs prerelease --pre alpha  # 0.12.0-alpha.1 -> alpha.2
node scripts/version.mjs release      # 0.12.0-rc.1 -> 0.12.0
node scripts/version.mjs set 0.12.0-beta.1
node scripts/version.mjs status       # 打印当前版本与 Tag 差异
```

脚本自动同步：
* `酒馆/package.json#version`
* `android/libs.versions.toml`（如 `appVersionName` 需跟随，仅在 `--sync-android` 时）

## 5. CHANGELOG 规范

* 文件：根 `CHANGELOG.md`
* 格式：`## [x.y.z] - YYYY-MM-DD` + `### 新增/修复/安全/变更`
* 每次发版必须有条目，未发布内容放在 `## [Unreleased]` 下（可选）。
* 0.11.28 起，安全修复需单列 `### Bridge 安全热修 / MCP 与工程门禁`。

## 6. CI 关联

`.github/workflows/ci.yml`：

* PR：`check + lint + test + coverage gate + dependency audit`
* Tag 推送：`build-windows + 签名 + 冒烟测试 + SBOM + Release 归档`

覆盖率门禁按 `vitest.config.ts#thresholds` 拆分（Bridge/MCP/Orchestrator 85-95%）。
