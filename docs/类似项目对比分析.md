> 调研日期：2026-08-14
> 调研范围：受 SillyTavern 启发 / 本地优先 / AI 角色扮演对话客户端生态
> 调研目的：定位轻语的竞品格局，识别差异化优势与可借鉴功能
> 共扒取 **11 个**项目，覆盖四个细分赛道

## 一、调研背景

**轻语 QingYu** 是一个基于 SillyTavern 理念的轻量级 AI 角色扮演桌面客户端。

- **技术栈**：Electron 32 + React 18 + TypeScript 5 + Vite 6 + Tailwind 3 + Zustand 5
- **定位**：Windows 桌面、中文优先、开箱即用、纯本地存储
- **配套**：Android 伴侣 App（`com.qingyu.companion`）+ Docker 公告服务端
- **核心特性**：多后端（OpenAI/Claude/Gemini/Ollama）、流式、对话分支、长记忆、翻译、心理描写、Swipe、群聊（@/轮询/自由三种模式）、角色卡 V1/V2/V3 兼容、批量导入、AI 翻译角色卡、图像生成（SD WebUI/DALL-E）、世界书（关键词+语义 RAG）、预设系统、正则替换、TTS（Windows+Edge）、MCP 工具集成、斜杠命令、Token 统计、Persona、6 主题、深浅色模式、API Key 加密、一键备份

本次调研扒取的 11 个项目按赛道分为四类：独立轻量实现、本地优先桌面 Agent、自托管多设备服务端、移动端。

## 三、标杆项目：SillyTavern

> 25,000+ GitHub stars / 300+ contributors / 最新稳定版 1.18.0（2026-05-03 发布）/ 轻语明确标榜"基于其理念"

> **2026-08-15 联网核实**：实际约 **31,000+ stars**（持续增长中），1.18.0 为当前最新稳定版 ✅

### 3.1 基本信息

- **起源**：2023 年 2 月从 TavernAI 1.2.8 fork
- **运行环境**：Node.js ≥ 20
- **协议**：AGPL-3.0（对衍生作品有传染性要求）
- **官方文档**：https://docs.sillytavern.app/

### 3.2 技术栈（从 package.json 还原）

| 维度 | 实现 |
|------|------|
| 后端 | Express 4 + body-parser + multer + compression + helmet + cors + CSRF |
| 前端 | jQuery + Popper + Select2 + Toastr + highlight.js + morphdom + slidetoggle |
| Markdown | Showdown |
| 模板 | Handlebars |
| 向量 | vectra（本地向量库）+ sillytavern-transformers（本地 transformers）|
| Token | tiktoken + @agnai/sentencepiece-js + @agnai/web-tokenizers |
| 翻译 | bing-translate-api + google-translate-api-x |
| 图像 | Jimp（多格式：bmp/gif/tiff/avif/jpeg/png/webp）|
| 角色卡 | png-chunk-text + png-chunks-extract（PNG 元数据读写）|
| Horde | @zeldafan0225/ai_horde（分布式推理网络）|
| Git 集成 | isomorphic-git + simple-git（扩展分发）|
| 存储 | node-persist + localforage |
| 多运行时 | 支持 Node / Deno / Bun / Electron 四种启动方式 |
| 安全 | host-validation-middleware + ip-matching + rate-limiter-flexible + proxy-agent |

### 3.3 核心能力

- 角色卡（Character Card V1/V2/V3）+ 群聊 + Persona + 世界书（World Info）
- 扩展系统（第三方插件生态，最大护城河）
- 表情精灵图（Sprites）+ 自动摘要 + TTS + STT + 数据银行（RAG）
- 斜杠命令子系统 + ST 脚本引擎
- 高级采样参数 + 社区预设
- 几乎兼容所有后端：OpenAI/Claude/Gemini/KoboldAI/Tabby/Ollama/OpenRouter/AI Horde/本地模型

### 3.4 对轻语的意义

轻语在 README 中明确"基于 SillyTavern 理念"，角色卡 V1/V2/V3 兼容、世界书、预设、正则、群聊、斜杠命令等概念均沿用。**SillyTavern 是轻语的功能上限参照系**，但轻语主动放弃了扩展生态和 Web 部署形态，换取原生桌面体验和中文优先。

## 四、独立轻量实现赛道

### 4.1 Midsummer's Bird（仲夏之鸟）

> 仓库：https://github.com/csjafuwvbegscbw-star/Midsummer-s-Bird
> 协议：MIT / 单 HTML 文件 / ~500KB

**核心理念**：与轻语一字不差--"受 SillyTavern 启发的第三方独立实现"，主打**单文件、轻量化、易用性**。

**功能完整度**：
- API 集成（OpenAI/DeepSeek/SiliconFlow/Gemini/Claude 中转/任意 OpenAI 兼容）
- 独立视觉识图 API 配置
- 角色卡 V2/V3 导入导出 + 多开场白 + 示例对话
- 世界书（全局 + 角色专属、关键词匹配、深度/优先级、递归排除）
- 高级预设（采样参数、可视化提示词构建、Token 预估）
- 全局/局部正则脚本
- 6 主题（默认/暗黑/海洋/森林/紫罗兰/樱花）+ 自定义 CSS 编辑器
- 多用户管理
- 聊天总结（自动加入世界书）
- 中英双语 UI

**明确不支持**：扩展系统、TTS/STT、SD 图像生成、**群聊**、背景音乐、向量数据库、长期记忆、Horde

**技术栈**：原生 JS + Tailwind + Font Awesome + Sortable.js + localStorage

**与轻语对比**：
- 轻语**赢**：群聊、TTS、图像生成、MCP、向量 RAG 世界书、Android 伴侣、在线公告
- 仲夏之鸟**赢**：零安装便携性（U 盘/云盘可带）、移动端浏览器即用、文件极小

**可借鉴**：单文件分发思路、6 主题命名美学、可视化提示词构建系统

## 五、本地优先桌面 + Agent 赛道

### 5.1 SweetrollLM

> 仓库：https://github.com/syfr512/SweetrollLM
> 协议：AGPL-3.0 / Python (FastAPI) + 原生 JS / 约 40 stars（新项目）
> **2026-08-15 联网核实**：存在，定位描述吻合 ✅

**核心理念**："SillyTavern 角色卡舒适感 + LM Studio 模型管理 + 现代 Agent 工作区"

**杀手锏功能**：

1. **自适应推理路由**
   - 先试 `llama-cpp-python` 原生加载
   - AVX/AVX2 不支持时自动降级到 `koboldcpp-oldpc.exe` 后台 worker
   - 用户看到的是干净诊断而非崩溃

2. **Ollama 一等公民支持**
   - 自动探测 `127.0.0.1:11434`，列出已装模型
   - 检查已加载模型、显示元数据和能力标签
   - SSE pull 进度条（拉模型不卡 UI）
   - 可作为本地运行时或云 provider 两种角色

3. **HuggingFace GGUF 市场 + 后台下载器**

4. **Agentic Workspace**（独立工作区，运行在 `./workspace`）
   - 文件夹感知工作区会话
   - **三级权限**：ask-first / read-only / full-access
   - 文件/文件夹工具 + 沙箱路径校验
   - 终端命令执行 + 后台服务管理 + 自动化脚本
   - 工作区图片附件（截图分析）

5. **聊天原生图片附件**
   - 上传 → 视觉 caption → 隐藏注入 → 气泡内联展示

6. **Per-chat Summary Memory**
   - 手动写总结 / 从最近 N 条生成 / Auto Summary 自动刷新
   - 每个时间线独立 lorebook/persona 覆盖

7. **角色聊天画廊**：自动从消息历史收集该时间线图片

8. **双层背景系统**：角色卡背景 → 角色头像 → 全局背景 → 主题默认，气泡透明度与背景透明度独立控制

**技术栈**：Python (FastAPI) + 原生 JS，`storage/` 本地 JSON 分目录存储，端口 7865

**与轻语对比**：
- 轻语**赢**：群聊、TTS、在线公告、Android 伴侣、中文优先
- SweetrollLM**赢**：**本地 GGUF 推理**（轻语完全依赖外部 API）、Agentic Workspace（轻语只有 MCP）、HF 模型市场、Ollama 深度集成、双层背景

**可借鉴**：自适应推理降级、GGUF 模型市场、Agentic Workspace 三级权限、双层背景系统、per-chat summary

### 5.2 Irori

> 仓库：https://github.com/hikariming/irori
> 协议：Apache-2.0 / Tauri + React + Rust + Node sidecar
> **2026-08-15 联网核实**：存在，Pi SDK 适配 + 安全确认门描述吻合 ✅

**核心理念**：基于 [Pi coding-agent SDK](https://www.npmjs.com/package/@earendil-works/pi-coding-agent) 的本地优先二次元 AI 伴侣，**角色真的能帮你干活**（写作/写码/规划/跟进）。

**杀手锏功能**：
- Agent 会话包装成角色陪伴：每个角色有角色卡、人设、工作风格、记忆上下文、模型设置
- **工具调用 + 安全门**：确认策略 + 受保护路径（独立 `safety` 包）
- 本地记忆与上下文（本地优先）
- 模型供应商预设 + OpenAI 兼容 Base URL
- 桌面优先体验：Tauri 外壳 + 本地 sidecar runtime + 安全确认门

**路线图**：多渠道接入（Discord）、陪伴手机 App、语音 + Live2D

**项目结构**（monorepo）：
```
apps/desktop/          Tauri + React 桌面端
  src/                 React 前端
  src-tauri/           Rust 后端
  sidecar/             Pi SDK runtime Node sidecar
characters/            内置角色卡包
packages/
  character-card/      角色卡 schema 与提示词组合
  companion-core/      共享类型
  memory/              本地优先记忆接口
  pi-runtime/          Pi SDK 适配层
  safety/              工具模式、确认策略、受保护路径
  ui/                  共享 UI 组件
```

**官方对比表**（Irori vs SillyTavern vs Open-LLM-VTuber vs OpenClaw）：

| | Irori | SillyTavern | Open-LLM-VTuber | OpenClaw |
|---|---|---|---|---|
| 核心定位 | 能干活的二次元伴侣 | 角色扮演前端 | 语音虚拟主播 | 通用 agent |
| 原生桌面 | ✅ Tauri | ⚠️ Web UI | ⚠️ Web/桌面 | ⚠️ CLI |
| 智能体协作 | ✅ 代码/复杂任务优化 | ❌ 仅聊天 | ❌ 仅聊天 | ✅ 通用 |
| 二次元陪伴 | ✅ 核心 | ✅ | ✅ | ❌ |
| 角色卡 | ✅ 可编辑 schema | ✅ | ✅ | ❌ |
| 本地记忆 | ✅ 本地优先 | ✅ Lorebook | ✅ | ✅ |
| 工具调用+安全门 | ✅ | ❌ | ❌ | ✅ |

**与轻语对比**：
- 轻语**赢**：群聊、图像生成、TTS、世界书、在线公告、Android 已落地
- Irori**赢**：**Tauri 原生桌面**（比 Electron 轻得多）、agent 真干活、safety 安全门设计、monorepo 工程化

**可借鉴**：Tauri 替代 Electron 的可行性评估、safety 包独立模块化、agent 工作流（拆解需求/跟进进度/整理结论）、角色卡 schema 与提示词组合分离

### 5.3 Soul-of-Waifu (SoW)

> 仓库：https://github.com/jofizcd/Soul-of-Waifu
> 协议：GPL-3.0 / Python + Web / v2.4.0 / Windows 10/11 64-bit
> **2026-08-15 联网核实**：存在，Soul Memory 四层认知架构描述吻合 ✅

**核心理念**："一个角色，多个维度"--角色不再锁在文本聊天，而是同时存在于文本语音对话、桌游 RPG、桌面陪伴多个维度，共享一个持续进化的身份。

**四大模式**：

1. **Soul Memory**（长期认知架构）
   - 不是简单的向量 RAG，而是自治后台 agent 实时重写四个隔离认知文件：
     - **Psychology Layer**：心情、内心张力、隐藏动机、角色发展
     - **Relationship Profile**：用户习惯、偏好、共同承诺、信任进度
     - **Episodic Topic Archive**：本地 `all-MiniLM-L6-v2` 嵌入分类知识库
     - **Personal Diary**：角色第一人称反思日记
   - **情感衰减**：负面情绪会随时间自然冷却
   - **记忆自愈**：检测新旧事实矛盾，自动覆写并记录修正
   - 四种认知档位（Full Sync / Soul Link / Mind Spark / Reflection Flow）适配不同 VRAM

2. **Text & Voice Chat**
   - 全双工对话 + Live2D（动作联动）+ VRM 3D 模型 + 语音通话
   - 6 TTS 引擎：Qwen3 TTS（本地，3 秒克隆）/ XTTSv2 / Kokoro 82M / Silero / EdgeTTS / ElevenLabs
   - RVC 语音转换
   - 28 状态情感分类 + LipSync
   - Silero VAD + Faster Whisper 全双工通话（可打断）

3. **Soul Stage**（桌游 RPG 引擎）
   - 独立 AI Game Master 维护世界状态
   - WorldState 引擎：时间/天气/地点/关键事实
   - 物品栏 + 状态 HUD（中毒/疲劳/激励）
   - 氛围自动化：场景背景 + 环境音频随地点切换
   - 选项栏 + 随机事件卡

4. **Soul Companion**（桌面陪伴 + MCP 助手）
   - 透明桌面 overlay
   - **神经激素驱动**：心情随活动/时间/交互模式变化，长时间会累，闲置会无聊，会主动发起对话
   - 6 内置工具：屏幕读取/剪贴板读取/Web 搜索/浏览器控制/音乐控制/自定义 MCP 服务器

**扩展集成**：
- 本地 Web 客户端（手机/平板通过 `http://<pc-ip>:8000` 接入，WebSocket 双向同步）
- Discord Gateway（角色接入 Discord bot）
- AI 图像生成（A1111/ComfyUI/FLUX/NovelAI/DALL-E 3）

**高级采样**：Dynamic Temperature / DRY Sampler / XTC / Min-P（防循环）

**Lorebook 增强**：多绑定 / 语义情境匹配 / 场景张力累积器 / 链式依赖 / 主动+被动注入

**模型支持**：本地 Llama.cpp（CUDA/HIP/SYCL/Vulkan）+ 10 云 provider

**与轻语对比**：
- 轻语**赢**：中文优先 UI、在线公告、轻量（SoW 需 10GB 空间 + 16GB RAM）
- Soul-of-Waifu**赢**：**Soul Memory 认知架构**（轻语的长记忆远不及）、桌游 RPG、桌面陪伴 overlay、神经激素系统、全双工语音、Live2D/VRM、Discord 接入、本地模型加速

**可借鉴**：Soul Memory 四层认知文件架构、情感衰减机制、记忆自愈、神经激素驱动主动对话、桌游 RPG 模式、28 状态情感分类、DRY/XTC/Min-P 高级采样

## 六、自托管多设备服务端赛道

### 6.1 PocketRisu

> 仓库：https://github.com/PocketRisu/PocketRisu
> 协议：GPL-3.0 / Node.js 22+ TypeScript / RisuAI fork / 约 260 stars
> **2026-08-15 联网核实**：存在，定位描述吻合 ✅

**核心理念**：RisuAI 的自托管精炼版，**一个服务端 + 多设备浏览器访问**。

**杀手锏功能**：

1. **服务器端持续生成**：锁屏/断线不打断，重连后自动恢复完整响应（轻语没有）
2. **统一 SQLite 存储**：所有数据（角色/聊天/设置/内联图片）一个库
3. **Dashboard**：按角色/模块统计磁盘占用、可回收快照空间、SQLite 优化
4. **HypaMemoryV3** 上下文记忆
5. **Quick Tunnel + Tailscale** 移动远程访问

## 十二、结论

轻语在"中文优先 + Windows 原生桌面 + 轻量"这个组合上是**唯一选手**，差异化清晰。但要警惕：

1. **本地推理缺失**是最大短板--SweetrollLM/SoW 都已支持 GGUF，轻语完全依赖外部 API，在中文本地模型（Qwen/GLM/DeepSeek）爆发的当下是战略劣势
2. **主动陪伴缺失**--Amiweave/SoW 都已实现，轻语的"陪伴感"还停留在被动响应
3. **多设备数据分离**--桌面和 Android 是两套数据，PocketRisu 的"一服务多端"模式更现代

**短期（P0）建议**：主动开场 + 服务端持久生成 + SSRF 防护，这三项能让轻语的"桌面+Android 联动"价值真正释放。

**中期（P1-P2）建议**：Per-chat summary + 本地 GGUF 推理 + HF 模型市场，补齐本地推理短板，卡位"中文桌面本地推理"蓝海。

**长期（P3-P4）建议**：Soul Memory 认知架构 + Tauri 重构，向"真正的 AI 陪伴"演进。
