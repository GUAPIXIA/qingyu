# 轻语 PC 端 AI Agent 验证测试规范

> 适用项目：轻语（QingYu）Windows Electron 客户端  
> 项目目录：`D:\Code\qingyu`  
> 适用对象：具备终端、Windows 桌面操作、截图和日志读取能力的 AI Agent  
> 文档目标：让其他 AI Agent 在**不修改业务代码、不破坏用户数据**的前提下，完成可复核的 PC 端验证测试，并输出发布建议。

## 1. 测试目标

本轮验证需要回答以下问题：

1. 当前代码是否通过类型、Lint、单元测试和生产构建门禁。
2. Windows Electron 客户端是否能够正常启动、关闭和重新启动。
3. 本轮改动涉及的核心流程是否真实可用，而不仅是“页面能打开”。
4. 单聊、群聊、角色、世界书、模型、设置等既有能力是否出现回归。
5. 异常、取消、无网络、未配置模型等边界场景是否给出明确反馈。
6. 是否存在 P0/P1 级问题，当前版本是否达到发布条件。

最终交付物必须是一份带证据的 Markdown 测试报告。禁止只给“基本正常”“测试通过”等无证据结论。

## 2. 执行边界

### 2.1 必须遵守

- 本任务是**验证测试**，不得修改源代码、配置实现或测试用例来让检查通过。
- 不得提交、暂存、回滚、清理或覆盖现有 Git 改动。
- 测试开始和结束时都记录 `git status --short`；若状态发生变化，必须说明新增文件及原因。
- 优先使用 Electron 客户端完成 UI 验证。直接打开 Vite 网页不能覆盖 preload、IPC、文件选择器、系统语音、更新器等桌面能力，不得以网页测试代替 Electron 测试。
- 不得展示、复制或写入真实 API Key。截图和报告中的令牌、地址参数、设备标识必须脱敏。
- 未获得明确授权时，不执行安装更新、恢复备份、重置全部设置、清空数据、删除真实角色或真实会话等高影响操作。
- 涉及删除、覆盖、导入恢复的场景，只能对本轮新建且明确标注为测试的数据执行。
- 不修改防火墙，不对公网开放端口，不启动收费调用的批量或压力测试。
- 每个失败至少重试一次；重试仍失败才记录为稳定失败。疑似偶发问题记录复现次数。

### 2.2 允许的测试动作

- 读取代码、文档、构建输出和应用日志。
- 运行项目已有的检查、测试和构建命令。
- 启动开发版或候选安装包并操作 UI。
- 创建名称带 `QA-日期-用途` 前缀的临时角色、会话、身份、世界书和预设。
- 导出到 `D:\Code\qingyu\output\pc-qa\` 下的本轮证据目录。
- 在确认目标是本轮创建的测试数据后，清理这些测试数据；若无法确认则保留并在报告中列出。

## 3. 输入信息与阻塞规则

执行前记录以下信息；拿不到的信息写“未提供”，不要猜测：

| 项目 | 记录内容 |
| --- | --- |
| 测试日期 | `YYYY-MM-DD HH:mm`，Asia/Shanghai |
| 分支 | 当前分支名 |

| Windows 版本 | 系统版本与架构 |
| Node / pnpm | 实际版本 |
| 屏幕与缩放 | 分辨率、系统缩放比例 |
| 测试入口 | 开发版 / 安装版 / 两者 |
| 模型运营商 | 实际使用的运营商/供应商名称，例如 OpenAI、Anthropic、DeepSeek、智谱、SiliconFlow、本地 Ollama 等；未接入时写“无” |
| 模型名称 | 实际使用的完整模型标识，例如 `deepseek-chat`、`gpt-4o`、`qwen-max`；未接入时写“无” |
| 模型连接 | 有可用测试模型 / 无；有则必须同时填写上方运营商与模型名称 |
| 外部依赖 | ComfyUI、Ollama、公告服务器、Relay 等是否可用 |

以下情况应标记为 `BLOCKED`，而不是误判为产品失败：

- 没有可用模型连接，导致无法验证真实 AI 返回。
- 未明确指定本轮测试使用的运营商与模型，无法保证结果可复现；执行前必须先向任务发起方确认，确认前相关用例标记 `BLOCKED`。
- 未指定运营商与模型，但应用内已配置多个连接/模型：禁止自行挑选后直接开测，应先确认目标运营商与模型，并在报告中写明选择依据。
- 没有 ComfyUI 服务或测试工作流，导致无法完成真实生图。
- 没有 Android 设备，导致无法完成 PC/Android 联动。
- 公告、GitHub、Relay 等外部服务不可达，且已确认是环境或网络限制。

即使专项被阻塞，仍应继续执行不依赖该条件的检查和 UI 测试。

## 4. 证据目录与命名

每次执行创建独立目录：

```text
D:\Code\qingyu\output\pc-qa\YYYYMMDD-HHmm-<commit>\
├── report.md
├── command-results.md
├── screenshots\
├── logs\
└── exports\
```

证据命名格式：

```text
<用例ID>-<PASS|FAIL|BLOCKED>-<简短说明>.png
```

示例：

```text
UI-CHAT-04-PASS-方向卡回填输入框.png
UI-A11Y-02-FAIL-弹窗Tab焦点逃逸.png
```

证据要求：

- 命令行检查保存命令、退出码、通过/失败数量和关键错误，不要只保存最后一行。
- UI 通过项至少保存关键结果截图；失败项必须保存失败画面和相关日志。
- 截图应包含足够上下文，例如页面标题、操作对象和结果提示。
- 日志中的用户内容、密钥、访问令牌和设备信息需要脱敏。
- 报告中的文件路径使用相对证据目录路径，确保其他人可打开复核。

## 5. 执行顺序

### 阶段 A：基线与工程门禁

先记录环境和 Git 状态，再依次执行：

```powershell
pnpm --version
node --version
pnpm check
pnpm lint
pnpm test
pnpm build
```

记录表：

| ID | 检查项 | 通过标准 |
| --- | --- | --- |
| GATE-01 | TypeScript 检查 | 退出码为 0，无类型错误 |
| GATE-02 | ESLint | 退出码为 0，无 error |
| GATE-03 | Vitest | 退出码为 0；记录测试文件数、用例数和跳过数 |
| GATE-04 | Renderer 构建 | 退出码为 0；警告需单独列出 |
| GATE-05 | Electron 主进程构建 | 相关产物生成，无编译错误 |

规则：

- 任一命令失败后保存完整错误，继续执行其余门禁，不要提前结束整个测试。
- 不允许通过修改代码、关闭规则、更新快照或跳过测试来获得绿色结果。
- 构建体积告警、React `act(...)` 告警、未处理 Promise 等虽然不一定阻断，也必须进入“风险与告警”。

优先启动 Electron 开发模式：

```powershell

```

若本轮验证的是安装包，还需单独安装候选版本后重复 `BOOT-01` 至 `BOOT-06`。安装版验证不得覆盖用户指定保留的正式数据。

| BOOT-01 | 首次显示 | 启动应用并等待主窗口 | 30 秒内显示可交互主窗口，无永久白屏 |
| BOOT-02 | 页面加载 | 依次进入侧栏所有入口 | 页面有内容，无崩溃、空白页或无限加载 |

### 阶段 D：核心功能回归

#### D1. 模型与设置

- 新增连接时，连接名称、地址、模型等必填项必须真实校验。
- 连接测试成功/失败反馈与实际结果一致，不显示“假成功”。
- 设置保存状态应由真实落盘结果驱动；重启后验证持久化。
- 深色、浅色、跟随系统及主题色切换正常，文字与焦点态可辨识。
- API Key 在普通界面和日志中不应明文暴露。
- 软件更新只执行“检查”与入口展示验证，禁止下载安装。

#### D2. 角色与单聊

- 新建测试角色，填写必要信息并保存；列表、搜索、编辑均可用。
- 新建会话，发送消息，验证流式输出、停止生成、重新生成、Swipe、编辑、删除和分支。
- `Enter` 发送、`Shift+Enter` 换行、`Esc` 关闭弹窗/停止生成符合预期。
- 长记忆面板可打开、滚动、关闭；无模型时的降级反馈明确。
- 对话导出取消时不提示成功；成功导出的 Markdown 可打开且格式未被消息内容破坏。

#### D3. 群聊

- 新建至少双角色群聊，三种发言方式均可选择。
- 指定成员回复、轮询和 AI 自选不出现错误身份或重复消息。
- 会话切换后消息不串聊，返回时定位合理。
- 中止生成、重新生成和角色主动接话不会留下永久加载状态。

#### D4. 世界书、预设、正则、快捷回复与身份

- 各资源支持新建、保存、搜索和重新进入后持久化。
- 导入取消不报成功，非法文件不覆盖现有数据。
- 世界书关键词触发和上下文预览结果一致；有条件时验证语义触发。
- 预设、身份、世界书的绑定只影响目标会话或角色，不污染其他会话。
- 正则规则启用/停用后的消息效果符合设置，错误表达式不会令页面崩溃。
- 快捷回复点击后的插入/发送行为与 UI 描述一致。

#### D5. 设置、公告、用量与 MCP

- 设置各分区可展开/折叠，重启后状态按产品约定保持。
- 备份仅做安全导出与取消验证；恢复测试必须使用隔离数据并另获授权。
- 公告在线时可刷新，离线时有缓存或明确错误，不出现永久空白。
- 用量统计日期、趋势和导出 CSV 可读；清空只对本轮测试数据执行。
- MCP 添加/编辑弹窗支持 Tab、Shift+Tab、Esc，焦点不能逃到背景；表单有明确标签和错误反馈。

## 6. 缺陷分级

| 级别 | 定义 | 示例 |
| --- | --- | --- |
| P0 | 数据安全、凭据泄露、任意文件写入、应用无法启动等发布阻断问题 | 恢复备份写出数据目录；API Key 明文泄露 |
| P1 | 核心流程不可用、数据错误或高概率丢失，且无合理绕过 | 无法发送消息；设置显示保存成功但重启丢失；会话串数据 |
| P2 | 重要功能受损但有绕过，或明显的可访问性/兼容性问题 | 弹窗键盘不可用；小窗口入口不可达 |
| P3 | 轻微视觉、文案或低频体验问题 | 间距不一致；非关键信息截断 |

缺陷标题格式：

```text
[P1][模块] 一句话描述用户可见的问题
```

每个缺陷必须包含：

1. 环境与前置条件。

## 7. 通过标准与发布建议

### 建议发布

需同时满足：

- `pnpm check`、`pnpm lint`、`pnpm test`、`pnpm build` 全部通过。
- 没有开放的 P0 或 P1。
- 本轮改动专项全部 `PASS`，或阻塞项已由负责人书面接受。
- Electron 开发版至少完成一次启动、核心流程和重启验证。
- 候选安装包存在时，安装、启动、基本对话、重启均通过。
- 报告中的每个结论都能由证据复核。

### 有条件发布

- 无 P0/P1，但存在少量已知 P2；
- 外部服务导致部分专项 `BLOCKED`，其余证据完整；
- 必须列出风险、影响用户和临时绕过方式，由发布负责人决定。

### 不建议发布

- 存在任一 P0/P1；
- 工程门禁失败；
- 应用白屏、无法稳定启动或核心数据串写；
- 本轮主功能缺少实际验证且风险无法界定。
