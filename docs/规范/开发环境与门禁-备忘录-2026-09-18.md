## 2. 工具链版本（本机实测）

| 工具 | 版本 |
|---|---|
| Node | v24.18.1 |
| pnpm | 11.21.0 |

> 画板（`spatial-board/`）使用自己的 `node_modules` 与锁文件，安装方式见 §3.1.1。
>
> **依赖审计与 electron 二进制（2026-10-17 实测）**：
> - 本机 registry 为 npmmirror（**无 audit 端点**，报 `ERR_PNPM_AUDIT_ENDPOINT_NOT_EXISTS`）；本地跑审计必须显式换源：`pnpm audit --registry=https://registry.npmjs.org --audit-level high`。CI 用默认官方源，不受影响。
> - `pnpm install` 按 `.npmrc` 的 `electron_mirror` 下载 electron 二进制；**手动补装必须带上同一镜像**，否则直连 GitHub 会 `ECONNRESET`：`$env:ELECTRON_MIRROR='https://npmmirror.com/mirrors/electron/'; node node_modules/electron/install.js`。二进制缺失时 `pnpm test` 会挂起（卡在某个 spawn/await electron 的用例）。

## 3. 门禁清单（判定标准）

### 3.1 PC 侧（仓库根）

| 命令 | 含义 | 期望 |
|---|---|---|
| `pnpm check` | `tsc -b --noEmit` + `tsc -p tsconfig.electron.json --noEmit` | exit 0 |
| `pnpm lint` | eslint | 0 error（2026-09-26：仅 1 条 `react-hooks` warning，不挡门禁） |
| `pnpm test` | vitest 全量 | 全绿（`comfyui.live.test.ts` 的 4 个 live 用例属既有跳过；2026-09-26：**3206 passed / 4 skipped**；2026-10-17 vitest 4：**3780 passed / 4 skipped**） |

#### 3.1.1 PC 多入口构建与画板依赖（2026-10-02 核对）

根 `pnpm build` 的 Vite 多入口同时产出 PC 主页面（`dist/index.html`）与画板页面（`dist/spatial-board/index.html`）；画板入口源码 `spatial-board/src/**` 依赖画板自己的 `node_modules`（React **19.3.0**），与 PC 根依赖（React **18.3.1**）互不合并。

安装步骤（跑多入口构建或画板联验前缺一不可）：

```powershell
cd spatial-board; npm ci; cd ..   # 画板独立锁文件（spatial-board/package-lock.json）
pnpm install --frozen-lockfile    # 根依赖（pnpm-lock.yaml）
```

解析边界实测（2026-10-02，证据 `output/structure-refactor/phase0/react-boundary.log`）：

- PC `src/**` → 根 `node_modules/.pnpm/react@18.3.1`；画板 `spatial-board/src/**` → `spatial-board/node_modules/react@19.3.0`（`@xyflow/react` 同）。
- 禁止把画板并入根 pnpm workspace、或强行统一 React 主版本；两侧产物分别检查：
  `dist/index.html` 引用 `main-*.js`，`dist/spatial-board/index.html` 引用 `spatial-*.js`（含 react-flow 标记）。

#### 3.1.2 空间核心包 `@qingyu/spatial-core`（2026-10-03 阶段 2 落地）

- 位置：`packages/spatial-core`（纯领域：文档/命令/校验/迁移/投影/导入防护）；原 `spatial-board/src/core/` 与 `persistence/importGuard.ts` 已迁入，**禁止再引用旧路径**。
- 接入：根 pnpm workspace 成员（`workspace:*`）+ 画板 `file:../packages/spatial-core`；Windows 上两侧都是 **junction（实时链接）**，改核心无需重装或重建即可被 PC 与画板读取（`Get-Item node_modules/@qingyu/spatial-core` 可查 LinkType）。
- 唯一引用方式：`import ... from '@qingyu/spatial-core'`（公开入口 `src/index.ts`）。禁止子路径导入、禁止宿主/React/Zustand 依赖。
- 门禁：`pnpm check:spatial-core`（零外部依赖、无 window/document/localStorage/require）；画板 `npm run check:boundary` 已允许该包并继续拦截 PC/shared 反向依赖。
- 核心改动需同时跑：根 `pnpm check` + `pnpm test`（含 `packages/spatial-core/tests`）、画板 `npm test`；构建链分别覆盖 PC 多入口（`pnpm build`）、Electron（`node electron-build.mjs`）、画板（`npm run build`）。

### 3.2 契约 fixture 一致性（shared）

| 命令 | 含义 |
|---|---|
| `pnpm exec vitest run shared/__tests__/chatCoreGolden.test.ts` | 只读校验：contracts / chat-core 实现与 fixture 必须一致 |
| `$env:CHAT_CORE_UPDATE_FIXTURES="1"; pnpm exec vitest run shared/__tests__/chatCoreGolden.test.ts` | 重新生成 fixture（改契约时用） |

- fixture 目录：`shared/fixtures/cross-platform/chat-core/`（**当前 34 组**）。
- TS 实现是 oracle：默认只读模式下 TS 侧漂移会让本测试先变红，
  迫使「改契约就连带更新 fixture」，而不是让下游静默漂移。
- 生成后**必须连跑 2–3 次确认稳定**（不稳定说明夹具含非确定性或不可往返数据）。

### 3.3 推送前自查：**没有任何源码被 .gitignore 吞掉**

2026-09-20 实测踩到：`.gitignore` 里一个**裸目录名** `data/` 会匹配任意深度的同名目录，
把子项目里的**源码包**一起忽略了——9 个源码文件**从未入库**，而 `git add -A` 会**静默跳过**它们，
任何门禁都不会报错。在没有这些文件的机器上**根本编译不过**（该子项目现已移出本仓，教训仍然适用）。

```powershell
# 期望：**没有输出**。已排除的都是"本来就不该入库"的：依赖/构建产物/本地评测与模型/IDE 工具。
git ls-files --others --ignored --exclude-standard |
  Select-String '\.(ts|tsx|js|mjs|cjs|java|json|toml)$' |
  Where-Object { $_ -notmatch 'node_modules/|^release-v2/|^\.tmp-archive/|^合并前备份|^output/|^coverage/|^\.qa|^\.poc-tmp/|^models/|\.mimosa/|\.idea/|/build/|^server/app/data/' }
```

> 2026-09-20 用这条命令复核过一遍：PC 侧 `electron` 257/257、`src` 311/311、`shared` 135/135——
> 源码与测试资产**全部入库**，仓库自洽。

写 `.gitignore` 的规则：**不要用裸目录名**（`data/`、`logs`、`dist`、`release`…），
一律根锚定（`/data/`）或写显式路径（`/server/app/data/`）；新加规则后**跑一遍上面的命令**。

## 4. 交付与验证约定（本会话验证有效，建议沿用）

1. **共享模块优先**：PC 与其消费方都要用的逻辑放进 `shared/`，
   这样契约 fixture 的 oracle **就是生产代码本身**，而不是测试里另抄一份。
   （`electron/` 依赖 Electron 运行时，无法直接作为 shared 测试的 oracle。）
2. **每个新守卫都要突变验证**：故意打破它一次，确认会变红。
   本会话靠这一步发现过**假守卫**：只检查字段名是否出现时，被 `x = null` **平凡满足**
   （已加强为「裸 null 不算接线」）。
3. **「功能在、接线不在」是本项目高发缺陷**：实现存在但没有生产调用者（历史上出现过
   `recordUsage`、世界书检索/渲染、会话预设、会话人设）。新增能力必须显式核对生产调用点。
4. **每个 fixture 用例自带语料**：语料放文件级共享时，曾出现「用例实际跑在空语料上，
   夹具消费方全绿但结论错误」。新增 fixture 一律遵守。
5. **不加条件跳过**：不要把守卫写成条件跳过（会把校验变成假守卫）；确需跳过时在汇报里写明理由与数量。
6. **结论必须带证据**：门禁全绿 ≠ 用户可用。涉及用户可见行为的结论，
   优先给**运行时证据**（实机走查、端到端断言），并写清哪部分是机制验证、哪部分是实测。

## 5. 高频陷阱（本会话实际踩到）

1. **PowerShell 单引号字符串不插值**：单引号里的 `` `n `` 会**原样写进源文件**，
   把后续代码变成注释（本会话多次造成「断言被静默禁用」）。
   **多行文本一律用编辑工具改**，不要用 shell 的 `-replace` 拼多行。
2. **fixture 必须可 JSON 往返**：`NaN`/`Infinity`/数组内 `undefined` 会被写成 `null`，
   产出「写进去与读回来不一致」的夹具（生成时通过、只读校验必失败）。
   生成器已加写入前守卫，会直接报错。
3. **JS/TS 侧高危细节**（已被 fixture 覆盖，改动时勿「顺手优化」）：
   - 引号：源码与文档里的引号用 **ASCII** `"` `'`，别写成弯引号；
   - 排序：JS 自 ES2019 起 `sort` **稳定**，同分保持输入顺序；
   - `String.slice` 越界自动截断；`lastIndexOf('@')` 为 -1 时 `slice(0,-1)` 会丢最后一个字符
     这类**切片怪癖**（已锁定）。

## 6. 目录卫生

- **测试沙盒**：两个测试会在**仓库根**落下一整套 Electron `userData` 副本
  （每个约 6 MB），目录名形如 `${cwd}/.tmp-<标记>-<pid>-<时间戳>`：

  | 前缀 | 产生者 |
  |---|---|
  | `.tmp-drill-*` | `electron/domain/__tests__/phase2.real-data-drill.test.ts` |
  | `.tmp-s204-*` | `electron/services/__tests__/charCard.domainWrite.test.ts` |

  两者都在 `afterAll` 里 `rmSync` 自清理，但**清理并不可靠**——本机实测：
  `drill` 用例**通过后仍留下 12 MB / 2464 文件**的沙盒（`s204` 留 4 个文件），
  推测与 Windows 上句柄未释放有关。因此残留是**持续累积**而非只在异常中断时发生，
  仓库根曾累积 **87 个 / 533 MB**。
  现已统一移入 **`.tmp-archive/`**（当前 90 条，约 545 MB；含历史上一次性脚本 `_tmp_fix_kt_space.py`），
  并在 `.gitignore` 封死 `.tmp-drill-*/`、`.tmp-s204-*/`、`.tmp-archive/`
  （已实测：新跑出的沙盒确实被 ignore 覆盖）。
  **每次跑完这组测试后，请把仓库根新出现的同类目录移入归档。**
- 其它位于仓库根的临时/工具目录（`.poc-tmp/`、`.qa/`、`.qa-poc/`、`.mimosa/`、
  `.playwright-cli/`、`coverage/`、`output/`、`dist/`、`dist-electron/`、
  `合并前备份-*/`、`release-v2/`）均已由 `.gitignore` 覆盖，本文件不改动它们。
