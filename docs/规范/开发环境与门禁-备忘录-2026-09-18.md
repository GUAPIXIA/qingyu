## 4. 门禁清单（判定标准）

### 4.1 PC 侧（仓库根）

| 命令 | 含义 | 期望 |
|---|---|---|
| `pnpm check` | `tsc -b --noEmit` + `tsc -p tsconfig.electron.json --noEmit` | exit 0 |
| `pnpm lint` | eslint | 0 error |
| `pnpm test` | vitest 全量 | 全绿（`comfyui.live.test.ts` 的 4 个 live 用例属既有跳过） |

### 4.2 跨语言一致性（本项目的核心门禁）

| 命令 | 含义 |
|---|---|
| `pnpm exec vitest run shared/__tests__/chatCoreGolden.test.ts` | 只读校验：TS 实现与 fixture 必须一致 |
| `$env:CHAT_CORE_UPDATE_FIXTURES="1"; pnpm exec vitest run shared/__tests__/chatCoreGolden.test.ts` | 重新生成 fixture（改契约时用） |

- fixture 目录：`shared/fixtures/cross-platform/chat-core/`（**当前 34 组**）。
- **TS（PC）是 oracle，Kotlin 必须逐字节匹配**；默认只读模式下 TS 侧漂移会让本测试先变红，
  迫使「改契约就同时改两端」，而不是让 Kotlin 静默漂移。
- 生成后**必须连跑 2–3 次确认稳定**（不稳定说明夹具含非确定性或不可往返数据）。

### 4.3 Android 侧

```powershell
cd android
$env:ANDROID_HOME="D:\Code\android-sdk"; $env:ANDROID_SDK_ROOT="D:\Code\android-sdk"
$env:ANDROID_AVD_HOME="D:\Code\android-avd"

.\gradlew.bat :app:testDebugUnitTest        # JVM 单测（当前 1078 tests / 0 failures / 0 skipped）
.\gradlew.bat :app:lintDebug                # lint（0 Error）
.\gradlew.bat :app:connectedDebugAndroidTest # 仪器化（当前每个 AVD 34 tests）
```

> **统计测试数必须强制真实执行**：`--tests` 定向跑会**只保留匹配类的结果 XML**，
> 之后若直接对 `test-results/*.xml` 求和会**显著低估**（曾把 1078 误报成 893）；
> 而任务命中构建缓存时结果文件时间戳会停留在旧时刻、并未真正执行。
> 要一个可信数字就用 `--rerun` 绕过缓存后再求和：
> ```powershell
> .\gradlew.bat :app:testDebugUnitTest --rerun --console=plain
> ```

定向跑单个用例（真机也支持）：

```powershell
.\gradlew.bat :app:connectedDebugAndroidTest "-Pandroid.testInstrumentationRunnerArguments.class=com.qingyu.companion.phase4.Phase4AcceptanceWalkthroughInstrumentedTest"
```

**结果文件位置**（读结果用这些路径，不要靠 Gradle 控制台尾部输出）：

| 类型 | 路径 |
|---|---|
| JVM 单测 | `android/app/build/test-results/testDebugUnitTest/TEST-*.xml` |
| 仪器化 | `android/app/build/outputs/androidTest-results/connected/debug/TEST-*.xml` |

> 仪器化文件名把设备名与版本直接写进了文件名，例如：
> `TEST-qingyu-api26(AVD) - 8.0.0-_app-.xml`、`TEST-qingyu-api31(AVD) - 12-_app-.xml`、
> `TEST-qingyu-api34(AVD) - 14-_app-.xml`（含空格，脚本里记得加引号）。

## 5. 交付与验证约定（本会话验证有效，建议沿用）

1. **共享模块优先**：PC 与 Android 都要用的逻辑放进 `shared/`，
   这样跨语言 fixture 的 oracle **就是生产代码本身**，而不是测试里另抄一份。
   （`electron/` 依赖 Electron 运行时，无法直接作为 shared 测试的 oracle。）
2. **每个新守卫都要突变验证**：故意打破它一次，确认会变红。
   本会话靠这一步发现两个**假守卫**：
   - 「提升 DB 版本但未导出 schema」不可测——Room 编译期**自己会写出** `3.json`；
   - 「接线审计」只检查字段名是否出现时，被 `x = null` **平凡满足**（已加强为「裸 null 不算接线」）。
3. **「功能在、接线不在」是本项目高发缺陷**：实现存在但没有生产调用者（历史上出现过
   `recordUsage`、世界书检索/渲染、会话预设、会话人设）。现有防线：
   `ChatBuilderWiringAuditTest`（装配器字段 ↔ 用例接线，双向检查：漏接线报错、清单过期也报错）。
4. **每个 fixture 用例自带语料**：语料放文件级共享时，曾出现「用例实际跑在空语料上，
   Kotlin 全绿但结论错误」。新增 fixture 一律遵守。
5. **不加条件跳过**：`@Ignore` / `Assume` 一律不要（会把校验变成假守卫）。
   当前 JVM 与仪器化均为 **0 skipped**，可作为回归基线。
6. **结论必须带证据**：门禁全绿 ≠ 用户可用。涉及用户可见行为的结论，
   优先给**运行时证据**（真机走查、端到端断言），并写清哪部分是机制验证、哪部分是实测。
7. **仪器化测试有两条路径，别把「缓存回放」当成真跑**（2026-09-20 实际踩到）：

   | 路径 | 命令 | 设备 | 数据/结果位置 |
   |---|---|---|---|
   | 连接设备 | `:app:connectedDebugAndroidTest` | 已启动的**经典 AVD**（`qingyu-api26/31/34`） | AVD：`D:\Code\android-avd\qingyu-api*.avd`；结果：`app/build/outputs/androidTest-results/connected/debug/` |
   | 托管设备 | `:app:deviceMatrixAndroidTest`（或 `pixel2Api26DebugAndroidTest` 等） | Gradle Managed Devices（`pixel2Api26/31/34`，见 `app/build.gradle.kts` §testOptions） | AVD：`D:\Code\android-avd\gradle-managed\dev*`；结果：`.../androidTest-results/managedDevice/debug/` |

   **陷阱**：任务命中构建缓存/UP-TO-DATE 时，Gradle 会**回放**缓存的测试事件，
   于是控制台照样打印「Finished N tests on qingyu-api31(AVD) - 12」这类**看起来是本次执行**的行，
   而结果 XML 的时间戳停留在旧时刻、模拟器也毫无活动。
   判定「真的跑了」必须三看：① 结果 XML 时间戳是**本次**；② `adb devices` 有设备且 AVD 目录有本次写入；
   ③ 需要确定时加 `--rerun` 绕过缓存。

## 6. 高频陷阱（本会话实际踩到）

1. **读测试报告前先确认构建成功**。编译失败时 Gradle 不会刷新结果 XML，
   于是**旧报告被当成新结果**——本会话因此误判成「连续 6 次失败」。
   凡复跑循环，先判定 `^e:` / `Compilation error` / `BUILD SUCCESSFUL`，再解释报告。
2. **仪器化测试共用同一个库文件**时，`@Before` 必须用 `context.deleteDatabase(NAME)`
   （连同 `-wal`/`-shm` 一起删）。只删主文件会留下残留 WAL，新连接读到空主库 →
   `no such table: local_messages` 的随机失败。
3. **PowerShell 单引号字符串不插值**：单引号里的 `` `n `` 会**原样写进源文件**，
   把后续代码变成注释（本会话多次造成「断言被静默禁用」）。
   **多行文本一律用编辑工具改**，不要用 shell 的 `-replace` 拼多行。
4. **fixture 必须可 JSON 往返**：`NaN`/`Infinity`/数组内 `undefined` 会被写成 `null`，
   产出「写进去与读回来不一致」的夹具（生成时通过、只读校验必失败）。
   生成器已加写入前守卫，会直接报错。
5. **Gradle 输入未声明会静默跳过**：读文件的任务若不声明 `inputs.file(...)`，
   文件变化时任务可能仍 `UP-TO-DATE`（曾被用作假守卫）。新增此类测试请一并声明输入。
6. **JS 与 Kotlin 的高危差异**（已被 fixture 覆盖，改动时勿「顺手优化」）：
   - `\s` 的空白集合（JVM 默认只保证 ASCII）；
   - 引号：PC 用 **ASCII** `"` `'`，别写成弯引号；
   - 排序：JS 自 ES2019 起 `sort` **稳定**，同分保持输入顺序；
   - JS 比较器返回 `NaN` 时规范视为 `+0`（相等），与 Kotlin 把 null 当 0 排序不同；
   - `String.slice` 越界自动截断（Kotlin `substring` 会抛异常，需显式夹取）；
   - `lastIndexOf('@')` 为 -1 时 `slice(0,-1)` 丢最后一个字符这类**切片怪癖**（已锁定）。

## 7. 目录卫生

- **测试沙盒**：两个测试会在**仓库根**落下一整套 Electron `userData` 副本
  （每个约 6 MB），目录名形如 `${cwd}/.tmp-<标记>-<pid>-<时间戳>`：

  | 前缀 | 产生者 |
  |---|---|
  | `.tmp-drill-*` | `electron/domain/__tests__/phase2.real-data-drill.test.ts` |
  | `.tmp-s204-*` | `electron/services/__tests__/charCard.domainWrite.test.ts` |

  两者都在 `afterAll` 里 `rmSync` 自清理，但**清理并不可靠**——本机实测：
  `drill` 用例**通过后仍留下 12 MB / 2464 文件**的沙盒（`s204` 留 4 个文件），
  推测与 Windows 上句柄未释放有关。因此残留是**持续累积**而非只在异常中断时发生，
  仓库根曾累积 **87 个 / 533 MB**。
  现已统一移入 **`.tmp-archive/`**（当前 90 条，约 545 MB；含历史上一次性脚本 `_tmp_fix_kt_space.py`），
  并在 `.gitignore` 封死 `.tmp-drill-*/`、`.tmp-s204-*/`、`.tmp-archive/`
  （已实测：新跑出的沙盒确实被 ignore 覆盖）。
  **每次跑完这组测试后，请把仓库根新出现的同类目录移入归档。**
- `android/app/build/tmp/**` 是 Gradle 构建中间产物（`**/build/` 已忽略），无需整理。
- 其它位于仓库根的临时/工具目录（`.poc-tmp/`、`.qa/`、`.qa-poc/`、`.mimosa/`、
  `.playwright-cli/`、`coverage/`、`output/`、`dist/`、`dist-electron/`、
  `合并前备份-*/`、`release-v2/`）均已由 `.gitignore` 覆盖，本文件不改动它们。
