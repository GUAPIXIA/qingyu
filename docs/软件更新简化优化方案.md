# 软件更新简化优化方案

> 状态：已实施，待发布验证
> 日期：2026-08-26
> 建议落地版本：v0.15.2（不要继续覆盖 v0.15.1）

## 一、优化目标

当前更新界面同时暴露自动更新、服务器镜像、GitHub、夸克网盘和镜像源配置，普通用户需要理解过多概念。此次优化采用“固定双源检查 + GitHub 默认更新 + 按需展示下载渠道”的方式：

1. 检查更新时，并行读取官方服务器和 GitHub 中的 `latest.yml`。
2. 分别显示“服务器最新版本”和“GitHub 最新版本”，不再合并成一个来源不明的版本号。
3. 自动下载与安装默认使用 GitHub Releases；服务器作为国内手动下载渠道。
4. 移除设置页中的“高级设置：更新镜像源”，不再允许用户填写或切换镜像源。
5. 两个来源都未发现新版本时，不显示“手动下载安装包”。
6. 任一来源确认存在新版本后，才按来源显示对应下载入口和夸克网盘备用链接。
7. 程序左上角继续从公告服务 `/api/version` 获取提示版本；点击版本提示改为进入“设置 → 软件更新”，不再打开 GitHub。
8. “帮助 → 关于”增加 GitHub 项目地址 `https://github.com/GUAPIXIA/qingyu`。
9. 本阶段只更新方案，不构建、不发布，也不上传 GitHub 或服务器。

## 二、目标交互

### 2.1 默认状态

设置页最上方保留“软件更新”卡片，仅显示：

- 当前版本；
- “检查更新”按钮；
- 最近一次检查结果（如“当前已是最新版本”）。

此时不显示：

- 手动下载安装包区域；
- GitHub、服务器和夸克网盘入口；
- 镜像源配置。

### 2.2 检查结果

点击“检查更新”后，同时请求：

- 官方服务器：`https://cjbtj.xyz/qingyu/update/latest.yml`
- GitHub Releases：由 `electron-updater` 的 GitHub Provider 获取 `latest.yml`

两个请求互不阻塞，完成后分别显示：

```text
当前版本       v0.15.1
服务器版本     v0.15.2
GitHub 版本     v0.15.2
```

如果某个来源请求失败，该来源显示“获取失败”，另一个来源的结果仍然有效；不能因为其中一个来源失败就丢弃另一个来源的版本信息。

### 2.3 检测到新版本

只要服务器版本或 GitHub 版本中至少一个高于当前版本，就确认存在新版并显示手动下载区域：

1. **GitHub 下载**：GitHub 版本高于当前版本时显示。自动“下载更新”也默认使用 GitHub。
2. **服务器下载**：服务器 `latest.yml` 版本高于当前版本时显示，下载文件名从该 `latest.yml` 的 `path` 或 `files[0].url` 获取，不依赖用户配置镜像地址。
3. **夸克网盘备用下载**：放在下载按钮下方，并提示“版本以网盘页面为准”。

当服务器与 GitHub 版本不一致时，界面按来源分别标注版本，例如“服务器下载 v0.15.3”和“GitHub 下载 v0.15.2”，不得把两个入口都标成同一个版本。

如果只有服务器存在新版、GitHub 尚未发布，则不显示自动更新按钮，改为提示“GitHub 暂未同步，可从服务器手动下载”。

### 2.4 下载过程

| 状态 | 主要内容 | 手动下载区域 |
|---|---|---|
| `idle` | 当前版本、检查更新 | 隐藏 |
| `checking` | 检查中 | 隐藏 |
| `none` | 已是最新版本 | 隐藏 |
| `available` | 分别显示服务器/GitHub 版本；GitHub 有新版时显示下载更新 | 按可用来源显示 |
| `downloading` | 下载进度 | 隐藏，避免重复操作 |
| `downloaded` | 重启安装 | 隐藏 |
| 单个来源失败 | 显示另一来源结果及局部错误 | 另一来源有新版时显示 |
| 两个来源均失败 | 错误信息、重新检查 | 隐藏，因为尚未确认有新版 |
| 已发现新版但下载失败 | 错误信息、重试 | 显示，作为备用方案 |

实现时应分别保留 `serverResult`、`githubResult` 和 `hasAvailableUpdate`，不能再用一个通用 `version/source/error` 覆盖两个来源的结果。

### 2.5 左上角版本入口

程序左上角继续通过 `/api/version` 获取公告服务器配置的 PC 最新版本，用于红点和“本地版本 → 公告版本”提示。

交互调整：

- 点击版本号或新版红点，跳转到 `/settings#settings-updater`；
- 设置页挂载后自动滚动到“软件更新”卡片；
- 不再直接打开下载地址；
- 左上角 GitHub 外链图标一并移除，GitHub 项目入口统一放到“帮助 → 关于”。

### 2.6 关于页面

在 `src/pages/HelpPage.tsx` 的“关于”卡片中增加：

- 文案：`GitHub 项目地址`；
- 地址：`https://github.com/GUAPIXIA/qingyu`；
- 点击后调用现有 `window.api.app.openExternal()` 安全打开系统浏览器；
- 显示完整地址或明确的“访问 GitHub 项目”按钮，不能只放一个无说明图标。

## 三、更新数据来源

### 3.1 检查更新：固定双源并行

Electron 主进程同时检查服务器与 GitHub：

```text
点击检查更新
    ├── 官方服务器 /latest.yml ──→ serverResult
    └── GitHub Releases/latest.yml → githubResult
                                  ↓
                 分别展示版本并与当前版本比较
```

这不是原来的“镜像优先、失败再回退 GitHub”串行策略。两个来源必须并行请求、分别保留结果，用户能够看到每个来源当前发布到了哪个版本。

服务器 URL 固定在程序内，不提供用户配置项；正式版仍只允许 HTTPS。

### 3.2 自动下载：默认 GitHub

即使服务器版本更高，`electron-updater` 的自动下载和安装也只绑定 GitHub Provider，以避免下载过程中动态切换 feed。

规则如下：

- GitHub 有新版：允许“下载更新”，走 GitHub 自动下载；
- 只有服务器有新版：提供服务器手动下载，不启动自动更新；
- 两边都有新版：自动更新走 GitHub，服务器作为手动备用；
- GitHub 下载失败但已确认有新版：继续显示 GitHub与服务器手动入口。

### 3.3 服务器 `latest.yml`

服务器 `latest.yml` 同时承担两项职责：

- 提供服务器当前发布版本，用于和本地/GitHub 分别比较；
- 提供服务器安装包相对路径与 SHA-512/文件大小信息，用于生成手动下载地址。

客户端不再从 `/api/version.downloadUrl` 推断服务器安装包版本，避免公告后台版本和实际更新文件不一致。

### 3.4 公告版本接口

`/api/version` 暂时保留，因为它仍服务于：

- PC 侧边栏版本提示；
- 安卓端独立版本信息与旧接口兼容。

它不参与设置页中服务器/GitHub `latest.yml` 的版本判断，也不再提供设置页手动下载地址。PC 字段仅保留左上角公告提示兼容；安卓字段继续独立使用。

### 3.5 四类版本的定义

| 名称 | 数据来源 | 用途 |
|---|---|---|
| 当前版本 | `app.getVersion()` / `package.json` | 本机已安装版本 |
| 公告版本 | `/api/version.version` | 左上角红点与公告提示 |
| 服务器版本 | 官方服务器 `/update/latest.yml` | 设置页版本展示、服务器手动下载 |
| GitHub 版本 | GitHub Releases `latest.yml` | 设置页版本展示、自动更新与 GitHub 下载 |

界面和日志必须使用这些明确名称，不再笼统称为“服务器版本”或“最新版本”。

## 四、代码调整范围

### 4.1 Electron 更新服务

文件：`electron/services/updater.ts`

计划调整：

- 将 `DEFAULT_MIRROR_URL` 改为不可配置的官方服务器常量，并改名为 `OFFICIAL_SERVER_FEED_URL`；
- 删除镜像地址读取、校验和写入逻辑；
- 删除“镜像优先、GitHub 回退”的串行短路逻辑；
- `checkForUpdates()` 并行获取服务器和 GitHub 两份 `latest.yml` 结果；
- 为服务器和 GitHub 分别保存版本、错误、更新日志与下载信息；
- GitHub 检查仍交给 `electron-updater`，服务器清单可通过独立请求解析，避免切换自动下载 Provider；
- 自动下载前明确将 Provider 保持或切回 GitHub；
- 保留下载进度、下载完成和静默安装逻辑；
- 区分单源失败、双源失败、单源新版和双源版本不一致。

### 4.2 IPC 与 Preload

## 五、兼容与迁移

### 5.1 已发布的 v0.15.1

v0.15.1 内置服务器镜像优先，但服务器无新版时会继续检查 GitHub。因此下一版只发布到 GitHub Releases，v0.15.1 仍能通过 GitHub 发现它。

建议下一次使用新版本号 v0.15.2，不能继续覆盖 v0.15.1。已安装 v0.15.1 的客户端不会把同版本的重新打包文件识别为更新。

从 v0.15.2 起，检查方式变为固定双源并行；历史自定义镜像不再参与检查。

### 5.2 用户保存过自定义镜像

升级后直接忽略旧镜像配置，服务器检查固定使用官方地址，自动更新固定使用 GitHub。不需要弹窗提示，也不需要要求用户手动清理。

### 5.3 GitHub 不可访问

如果 GitHub 检查失败但服务器检查成功：

- 正常显示服务器版本；
- 服务器存在新版时显示服务器手动下载；
- 不提供 GitHub 自动更新，明确显示“GitHub 获取失败”。

如果服务器检查失败但 GitHub 成功，自动更新仍正常工作。只有两个来源都失败时，才显示整体检查失败且隐藏全部手动下载入口。
