## 1. 项目概览

| 维度 | 情况 |
|------|------|
| 定位 | 轻量级 AI 角色扮演桌面客户端（SillyTavern 理念，Windows 优先） |
| 技术栈 | Electron 32 + React 18 + TypeScript 5.8 + Vite 6 + Tailwind 3 + Zustand 5 |
| 架构 | 四层：渲染层（`src/`，zustand 业务 store）→ preload 类型桥（`electron/preload.ts`）→ 主进程（`electron/ipc` + `electron/services` + `electron/mcp`）→ 磁盘存储（JSON / JSONL，`app.getPath('userData')/data`） |
| 服务端 | `server/app`（Express + better-sqlite3 + JWT），负责在线公告，已纳入 pnpm workspace |
| 共享契约 | `shared/`（types.ts / ipc-api.ts / ipc-channels.ts / defaults.ts） |
| 代码规模 | 304 个 git 跟踪文件；渲染层最大文件 38KB，主进程最大 41KB |
| 测试 | 72 个测试文件、867 个用例；CI 含 tsc / coverage / audit / lint / Windows 打包五个 Job |
| 版本历史 | 0.11.15 → 0.11.22 已完成 4 轮审查修复（安全 26 项、凭据加密、性能、打包、契约清理） |

**总体评价**：这是一个成熟度相当高的项目。安全基线（SSRF 防护含 IPv4-mapped IPv6 变体、路径穿越防护、XSS 收敛、凭据系统级加密、MCP 命令注入白名单、JWT 算法锁定、公告下载重定向校验）远超同类业余项目水准；测试体系完整且 CI 门禁真实有效。剩余问题集中在 **lint 门禁回归、少量技术债与部分功能空白**，无严重安全漏洞。

## 3. 发现的问题

### 3.1 🔴 高严重度（当前就会红 / 直接影响交付）

#### P-1：lint 门禁失败 —— CI `lint` Job 当前必然变红

`npm run lint` 实测 8 个 error：

| 位置 | 问题 | 修复方式 |
|------|------|----------|
| `src/App.tsx:11` | `ComponentType<any>` 触发 `no-explicit-any` | 改为 `ComponentType<Props>` 或引入具体泛型约束 |
| `src/store/useChatStore.ts:9` | `stripThought` / `normalizeThoughtTags` / `trimContinuationOverlap` 三个导入未使用（双轨正则收敛后遗留） | 删除未用导入 |
| `electron/ipc/__tests__/chat.test.ts:6,15` | `existsSync` / `DIRS` 未使用 | 删除未用导入 |
| `electron/ipc/__tests__/settings.test.ts:44,45` | `require()` 风格导入（该文件是 TS 测试却用了 CJS require） | 改为 `import` 或换 vi.mock 方案 |

4 个 warning 同样值得清零：

- `coverage/block-navigation.js`、`coverage/prettify.js`、`coverage/sorter.js`：**coverage 目录未加入 eslint ignores**，导致 lint 扫描构建产物；
- `server/app/server.js:62`：`eslint-disable` 指令无对应规则（见 P-2）。

**证据**：CI 配置（`.github/workflows/ci.yml`）明确 lint 是硬门禁——"已清零存量错误（2026-08 清理 125 个），现在硬性门禁"。

#### P-2：eslint 配置盲区 —— server 代码没有任何实质 lint 规则

`eslint.config.js` 只有两个带 `files` 的配置块（`**/*.{ts,tsx}` 与测试文件），**`server/app/*.js` 不匹配任何块**——server 的 JS 代码完全不参与规则检查（本次 lint 中 server.js 仅因 eslint-disable 指令产生了 warning，其余文件全部裸奔）。而 server 恰恰是面向公网的组件（JWT、SQLite、公告 CRUD）。

**建议**：增加一个 `files: ['server/**/*.js']` 配置块（`globals.node` + js recommended + 适当的宽松规则），并把 `coverage`、`dist-electron`、`.reasonix` 加入全局 ignores。

### 3.2 🟡 中严重度（技术债 / 长期维护性）

#### P-3：IPC invoke 通道字符串仍然三处硬编码

`shared/ipc-channels.ts` 目前只有 **5 个事件通道**（ai:chunk 等），preload 中 **约 100 处 `ipcRenderer.invoke('xxx')`、主进程约 120 处 `ipcMain.handle('xxx')` 仍是字符串字面量**。事件通道已常量化（v0.11.19），invoke 通道常量化是 docs/优化建议.md 1.1 的未完成部分。拼写错误只能在运行时发现。

**建议**：补齐 `IPC_CHANNELS` 常量 + `ipcMain.handle` 的 channel 参数类型约束（模板字面量类型），预计 1-2 天纯机械替换，风险低。

#### P-4：IPC 错误响应风格两套并存

- `ai:listModels` / `ai:testConnection` 返回 `{ success: false, error }` 对象；
- 其余 handler 直接抛异常，由 `main.ts` 全局包装统一记录并回传 rejection。

渲染层 `window.api` 调用方需要同时处理两种失败形态。建议统一为「抛错 + 全局 catch + `friendlyError` 映射」一种约定（docs 1.2 的收尾项）。

#### P-5：死代码与临时代码

- `electron/ipc/chat.ts:156` 的 `updateSessionMeta` 函数依赖 `eslint-disable` 注释存活，注释自述"保留供未来扩展使用"——**超过两个版本未使用的保留代码应删除**（git 历史可找回）；
- `electron/services/ai.ts:88-91` 存在空 if 块（`if (errName === 'AbortError' && !signal.aborted) { /* 是超时 abort，可重试 */ }`），无实际逻辑，阅读者易误解。

#### P-6：巨型组件/文件仍然存在

| 文件 | 大小 | 问题 |
|------|------|------|
| `src/pages/LorebookPage.tsx` | 38KB | 单页含列表+编辑器+语义索引管理+导入导出，职责过多 |
| `src/components/chat/QuickSettingsPanel.tsx` | 37KB | 快捷设置面板含大量子面板内联 |
| `src/pages/ApiPage.tsx` | 35KB | 四个子 Section 已拆分但仍由单页串联全部逻辑 |
| `src/pages/ChatPage.tsx` | 33KB | 可拆消息列表/输入区/头部 |
| `src/pages/GroupChatPage.tsx` | 29.5KB | 同上 |
| `src/components/chat/useChatInputState.ts` | 27KB | 输入状态机过于庞大 |

MessageBubble/useChatStore 已拆分（v0.11.21/v0.11.20），以上为继续推进项。

#### P-7：数据迁移双轨并存

主进程 `electron/services/migration.ts`（`migrateData` + schemaVersion）与渲染进程 `useSettingsStore.ts:95` 自建迁移（providers→profile）并存。渲染层迁移不经过版本号体系，未来演进可能分叉。建议统一到主进程（docs 1.4）。

#### P-8：`ipcMain.handle` 运行时 monkey-patch 脆弱

`electron/main.ts:170-184` 通过替换 `ipcMain.handle` 实现全局异常记录，依赖 `as typeof ipcMain.handle` 强制断言。当前可用，但属于对 Electron 内部 API 的侵入式修改，升级 Electron 大版本时需要验证。可考虑在 safeHandle 中显式包装（标记 + 单次记录）替代 monkey-patch。

#### P-9：tiktoken 体积负担（待评估）

`tiktoken` 被 esbuild bundle 进 main.cjs（450KB 产物中占可观比例），且 `package.json` 的 electron-builder `files` 还单独白名单了 `node_modules/tiktoken/**/*`（wasm/数据文件，安装包体积大头，CHANGELOG 提及约 22.5MB）。CHANGELOG 已记录"替换需基准验证"的评估结论——建议尽快完成 `gpt-tokenizer`（<1MB 纯 JS）的精度对比实验，或至少移除打包白名单中不必要的数据文件。

#### P-10：覆盖率阈值仍处低水位

`vitest.config.ts` 阈值：lines 15% / statements 15% / functions 35% / branches 65%。当前只是"防明显回退"的下限。867 个用例集中在 store/utils/services 层，**页面组件（pages/）覆盖率接近 0**（仅 4 个页面有测试）。建议分季度逐步抬升（如每版本 +5% lines），并优先补 ChatPage/GroupChatPage 的关键交互测试。

### 3.3 🟢 低严重度（兼容性 / 体验细节 / 环境）

#### P-11：流式空闲超时 60s 对长思考模型不友好

`src/store/chatConstants.ts` `STREAM_IDLE_TIMEOUT_MS = 60 * 1000`。注释声称"对慢推理模型也公平"（每次 chunk 续期），但 Claude extended thinking / DeepSeek R1 / o 系列模型在复杂问题上**思考阶段可以超过 60 秒不发任何 token**，会被判定卡死而中断（用户侧表现为"请求超时"）。建议：改为可配置（设置页项），或对 reasoning 模型放宽到 3-5 分钟。

#### P-12：AI 错误消息回传渲染层未脱敏

`electron/services/ai.ts:201` 将 `err.message` 原样经 `ai:error` 发给渲染进程。日志侧已做 `sanitizeApiKey`，但**用户可见的错误提示没有脱敏**——若第三方 API 的错误响应回显请求 URL 或 Header（某些网关会这样做），API Key 可能出现在 UI 错误横幅中。建议发送前同样过一遍 `sanitizeApiKey`。

#### P-13：日志 IPC 缺少上限

`electron/main.ts:239-241` `log:getRecent` 的 `limit` 无上限校验（可传 1e9），`log:write` 的 `message/meta` 无长度限制。渲染进程被攻破时可用于内存放大。建议 `limit` 夹取到 [1, 1000]、message 截断（如 8KB）。

#### P-14：dev 模式强制打开 DevTools

`electron/main.ts:73` 开发模式自动 `openDevTools({ mode: 'detach' })`，每次启动多弹一个窗口，无开关。建议改为环境变量或启动参数控制。

#### P-15：全局快捷键未区分输入框场景

`src/App.tsx:154-182` 的 Ctrl+N / Ctrl+E / Ctrl+/ 等快捷键在任何焦点下生效——用户在消息输入框、角色卡编辑器等 textarea 中按 Ctrl+E 会误触发"导出对话"。建议检测 `event.target` 是否为可编辑元素时跳过。

#### P-16：esbuild 警告噪音

`node electron-build.mjs` 每次输出 1 条警告：`electron/services/tokenizer.ts:20` 的 `import.meta.url` 在 cjs 格式下为空。运行时有 `__filename` 兜底、无害，但属构建噪音。可改为 cjs 环境下直接使用 `__filename`（或接受警告并加注释）。

#### P-17：npm / pnpm 混用导致环境噪音

`.npmrc` 中 `verify-deps-before-run`、`electron_mirror`、`better_sqlite3_binary_host` 是 **pnpm 专属键**；本地用 npm 运行任何脚本都会输出 3 条 "Unknown project config" 警告（本机 node_modules 即 npm 安装）。CI 用 pnpm。建议：文档统一声明包管理器（README 注明 pnpm），或把镜像配置挪到 `pnpm` 专属配置。

#### P-18：仓库卫生问题

- 工作区存在 **4 个未提交的删除**：`.claude/settings.json`、`docs/优化路线图.md`、`docs/功能状态.md`、`docs/对话优化方案.md`（`git status` 显示 ` D`）。若非有意删除，应恢复；若有意，应提交；
- `.reasonix/` 目录未跟踪且**不在 `.gitignore` 中**（agent 会话产物），应加进 ignore 列表。

#### P-19：server 管理后台关闭 CSP

`server/app/server.js:22` `helmet({ contentSecurityPolicy: false })`——注释说明是管理后台内联脚本所致。属于有意识的取舍，但管理后台是登录后的高权限面，建议后续给 admin/index.html 迁移外置 JS 后重新开启 CSP。

#### P-20：MCP SSE URL 仅校验协议

`electron/mcp/manager.ts:77` 只校验 `^https?://`，未做 SSRF 防护（stdio 命令做了完整的解释器黑名单）。本地 MCP server 用 localhost 是合法场景，因此不能照搬 `isSafeUrl`；建议至少提示风险（UI 警告"连接远程 SSE 服务器将使其可访问本机网络"）或提供显式信任开关。
