## 1. 总则

### 1.1 目的

统一三端（桌面 Electron、Android、Server）的版本号管理、分支策略、提交规范、推送门禁与发布流程，确保：

- `main` 分支永远可发布
- 每次推送前通过全量门禁（类型检查 / Lint / 测试 / 安全审计）
- 版本号、Tag、CHANGELOG 三者一致
- 敏感文件不进入版本库

### 1.2 三端版本权威来源

| 服务端 | [server/app/package.json](file:///d:/Code/qingyu/酒馆/server/app/package.json)`#version` | `1.0.4` | `npm version`（在 `server/app/` 下执行） |

> 桌面端与 Android 端可联动发版（`--sync-android`），服务端独立 SemVer。

## 2. 版本号规则

### 2.1 SemVer 变体

```
主版本.次版本.修订号[-预发布.序号]

0.12.0              正式版
0.12.0-alpha.1      内部联调
0.12.0-beta.1       公测
0.12.0-rc.1         候选
0.1.5               Android（独立次版本体系）
1.0.4               Server（独立 SemVer）
```

| 段 | 含义 | 递增时机 |
|---|---|---|
| 主版本 | 不兼容的大架构变更 | 1.0.0 之前保持 `0` |
| 次版本 | 架构升级 / 批量新功能 | 如 `0.11 → 0.12`（统一 ChatOrchestrator） |
| 修订号 | 热修 / Bug 修复 / 安全修复 | 如 `0.12.0 → 0.12.1` |
| 预发布 | 开发阶段标记 | `alpha` 内部 → `beta` 公测 → `rc` 候选 → 正式 |

### 2.2 版本递增决策

| 变更类型 | 递增 | 示例 |
|---|---|---|
| Bug 修复、安全热修 | `patch` | `0.12.0 → 0.12.1` |
| 新功能、架构升级 | `minor` | `0.12.0 → 0.13.0` |
| 不兼容变更 | `major` | `0.12.0 → 1.0.0` |
| 预发布迭代 | `prerelease --pre <phase>` | `0.13.0-alpha.1 → 0.13.0-alpha.2` |
| 预发布转正 | `release` | `0.13.0-rc.1 → 0.13.0` |

> `main` 分支的 `package.json#version` 始终指向**当前开发版本**。Tag 才标记正式发布点。

### 2.3 版本脚本

[scripts/version.mjs](file:///d:/Code/qingyu/酒馆/scripts/version.mjs) 是桌面端版本号的唯一入口：

```bash
# 查看当前版本与最近 Tag
node scripts/version.mjs status

# 递增修订号
node scripts/version.mjs patch

# 递增次版本
node scripts/version.mjs minor

# 预发布迭代（默认 alpha，可指定 beta/rc）
node scripts/version.mjs prerelease --pre beta

# 预发布转正式
node scripts/version.mjs release

# 直接设定版本号（需校验格式）
node scripts/version.mjs set 0.13.0-beta.1

# 联动同步 Android 版本
node scripts/version.mjs patch --sync-android
```

也可通过 `package.json` scripts 别名调用：

```bash
pnpm version:status
pnpm version:patch
pnpm version:minor
pnpm version:prerelease
pnpm version:release
```

脚本自动写入：
- `package.json#version`
- `android/gradle/libs.versions.toml`（仅 `--sync-android` 时更新 `appVersionName`）

## 3. 分支模型

```
origin/main          唯一保护分支，永远可发布，仅通过 PR 合入
├─ feat/*            功能分支（从 main 切出）
├─ fix/*             修复分支
├─ chore/*            工程治理 / 依赖升级 / 文档
└─ release/vX.Y.Z    热修或预发布分支（从对应 Tag 切出，合回 main 后删除）
```

### 3.1 规则

| 规则 | 说明 |
|---|---|
| 禁止直接 push main | 所有变更走 PR，CI 全绿后合入 |
| 功能分支命名 | `feat/<简述>` 或 `fix/<issue号>-<简述>` |
| 分支生命周期 | 合入 main 后立即删除 |
| 热修分支 | 从最近正式 Tag 切 `release/vX.Y.Z`，修复合回 main 并打新 Tag |
| 禁止 rebase 已推送的公共分支 | 保持 merge commit，保留完整历史 |

## 4. 提交规范

### 4.1 Commit Message 格式

```
<type>(<scope>): <subject>

<body 可选>
```

| type | 用途 |
|---|---|
| `feat` | 新功能 |
| `fix` | Bug 修复 |
| `security` | 安全修复 |
| `refactor` | 重构（无行为变更） |
| `perf` | 性能优化 |
| `test` | 测试补充 |
| `docs` | 文档 |
| `chore` | 工程 / 依赖 / 配置 |
| `release` | 发版提交（升版本 + CHANGELOG） |

scope 示例：`bridge` / `chat` / `mcp` / `android` / `server` / `settings` / `character`。

示例：

```
feat(chat): 持久任务恢复与事件补播
fix(android): WS 重连 target 校验缺失
security(bridge): JWT 密钥明文落盘收敛
release: v0.12.1 - 修复群聊保存竞态
```

### 4.2 提交粒度

- 一个提交做一件事，避免大杂烩。
- 发版提交仅包含版本号 + CHANGELOG + lockfile，不含功能代码。
- 敏感文件（`.env` / `*.pem` / `*.key` / `*.keystore` / `*.apk`）**永不提交**，见 [§8](#8-安全与敏感文件管理)。

## 5. 推送前门禁

### 5.1 本地门禁（每次 push 前必须全绿）

```powershell
Set-Location D:\Code\qingyu\酒馆

# 1. TypeScript 类型检查（双 tsconfig）
pnpm check

# 2. ESLint（0 errors）
pnpm lint

# 3. 全量单元测试
pnpm test
# 若需覆盖率门禁：
# pnpm test:coverage

# 4. 服务端测试（如改动了 server/）
Set-Location server/app; npm test; Set-Location ../..

# 5. Android 构建（如改动了 android/）
# 本地因中文路径可能导致 Gradle 锁，CI 英文路径不受影响
# 可在英文路径副本中验证：./gradlew assembleDebug

# 6. 工作区检查
git status          # 确认无敏感文件
git diff --stat     # 确认变更范围符合预期
git log --oneline -5
```

### 5.2 CI 自动门禁

[.github/workflows/ci.yml](file:///d:/Code/qingyu/酒馆/.github/workflows/ci.yml) 定义了 4 个 Job：

| Job | 触发 | 内容 |
|---|---|---|
| **test** | push main + PR | `pnpm check` → `pnpm test:coverage`（覆盖率门禁） → esbuild 编译 → `pnpm audit --audit-level=critical` |
| **lint** | push main + PR | `pnpm lint`（0 errors 硬门禁） |
| **build-windows** | 仅 push main | electron-builder NSIS 安装包 → 上传 artifact |
| **audit** | push main + PR | `pnpm audit --audit-level high`（信息性，不阻塞） |

> PR 不通过 `test + lint` 无法合入 main。`build-windows` 仅在 main 推送时运行。

## 6. 发布流程

### 6.1 标准发布（桌面 + Android 联动）

```powershell
Set-Location D:\Code\qingyu\酒馆

# 1. 确认工作区干净
git status

# 2. 升版本（自动写 package.json + CHANGELOG 需手动编辑）
node scripts/version.mjs status
node scripts/version.mjs patch --sync-android
#   0.12.0 -> 0.12.1，Android 0.1.5 -> 0.1.5（patch 只升桌面端修订号）
#   如需 Android 也跟随，用 set 并带 --sync-android：
#   node scripts/version.mjs set 0.12.1 --sync-android

# 3. 编辑 CHANGELOG.md（见 §7）

# 4. 提交 + 打 Tag
git add package.json android/gradle/libs.versions.toml CHANGELOG.md pnpm-lock.yaml
git commit -m "release: v0.12.1 - <一句话摘要>"
git tag -a v0.12.1 -m "v0.12.1"

# 5. 推送（触发 CI 构建 Windows 安装包）
git push origin main --follow-tags

# 6. GitHub Release
#    Releases → Draft from Tag → 粘贴 CHANGELOG 段 → 附 artifacts/desktop/*.exe + SHA256
```

### 6.2 预发布流程（alpha / beta / rc）

```powershell
# 从 main 切预发布分支
git checkout main
git pull origin main
git checkout -b release/v0.13.0

# 升预发布版本
node scripts/version.mjs minor          # 0.12.1 -> 0.13.0
node scripts/version.mjs prerelease --pre alpha
#   -> 0.13.0-alpha.1

# 更新 CHANGELOG，提交 + Tag
git add package.json CHANGELOG.md
git commit -m "release: v0.13.0-alpha.1 - <摘要>"
git tag -a v0.13.0-alpha.1 -m "v0.13.0-alpha.1"
git push origin release/v0.13.0 --follow-tags

# 迭代下一预发布
node scripts/version.mjs prerelease --pre alpha
#   -> 0.13.0-alpha.2

# 预发布转正
node scripts/version.mjs release
#   0.13.0-rc.1 -> 0.13.0

# 合回 main
git checkout main
git merge --no-ff release/v0.13.0
git tag -a v0.13.0 -m "v0.13.0"
git push origin main --follow-tags
git branch -d release/v0.13.0
```

### 6.3 热修流程

```powershell
# 从最近正式 Tag 切热修分支
git checkout -b release/v0.12.1 v0.12.0

# 修复代码...
git commit -m "fix: <描述>"

# 升版本
node scripts/version.mjs patch    # 0.12.0 -> 0.12.1

# 更新 CHANGELOG，提交 + Tag
git add package.json CHANGELOG.md
git commit -m "release: v0.12.1 - <热修摘要>"
git tag -a v0.12.1 -m "v0.12.1"

# 合回 main
git checkout main
git merge --no-ff release/v0.12.1
git push origin main --follow-tags
git branch -d release/v0.12.1
```

### 6.4 服务端独立发布

服务端版本号独立于桌面端，在 `server/app/` 下管理：

```powershell
Set-Location D:\Code\qingyu\酒馆\server\app

# 升版本
npm version patch    # 1.0.4 -> 1.0.5（自动写 package.json + 创建 commit + Tag）

Set-Location ../..

# 更新 server/CHANGELOG.md
# 提交（npm version 已自动 commit，如需补充 CHANGELOG 则 amend 或追加）
git add server/CHANGELOG.md
git commit --amend --no-edit    # 或 git commit -m "docs: 补充 server CHANGELOG"

# Tag 用 server- 前缀区分
git tag -a server-v1.0.5 -m "server v1.0.5"

git push origin main --follow-tags
```

> 服务端 Tag 使用 `server-v*` 前缀，与桌面端 `v*` 区分。

### 7.2 规则

| 规则 | 说明 |
|---|---|
| 每次发版必须有条目 | 未发布内容放 `## [Unreleased]` 下 |
| 分类标签 | `### 新增` / `### 修复` / `### 安全` / `### 变更` / `### 性能` / `### 废弃` |

- 桌面端变更写入根 `CHANGELOG.md`。
- Android 变更写入 `android/CHANGELOG.md`（独立），与桌面同步发布时在根 CHANGELOG 中追加摘要。
- 服务端变更写入 `server/CHANGELOG.md`（独立）。

## 8. 安全与敏感文件管理

### 8.1 永不提交的文件

[.gitignore](file:///d:/Code/qingyu/酒馆/.gitignore) 已覆盖：

| 类别 | 模式 |
|---|---|
| 环境配置 | `.env` / `.env.*`（`.env.example` 例外） |
| 密钥证书 | `*.pem` / `*.key` / `*.keystore` / `*.jks` |
| 构建产物 | `dist/` / `dist-electron/` / `release-v2/` / `**/build/` / `*.apk` / `*.aab` |
| 缓存 | `node_modules/` / `.cache/` / `coverage/` / `.gradle/` |
| 本地工具 | `.trae/` / `.reasonix/` / `.qoder/` / `.codebuddy/` / `.workbuddy/` |
| 审查产物 | `lint*.json` / `.poc-tmp/` / `piolium/` |

### 8.2 推送前检查

```powershell
# 确认无敏感文件被跟踪
git status --porcelain | findstr /i "\.env \.pem \.key \.keystore \.apk token \.db"

# 如果输出非空，立即停止：
git reset HEAD <file>        # 从暂存区移除
echo <file> >> .gitignore    # 补充忽略
```

### 8.3 敏感配置管理

- API Key / 密码等通过 Electron `safeStorage` 加密存储，不入库。
- 服务端 `JWT_SECRET` / `ADMIN_PASSWORD` 通过 `.env` 环境变量注入，仓库仅留 `.env.example`。
- 如误提交了敏感文件：`git filter-branch` 或 BFG 清理历史，并**立即轮换泄露的凭据**。

## 9. 回滚策略

### 9.1 未分发给用户

```powershell
# revert 发版提交，然后发新修订版
git revert <release-commit>
git push origin main
# 按 §6.1 流程发 patch
```

### 9.2 已分发给用户

无法撤回已安装的版本，采取：

1. **Feature Flag 回滚**：通过 `chatEngineV2` 等运行时开关关闭问题功能，不需要重新发版。
2. **紧急热修**：按 §6.3 热修流程发 `patch` 版本。
3. **GitHub Release 标注**：在问题版本 Release 页标注已知问题，指向修复版本。

## 10. Tag 管理规范

### 10.1 Tag 命名

| 端 | 格式 | 示例 |
|---|---|---|
| 桌面端 | `vX.Y.Z[-prerelease.seq]` | `v0.12.0` / `v0.13.0-beta.1` |

### 10.2 Tag 操作

```powershell
# 查看本地所有 Tag（按版本排序）
git tag --list | Sort-Object -Descending

# 推送单个 Tag
git push origin v0.12.1

# 推送所有本地 Tag
git push origin --tags

# 删除本地误打的 Tag
git tag -d v0.12.1

# 删除远端误推的 Tag
git push origin --delete v0.12.1
```

> 发版时务必使用 `--follow-tags` 确保提交和 Tag 一起推送。

## 12. CI 流水线详解

### 12.1 触发条件

| 事件 | 触发的 Job |
|---|---|
| push → main | test + lint + build-windows + audit |
| PR → main | test + lint + audit |

### 12.2 各 Job 职责

**test**（`ubuntu-latest`）：
1. `pnpm install --frozen-lockfile`
2. `pnpm check` — TypeScript 双配置编译（`tsconfig.json` + `tsconfig.electron.json`）
3. `pnpm test:coverage` — vitest 全量测试 + 覆盖率门禁（`vitest.config.ts#thresholds`）
4. `node electron-build.mjs` — Electron 主进程 esbuild 编译验证
5. `pnpm audit --audit-level=critical` — critical 漏洞硬门禁

**lint**（`ubuntu-latest`）：
- `pnpm lint` — ESLint，0 errors 硬门禁

**build-windows**（`windows-latest`，仅 main push）：
- `pnpm electron:build` — electron-builder NSIS 安装包
- 上传 artifact `qingyu-win-x64`（`release-v2/*.exe`）

**audit**（`ubuntu-latest`）：
- `pnpm audit --audit-level high` — 信息性扫描，不阻塞

### 12.3 覆盖率门禁

`vitest.config.ts` 的 `thresholds` 定义各模块覆盖率下限。覆盖率下降会直接导致 CI 红灯。新增代码需同步补测，保持阈值。
