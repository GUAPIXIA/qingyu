## 2. 分支与版本模型

### 2.1 分支

```
origin/main  ← 唯一保护分支，永远可发布
  ├─ feat/*          功能分支（从 main 切）
  ├─ chore/*         工程治理（本次 consolidation）
  └─ release/vX.Y.Z  热修/预发布（从 Tag 切，合回 main 即删）
```

- 禁止直接在 `main` 做大重构；`feat/` 需 PR。
- 本次 `chore/consolidate-*` 已合入 `main`，可 `git branch -d chore/consolidate-android chore/consolidate-server`。

### 2.2 版本号（`docs/版本管理规范 1.0`）

```
0.12.0
0.12.0-alpha.1 → alpha.2 → beta.1 → rc.1 → 0.12.0
0.1.5 (Android build6)
1.0.4 (Server)
```

- 桌面：`scripts/version.mjs` 为唯一入口，`package.json` 为权威。
- 安卓：`libs.versions.toml` 为权威，`--sync-android` 才跟随桌面。
- Server：独立 `server/app/package.json`，与桌面解耦。

## 4. 发布流程（日常）

### 4.1 标准发布（桌面+安卓联动）

```powershell
# 1. 升版本（自动写 package.json + 可选同步安卓）
node scripts/version.mjs status
node scripts/version.mjs patch --sync-android   # 0.12.0 -> 0.12.1 + 安卓 0.1.5->0.1.6
# 或：minor / prerelease --pre beta

# 2. 更新 CHANGELOG.md（Keep a Changelog 格式）

# 3. 提交 + Tag
git add package.json android/gradle/libs.versions.toml CHANGELOG.md
git commit -m "release: v0.12.1 — <一句话>"
git tag -a v0.12.1 -m "v0.12.1"

# 4. 推送触发 CI
git push origin main --follow-tags
```

### 4.2 Server 单独发布

```powershell
Set-Location server/app
npm version patch   # 1.0.4 -> 1.0.5（写 package.json）
Set-Location ../..
git add server/app/package.json server/CHANGELOG.md
git commit -m "release(server): v1.0.5"
git tag -a server-v1.0.5 -m "server v1.0.5"
git push origin main --follow-tags
```

### 4.3 热修

```powershell
git checkout -b release/v0.12.1 v0.12.0
# 修复...
git commit -m "fix: 热修"
git checkout main; git merge --no-ff release/v0.12.1
git tag -a v0.12.1 -m "v0.12.1"
git branch -d release/v0.12.1
git push origin main --follow-tags
```

### 4.4 回滚

- 未分发：`git revert <release-commit>` + 发 `patch`
- 已分发：关 Feature Flag（`chatEngineV2` 等），见 `PC端0.12版本实施方案 §18`
